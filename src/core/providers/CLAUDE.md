# プロバイダー（src/core/providers）の説明

エージェントの実行基盤。コア（`chat/`）はこの抽象だけを使い、Claude Code の SDK を直接呼ばない。

## 抽象（types.ts）

- `AgentProvider`: `id`・`label`・`implemented`（false なら画面は「未対応」と出し、実行を受け付けない）・CLI の状態 `status()`・1 回の実行 `run(params, callbacks, signal)`。任意の機能（`usage` / `models` / `commands` / `title` / `summarize` / `ask`（ツールを使わず 1 回だけ聞く。メモの AI の整理。`AskModel` で haiku（既定）/ sonnet）/ `fork` / `rewindFiles` / `subagentLog`（サブエージェントの会話の記録を読む。サブエージェントに子チャットで聞くときに添える）は対応しなければ持たない（ないときコアは、一覧なら空・名前は付けない・分岐と巻き戻しは 400 にする）。
- 渡すもの `ProviderTurnParams`: 作業場所・指示と、その ID `promptId`（記録の `message_uuid`）・既定のシステムプロンプトに足す文 `systemPrompt`・許可 `policy`（`ChatPolicy`）・続きのセッション `resumeSessionId`・選択（`model` / `effort` / `permissionMode` / `fastMode`。null は指定しない）・自動圧縮を始める使用率 `autoCompactPct`（設定の `auto_compact_pct`。決めていれば Claude Code に `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` で渡す。`@shared/chat/autoCompact`）・読めるフォルダ `additionalDirectories`・読むだけのパス `readOnlyPaths`・自動の圧縮の前に足す圧縮前指示 `preCompact`（AI に足す文・コンテキストウィンドウ・始めの大きさ。null なら足さない）・指示に添える文脈 `turnContext`（子チャットの親など。null なら添えない）・埋め込みブラウザ `browser`・プロジェクトの DB を読ませる口 `database`（`core/databases/aiTools.ts` の `DbAiTools`。AI に見せる接続があるときだけ）・「見せない」DB の接続のつなぎ先 `hiddenDb`（AI が直接入るのを断る）。
- 知らせ `ProviderCallbacks`: `emit`（記録になる形。`user` / `approval` / `approval_resolved` / `result` はコアが作るので含めない）・途中経過 `stream` / `subagentProgress` / `commandOutput`（実行中のコマンドの出力の終わりの部分。保存しない）・承認 `requestApproval`（回答まで待つ）・作業中の様子 `retry` / `background` / `compacting`・圧縮の直後のコンテキストの大きさ `context`（作業の終わりを待たずに入力欄のメーターへ反映するため）・圧縮の失敗 `compactFailed`（理由を渡すだけで、お知らせに残すかはコアが決める）・自動の圧縮の前に圧縮前指示を足した `preCompactSent`（足した発言の ID。記録はコアが残す）・作業中の操作 `control`（`TurnControl` の `tell` = 止めずに発言を足す / `stopTask` = 裏の作業を 1 つ止める。終わったら null）。
- 結果 `ProviderTurnResult`: 状態（`completed` / `failed` / `cancelled`）・セッション・費用・回数・コンテキストの大きさと上限・メインの会話の最後のメッセージの ID `lastMessageId`（分岐の起点）・通信の切断か `network`・使用枠の上限 `usageLimit`（枠が戻る時刻）。失敗は投げずに結果で返し、止められたら `cancelled`。
- 足すときは `index.ts` の `createProviders` に足す。Codex・Gemini はまだ使えない `planned.ts` の `PlannedProvider`（CLI が入っているかだけ確かめ、実行は断る）。認証は各 CLI のログインをそのまま使い、アプリは資格情報を持たない。

## Claude（claude/）

役割ごとにファイルを分ける:

- `provider.ts` の `ClaudeProvider`: 状態（`claude auth status`。プランは種類より表示名 `readPlanDisplayName`）・使用枠・モデル・/ のコマンド・実行・分岐（`forkSession`。作業フォルダが消えていれば、すべてのプロジェクトから探す）・ファイルを戻す・サブエージェントの会話の記録（`getSubagentMessages` で作業フォルダの記録から読み、なければすべてのプロジェクトから探す。形は `subagentLog.ts` の `subagentLogOf`: 発言・ツールの呼び出しと結果の組。思考・`<system-reminder>` は除く）・名前を付ける・メモにするため要約する（どちらも `askOnce` で haiku に 1 回だけ。空の一時フォルダで動かす。Kickoff を起動したフォルダで動かすと、そこの CLAUDE.md・自動のメモリーを読み込んで答えに混ざる）。
- `env.ts`: 同梱の Claude Code の実行ファイル（`resolveClaudeExecutable`。製品版では `app.asar.unpacked` の中）と、子プロセスの環境変数（`agentEnv`。プランで動かすため API キーの環境変数は渡さない。`KICKOFF_ALLOW_API_KEY=1` のときだけ許す）。`params.env` は実行ごとに足す環境変数で、いちばん後に重ねる（プロジェクトで選んだ GitHub のアカウントの `GH_TOKEN`。AI が動かす gh・git もそのアカウントになる）。
- `policy.ts`: 指示に文脈を添えるフック `turnContextHook`（`params.turnContext` があるときだけ。UserPromptSubmit の `additionalContext` で、実行の初めの指示にだけ添え、作業中に足した発言には添えない。Claude Code は続きのセッションではシステムプロンプトを取り直さず、セッションの記録の `prompt_snapshot` を使い回す（取り直すのは、しばらくあいてキャッシュが切れたときなど）ので、送るたびに変わる文脈・分岐したセッションに足した文脈はシステムプロンプトでは届かない）と、断るフック `turnHooks`（PreToolUse。Kickoff 自身を守る判定はいつも、参照資料への書き込みの判定は参照資料があるときだけ、「見せない」DB の接続に直接入る判定は `params.hiddenDb` があるときだけ。判定そのものは `chat/guard/`）と、`ChatPolicy` を `allowedTools` にする `toAllowedTools`（Read・Glob・Grep・TodoWrite・Web と、許すコマンドの `Bash(<コマンド>:*)`。ファイルの編集は権限モードに任せる）。
- `preCompact.ts` の `createPreCompactGate` ＋ `preCompactHook`: 自動の圧縮の前に圧縮前指示を済ませてもらう PreCompact フック（`params.preCompact` があるときだけ）。Claude Code は上限を超えていると、ツールの結果が返るたびと指示を受けた直後（区切りの圧縮も次の作業の初め）に、送る前にフックを呼び、`decision: "block"` で止めると圧縮せずに送る（止めても圧縮中のまま固まらず、何度止めても自動の圧縮を切らない）。1 回目に止めたときに指示を入力に足し（AI は次の送信から読む。文だけの返答で終わっても、同じ実行の中で次の作業として読む）、メインの返答に合図の一文（`PRE_COMPACT_DONE`）が来るまで止め続ける。止めずに通すのは、手で頼んだ圧縮・サブエージェント（`agent_id`）の圧縮・残りが少ない（始めるのに `START_MARGIN` 30k、止め続けるのに `KEEP_MARGIN` 20k）・止めた回数が `MAX_HOLDS`（8）・前に止めてから応答がないまま呼ばれた（送ったら上限を超えた = あふれたときの圧縮）・足せなかったとき。圧縮したら（区切り）次に近づいたときにまた足す。Claude Code は、圧縮してから 3 回のやり取りのうちに上限まで戻ることが 3 回続くと「Autocompact is thrashing」で作業を失敗にするので、指示は短い作業にしてもらう。
- `messages.ts` の `emitSdkMessage`: SDK のメッセージを記録の形にする（思考の時間・サブエージェントの開始と終了・圧縮の `status` / `compact_boundary`（圧縮中は `compacting` で立て、null か区切りで外す。区切りでは要約の記録 `compact` を先に出してから外す（圧縮中に預かった「いま」は外れたときに伝えるので、記録で圧縮の下に並ぶ）。`requesting` では外さない）・圧縮の失敗の理由（`compactFailed` に渡す）。裏のコマンドなど、サブエージェントでないタスクは除く）。
- `browserTools.ts` の `browserMcpServer`: Kickoff の埋め込みブラウザを AI が見る・操作するツール（SDK のプロセス内の MCP サーバー `kickoff_browser`。`params.browser`（`ExecutionDeps.browser` があるとき）があるときだけ `mcpServers` に足す）。`browser_tabs`・`browser_open`（tab_id を省くと、このプロジェクトのチャット欄に表に出さずに新しいタブを足す）・`browser_navigate`（戻る・進む・読み込み直す）・`browser_read`（押せる要素に番号 ref を振る）・`browser_screenshot`（画像）・`browser_click` / `browser_type` / `browser_press`・`browser_scroll`・`browser_eval`（ページで JavaScript）・`browser_console`。tab_id を省くと、このチャットで前に使ったタブ → このプロジェクトのタブ（いちばん新しいもの）。見るだけのツール（`browserReadOnlyTools`: tabs・read・screenshot・scroll・console）は `allowedTools` に足して聞かずに使わせ、開く・押す・打つ・JS は、ほかのツールと同じく権限モードと承認（`canUseTool`）に従う。使い方とページの文を信頼しないことは MCP の `instructions` で AI に渡す。
- `dbTools.ts` の `dbMcpServer`: プロジェクトの DB を AI が読むツール（SDK のプロセス内の MCP サーバー `kickoff_db`。`params.database` があるときだけ `mcpServers` に足す）。`db_connections`・`db_objects`・`db_describe`・`db_query`（`timeout_minutes` で 30 秒を超えて流す時間を頼める。そのときは接続の許可によらず承認を聞き、題に分を出す。実行の `signal` を渡して、チャットの作業を止めたら SQL も止める）。中身は `DbAiTools`（`src/core/CLAUDE.md` の「DB クライアント」）で、ここは引数の形と失敗の文だけ。4 つとも `allowedTools`（`dbToolNames`）に入れて `canUseTool` を通さず、承認して見せる接続の `db_query` はツールの中で `requestApproval`（`permission`・`toolName` は `mcp__kickoff_db__db_query`・入力は接続の名前と SQL・覚えない）で聞く（権限モード・Auto mode によらず必ず聞くため）。使い方とデータを信頼しないことは MCP の `instructions` で渡す。
- `approvals.ts` の `createCanUseTool`: `canUseTool` を承認依頼にし、回答を判定にする（AskUserQuestion は質問で、回答は入力に足して通す。答えなければスキップとして断る。それ以外は許可で、「常に許可」は提案された許可ルールを当てる）。依頼には呼び出し ID（`toolUseID` → `toolUseId`）と、サブエージェントの中ならそのサブエージェントの ID（`agentID` → `agentId`）を添え、画面がどのサブエージェントが待っているかを見せられるようにする。
- `input.ts` の `createInputChannel`: ストリーミング入力。最初の指示のあとも開いておき、作業中に発言を足す・裏の作業を止める（`stopTask` にも入力が開いている必要がある）。まだ渡していない発言があるうちは閉じない（足した発言を落とさない）。
- `commandOutput.ts` の `createCommandOutputWatcher`: 実行中のコマンドの出力を終わる前から届ける（SDK は Bash の出力を終わってからしか渡さず、`tool_progress` も Bash には届かない）。Claude Code はコマンドの出力をその場で `<一時フォルダ>/claude-<uid>/<作業場所>/<セッション ID>/tasks/<作業 ID>.output` に書いているので、`task_started`（`task_type: local_bash`。手前のコマンドも裏のコマンドも）が届いたらそのファイルを探し（作業場所の部分は Claude Code の内部の決まりなので計算せず、`findOutputFile` で `<セッション ID>/tasks/<作業 ID>.output` を探す。場所の候補は `defaultOutputRoots`）、0.5 秒ごとに増えた分を読んで、最後の `COMMAND_OUTPUT_LINES` 行が変わったときだけ `commandOutput` で知らせる（色の制御文字を除き、`\r` で上書きした行は最後の状態だけ `cleanTerminalText`）。`task_notification`・`task_updated` の終わりの状態・実行の終わり（`stopAll`）でやめる。15 秒探して見つからなければあきらめる（結果は今までどおり終わってから届く）。
- `background.ts` の `createBackgroundTracker`: 裏の作業は `background_tasks_changed`（いま動いているものの一覧）で丸ごと置き換え、開始・終了の知らせの組み合わせには頼らない（1 つ取りこぼしても、実行中のまま固まらない）。返答は result で書き終わり、メインの次の発言で書き始めたとみなす。作業を起動した呼び出しの ID は一覧に載らないので、開始の知らせ（task_started）で作業 ID ごとに覚えて `BackgroundTask.tool_use_id` に添える（一覧より後に届いても添え直す。画面が、裏で動かしたコマンドの呼び出しを終わるまで実行中に見せるため）。
- `usage.ts`: 使用枠の変換 `normalizeUsage`（SDK の EXPERIMENTAL な API。形が変わったらここを直す）。Claude Code の設定ファイル（`~/.claude.json`）は読むだけ。
- `labels.ts`: 文言の定数（チャット欄の / に出さないターミナル専用のコマンド `TERMINAL_ONLY_COMMANDS`・ファストモードが使われなかった理由・失敗の種類）。
- `effortDefault.ts` の `claudeEffortDefault`: 推論の深さを指定しないときに Claude Code が使う深さ（環境変数 `CLAUDE_CODE_EFFORT_LEVEL` → 作業フォルダの `.claude/settings.local.json` → `.claude/settings.json` → `~/.claude/settings.json`。各ファイルはモデルの ID ごとの `modelSettings` → 全体の `effortLevel`。どこにもなければモデル任せ。読むだけ）。API は `GET /api/projects/:id/effort-default?model=`。モデルの別名は `ModelOption.resolved_model` で ID にする。

## 実行（run）の決まり

- 設定は Claude Code と同じく読む（`settingSources` に user / project / local。システムプロンプトは `claude_code` の preset に足す）。モデル・推論の深さは決めていなければ指定しない（SDK とモデルの既定）。ファストモードを指定したのに使われなかったら、理由をお知らせに残す。
- 入力はストリーミングで、作業中の操作を `control` で渡す。返答を書き終え、裏の作業もなくなったら入力を閉じて Claude Code を終わらせる。止めるとプロセスごと終わり、サブエージェント・裏のコマンドも止まる。
- `enableFileCheckpointing` で編集の前のファイルを取っておき、指示には `promptId` を `uuid` として渡す（巻き戻しでその発言の時点に戻すため）。
- 通信の再試行（`api_retry`）は `retry` で知らせ、返答が届き始めたら null。応答のないまま（`error_status` が null）の再試行があった・失敗の文が `isNetworkError` なら、失敗は通信の切断（`network`）。
- 使用枠: `rate_limit_event` の `rejected`（戻る時刻は `resetTimeOf`）・返答のエラー `rate_limit`・失敗の文の `isUsageLimitError` で `usageLimit` を付ける。
- コンテキストの大きさは、メインエージェントの最後の応答のトークン数（要約のあとは `compact_boundary` の `post_tokens`）と、使ったモデルのうちいちばん大きいコンテキストウィンドウ（サブエージェントの小さいモデルを除くため）。自動の圧縮は作業の途中で起きるので、要約したら作業の終わりを待たずに `context` で知らせる（`post_tokens` があればその値、なければ要約のあとの最初のメインの応答のトークン数）。
- 使用枠・モデル・/ のコマンド・ファイルを戻すは、メッセージを送らないセッションを一瞬開いて、制御用の API だけを呼ぶ（`withIdleSession`。モデルへのリクエストがないので枠を使わない）。モデル（1 時間）と / のコマンド（作業場所ごとに 5 分）の一覧は、ルート（`http/routes/providers.ts`）で `ttlCache` に覚える（空の結果は覚えない）。
