# プロバイダー（src/core/providers）の説明

エージェントの実行基盤。コア（`chat/`）はこの抽象だけを使い、Claude Code の SDK を直接呼ばない。

## 抽象（types.ts）

- `AgentProvider`: `id`・`label`・`implemented`（false なら画面は「未対応」と出し、実行を受け付けない）・CLI の状態 `status()`・1 回の実行 `run(params, callbacks, signal)`。任意の機能（`usage` / `models` / `commands` / `title` / `summarize` / `ask`（ツールを使わず 1 回だけ聞く。メモの AI の整理。`AskModel` で haiku（既定）/ sonnet）/ `fork` / `rewindFiles` / `subagentLog`（サブエージェントの会話の記録を読む。サブエージェントに子チャットで聞くときに添える）/ `discardSessions`（消したチャットのセッションの記録をゴミ箱へ移す。`chat/sessionCleanup.ts`）は対応しなければ持たない（ないときコアは、一覧なら空・名前は付けない・分岐と巻き戻しは 400 にする・記録は残す）。
- 渡すもの `ProviderTurnParams`: 作業場所・指示と、その ID `promptId`（記録の `message_uuid`）・既定のシステムプロンプトに足す文 `systemPrompt`・許可 `policy`（`ChatPolicy`）・続きのセッション `resumeSessionId`・選択（`model` / `effort` / `permissionMode` / `fastMode`。null は指定しない）・自動圧縮を始める使用率 `autoCompactPct`（設定の `auto_compact_pct`。決めていれば Claude Code に `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` で渡す。`@shared/chat/autoCompact`）・読めるフォルダ `additionalDirectories`・読むだけのパス `readOnlyPaths`・Git で管理していないファイルだけを書けるか `untrackedOnly`（`turnHooks` が `evaluateUntrackedWrite` のフックを付ける）・自動の圧縮の前に足す圧縮前指示 `preCompact`（AI に足す文・コンテキストウィンドウ・始めの大きさ。null なら足さない）・指示に添える文脈 `turnContext`（子チャットの親など。null なら添えない）・埋め込みブラウザ `browser`・プロジェクトの DB を読ませる口 `database`（`core/databases/aiTools.ts` の `DbAiTools`。AI に見せる接続があるときだけ）・「見せない」DB の接続のつなぎ先 `hiddenDb`（AI が直接入るのを断る）・AI の Docker の守り `dockerGuard`（`chat/guard/dockerGuard.ts` の `DockerGuard`。null なら付けない）。
- 知らせ `ProviderCallbacks`: `emit`（記録になる形。`user` / `approval` / `approval_resolved` / `result` はコアが作るので含めない）・途中経過 `stream` / `subagentProgress` / `commandOutput`（実行中のコマンドの出力の終わりの部分。保存しない）・承認 `requestApproval`（回答まで待つ）・作業中の様子 `retry` / `background` / `compacting` / `drawingVisual`（図のツールの中身を書いている途中。`messages.ts` が `content_block_start` / `content_block_stop` の tool_use の名前で見る。メインエージェントだけ）・圧縮の直後のコンテキストの大きさ `context`（作業の終わりを待たずに入力欄のメーターへ反映するため）・圧縮の失敗 `compactFailed`（理由を渡すだけで、お知らせに残すかはコアが決める）・自動の圧縮の前に圧縮前指示を足した `preCompactSent`（足した発言の ID。記録はコアが残す）・合図のあとに止まったので圧縮を走らせる発言を足した `preCompactNudged`（記録はコアがお知らせで残す）・作業中の操作 `control`（`TurnControl` の `tell` = 止めずに発言を足す / `stopTask` = 裏の作業を 1 つ止める。終わったら null）。
- 結果 `ProviderTurnResult`: 状態（`completed` / `failed` / `cancelled`）・セッション・費用・回数・コンテキストの大きさと上限・メインの会話の最後のメッセージの ID `lastMessageId`（分岐の起点）・通信の切断か `network`・使用枠の上限 `usageLimit`（枠が戻る時刻）。失敗は投げずに結果で返し、止められたら `cancelled`。
- 足すときは `index.ts` の `createProviders` に足す。Codex・Gemini はまだ使えない `planned.ts` の `PlannedProvider`（CLI が入っているかだけ確かめ、実行は断る）。認証は各 CLI のログインをそのまま使い、アプリは資格情報を持たない。

## Claude（claude/）

役割ごとにファイルを分ける:

- `provider.ts` の `ClaudeProvider`: 状態（`claude auth status`。プランは種類より表示名 `readPlanDisplayName`）・使用枠・モデル・/ のコマンド・実行・分岐（`forkSession`。作業フォルダが消えていれば、すべてのプロジェクトから探す。下の `sessionFiles.ts` で直近の区切り（`fork` の `keep`。既定 3、子チャットは `CHILD_FORK_KEEP` の 1）だけの一時のセッションを作ってからそれを写し、写したら一時のセッションを消す。切り出せない・写せなければ丸ごと写す）・消したチャットのセッションの記録をゴミ箱へ（`discardSessions`）・長いチャットの乗り換え（`trimSession`。下の `trimToRecentSegments`）・会話記録の大きさ（`sessionsSize`。アーカイブ済みのチャットの整理の見込み）・ファイルを戻す・サブエージェントの会話の記録（`getSubagentMessages` で作業フォルダの記録から読み、なければすべてのプロジェクトから探す。形は `subagentLog.ts` の `subagentLogOf`: 発言・ツールの呼び出しと結果の組。思考・`<system-reminder>` は除く）・名前を付ける・メモにするため要約する（どちらも `askOnce` で haiku に 1 回だけ。会話記録は残さない `persistSession: false`（残すとチャットを作るたびに使わない記録が増えていた）。空の一時フォルダで動かす。Kickoff を起動したフォルダで動かすと、そこの CLAUDE.md・自動のメモリーを読み込んで答えに混ざる）。
- `sessionFiles.ts`: Claude Code の会話記録のファイル（`<CLAUDE_CONFIG_DIR か ~/.claude>/projects/<作業フォルダの英数字以外を - にした名前>/<セッション ID>.jsonl`。場所は Claude Code の内部の決まりなので、作業フォルダから決まる場所になければすべてのプロジェクトのフォルダを探す `findSessionFile`）を扱う。Claude Code は圧縮しても古いやり取りを消さず、印（`compact_boundary`）を書き足すだけで、続きのセッションでは最後の印から後ろだけを読む。それで長く続けたチャットの記録は 1GB を超え、`forkSession` が丸ごと写して 1 回ごとに十数秒・1GB かかった。分岐する位置（`messageId` の行）の手前の直近 `keep` 個（既定 `FORK_KEEP_SEGMENTS` = 3。同じ会話を続けるもの。子チャットは 1。メモの仕様書「ファイル削除」の Q18。2026-11-14 に 11-13 の「どれも 2」から改めた）の区切りを、ファイルを後ろから読んで（`recentSegmentsRange`。全部をメモリに持たない）切り出し、別の ID の一時のセッションとして同じフォルダに書く（`writeRecentSegments`。記録の `sessionId` の欄だけ置き換える。SDK で写したあとのファイルを切り詰めると続きで会話を覚えていなかったので、写す前の元を切る）。消したチャットの記録と同じ名前のフォルダ（サブエージェントの記録など）は `trashSessions` でゴミ箱へ。長いチャットの乗り換え（`trimToRecentSegments`）は、終わりの直近 3 区切りだけを新しい ID のセッションとして同じフォルダに書く（`forkSession` を通さないので、発言の ID とファイルの控え `file-history-snapshot` がそのまま残り、残した区切りの中の発言へは巻き戻し・「ファイルを戻す」ができる。最初の行が圧縮の印のファイルを Claude Code がそのまま続けられ、会話を覚えていることを 2026-11-14 に確かめた）。区切りが 3 つに足りなければ切らない。同じ名前のフォルダ（サブエージェントの記録など）は新しいセッションの名前に移す（乗り換えたあとも前のサブエージェントの会話を読めるように）。会話記録の様子（頭の作業フォルダと最初の発言 `readSessionHead`・`sessionFileInfo`・すべての記録 `listSessionFiles`）もここ。テストは `sessionFiles.test.ts`。
- `env.ts`: 同梱の Claude Code の実行ファイル（`resolveClaudeExecutable`。製品版では `app.asar.unpacked` の中）と、子プロセスの環境変数（`agentEnv`。プランで動かすため API キーの環境変数は渡さない。`KICKOFF_ALLOW_API_KEY=1` のときだけ許す）。`params.env` は実行ごとに足す環境変数で、いちばん後に重ねる（プロジェクトで選んだ GitHub のアカウントの `GH_TOKEN`。AI が動かす gh・git もそのアカウントになる）。
- `policy.ts`: 指示に文脈を添えるフック `turnContextHook`（`params.turnContext` があるときだけ。UserPromptSubmit の `additionalContext` で、実行の初めの指示にだけ添え、作業中に足した発言には添えない。Claude Code は続きのセッションではシステムプロンプトを取り直さず、セッションの記録の `prompt_snapshot` を使い回す（取り直すのは、しばらくあいてキャッシュが切れたときなど）ので、送るたびに変わる文脈・分岐したセッションに足した文脈はシステムプロンプトでは届かない）と、断るフック `turnHooks`（PreToolUse。Kickoff 自身を守る判定はいつも、参照資料への書き込みの判定は参照資料があるときだけ、「見せない」DB の接続に直接入る判定は `params.hiddenDb` があるときだけ、ファイルを消すコマンドの判定は `params.deleteGuard` のときだけ。判定そのものは `chat/guard/`）と、Docker の守りのフック `dockerGuardHook`（`params.dockerGuard` があるとき。Bash の前に判定を待ち、聞くなら `cb.requestApproval`（`permission`・Bash・`canRemember: false`・`tool_use_id` とサブエージェントの ID）で承認カードを出して答えを待つ。許せば流し、断られたら `permissionDecision: "deny"` と利用者の言葉。待ち時間 `timeout` は 7 日（書かないと Claude Code の既定の待ち時間で止める知らせが来て、答える前にカードが閉じて拒否になるため）。権限モードに関係なく効く。`turnHooks(params, self, cb)` が付ける）と、`ChatPolicy` を `allowedTools` にする `toAllowedTools`（Read・Glob・Grep・TodoWrite・Web と、許すコマンドの `Bash(<コマンド>:*)`。ファイルの編集は権限モードに任せる）。
- `preCompact.ts` の `createPreCompactGate` ＋ `preCompactHook`: 自動の圧縮の前に圧縮前指示を済ませてもらう PreCompact フック（`params.preCompact` があるときだけ）。Claude Code は上限を超えていると、ツールの結果が返るたびと指示を受けた直後（区切りの圧縮も次の作業の初め）に、送る前にフックを呼び、`decision: "block"` で止めると圧縮せずに送る（止めても圧縮中のまま固まらず、何度止めても自動の圧縮を切らない）。1 回目に止めたときに指示を入力に足し（AI は次の送信から読む。文だけの返答で終わっても、同じ実行の中で次の作業として読む）、メインの返答に合図の一文（`PRE_COMPACT_DONE`）が来るまで止め続ける。止めずに通すのは、手で頼んだ圧縮・サブエージェント（`agent_id`）の圧縮・残りが少ない（始めるのに `START_MARGIN` 30k、止め続けるのに `KEEP_MARGIN` 20k）・止めた回数が `MAX_HOLDS`（8）・前に止めてから応答がないまま呼ばれた（送ったら上限を超えた = あふれたときの圧縮）・足せなかったとき。圧縮したら（区切り）次に近づいたときにまた足す。合図のあとの圧縮は Claude Code が次に送るとき（ツールの結果・指示を受けたとき）に始まるので、AI が合図だけを書いてツールを呼ばずに返答を終え、裏の作業（開発サーバー・`tail -f`・監視など、自分では終わらないもの）の終わりだけを待つと、いつまでも始まらなかった（2026-11-13 に、開発版を裏で動かしたまま合図を書いたチャットが 7 分止まった）。そこで、合図のあとに Claude Code が手の空いたまま裏の作業だけを待っている（`turnOver.ts` の `waitingOnBackground`: 裏の作業があり、`session_state_changed` が `idle`。出さない古い Claude Code では返答の終わり）状態が `PRE_COMPACT_NUDGE_MS`（5 秒。`TURN_OVER_GRACE_MS` より長くし、Claude Code が自分で次を始めるときは足さない）続いたら、ゲートの `noteWaiting` が `@shared/chat/prompts` の `PRE_COMPACT_NUDGE`（Kickoff が送った・圧縮のあとは届く指示に従って作業を続ける、という文）を圧縮前指示と同じ `push` で 1 回だけ足して送らせ、圧縮を走らせる（圧縮したら、いつもどおりコアが圧縮後指示から続ける）。その前に動き出した・裏の作業がなくなった（入力を閉じて作業が終わる。続けての圧縮はコア）・圧縮が走ったら足さない。足したら `preCompactNudged`。Claude Code は、圧縮してから 3 回のやり取りのうちに上限まで戻ることが 3 回続くと「Autocompact is thrashing」で作業を失敗にするので、指示は短い作業にしてもらう。
- `messages.ts` の `emitSdkMessage`: SDK のメッセージを記録の形にする（思考の時間・サブエージェントの開始と終了・圧縮の `status` / `compact_boundary`（圧縮中は `compacting` で立て、null か区切りで外す。区切りでは要約の記録 `compact` を先に出してから外す（圧縮中に預かった「いま」は外れたときに伝えるので、記録で圧縮の下に並ぶ）。`requesting` では外さない）・圧縮の失敗の理由（`compactFailed` に渡す）。裏のコマンドなど、サブエージェントでないタスクは除く）。
- `browserTools.ts` の `browserMcpServer`: Kickoff の埋め込みブラウザを AI が見る・操作するツール（SDK のプロセス内の MCP サーバー `kickoff_browser`。`params.browser`（`ExecutionDeps.browser` があるとき）があるときだけ `mcpServers` に足す）。`browser_tabs`・`browser_open`（tab_id を省くと、このプロジェクトのチャット欄に新しいタブを足す）・`browser_navigate`（戻る・進む・読み込み直す）・`browser_read`（押せる要素に番号 ref を振る）・`browser_screenshot`（画像）・`browser_click` / `browser_type` / `browser_press`・`browser_scroll`・`browser_eval`（ページで JavaScript）・`browser_console`。tab_id を省くと、このチャットで前に使ったタブ → このプロジェクトのタブ（いちばん新しいもの）。見るだけのツール（`browserReadOnlyTools`: tabs・read・screenshot・scroll・console）は `allowedTools` に足して聞かずに使わせ、開く・押す・打つ・JS は、ほかのツールと同じく権限モードと承認（`canUseTool`）に従う。作業（Turn）の初めにタブを使うとき（新しいタブを開く・その作業で初めて既存のタブを操作する）1 回だけ、そのタブのある欄を開いて表に出す（`browserReveal.ts` の `turnReveal`。MCP サーバーは作業ごとに作るので、覚えは作業ごと。利用者が AI の操作に気づけるように。Auto mode では承認カードが出ないため。利用者と決めた）。そのあと別のタブに移ったときは、利用者がまだ前に表に出したタブを見ているときだけ切り替え（`RevealRequest` の `after`）、出せなかった（利用者がほかのタブに切り替えた・欄を閉じた）なら、その作業の間はもう出さない。出すときは画面が出し終え、ページが開いた欄の大きさで並ぶまで待ってから操作する。どのツールにも `background`（利用者が「裏で」と言ったときだけ付ける。その作業の間は表に出さない）がある。使い方とページの文を信頼しないことは MCP の `instructions` で AI に渡す。
- `dbTools.ts` の `dbMcpServer`: プロジェクトの DB を AI が読むツール（SDK のプロセス内の MCP サーバー `kickoff_db`。`params.database` があるときだけ `mcpServers` に足す）。`db_connections`・`db_objects`・`db_describe`・`db_query`（`timeout_minutes` で 30 秒を超えて流す時間を頼める。そのときは接続の許可によらず承認を聞き、題に分を出す。実行の `signal` を渡して、チャットの作業を止めたら SQL も止める）。中身は `DbAiTools`（`src/core/CLAUDE.md` の「DB クライアント」）で、ここは引数の形と失敗の文だけ。4 つとも `allowedTools`（`dbToolNames`）に入れて `canUseTool` を通さず、承認して見せる接続の `db_query` はツールの中で `requestApproval`（`permission`・`toolName` は `mcp__kickoff_db__db_query`・入力は接続の名前と SQL・覚えない）で聞く（権限モード・Auto mode によらず必ず聞くため）。使い方とデータを信頼しないことは MCP の `instructions` で渡す。
- `chatTools.ts` の `chatMcpServer`: AI が Kickoff のチャットなどを操作するツール（SDK のプロセス内の MCP サーバー `kickoff_chat`。`ChatTools` = `params.createChat`・`params.chatEdit`・`params.open`・`params.chatRead`・`params.chatProject`・`params.chatTerminal`・`params.chatVisual`・`params.chatWorktree`・`params.chatNotify`・`params.chatUserView`・`params.chatRemove` のどれかがあれば `mcpServers` に足し、渡すツールだけを入れる。MCP の `instructions` も渡すツールの分だけ）。名前・固定・グループのツール（`list_family_chats`・`update_chat`。`params.chatEdit`）: `list_family_chats` は引数なしで、同じ家系のチャットとグループの一覧（JSON によらず。利用者がいつでも戻せるため）。中身は `AiChatEditTools`（`src/core/chat/CLAUDE.md` の「子チャット」の AI が変える家系のチャット）で、断るときは理由の文を `isError` で返す。チャットを作るツール（`create_chat`。`params.createChat` があるときだけ。前の版の `create_child_chat` をまとめた）は、引数は作る場所 `relation`（`child` / `sibling` / `root`。必須）・依頼の文 `text`・名前 `title`（省ける）・グループ `group_id`（root だけ）・新しいワークツリーのブランチ `worktree_branch`・会話を引き継ぐか `inherit`（既定は child が true、ほかは false）。中身は `AiCreateChatTools`（`src/core/chat/CLAUDE.md` の「子チャット」の AI が作るチャット）で、ここは引数の形と失敗の文と承認の聞き方だけ。`allowedTools`（`chatToolNames`）に入れて `canUseTool` を通さず、設定が「毎回聞く」なら、ツールの中で `requestApproval`（`permission`・`toolName` は `AI_CREATE_CHAT_TOOL`・入力は何を作るか・依頼・名前・引き継ぐか・グループ・ブランチ・作業場所の説明・見出しと説明は `approvalText`・覚える `canRemember: true`）で聞く（権限モード・Auto mode によらず必ず聞くため）。「常に許可」は Claude Code の許可ルールにせず、中身が設定を「聞かずに作る」にする。使い方（利用者が頼んだときだけ・自分で分けるならサブエージェント・作るだけで答えは返らない・引き継げるのはいまの作業より前まで・root は家系の外）は MCP の `instructions` ## 実行（run）の決まり

- 設定は Claude Code と同じく読む（`settingSources` に user / project / local。システムプロンプトは `claude_code` の preset に足す）。モデル・推論の深さは決めていなければ指定しない（SDK とモデルの既定）。ファストモードを指定したのに使われなかったら、理由をお知らせに残す。
- 入力はストリーミングで、作業中の操作を `control` で渡す。Claude Code の手が空き、裏の作業もなくなったら入力を閉じて終わらせる（`turnOver.ts` の `createTurnOver`）。目印は Claude Code の `session_state_changed` の `idle`（`env.ts` が `CLAUDE_CODE_EMIT_SESSION_STATE_EVENTS` で頼む）で、返答の終わり（`result`）だけでは閉じない: 返答の終わりの直前に届いた発言・裏の作業の終わりの知らせがあると、Claude Code は次の返答を続けるため（前は `result` と裏の作業 0 件で閉じていて、その続きの返答の間ずっと、作業中の発言が足せず送信待ちに戻った。利用者の指摘）。前の `running` のあとに発言を足していた `idle` と、`idle` の間に裏の作業が 0 件になったとき（Claude Code は 0 件を知らせてから終わりの知らせへの返答を始める）は、`TURN_OVER_GRACE_MS`（2 秒）だけ待ち、その間に返答を始めたらその返答の `idle` まで待つ。`session_state_changed` を出さない古い Claude Code では、返答の終わりと裏の作業 0 件で閉じる。止めるとプロセスごと終わり、サブエージェント・裏のコマンドも止まる。
- `enableFileCheckpointing` で編集の前のファイルを取っておき、指示には `promptId` を `uuid` として渡す（巻き戻しでその発言の時点に戻すため）。
- 通信の再試行（`api_retry`）は `retry` で知らせ、返答が届き始めたら null。応答のないまま（`error_status` が null）の再試行があった・失敗の文が `isNetworkError` なら、失敗は通信の切断（`network`）。
- 使用枠: `rate_limit_event` の `rejected`（戻る時刻は `resetTimeOf`）・返答のエラー `rate_limit`・失敗の文の `isUsageLimitError` で `usageLimit` を付ける。
- コンテキストの大きさは、メインエージェントの最後の応答のトークン数（要約のあとは `compact_boundary` の `post_tokens`）と、使ったモデルのうちいちばん大きいコンテキストウィンドウ（サブエージェントの小さいモデルを除くため）。自動の圧縮は作業の途中で起きるので、要約したら作業の終わりを待たずに `context` で知らせる（`post_tokens` があればその値、なければ要約のあとの最初のメインの応答のトークン数）。
- 使用枠・モデル・/ のコマンド・ファイルを戻すは、メッセージを送らないセッションを一瞬開いて、制御用の API だけを呼ぶ（`withIdleSession`。モデルへのリクエストがないので枠を使わない）。モデル（1 時間）と / のコマンド（作業場所ごとに 5 分）の一覧は、ルート（`http/routes/providers.ts`）で `ttlCache` に覚える（空の結果は覚えない）。
