# プロバイダー（src/core/providers）の説明

エージェントの実行基盤。コア（`chat/`）はこの抽象だけを使い、Claude Code の SDK を直接呼ばない。

## 抽象（types.ts）

- `AgentProvider`: `id`・`label`・`implemented`（false なら画面は「未対応」と出し、実行を受け付けない）・CLI の状態 `status()`・1 回の実行 `run(params, callbacks, signal)`。任意の機能（`usage` / `models` / `commands` / `title` / `summarize` / `ask`（ツールを使わず 1 回だけ聞く。メモの AI の整理。`AskModel` の段で light（既定。軽い問い合わせ）/ standard（文を書き直すなど）。どのモデルに当てるかはプロバイダー（Claude は haiku / sonnet）。メモの仕様書「0021」の Q5）/ `fork` / `rewindFiles` / `subagentLog`（サブエージェントの会話の記録を読む。サブエージェントに子チャットで聞くときに添える）/ `discardSessions`（消したチャットのセッションの記録をゴミ箱へ移す。`chat/sessionCleanup.ts`）は対応しなければ持たない（ないときコアは、一覧なら空・名前は付けない・分岐と巻き戻しは 400 にする・記録は残す）。
- 渡すもの `ProviderTurnParams`: 作業場所・指示と、その ID `promptId`（記録の `message_uuid`）・既定のシステムプロンプトに足す文 `systemPrompt`・許可 `policy`（`ChatPolicy`）・続きのセッション `resumeSessionId`・選択（`model` / `effort` / `permissionMode` / `fastMode`。null は指定しない）・自動圧縮を始める使用率 `autoCompactPct`（設定の `auto_compact_pct`。決めていれば Claude Code に `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` で渡す。`@shared/chat/autoCompact`）・読めるフォルダ `additionalDirectories`・読むだけのパス `readOnlyPaths`・Git で管理していないファイルだけを書けるか `untrackedOnly`（`turnHooks` が `evaluateUntrackedWrite` のフックを付ける）・自動の圧縮の前に足す圧縮前指示 `preCompact`（AI に足す文・コンテキストウィンドウ・始めの大きさ。null なら足さない）・指示に添える文脈 `turnContext`（子チャットの親など。null なら添えない）・AI の操作ツールの口 `tools`（下）・埋め込みブラウザ `browser`・プロジェクトの DB を読ませる口 `database`（`core/databases/aiTools.ts` の `DbAiTools`。AI に見せる接続があるときだけ）・「見せない」DB の接続のつなぎ先 `hiddenDb`（AI が直接入るのを断る）・AI の Docker の守り `dockerGuard`（`chat/guard/dockerGuard.ts` の `DockerGuard`。null なら付けない）・AI の書き込み先の守り `writeScope`（`chat/guard/writeScope.ts` の `WriteScopeParams`: いつも書けるフォルダ・作業場所の一覧・「このチャットでは許可」で許したファイル。null なら付けない）・AI の Bash の砂場 `bashSandbox`（`chat/sandbox/bashSandbox.ts` の `BashSandbox`: 書けるフォルダ・書かせないフォルダ・砂場の外で流すコマンド・通信の中継のポート。プロバイダーが自分の砂場の設定に直す。null ならかけない）。
- 知らせ `ProviderCallbacks`: `emit`（記録になる形。`user` / `approval` / `approval_resolved` / `result` はコアが作るので含めない）・途中経過 `stream` / `subagentProgress` / `commandOutput`（実行中のコマンドの出力の終わりの部分。保存しない）・承認 `requestApproval`（回答まで待つ）・作業中の様子 `retry` / `background` / `compacting` / `drawingVisual`（図のツールの中身を書いている途中。`messages.ts` が `content_block_start` / `content_block_stop` の tool_use の名前で見る。メインエージェントだけ）・圧縮の直後のコンテキストの大きさ `context`（作業の終わりを待たずに入力欄のメーターへ反映するため）・圧縮の失敗 `compactFailed`（理由を渡すだけで、お知らせに残すかはコアが決める）・自動の圧縮の前に圧縮前指示を足した `preCompactSent`（足した発言の ID。記録はコアが残す）・合図のあとに止まったので圧縮を走らせる発言を足した `preCompactNudged`（記録はコアがお知らせで残す）・作業中の操作 `control`（`TurnControl` の `tell` = 止めずに発言を足す / `stopTask` = 裏の作業を 1 つ止める。終わったら null）。
- 結果 `ProviderTurnResult`: 状態（`completed` / `failed` / `cancelled`）・セッション・費用・回数・コンテキストの大きさと上限・メインの会話の最後のメッセージの ID `lastMessageId`（分岐の起点）・通信の切断か `network`・使用枠の上限 `usageLimit`（枠が戻る時刻）。失敗は投げずに結果で返し、止められたら `cancelled`。
- 足すときは `index.ts` の `createProviders` に足す（AI の一覧は `@shared/types` の `PROVIDER_IDS`、名前は `PROVIDER_LABELS`）。Codex・GitHub Copilot・Cursor・Gemini（Antigravity）はまだ使えない `planned.ts` の `PlannedProvider`（CLI（`codex`・`copilot`・`agent`・`agy`）が入っているかだけ確かめ、実行は断る。本物の CLI・アカウントで確かめるまで画面では「対応予定」）。作ってあっても確かめる前のもの（いまは Codex・GitHub Copilot）は、開発用の環境変数 `KICKOFF_EXPERIMENTAL_PROVIDERS`（, 区切りの ID。`experimentalProviders`）のときだけ本物の実装を使う。対応はメモの仕様書「0021_Codex・Copilot・Cursor 対応」。名前を付ける・要約の頼み方はプロバイダーに依らない `askPrompts.ts`。
- チャットごとの AI（Q1・Q8）: チャットの `provider` は作るときに決め（新しいチャット・子チャットの本文の `provider`、AI の create_chat の `provider`。省けばプロジェクトの AI、子チャットは親の AI）、途中では変えない。親と違う AI の子チャットは会話を引き継がない（セッションの形が違う）。
- できること（Q4）: `features.ts` の `providerFeatures` が任意の機能を持つかから `ProviderFeature` の一覧を作り、`GET /api/providers` の `features` で画面に渡す（画面はないものを理由付きで押せない形にする）。コアが断るときの文も同じ `providerFeatureMissing`（「Codex のチャットでは分岐・巻き戻しは使えません」）。
- ログインの仕方（Q13）: 設定の `provider_auth`（AI ごとに `subscription` = 各 CLI のログイン・定額のプラン / `api_key` = API キー。省けば subscription）。API キーは `keys.ts` の `ProviderKeyVault` が `secrets` の `provider_api_key:<AI>` に safeStorage で暗号化して置き（`system/sealedSecret.ts` の `sealSecret` / `openSecret`。DB のパスワードと同じ形）、`PUT /api/providers/:id/api-key`（本文 `{ key }`。null・空で消す。204）で置く。応答・SSE にはキーを出さず `has_api_key` だけ。実行のたびに `turn.ts` が `authFor` で開いて `ProviderTurnParams.auth` に渡し、API キーの設定なのに開けなければ分かる文で失敗にする。キーを AI に読ませないため、CLI のログインの口があればそれを使い、環境変数で渡すのは CLI が子プロセスから外せると確かめたものだけ（Claude Code は `ANTHROPIC_API_KEY` と `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB`。`env.ts` の `claudeAuthEnv`）。Codex の Sign in with ChatGPT のトークンの置き場の名前 `codex_chatgpt_tokens` は取ってあるが、いまの道（下の Codex の認証）では Codex が自分の置き場に書くので使わない。サブスクのときは今までどおり各 CLI のログインをそのまま使い、アプリは資格情報を持たない。
- AI の操作ツール（埋め込みブラウザ・DB・チャット）はプロバイダーが作らない: `turn.ts` がコアの MCP サーバーに実行ごとの鍵で出し（`src/core/CLAUDE.md` の「AI の操作ツール（mcp/）」）、`ProviderTurnParams.tools`（`ToolEndpoint`: 名前・URL・鍵の見出し・聞かずに使わせるツール）で渡す。プロバイダーはそれを自分の CLI の MCP の登録の書き方にするだけ。ツールの中身の口（`browser`・`database`・`createChat` など）は `turn.ts` がツールを作るのに使う。

## Claude（claude/）

役割ごとにファイルを分ける:

- `provider.ts` の `ClaudeProvider`: 状態（`claude auth status`。プランは種類より表示名 `readPlanDisplayName`）・使用枠・モデル・/ のコマンド・実行・分岐（`forkSession`。作業フォルダが消えていれば、すべてのプロジェクトから探す。下の `sessionFiles.ts` で直近の区切り（`fork` の `keep`。既定 3、子チャットは `CHILD_FORK_KEEP` の 1）だけの一時のセッションを作ってからそれを写し、写したら一時のセッションを消す。切り出せない・写せなければ丸ごと写す）・消したチャットのセッションの記録をゴミ箱へ（`discardSessions`）・長いチャットの乗り換え（`trimSession`。下の `trimToRecentSegments`）・会話記録の大きさ（`sessionsSize`。アーカイブ済みのチャットの整理の見込み）・ファイルを戻す・サブエージェントの会話の記録（`getSubagentMessages` で作業フォルダの記録から読み、なければすべてのプロジェクトから探す。形は `subagentLog.ts` の `subagentLogOf`: 発言・ツールの呼び出しと結果の組。思考・`<system-reminder>` は除く）・名前を付ける・メモにするため要約する（どちらも `askOnce` で haiku に 1 回だけ。会話記録は残さない `persistSession: false`（残すとチャットを作るたびに使わない記録が増えていた）。空の一時フォルダで動かす。Kickoff を起動したフォルダで動かすと、そこの CLAUDE.md・自動のメモリーを読み込んで答えに混ざる）。
- `sessionFiles.ts`: Claude Code の会話記録のファイル（`<CLAUDE_CONFIG_DIR か ~/.claude>/projects/<作業フォルダの英数字以外を - にした名前>/<セッション ID>.jsonl`。場所は Claude Code の内部の決まりなので、作業フォルダから決まる場所になければすべてのプロジェクトのフォルダを探す `findSessionFile`）を扱う。Claude Code は圧縮しても古いやり取りを消さず、印（`compact_boundary`）を書き足すだけで、続きのセッションでは最後の印から後ろだけを読む。それで長く続けたチャットの記録は 1GB を超え、`forkSession` が丸ごと写して 1 回ごとに十数秒・1GB かかった。分岐する位置（`messageId` の行）の手前の直近 `keep` 個（既定 `FORK_KEEP_SEGMENTS` = 3。同じ会話を続けるもの。子チャットは 1。メモの仕様書「ファイル削除」の Q18。2026-11-14 に 11-13 の「どれも 2」から改めた）の区切りを、ファイルを後ろから読んで（`recentSegmentsRange`。全部をメモリに持たない）切り出し、別の ID の一時のセッションとして同じフォルダに書く（`writeRecentSegments`。記録の `sessionId` の欄だけ置き換える。SDK で写したあとのファイルを切り詰めると続きで会話を覚えていなかったので、写す前の元を切る）。消したチャットの記録と同じ名前のフォルダ（サブエージェントの記録など）は `trashSessions` でゴミ箱へ。長いチャットの乗り換え（`trimToRecentSegments`）は、終わりの直近 3 区切りだけを新しい ID のセッションとして同じフォルダに書く（`forkSession` を通さないので、発言の ID とファイルの控え `file-history-snapshot` がそのまま残り、残した区切りの中の発言へは巻き戻し・「ファイルを戻す」ができる。最初の行が圧縮の印のファイルを Claude Code がそのまま続けられ、会話を覚えていることを 2026-11-14 に確かめた）。区切りが 3 つに足りなければ切らない。同じ名前のフォルダ（サブエージェントの記録など）は新しいセッションの名前に移す（乗り換えたあとも前のサブエージェントの会話を読めるように）。会話記録の様子（頭の作業フォルダと最初の発言 `readSessionHead`・`sessionFileInfo`・すべての記録 `listSessionFiles`）もここ。テストは `sessionFiles.test.ts`。
- `env.ts`: 同梱の Claude Code の実行ファイル（`resolveClaudeExecutable`。製品版では `app.asar.unpacked` の中）と、子プロセスの環境変数（`agentEnv`。プランで動かすため API キーの環境変数は渡さない。`KICKOFF_ALLOW_API_KEY=1` のときだけ許す）。`params.env` は実行ごとに足す環境変数で、いちばん後に重ねる（プロジェクトで選んだ GitHub のアカウントの `GH_TOKEN`。AI が動かす gh・git もそのアカウントになる）。
- `policy.ts`: 指示に文脈を添えるフック `turnContextHook`（`params.turnContext` があるときだけ。UserPromptSubmit の `additionalContext` で、実行の初めの指示にだけ添え、作業中に足した発言には添えない。Claude Code は続きのセッションではシステムプロンプトを取り直さず、セッションの記録の `prompt_snapshot` を使い回す（取り直すのは、しばらくあいてキャッシュが切れたときなど）ので、送るたびに変わる文脈・分岐したセッションに足した文脈はシステムプロンプトでは届かない）と、断るフック `turnHooks`（PreToolUse。Kickoff 自身を守る判定はいつも、参照資料への書き込みの判定は参照資料があるときだけ、「見せない」DB の接続に直接入る判定は `params.hiddenDb` があるときだけ、ファイルを消すコマンドの判定は `params.deleteGuard` のときだけ。判定そのものは `chat/guard/`）と、Docker の守りのフック `dockerGuardHook`（`params.dockerGuard` があるとき。Bash の前に判定を待ち、聞くなら `cb.requestApproval`（`permission`・Bash・`canRemember: false`・`tool_use_id` とサブエージェントの ID）で承認カードを出して答えを待つ。許せば流し、断られたら `permissionDecision: "deny"` と利用者の言葉。待ち時間 `timeout` は 7 日（書かないと Claude Code の既定の待ち時間で止める知らせが来て、答える前にカードが閉じて拒否になるため）。権限モードに関係なく効く。`turnHooks(params, self, cb)` が付ける）と、書き込み先の守りのフック `writeScopeHook`（`params.writeScope` があるとき。Write / Edit / MultiEdit / NotebookEdit の前に、Claude Code の例外（計画・メモリのフォルダ）を足して `judgeFileWrite` で判定する。ほかの作業場所は断る。外は `cb.requestApproval`（`permission`・`canRemember: true`・`rememberScope: "chat"`）で聞き、［許可］［このチャットでは許可］なら `permissionDecision: "allow"` で流す（Claude Code の作業フォルダの外の確かめで 2 回聞かないため。計画モードでは何も返さず権限モードに任せる）。後者はそのファイルを `writeScope.allowed` に足して以後は聞かない。ほかの断る守り（自分を守る・参照資料・［AI で整える］・見せない DB）が断るものはカードを出さない。待ち時間は Docker と同じ 7 日）と、`ChatPolicy` を `allowedTools` にする `toAllowedTools`（Read・Glob・Grep・TodoWrite・Web と、許すコマンドの `Bash(<コマンド>:*)`。ファイルの編集は権限モードに任せる）。
- `sandbox.ts` の `claudeSandbox`: `params.bashSandbox` を SDK の `sandbox` に直す（`provider.ts` が `query` の options に入れる。メモの仕様書「開発履歴/0020_【仕様済】AI の書き込み先」の段階 2）。`enabled`・起こせなければ作業を失敗にする `failIfUnavailable`・外で流し直す道（`dangerouslyDisableSandbox`）を切る `allowUnsandboxedCommands: false`・外で流すコマンド `excludedCommands`・`filesystem` の `allowWrite`（書けるフォルダ）と `denyWrite`（書かせないフォルダ。Claude Code は `additionalDirectories` も書けるようにするため）。絞るのは書き込みだけなので、Claude Code の砂場が既定で断るほかのものは通す: この Mac の中の接続と待ち受け `allowLocalBinding`・docker などの Unix ソケット `allowAllUnixSockets`・キーチェーン（gh の鍵）などのシステムのサービス `allowMachLookup: ["*"]`・外への通信はコアの中継 `httpProxyPort`。Claude Code の砂場は作業場所の `.claude/settings.json`・git のフックと設定をいつも書かせない。中継の承認 `SandboxNetworkAccess`（Kickoff の中継がなく Claude Code の中継を使うときだけ来る）は、`approvals.ts` の `createCanUseTool` が聞かずに許す（Auto mode では来ずに断られるので、中継を渡すのが本命）。砂場で止まったときの文は `policy.ts` の `sandboxDeniedHook`（`turnHooks` が `params.bashSandbox` のときに付ける PostToolUse・PostToolUseFailure の Bash のフック。結果の文を `chat/sandbox/sandboxDenied.ts` の `sandboxDeniedNote` に渡し、断られた場所があれば `additionalContext` で添える。ほかの作業場所かは書き込み先の守りと同じ `judgeFileWrite`）。
- `preCompact.ts` の `createPreCompactGate` ＋ `preCompactHook`: 自動の圧縮の前に圧縮前指示を済ませてもらう PreCompact フック（`params.preCompact` があるときだけ）。Claude Code は上限を超えていると、ツールの結果が返るたびと指示を受けた直後（区切りの圧縮も次の作業の初め）に、送る前にフックを呼び、`decision: "block"` で止めると圧縮せずに送る（止めても圧縮中のまま固まらず、何度止めても自動の圧縮を切らない）。1 回目に止めたときに指示を入力に足し（AI は次の送信から読む。文だけの返答で終わっても、同じ実行の中で次の作業として読む）、メインの返答に合図の一文（`PRE_COMPACT_DONE`）が来るまで止め続ける。止めずに通すのは、手で頼んだ圧縮・サブエージェント（`agent_id`）の圧縮・残りが少ない（始めるのに `START_MARGIN` 30k、止め続けるのに `KEEP_MARGIN` 20k）・止めた回数が `MAX_HOLDS`（8）・前に止めてから応答がないまま呼ばれた（送ったら上限を超えた = あふれたときの圧縮）・足せなかったとき。圧縮したら（区切り）次に近づいたときにまた足す。合図のあとの圧縮は Claude Code が次に送るとき（ツールの結果・指示を受けたとき）に始まるので、AI が合図だけを書いてツールを呼ばずに返答を終え、裏の作業（開発サーバー・`tail -f`・監視など、自分では終わらないもの）の終わりだけを待つと、いつまでも始まらなかった（2026-11-13 に、開発版を裏で動かしたまま合図を書いたチャットが 7 分止まった）。そこで、合図のあとに Claude Code が手の空いたまま裏の作業だけを待っている（`turnOver.ts` の `waitingOnBackground`: 裏の作業があり、`session_state_changed` が `idle`。出さない古い Claude Code では返答の終わり）状態が `PRE_COMPACT_NUDGE_MS`（5 秒。`TURN_OVER_GRACE_MS` より長くし、Claude Code が自分で次を始めるときは足さない）続いたら、ゲートの `noteWaiting` が `@shared/chat/prompts` の `PRE_COMPACT_NUDGE`（Kickoff が送った・圧縮のあとは届く指示に従って作業を続ける、という文）を圧縮前指示と同じ `push` で 1 回だけ足して送らせ、圧縮を走らせる（圧縮したら、いつもどおりコアが圧縮後指示から続ける）。その前に動き出した・裏の作業がなくなった（入力を閉じて作業が終わる。続けての圧縮はコア）・圧縮が走ったら足さない。足したら `preCompactNudged`。Claude Code は、圧縮してから 3 回のやり取りのうちに上限まで戻ることが 3 回続くと「Autocompact is thrashing」で作業を失敗にするので、指示は短い作業にしてもらう。
- `messages.ts` の `emitSdkMessage`: SDK のメッセージを記録の形にする（思考の時間・サブエージェントの開始と終了・圧縮の `status` / `compact_boundary`（圧縮中は `compacting` で立て、null か区切りで外す。区切りでは要約の記録 `compact` を先に出してから外す（圧縮中に預かった「いま」は外れたときに伝えるので、記録で圧縮の下に並ぶ）。`requesting` では外さない）・圧縮の失敗の理由（`compactFailed` に渡す）。裏のコマンドなど、サブエージェントでないタスクは除く）。

## Codex（codex/）

Codex CLI を `codex app-server`（JSON-RPC。標準入出力に 1 行 1 つの JSON。"jsonrpc" の欄なし）で動かす（メモの仕様書「0021」の段階 3。2026-11-15 に作った）。やり取りの形は codex-cli 0.169.0 の `codex app-server generate-ts` の出力から、使う分だけを `protocol.ts` に手で写した（生成物は入れない。版が上がったら生成し直して見比べる）。本物のアカウントではまだ動かしていない（確かめは偽の app-server `src/core/testing/fakeStdioServer.ts` の `fakeCodexServer`）ので、画面では対応予定のまま（上の `KICKOFF_EXPERIMENTAL_PROVIDERS`）。

- 役割: JSON-RPC の口は ACP と共有の `providers/stdioRpc.ts`（起動の口 `StdioSpawn` と `StdioRpc`。サーバーからの頼みにも答え、落ちたら待っている頼みを失敗にする。Codex は "jsonrpc" の欄を付けない）・`session.ts`（initialize → initialized。`experimentalApi` は AI からの質問を受けるため）・`config.ts`（純粋関数: スレッドの上書き・砂場・MCP・起動の引数と環境変数）・`items.ts`（会話の項目 → 記録）・`approvals.ts`（承認と質問）・`turn.ts`（1 回の実行）・`catalog.ts`（モデルの一覧・使用枠の形）・`login.ts`（Sign in with ChatGPT の骨組み）・`provider.ts`（`CodexProvider`）。
- 会話: Kickoff のセッション ID = Codex のスレッドの ID、分岐の起点（`lastMessageId`）= ターンの ID。初めは `thread/start`、続きは `thread/resume`、そのあと `turn/start`（指示に添える文脈は指示の前の別の塊）。システムプロンプトに足す文は `developerInstructions`（Codex の既定の指示は残す）。利用者の `~/.codex/config.toml` はそのまま読ませ、Kickoff が決めるものだけを `config` の点区切りのキーで上書きする（Claude Code の settingSources と同じ考え）。作業中に足す発言は `turn/steer`（`control.tell`）、止めるのは `turn/interrupt`（5 秒で答えがなければ app-server ごと止める）、裏の作業を 1 つ止める口はない。チャット欄の `/compact` は `thread/compact/start`（記録の `compact` は manual）。

- 承認と守り: 承認の決まり（approvalPolicy）はいつも `untrusted` にして Codex に聞かせ、聞かれたもの（コマンド・ファイルの変更・追加の権限）に Kickoff の守りをプロバイダー非依存の `chat/guard/judgeTool.ts`（`judgeCommand` / `judgeWritePath`）で当てる（決まりは下の共通の `guardedApproval.ts`）: 断る守り → decline、聞く守り（Docker・作業場所の外）→ 権限モードによらず承認カード、何もなし → 権限モード（Auto mode = 通す・編集を自動承認 = ファイルの変更だけ通す・毎回確認 = 聞く（「常に許可」は acceptForSession）・計画 = 断る）。Codex の承認の答えには理由の欄がないので、断った理由は `turn/steer` でいまの作業に伝える（ターンが分かる前なら分かってから）。ファイルの変更の承認は項目の ID だけで来るので、始まった項目（`item/started` の `fileChange`）から変えるファイルを引く（分からなければ断る）。`untrusted` でも Codex が安全とみなす読むだけのコマンドは聞かずに流れるので、読み取りに効く守り（自分を守るの保存先を読む・見せない DB の SQLite を読む）はそこでは効かない。AI からの質問（`item/tool/requestUserInput`）は質問カード（AskUserQuestion の形）に写し、答えを質問の ID ごとに返す。MCP の確かめ（`mcpServer/elicitation/request`）は Auto mode なら通し、ほかは承認カード。知らない頼み（ChatGPT のトークンの更新・動的なツールなど）は断る。
- 砂場: Kickoff の Bash の砂場（`params.bashSandbox`）の書けるフォルダを `sandbox_workspace_write.writable_roots` とターンの `sandboxPolicy`（workspaceWrite・ネットワークは通す）に。計画モードは read-only。書かせないフォルダ（添付・参照資料）は Codex に読めるフォルダとして渡さないので、もともと書けない。砂場の外で流すコマンド（`unsandboxedCommands`）の決まりは写せない（Codex は砂場で失敗したコマンドを砂場の外で流し直すかを承認で聞くので、そこで上の決まりに従う）。Kickoff の通信の中継は使わない（Codex の砂場はネットワークを通す設定にする）。
- AI の操作ツール: `params.tools` を `mcp_servers.<名前>`（`url`・鍵の見出し `http_headers`・`tool_timeout_sec` 7 日・聞かずに使わせるツールは `tools.<名前>.approval_mode = "approve"`、ほかは Auto mode なら approve・それ以外は prompt）に。鍵は JSON-RPC の中で渡し、起動の引数・環境変数に載せない。
- 認証（Q13）: サブスクは Codex のログインのまま（起動の環境から `CODEX_API_KEY`・`OPENAI_API_KEY`・`CODEX_ACCESS_TOKEN` を外す）。API キーは起動の環境の `CODEX_API_KEY` と `-c forced_login_method="api"` で渡す（`account/login/start` の apiKey は Codex の資格情報の置き場を書き換えて利用者のサブスクのログインを消すので使わない）。鍵の入る変数は Codex の既定（shell_environment_policy）がコマンドの環境から外し、API キーのときはスレッドの上書きでその既定を強める（本物で効くかは使い始める前に確かめる）。同じ既定が名前で外すプロジェクトの GitHub のアカウントのトークン（`GH_TOKEN`・`GH_ENTERPRISE_TOKEN`。`params.env`）は AI の gh・git に届ける約束なので、`shell_environment_policy.set` で明示して渡す（`config.ts` の `shellEnvSet`）。Sign in with ChatGPT（Q12）は `account/login/start`（chatgpt）で Codex がブラウザの OAuth と戻り先を受け、資格情報を自分の置き場（`codex login` と同じ）に書く道にした（`startLogin`。画面からつなぐのは段階 6）。Kickoff がトークンを持つ道（chatgptAuthTokens・secrets の `codex_chatgpt_tokens`）は OAuth のクライアントの登録が要るので取らない。

## 承認の頼みで聞いてくる CLI の共通の決まり（guardedApproval.ts）

フックを持たず承認の頼みで聞いてくる CLI（Codex・Copilot、のちに ACP）は、守りの判定（`chat/guard/judgeTool.ts`）と権限モードから「通す / 断る（AI に伝える理由）」を同じ決まりで決める: `guardOutcome`（断る守り → 断る、聞く守り（Docker・作業場所の外）→ 権限モードによらず承認カード `guardAskOutcome`。「このチャットでは許可」なら書く先を `writeScope.allowed` に覚える）→ 何も言わなければ `modeOutcome`（Auto mode = 通す・編集を自動承認 = ファイルの変更だけ通す・毎回確認 = 聞く（「常に許可」は `forSession`）・計画 = 断る `PLAN_MODE_DECLINED`）。結果 `ApprovalOutcome` を各 CLI の答えに直し、断った理由の渡し方も CLI ごと（Codex = turn/steer、Copilot = reject の feedback）。

- 会話: Kickoff のセッション ID = Copilot のセッション ID。用事・実行ごとにクライアント（ランタイム）を起こして止める。初めは `createSession`、続きは `resumeSession`（砂場・MCP・承認の口は渡し直す）、送るのは `send`、手が空いた（`session.idle`。送る前の空きは数えない）ら結果。システムプロンプトに足す文は `systemMessage.content`（既定の指示に足す）、指示に添える文脈は指示の前の段落。作業中に足す発言は `send` の `mode: "immediate"`（`control.tell`）、止めるのは `abort`（5 秒で手が空かなければ中断で返す）、裏の作業を 1 つ止める口はない。チャット欄の `/compact` は `history.compact`（SDK が圧縮の知らせを出さなければ記録の `compact` をここで残す）。分岐の起点（`lastMessageId`）は作業の終わりに覚えた最後の記録に残るイベント（ephemeral でないもの）の ID で、分岐は `sessions.fork` の境目（その手前まで）に、元の会話の記録（`getEvents`）で起点の次のイベントを渡す。利用者の Copilot の設定はそのまま読ませる。
- 記録: 名前と入力の形を Claude Code にそろえる（`events.ts` の `toolAsKickoff`。引数の形で見分ける: `command` = `Bash`・`path` と `file_text` = `Write`・`path` と `old_str` / `new_str` = `Edit`・view / read の `path` = `Read`・MCP（`mcpServerName` と `mcpToolName`）= `mcp__<サーバー>__<ツール>`・ほかは Copilot の名前のまま）。返答 = `assistant.message`（途中は `assistant.message_delta` を `stream`。`streaming: true`）・思考 = `assistant.reasoning`・実行中の出力 = `tool.shell_output` を `commandOutput`・圧縮 = `session.compaction_start` / `_complete`（失敗は `compactFailed`）・コンテキストの大きさ = `session.usage_info`。サブエージェントの中のもの（`parentToolCallId`）はまだ写さない。
- 承認と守り: セッションは `permissionMode: "manual"`（すべて聞く）にし、`onPermissionRequest` の種類ごとに上の共通の決まりで答える（`shell` = `judgeCommand`・`write` = `judgeWritePath`。断る理由は `reject` の `feedback` でそのまま AI に届く。「常に許可」は `approve-for-session`）。`read` は自分の保存先・見せない DB の SQLite だけ断り（`judgeReadPath`）ほかは通す、`mcp` は聞かずに使わせるツール（`autoAllow`）を通しほかは権限モード、`url`（Web）・`memory`・`hook` は通す、知らない種類（拡張の管理・独自のツールなど）は断る。砂場の外で流す頼み（`requestSandboxBypass`）は断る。承認を通らないコマンドがあっても断る守りは効くよう、ツールの前のフック `onPreToolUse` でもコマンドに断る守りだけを当てる（`createPreToolUseHook`。Docker の聞く守りは承認の側）。AI からの質問（`onUserInputRequest`）は質問カード（AskUserQuestion の形の 1 問）に写して答えの文を返す。
- 砂場（`sandboxConfig`。SDK では実験的）: 書けるのは作業場所（`addCurrentWorkingDirectory`）と Kickoff の書けるフォルダ（`readwritePaths`）、読むのは絞らない（`readonlyPaths` に `/` と書かせないフォルダ）、通信は絞らない（`allowOutbound`・`allowLocalNetwork`）、キーチェーンは使える、コアの MCP サーバー（127.0.0.1）につなぐので MCP は砂場に入れない（`sandboxMcpServers: false`）、砂場の外で流す道（`allowBypass`）は切る。計画モードは何も書かせない。砂場の外で流すコマンド（`unsandboxedCommands`）の決まりは写せない。`readonlyPaths` の `/` と書けるフォルダの重なりの効き方は本物で確かめる。
- AI の操作ツール: `params.tools` を `mcpServers.<名前>`（`type: "http"`・URL・鍵の見出し `headers`・`timeout` 7 日）に。鍵は JSON-RPC の中で渡し、起動の引数・環境変数に載せない。
- 認証（Q13）: サブスクは Copilot のログインのまま（`useLoggedInUser`）。Copilot のランタイムは `COPILOT_GITHUB_TOKEN`・`GH_TOKEN`・`GITHUB_TOKEN` などの環境変数があるとそれでログインするので、ランタイムの環境から外す（`runtimeEnv`）。そのため Copilot のチャットの gh・git は、プロジェクトで選んだ GitHub のアカウントでなく gh で有効なアカウントで動く（ほかの環境変数 `PORT`・kickoff-trash などは渡す）。API キー（BYOK）はセッションの `provider`（種類・つなぎ先・`apiKey`）で JSON-RPC の中で渡す（`byokProvider`）。Kickoff が置けるキーは AI ごとに 1 つなので、キーの頭で種類を決める（`sk-ant-` = Anthropic・`AIza` = Google・ほか = OpenAI の Responses API）。BYOK はモデルの指定が要るので、選んでいなければ種類ごとの既定のモデル（`BYOK_KINDS`。名前は使い始める前に確かめる）。Azure・自前のつなぎ先は今の 1 つのキーの形に収まらないので持たない。
- そのほか: モデルは `listModels`（組織の決まりで切られたものは除く。説明にプレミアムリクエストの倍率。ファストモードはない）、使用枠は `account.getQuota`（実験的。月のプレミアムリクエスト `premium_interactions` を長い枠の欄に「月（プレミアム）」で、5 時間の欄は分からない）、状態は `getAuthStatus`、1 回だけ聞く（ask・名前・要約）は一時フォルダのツールなし（`availableTools: []`）・承認はすべて断る・セッションの検索に入れないセッションで、モデルは一覧の値段の倍率でいちばん安いもの（light）・倍率 1 以下でいちばん高いもの（standard）。ファイルを戻す・サブエージェントの記録・会話記録のファイルの片付けはまだ持たない。

## 実行（run）の決まり

- 設定は Claude Code と同じく読む（`settingSources` に user / project / local。システムプロンプトは `claude_code` の preset に足す）。モデル・推論の深さは決めていなければ指定しない（SDK とモデルの既定）。ファストモードを指定したのに使われなかったら、理由をお知らせに残す。
- 入力はストリーミングで、作業中の操作を `control` で渡す。Claude Code の手が空き、裏の作業もなくなったら入力を閉じて終わらせる（`turnOver.ts` の `createTurnOver`）。目印は Claude Code の `session_state_changed` の `idle`（`env.ts` が `CLAUDE_CODE_EMIT_SESSION_STATE_EVENTS` で頼む）で、返答の終わり（`result`）だけでは閉じない: 返答の終わりの直前に届いた発言・裏の作業の終わりの知らせがあると、Claude Code は次の返答を続けるため（前は `result` と裏の作業 0 件で閉じていて、その続きの返答の間ずっと、作業中の発言が足せず送信待ちに戻った。利用者の指摘）。前の `running` のあとに発言を足していた `idle` と、`idle` の間に裏の作業が 0 件になったとき（Claude Code は 0 件を知らせてから終わりの知らせへの返答を始める）は、`TURN_OVER_GRACE_MS`（2 秒）だけ待ち、その間に返答を始めたらその返答の `idle` まで待つ。`session_state_changed` を出さない古い Claude Code では、返答の終わりと裏の作業 0 件で閉じる。止めるとプロセスごと終わり、サブエージェント・裏のコマンドも止まる。
- `enableFileCheckpointing` で編集の前のファイルを取っておき、指示には `promptId` を `uuid` として渡す（巻き戻しでその発言の時点に戻すため）。
- 通信の再試行（`api_retry`）は `retry` で知らせ、返答が届き始めたら null。応答のないまま（`error_status` が null）の再試行があった・失敗の文が `isNetworkError` なら、失敗は通信の切断（`network`）。
- 使用枠: `rate_limit_event` の `rejected`（戻る時刻は `resetTimeOf`）・返答のエラー `rate_limit`・失敗の文の `isUsageLimitError` で `usageLimit` を付ける。
- コンテキストの大きさは、メインエージェントの最後の応答のトークン数（要約のあとは `compact_boundary` の `post_tokens`）と、使ったモデルのうちいちばん大きいコンテキストウィンドウ（サブエージェントの小さいモデルを除くため）。自動の圧縮は作業の途中で起きるので、要約したら作業の終わりを待たずに `context` で知らせる（`post_tokens` があればその値、なければ要約のあとの最初のメインの応答のトークン数）。
- 使用枠・モデル・/ のコマンド・ファイルを戻すは、メッセージを送らないセッションを一瞬開いて、制御用の API だけを呼ぶ（`withIdleSession`。モデルへのリクエストがないので枠を使わない）。モデル（1 時間）と / のコマンド（作業場所ごとに 5 分）の一覧は、ルート（`http/routes/providers.ts`）で `ttlCache` に覚える（空の結果は覚えない）。
