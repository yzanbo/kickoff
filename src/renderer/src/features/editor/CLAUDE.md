# ファイル・検索・変更と履歴（`features/editor`・`features/history`）

プロジェクトの画面の「ファイル」「検索」「変更」タブ（Git の変更とファイル。URL は `#/projects/:id/files`・`/search`・`/changes`。以前は「エディタ」タブの中の切り替えだったもの）と「履歴」タブ（`#/projects/:id/history`。部品は `features/history/`）。どちらも上の `WorktreePicker` で見る作業場所を切り替える（作業場所は共通。`features/worktree/CLAUDE.md`）。Git・ファイル・検索の操作先は `useGitTarget`（いま見ている作業場所に向けた `GitTarget`。API は `?worktree=`）。

## ファイル・検索・変更（`EditorTab`）

- プロジェクトの左の縦の列で表示を切り替える（VS Code のアクティビティバーと同じ。タブ `files` / `search` / `changes` を `EditorTab` の `view` に渡す）: ファイル（エクスプローラー `FilesPane` ＋ `FileTree`。木は `useProjectFiles`・`treeModel.ts` の `buildTree`、変更のあるファイルとフォルダだけ色を変える `changeKinds`。木だけを流して上の見出しはいつも出し、開いたフォルダの行は VS Code の Sticky Scroll と同じく、中身を流している間は深さの順に上へ貼り付け、中身が流れ切ると次のフォルダに押し出される（CSS の sticky だけ。`editor-explorer.css` の `.files-pane`。利用者の依頼））・検索（下の「検索と置換」）・変更（ソース管理 `ChangesPane`。タブのアイコンに変更のあるファイルの数）。Git で管理していないプロジェクトでも、ファイル・検索は出す（変更のタブだけ `GitInitNotice`。変更の色・行ごとの変更の記録・差分の印は出さず、ファイルの見出しの「変更あり / 変更なし」も出さない。利用者の依頼）。3 つのタブを行き来しても同じ部品のまま（`ProjectPage` が同じ位置に描く）なので、開いたファイルのタブ・開いたフォルダ・検索・Git の操作の様子は共有する。右側は開いたファイルをタブで並べる欄（下の「右のファイルのタブ」）で、タブの中身は `ProjectFileTab`（変更の一覧から選んだファイルは、VS Code と同じく編集ボタンなしで差分を見ながら書ける形（利用者の依頼。`changeSelection` が選択に `edit` を付け、下の「差分を見ながら編集」と同じ `FileView` の `diffBase`。前は読むだけの差分 `DiffView` で、「編集」を押すと書けた）。読むだけの差分 `DiffView`（見出しに「編集」）のままにするのは、消したファイルと、ステージ済みの差分でまだステージしていない変更もあるファイル（書けるのは作業中のファイルなので、ステージした差分と違うものになる）。エクスプローラー・検索の行から開いたファイルは変更があっても中身 `FileView`（VS Code と同じく、変更は行の横の色の帯で見せる）。検索の行から開いたときはその行へ移る）。左の一覧の幅は `CHANGES_LIST_WIDTH`（履歴・メモと共通）。
- 右のファイルのタブ（利用者の依頼。メモのタブの右と同じ形）: チャットのパネルと同じタブの入れ物（`features/panel` の `Panel`。欄は `SURFACES.files`、覚える名前は `files:<プロジェクト>`。チャットの右の欄の「ファイル」「検索」タブの中は、プロジェクトのタブとは別に `files:view-<チャット>-<タブの種類>`（`ViewScope`）。タブの種類は `projectFile`（チャットなし）。状態と開き方は `useFileTabs` ＋ `fileTabs.ts`）。いつも開いておき（閉じるボタン・幅のつまみは出さない `PanelFrame.fixed`）、タブがなければ案内を出す。タブの中身が使う Git の状態などは `EditorTab` が `FileTabsContext` で渡す。
  - 開き方（`openFileTab`。メモのタブと同じ）: 一覧（ファイルの木・検索の行・変更の行）をふつうに押すと、ピントのあるペインで表示中のファイルのタブの中身を入れ替える（保存していない変更があれば保存するかを聞く。表示中がファイルでなければ新しいタブ）。新しく作ったファイル・チャットから来たファイル（URL の `?file=`）・行の右クリックの「新しいタブで開く」は新しいタブ（ファイルタブの木と変更の一覧の ⌘クリックは、複数選択に使うので右クリックへ移した。検索の行の ⌘クリックは新しいタブのまま）。開いているファイルはそのタブを表示する（検索の別の行・差分の「編集」なら、そのタブの中身を替える）。タブは中身（エクスプローラー・検索の行から）はファイルごとに 1 つ、差分（変更の一覧から）はステージ済み・未ステージごとに 1 つで、名前に「（変更）」「（ステージ済み）」を添える（VS Code の「(Working Tree)」「(Index)」と同じ。`fileTabKeyOf`）。一覧の選んでいる行は、ピントのあるペインで表示中のタブのファイル。
  - 分ける: タブをドラッグして中身の端に落とすと上下・左右に分けて並べられ、タブの右クリック・⌘\・タブの列の右端のボタンでも分けられる（`features/panel/CLAUDE.md` の「ペインの分割」）。ファイルタブの木のファイルの行も、右の欄へドラッグして落とせる（VS Code と同じ。タブの列ならその位置、中身の端ならその側に分けて開く。`fileDragProps` → パネルの外からのドラッグ `features/panel/layout/externalTabDrag.ts`）。
  - 保存していない変更はタブごとに覚え（`FileView` の `onDirtyChange` → `setFileTabDirty`）、VS Code と同じくタブの × の代わりに「●」を出し（表示中でない・細いタブでも出す）、● に乗せたときだけ × に戻す（利用者の依頼。`useFileTabDirty` → `PanelTab` の `dirty`）。タブの ×・右クリックの「タブを閉じる」・ペインを閉じる（どれも `panel/tabs/confirmUnsaved.ts` の `confirmCloseUnsaved` → `confirmCloseFileTab`。メモのタブも同じく `confirmLeaveMemo`。前はメニュー・ペインから閉じると書きかけを黙って捨てていた）・中身の入れ替えの前に、VS Code と同じく 保存 / 保存しない / キャンセル を選んでもらう（`choiceDialog`。保存は ⌘S と同じ保存のしかたで（`FileView` の `registerSave` → `registerFileTabSaver`）、保存できたときだけ閉じる・入れ替える。ほかで変わっていて上書きをやめたらそのまま残す）。名前を変えたファイル・フォルダのタブは新しいパスに付け替え（`relocate`）、ゴミ箱に入れたもののタブは閉じる（`forget`）。名前の変更・置換の前は、保存していない変更のあるタブのファイルを先に保存してもらう（`dirtyUnder` / `dirtyPaths`）。履歴・ボードなどの画面へ移るとタブの中身はなくなり、書きかけも消える（前と同じ）。
- 検索と置換（利用者の依頼で VS Code の検索に合わせた。⌘⇧F で、いまのプロジェクト（全プロジェクトの画面ではサイドバーで選んでいるもの）の検索タブへ移り、検索の欄にピントを置いて書いてある文を選ぶ。`app/shortcuts.ts` → App の `openCodeSearch` → `codeSearchFocus.ts` の `requestCodeSearchFocus`）: `SearchView`（入力の欄）＋ `SearchResults`（結果）＋ `useProjectSearch`（状態）＋ `useSearchReplace`（置換）。検索の欄は大文字と小文字の区別・単語単位・正規表現（打つと探し直す。↑↓ で履歴 `SEARCH_HISTORY`。結果が出た文字だけ残す）。左の ▸ で置換の欄（大文字と小文字を保持・すべて置換。⌘Enter でもすべて置換）、… で詳細（含める・除外するファイル。VS Code と同じ glob のカンマ区切りで、コアが git の pathspec にする。除外設定と .gitignore を使うかの切り替え）。見出しに探し直す・すべて閉じる / 開く・結果を消す。結果はファイルごとで、置換の欄を開いていれば行の中に置き換えたあとの形（消える部分は赤の打ち消し線・入る部分は緑）を見せる。行・ファイルの見出しの右に置換（置換の欄を開いているとき）と結果から外す（乗せたとき・選んでいるときに出す。同じ操作とコピーを右クリックにも置く）。外したもの・数は `searchHits.ts`（`visibleResults` / `replaceTargets` / `resultCounts` / `pushHistory`）。印と置き換えの形は `@shared/search/searchMatch`（`searchPattern` / `splitMatches` / `splitReplacements`。コアの置換と同じ探し方・置き換え方にするため共有の層に置く）。置換は結果を出したときの探し方で、結果の行だけをコアが置き換える（`POST /search/replace`。探したあとで変わった行は置換しない）。すべて置換は確かめてから、開いているファイルに保存していない変更があれば先に保存してもらう。置換したら探し直して Git の状態を取り直し、置換する前の中身を覚えて「元に戻す」（置換したあとの指紋で保存し直す。そのあとほかで変わったファイルは戻さず知らせる）。ファイルタブの木のフォルダーの右クリック「フォルダー内を検索」で、含めるファイルをそのフォルダーにして検索タブへ移る（`useFileActions` の `onFindInFolder`）。
- 変更（`ChangesPane`。利用者の依頼で、ボタンと大きさを VS Code のソース管理にそろえた）: 見出しの左にブランチと進み・遅れ、右に VS Code と同じアイコンのボタン（22px の枠に 16px のアイコン。ファイルタブの見出しも同じ大きさ）でコミット ✓（⌘Enter と同じ）・取り直す（リモートの情報も取ってくる）・一覧 / 木の切り替え（`CHANGES_TREE`）・「…」のメニュー（プル・プッシュ・フェッチ・すべての変更をステージ・すべてのステージを取り消す・すべて閉じる / 開く（利用者の依頼。開いているまとまりが 1 つでもあれば閉じる方で、まとまりも木の中のフォルダもまとめて閉じる。開閉は `ChangeGroup` の `ChangeFold` を `ChangesPane` が持つ））。上にコミットの欄 `CommitBox`（メッセージは 1 行から書いた分だけ伸びる欄（`field-sizing: content`。空のときは案内を 1 行に収める）。⌘Enter でコミット。ボタンは VS Code と同じ 26px の高さで、コミットの右の ▾ で コミット / コミット (修正) / コミットしてプッシュ / コミットして同期 を選ぶ。修正は直前のコミットに足して書き直し（コアの `amend`。メッセージが空なら前のメッセージのまま）、プッシュ済みのコミットなら確かめる。同期は遅れていれば先に早送りで取り込み、コミットしてからプッシュ。ステージしたものがなければ、すべてステージするか確かめる。下に、遅れていればプル、進んでいればプッシュ、追いかけるブランチがなければ「ブランチを公開」のボタンを出す（VS Code はコミットのボタンを替えるが、利用者の依頼で別のボタンとして残す）。状態と操作は見出しの ✓・「…」と共通の `useCommitActions`）、下に「ステージされている変更」「変更」（`ChangeGroup`。見出しもファイルの行も VS Code と同じ 22px・13px の 1 行（ファイルタブの木の行も 22px）。行の右のステージ・ステージの取り消し・元に戻すのボタン（`FileTree` の `actions`・`.row-actions`）は、VS Code と同じく乗せた行・選んだ行・ピントのある行だけに出し（木では乗せたいちばん内側の行だけ）、行の地をボタンの所まで伸ばす。元に戻すは確かめてから）。操作の実行中と失敗は親が持ち、表示を切り替えても残る。
- 複数選択（利用者の依頼。Finder・VS Code と同じ。決まりは `useMultiSelect`）: ファイルタブの木（`FilesPane`。ファイルもフォルダも）と変更の一覧（`useChangeSelection`。「ステージされている変更」「変更」をまたいで 1 つで、選ぶ印はまとまりとパスの組。木の表示でもフォルダの行は選ばない）で、⌘ / Ctrl ＋クリックで 1 つずつ足す・外す、Shift ＋クリックで見えている並び（木は開いているフォルダの中まで `visibleTreePaths`、変更はステージ済み → 未ステージ `visibleChangePaths`）の範囲を足す。まだ何も選んでいなければ、開いているファイルも入れて起点にする。木の部品 `FileTree` は `multi`（`TreeMulti`）を受けて、選んだ行の色・クリック・右クリックを任せる（履歴・PR の木は渡さず、⌘クリックは新しいタブのまま）。ふつうのクリック・行の外を押す・Esc・選んでいない行の右クリックで外す。選んだ行の 1 つを右クリックすると、選んでいるものすべてのメニュー（`useFileActions` の `ManyMenu`: 新しいタブで開く（ファイルだけ。変更の一覧からはそのまとまりの差分）・ステージする / ステージを取り消す / 変更を元に戻す…（変更の一覧。まとまりごとに効く。元に戻すは確かめてから）・パスをコピー / 相対パスをコピー（1 行に 1 つ）・ゴミ箱に入れる…（ファイルタブ。確かめは 1 回、フォルダとその中を両方選んでいればフォルダだけ `topLevelPaths`、失敗したものは最後にまとめて知らせる））。変更の一覧で選んだ行の右のボタン（ステージなど）は、そのまとまりで選んでいるものすべてに効く（VS Code と同じ）。
- 名前の変更（利用者の依頼: メモの木・チャットの行と同じく、選んでいる行で Enter を押すと名前の変更にする。開くのは押す・Space）: ファイルタブの木（ファイル・フォルダ）と変更タブの行（ファイルだけ。消したファイルは変えない。木の表示でもフォルダは変えない（変更のないファイルも入っているので））で、行にピントがあるときの Enter・右クリックの「名前を変更」。その行が名前の欄（`InlineName`。Enter・ピントを外すと決め、Esc でやめる。木では同じフォルダの同じ名前・「/」を書くたびに断る `siblingNameError`）になる。状態と操作は `useFileActions`（`FileTree` / `ChangeGroup` に `FileRename` を渡す）。同じフォルダの中で名前だけを変え（コアの `POST /api/projects/:id/file/rename`）、開いているファイル（とフォルダの中）は新しいパスに付け替え（タブを付け替える `useFileTabs` の `relocate`）、開いていたフォルダも付け替えて、Git の状態を取り直す。開いているファイルに保存していない変更があれば、先に保存してもらう（`dirtyUnder`）。
- ファイルタブの見出し（`FilesPane`。利用者の依頼で VS Code のエクスプローラーと同じ並び）: 新しいファイル… / 新しいフォルダー…（開いているファイルの入ったフォルダーに作る。開いていなければいちばん外側。`FileCreate` の `start`）・取り直し・すべて開く / すべて閉じる（開いているフォルダが 1 つでもあれば閉じる方。開くのは無視しているフォルダとその中を除いたすべて `openableFolders`）。
- 右クリックのメニュー（`useFileActions`。VS Code のエクスプローラーと同じ並び）: ファイルタブの行は 新しいファイル… / 新しいフォルダー…・新しいタブで開く（ファイル）・Finder で表示（Mac のアプリだけ）・フォルダー内を検索（フォルダー）・パスをコピー（フルパス）/ 相対パスをコピー・名前を変更・ゴミ箱に入れる…。木の下の空いている所（利用者の依頼。メモの一覧と同じ。`FilesPane` の `.files-pane` が残りの高さを埋める）は 新しいファイル… / 新しいフォルダー…（いちばん外側）・Finder で表示・パスをコピー。変更タブの行は 新しいタブで開く・Finder で表示・パスのコピー・名前を変更だけ（`explorer` が false）。⌘ / Shift ＋クリックで選んだ行の 1 つなら、上の「複数選択」の組。
  - 新しいファイル・フォルダー: VS Code と同じく、名前を書いてから作る（フォルダーの行ならその中、ファイルの行ならその入ったフォルダー、空いている所ならいちばん外側の、いちばん上に名前の欄 `FileCreate` を出し、そのフォルダーを開く。Esc なら何も残さない。メモの一覧のように仮の名前ですぐ作らないのは、Git の作業場所に仮の名前のファイルを残さないため）。「a/b.ts」と書けば途中のフォルダーも作る。同じ名前・空の段・「..」は書くたびに断る（`treeModel.ts` の `newEntryNameError`）。無視しているフォルダーの中には作らない（開けないため）。作ったら（コアの `POST /api/projects/:id/files`）Git の状態を取り直し、ファイルは開いて編集の部品にピントを置く（選択の `focus`）。Git はフォルダーを覚えないので、空のフォルダーはコアの一覧の `empty_dirs` から木に出す（`buildTree`）。
  - ゴミ箱に入れる: 確かめてから（Finder のゴミ箱から戻せる。開いているファイルに保存していない変更があれば、消えることも確かめの文で伝える）、コアの `DELETE /api/projects/:id/file`。開いていたファイル（フォルダーならその中）のタブは閉じる（`useFileTabs` の `forget`）。
- Git の状態は `useGitStatus`（開いたとき・ウィンドウに戻ったとき・このプロジェクトのチャットが動いたとき（作業中のツールの結果も）に取り直し、変更のタブを開いている間は 5 秒ごとにも取り直す。`count` はタブのバッジ、`refreshing` はバッジの更新中の印（5 秒ごとの取り直しでは立てない））。
- 差分は `DiffView`（左右に並べる・1 列。`DIFF_LAYOUT`。切り替えのボタンは `DiffLayoutToggle` で、ファイルタブの差分・右の欄の「変更」・差分から編集しているときで共通）。行に分けるのは `parseDiff` / `toSplitRows`。差分の表の行のクラスは `line-add` など（タイムラインの `.diff-add` とは別）。

## 右の欄の変更とファイル（`SideChanges`・`SideFileView`）

チャットの画面の右の欄（`features/panel/CLAUDE.md`）のタブの中身。チャットの作業場所（ワークツリーならそのフォルダ。`WorktreeContext` で渡す）を見る。Git の状態は `useGitStatus`（チャットが動いた・作業中にツールの結果が届いた（SSE の `chat_event` の `tool_result`）・ウィンドウに戻ったら取り直すので、AI が作業を続けて変わっても差分が追いつく。続けて届く知らせは最初の知らせから 1.5 秒後の 1 回にまとめる（届くたびに待ち直すと、ツールが続く間は取り直さない）。5 秒ごとの取り直しはしない。以前はチャットの行の変化だけを見ていて、作業が終わるまで差分が止まっていた）。

- 変更（`SideChanges`）: コミットしていない変更のあるファイル（`sideFile.ts` の `changedFiles`。同じファイルは 1 つにまとめ、どの差分を出すかは `changeOf`: 競合 → 未ステージ → ステージ済み）を、上に一覧、下に差分を縦に並べる。上の帯に件数・表示のしかた（`DIFF_LAYOUT`。ファイルタブと共通）・取り直し。押したファイル（タブの `focus` / `focusAt`。押し直しても移る）の位置へ移り、一覧の行でもそのファイルへ移る。ファイルごとに見出しで畳め（20 個より多ければ、初めは移る先のファイルだけ開く）、見出しはスクロールしても上に残る。見出しの右に「確認済み」と「ファイルタブで開く」、見出し・一覧の右クリックはファイルのメニュー。差分は 1 つのファイルにつき 1 回だけ読む（`useFileDiff` を見出しで読み、開いていれば `DiffView` の `source` に渡す。読むのは開いている・確認済みの印があるファイルだけ）。
- 確認済み: 見出しの「確認済み」を付けると差分を畳み、一覧に ✓、上の帯に「確認済み n/m」。確認したときの差分の指紋（`sideFile.ts` の `diffFingerprint`）を作業場所ごとに覚え（`sideViewedFiles`）、あとで差分が変わったら（`viewedStateOf` の `changed`）「確認後に変更」と出して開き、確認済みに数えない（付け直すといまの差分で覚え直す）。もう変更のないファイルの印は外す（`pruneViewed`）。差分の行を選ぶと「チャットに追加」で、右クリックの、足す先のチャットの名前の組で、足す先のチャットの入力欄に引用・パスを足せる（`useCodeQuoteMenu`。`features/chat/CLAUDE.md` の「選択部分をチャットに追加」）。
- ファイル（`SideFileView`）: 中身（`FileView`。開いたらすぐ書け、Git との違いの帯も出す。行の番号があればその行へ移る）。上の帯に、コミットしていない変更があれば「差分を見る」（変更のタブのそのファイルの位置へ）と「ファイルタブで開く」。中身の行も、選ぶ・右クリックで差分と同じく足す先のチャットに足せる（Monaco の選択はページの選択にならないので、`CodeEditor` が入れ物（`data-quote-path`）に選んでいる行と文の読み方を置き（`codeSelection.ts` の `registerCodeSelection`）、`pickedInCode` と `useCodeQuoteMenu` がピントのある部品から読む。右の欄・別ウィンドウでは Monaco の右クリックのメニューを出さず、チャットに足すメニューにする（`nativeContextMenu`）。読むだけの表は行の `data-no`、表の `data-quote-path`）。

- 上の帯（`HistoryToolbar`。利用者の依頼で、よく使う Git の操作を名前つきのボタン（上にアイコン・下に名前）で並べた。操作は帯と Git の操作の窓で共通の `useHistoryOps`）: 左から 一覧（左の一覧の開閉）・操作（Git の操作の窓）｜ フェッチ（作業場所は変えない）・プル（いまのブランチの `pull`。遅れの数を右上に）・プッシュ（いまのブランチの `push`。進みの数を右上に）・退避 ▾（押すと退避、▾ で最新の退避を戻す / 適用）｜ 真ん中にプロジェクト名と、いまのブランチ ▾（押すとほかのブランチへチェックアウト。ほかの作業場所で取り出しているブランチは選べない）と作業場所の切り替え（`WorktreePicker`。前は帯の上の行だった）｜ ブランチ ▾（押すといまのコミットから新しいブランチ、▾ で新しいタグ・ワークツリーを作る）｜ 右に 外で開く（見ている作業場所のフォルダを Finder・VS Code・外のターミナルで。Mac のアプリだけ）。全プロジェクトの画面へのボタンは置かない（利用者の依頼で外した。サイドバーから移る）。プル・プッシュは確かめ・衝突の扱いもブランチの右クリックと同じ。ブランチから外れている・追いかけ先がない・origin がないときは押せず、理由を乗せたときの説明に出す。狭ければ（帯の幅 820px 未満）名前を隠してアイコンだけ。
- Git の操作の窓（`GitCommandPalette`。帯の「操作」で開く `Popover`）: 名前の一部（空白で区切ると全部を含むもの）で絞り込み、↑↓・Enter・押すで実行する。並べるのは帯の操作と、ほかのブランチごとのチェックアウト・マージ・リベース、外で開く、一覧の開閉。選ぶと窓を閉じてから実行する（確かめのダイアログが窓に重ならないように）。
- 退避（`useStashActions`。コアの `stash_save` / `stash_pop` / `stash_apply` / `stash_drop`）: 帯の「退避」はメッセージ（省ける。`promptWithCheck` の `optional`）と「未追跡のファイルも退避する」（初めはオン）を聞いてから。左の一覧の退避の行の右クリックで 戻す（確かめてから。戻したら一覧から消す）・適用（一覧に残す）・削除…（確かめる）。戻したら作業中の変更とぶつかったときは、変更タブで直すか選んでもらう（途中の操作にはならないので取りやめはない。pop でも退避は残る）。

- コミットの表の札（`CommitRefBadges.tsx` の `RefBadges`。コミットの詳細の「参照」も同じ札。線の色は `laneColors.ts`。利用者の依頼で、件名に埋もれないよう目立たせた）: その行のグラフの線の色（`--ref-color`）で塗り、太字。いまのブランチは ✓ と濃い塗り、タグはタグのマーク、リモートだけの札は薄い塗り。リモートのブランチには remote のマーク（GitHub を指す remote なら GitHub のマーク `ui/GitHubMark`、ほかは雲。GitHub かはコアの参照の一覧の `remotes[].github`）を付ける。手元のブランチと同じコミットにある追いかけ先（なければ同じ名前）のリモートのブランチは、手元の札にまとめてマークだけを添える（プッシュ済みと分かる。`refBadges.ts` の `refBadgesOf`。右クリックは手元のブランチのメニュー）。
- ブランチ・タグの右クリック（利用者の依頼。`RefMenu` ＋ 操作と確かめのダイアログ `useBranchActions`）: 左の一覧の手元のブランチ・リモートのブランチ・タグと、コミットの表の札（札の文を `refTarget.ts` の `refTargetOf` で手元・リモート・タグに分ける。「/」を含む手元のブランチは一覧で見分ける）で同じメニュー。手元のブランチは チェックアウト… / ワークツリーとしてチェックアウト…（作ったら、見る作業場所をそこへ切り替えるか聞く）｜「追いかけ先」へ早送り / をプル / 「リモート」へプッシュ… / プッシュして PR を作る ｜「いまのブランチ」に「このブランチ」をマージ… / 「いまのブランチ」を「このブランチ」の上にリベース… ｜ 新しいブランチ…（「作ったらチェックアウトする」のチェック付き `promptWithCheck`）/ 新しいタグ…（注釈つき・origin にもプッシュするか）｜ 追跡 ›（リモートのブランチから選ぶ・追跡をやめる）/ 名前を変更… / 削除…（リモートのブランチも消すか。マージしていなければ確かめ直して強制）｜ ブランチ名をコピー。リモートのブランチは チェックアウト（追いかける手元のブランチがあればそれ）・マージ・リベース・新しいブランチ / タグ・リモートのブランチを削除・コピー、タグは チェックアウト（ブランチから外れる）・マージ・リベース・新しいブランチ・プッシュ・削除・コピー。いまのブランチに意味のない項目（自分のチェックアウト・自分へのマージ・遅れていないときの早送り・ほかの作業場所で取り出しているブランチのチェックアウトと削除など）は押せなくし、理由を乗せたときの説明に出す。対話式のリベースは置かない（並べ替えを書く画面が要るため）。
- ファイルが入れ替わる操作（チェックアウト・マージ・リベース・いまのブランチのプル）は、この作業場所で作業中のチャットがある・コミットしていない変更があるとき、その注意を添えて確かめる。マージ・リベースは前に見込み（コアの `merge-preview`）を出す（取り込むものがない / 早送りで済む / 衝突せずにできる / 衝突しそうなファイル）。プッシュ・PR・削除も確かめてから。実行中は左の一覧の見出しに「プッシュ中…」などを出し、失敗はお知らせのダイアログ。終わったら Git の状態（応答の状態を `useGitStatus` の `applyStatus` で）と履歴を取り直す。
- 衝突したら（利用者の依頼。どうするかは利用者が決める）: 衝突したファイルを並べたダイアログで「変更タブで解決する」（変更タブへ移る）か「取りやめる」（`git … --abort` で前の状態に戻す）を選んでもらう。変更タブには途中の操作の帯 `OperationBanner`（「マージの途中です（衝突 n 件）」。衝突したファイルごとに「こちら」「取り込む側」（どちらが何かは操作ごとに乗せたときの説明。リベースでは git の ours が土台のブランチ）「解決済み」（印の行を直したいまの中身で）と、取りやめる・スキップ（マージ以外）・続ける（衝突が残っていれば押せない）。続けた先でまた衝突したら知らせる。操作は `useGitStatus` の `operate` / `resolve`）。
