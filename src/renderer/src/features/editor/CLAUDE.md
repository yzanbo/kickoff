# ファイル・検索・変更と履歴（`features/editor`・`features/history`）

プロジェクトの画面の「ファイル」「検索」「変更」タブ（Git の変更とファイル。URL は `#/projects/:id/files`・`/search`・`/changes`。以前は「エディタ」タブの中の切り替えだったもの）と「履歴」タブ（`#/projects/:id/history`。部品は `features/history/`）。どちらも上の `WorktreePicker` で見る作業場所を切り替える（作業場所は共通。`features/worktree/CLAUDE.md`）。Git・ファイル・検索の操作先は `useGitTarget`（いま見ている作業場所に向けた `GitTarget`。API は `?worktree=`）。

## ファイル・検索・変更（`EditorTab`）

- プロジェクトの左の縦の列で表示を切り替える（VS Code のアクティビティバーと同じ。タブ `files` / `search` / `changes` を `EditorTab` の `view` に渡す）: ファイル（エクスプローラー `FilesPane` ＋ `FileTree`。木は `useProjectFiles`・`treeModel.ts` の `buildTree`、変更のあるファイルとフォルダだけ色を変える `changeKinds`）・検索（下の「検索と置換」）・変更（ソース管理 `ChangesPane`。タブのアイコンに変更のあるファイルの数）。3 つのタブを行き来しても同じ部品のまま（`ProjectPage` が同じ位置に描く）なので、選んでいるファイル（`useChangesSelection`。編集中に保存していない変更があれば、別のファイルを開く前に確かめる）・開いたフォルダ・検索・Git の操作の様子は共有する。右側は `ChangesDetail`（変更の一覧から選んだファイルは、VS Code と同じく編集ボタンなしで差分を見ながら書ける形（利用者の依頼。`changeSelection` が選択に `edit` を付け、下の「差分を見ながら編集」と同じ `FileView` の `diffBase`。前は読むだけの差分 `DiffView` で、「編集」を押すと書けた）。読むだけの差分 `DiffView`（見出しに「編集」）のままにするのは、消したファイルと、ステージ済みの差分でまだステージしていない変更もあるファイル（書けるのは作業中のファイルなので、ステージした差分と違うものになる）。エクスプローラー・検索の行から開いたファイルは変更があっても中身 `FileView`（VS Code と同じく、変更は行の横の色の帯で見せる）。検索の行から開いたときはその行へ移る）。左の一覧の幅は `CHANGES_LIST_WIDTH`（履歴・メモと共通）。
- 検索と置換（利用者の依頼で VS Code の検索に合わせた。⌘⇧F で、いまのプロジェクト（全プロジェクトの画面ではサイドバーで選んでいるもの）の検索タブへ移り、検索の欄にピントを置いて書いてある文を選ぶ。`app/shortcuts.ts` → App の `openCodeSearch` → `codeSearchFocus.ts` の `requestCodeSearchFocus`）: `SearchView`（入力の欄）＋ `SearchResults`（結果）＋ `useProjectSearch`（状態）＋ `useSearchReplace`（置換）。検索の欄は大文字と小文字の区別・単語単位・正規表現（打つと探し直す。↑↓ で履歴 `SEARCH_HISTORY`。結果が出た文字だけ残す）。左の ▸ で置換の欄（大文字と小文字を保持・すべて置換。⌘Enter でもすべて置換）、… で詳細（含める・除外するファイル。VS Code と同じ glob のカンマ区切りで、コアが git の pathspec にする。除外設定と .gitignore を使うかの切り替え）。見出しに探し直す・すべて閉じる / 開く・結果を消す。結果はファイルごとで、置換の欄を開いていれば行の中に置き換えたあとの形（消える部分は赤の打ち消し線・入る部分は緑）を見せる。行・ファイルの見出しの右に置換（置換の欄を開いているとき）と結果から外す（乗せたとき・選んでいるときに出す。同じ操作とコピーを右クリックにも置く）。外したもの・数は `searchHits.ts`（`visibleResults` / `replaceTargets` / `resultCounts` / `pushHistory`）。印と置き換えの形は `@shared/search/searchMatch`（`searchPattern` / `splitMatches` / `splitReplacements`。コアの置換と同じ探し方・置き換え方にするため共有の層に置く）。置換は結果を出したときの探し方で、結果の行だけをコアが置き換える（`POST /search/replace`。探したあとで変わった行は置換しない）。すべて置換は確かめてから、開いているファイルに保存していない変更があれば先に保存してもらう。置換したら探し直して Git の状態を取り直し、置換する前の中身を覚えて「元に戻す」（置換したあとの指紋で保存し直す。そのあとほかで変わったファイルは戻さず知らせる）。ファイルタブの木のフォルダーの右クリック「フォルダー内を検索」で、含めるファイルをそのフォルダーにして検索タブへ移る（`useFileActions` の `onFindInFolder`）。
- 変更（`ChangesPane`）: 見出しにブランチと進み・遅れ、一覧 / 木の切り替え（`CHANGES_TREE`）、取り直し、すべて開く / すべて閉じる（利用者の依頼。開いているまとまりが 1 つでもあれば閉じる方で、まとまりも木の中のフォルダもまとめて閉じる。開閉は `ChangeGroup` の `ChangeFold` を `ChangesPane` が持つ）。上にコミットの欄 `CommitBox`（⌘Enter でコミット。ステージしたものがなければ、すべてステージするか確かめる。進んでいればプッシュ、追いかけるブランチがなければ「ブランチを公開」）、下に「ステージされている変更」「変更」（`ChangeGroup`。行の右にステージ・ステージの取り消し・元に戻すのボタン（薄い色。乗せたボタンだけ濃くする。`FileTree` の `actions`・`.row-actions`）。元に戻すは確かめてから）。操作の実行中と失敗は親が持ち、表示を切り替えても残る。
- 名前の変更（利用者の依頼: メモの木・チャットの行と同じく、選んでいる行で Enter を押すと名前の変更にする。開くのは押す・Space）: ファイルタブの木（ファイル・フォルダ）と変更タブの行（ファイルだけ。消したファイルは変えない。木の表示でもフォルダは変えない（変更のないファイルも入っているので））で、行にピントがあるときの Enter・右クリックの「名前を変更」。その行が名前の欄（`InlineName`。Enter・ピントを外すと決め、Esc でやめる。木では同じフォルダの同じ名前・「/」を書くたびに断る `siblingNameError`）になる。状態と操作は `useFileActions`（`FileTree` / `ChangeGroup` に `FileRename` を渡す）。同じフォルダの中で名前だけを変え（コアの `POST /api/projects/:id/file/rename`）、開いているファイル（とフォルダの中）は新しいパスに付け替え（`useChangesSelection` の `relocate`）、開いていたフォルダも付け替えて、Git の状態を取り直す。開いているファイルに保存していない変更があれば、先に保存してもらう（`isDirty`）。
- ファイルタブの見出し（`FilesPane`。利用者の依頼で VS Code のエクスプローラーと同じ並び）: 新しいファイル… / 新しいフォルダー…（開いているファイルの入ったフォルダーに作る。開いていなければいちばん外側。`FileCreate` の `start`）・取り直し・すべて開く / すべて閉じる（開いているフォルダが 1 つでもあれば閉じる方。開くのは無視しているフォルダとその中を除いたすべて `openableFolders`）。
- 右クリックのメニュー（`useFileActions`。VS Code のエクスプローラーと同じ並び）: ファイルタブの行は 新しいファイル… / 新しいフォルダー…・Finder で表示（Mac のアプリだけ）・フォルダー内を検索（フォルダー）・パスをコピー（フルパス）/ 相対パスをコピー・名前を変更・ゴミ箱に入れる…。木の下の空いている所（利用者の依頼。メモの一覧と同じ。`FilesPane` の `.files-pane` が残りの高さを埋める）は 新しいファイル… / 新しいフォルダー…（いちばん外側）・Finder で表示・パスをコピー。変更タブの行は Finder で表示・パスのコピー・名前を変更だけ（`explorer` が false）。
  - 新しいファイル・フォルダー: VS Code と同じく、名前を書いてから作る（フォルダーの行ならその中、ファイルの行ならその入ったフォルダー、空いている所ならいちばん外側の、いちばん上に名前の欄 `FileCreate` を出し、そのフォルダーを開く。Esc なら何も残さない。メモの一覧のように仮の名前ですぐ作らないのは、Git の作業場所に仮の名前のファイルを残さないため）。「a/b.ts」と書けば途中のフォルダーも作る。同じ名前・空の段・「..」は書くたびに断る（`treeModel.ts` の `newEntryNameError`）。無視しているフォルダーの中には作らない（開けないため）。作ったら（コアの `POST /api/projects/:id/files`）Git の状態を取り直し、ファイルは開いて編集の部品にピントを置く（選択の `focus`）。Git はフォルダーを覚えないので、空のフォルダーはコアの一覧の `empty_dirs` から木に出す（`buildTree`）。
  - ゴミ箱に入れる: 確かめてから（Finder のゴミ箱から戻せる。開いているファイルに保存していない変更があれば、消えることも確かめの文で伝える）、コアの `DELETE /api/projects/:id/file`。開いていたファイル（フォルダーならその中）は閉じる（`useChangesSelection` の `forget`）。
- Git の状態は `useGitStatus`（開いたとき・ウィンドウに戻ったとき・このプロジェクトのチャットが動いたとき（作業中のツールの結果も）に取り直し、変更のタブを開いている間は 5 秒ごとにも取り直す。`count` はタブのバッジ、`refreshing` はバッジの更新中の印（5 秒ごとの取り直しでは立てない））。
- 差分は `DiffView`（左右に並べる・1 列。`DIFF_LAYOUT`。切り替えのボタンは `DiffLayoutToggle` で、ファイルタブの差分・右の欄の「変更」・差分から編集しているときで共通）。行に分けるのは `parseDiff` / `toSplitRows`。差分の表の行のクラスは `line-add` など（タイムラインの `.diff-add` とは別）。
- ファイルの中身は `FileView`。利用者の依頼で VS Code と同じく「編集」ボタンをなくし、開いたらすぐ書ける `CodeEditor`（Monaco。ファイルの中身を初めて開いたときに読み込む。入口は補完・型チェックの言語サービスを除いた `monacoEditor.ts`。Monaco を上げたときは `editor.main.js` と見比べて作り直す）で出す。保存は ⌘S・保存ボタン（⌘⇧S のすべて保存でも。`lib/saveAll` の `registerSavable`）で、保存していなければ見出しに「● 未保存」（注意の色 `.diff-state.unsaved`）。バイナリ・大きすぎて途中までのファイルだけ、読むだけの表（`useHighlight` ＋ `CodeLine`）。保存は開いたときの指紋（`hash`）と比べ、ほかで（エージェントなどが）変えていれば上書きするか聞く。開いている間にほかで変わったら、未保存の変更がなければそのまま読み直し（`CodeEditor` が書いている中身を、元に戻すで戻せる編集として差し替え、見ている位置は保つ）、あれば知らせ（`.file-changed-notice`）の「読み直す」で選ばせる。保存した直後の、取り直す前の古い中身はほかでの変更と見ない（`ignoreHash`）。ピントは、差分の「編集」のボタン・右クリックの「新しいファイル」から来たとき（選択の `focus` → `FileView` の `autoFocus`）だけ置く（チャット欄・変更の一覧のピントを奪わない。一覧から選んだときは一覧に残し、続けて ↑↓ で移れる）。
- 行番号の横の Git との違いの帯（VS Code のガターの色の帯と同じ）: 足した行 = 緑 `--ok`・変えた行 = 青 `--info`・消した所 = 直前の行の下の端に赤の三角 `--ng`（`.quick-diff-*`。右端の概要の帯にも同じ色の印）。比べる相手は、ステージしていない変更があればステージした中身（なければコミットの中身。コアの `GET /git/original`。Git の状態を取り直すたびに読み直す `useQuickDiffBase`）、なければ読み込んだ中身（ステージした中身と同じ）。Git の外・未追跡・元がバイナリか大きすぎるときは出さない。打つのが止まって 200ms で付け直す（比べ方は `quickDiff.ts`。行の比べ合わせは `lib/lineDiff`）。差分から編集しているときは差分そのものが出ているので付けない。Git の状態は呼ぶ側が `gitStatus` で渡す（見出しの「変更あり」もそこから `changeOf`）。
- 差分を見ながら編集（変更の一覧から選んだとき・差分の「編集」から開いたとき。選択の `edit` と、どちらの差分から来たかの `staged`。`editedChange` がその差分を探し（保存して差分がなくなっても開いたまま）、`FileView` の `diffBase` に渡す）は、利用者の依頼で VS Code と同じく: `CodeEditor` の `original` に元の中身（コアの `GET /git/original`。ステージ済みの差分ならコミット（HEAD）、未ステージならステージした中身。未追跡は空）を渡すと Monaco の差分の部品（`createDiffEditor`）になり、左は読むだけ・右を編集し、打つたびに差分が変わる。元の中身は開いたときに一度だけ読む（保存して差分がなくなっても比べる相手は変えない。元がバイナリ・大きすぎれば差分なしで編集する）。表示のしかたは `DIFF_LAYOUT`（作り直さずに切り替える。狭ければ差分の表と同じ幅 `SPLIT_MIN_WIDTH` でまとめて表示）、見出しに前・次の変更へ（`goToDiff`）。
- ⌘F（利用者の依頼。ブラウザと同じく、開いているページの中を探す。全体を探すのは ⌘K）: ファイル・検索・変更の右側（`ChangesDetail`。ファイルを開いているときだけ）は開いているファイルの中、履歴は下の詳細（コミットを選んでいるときだけ）を探す（`ui/usePageFind`）。編集の部品（Monaco）があれば Monaco の検索の欄（見えていない行も探せる。`editorFind.ts` の `openEditorFind`。`CodeEditor` が入れ物に開き方を置く `registerEditorFind`。部品の中にピントがあれば Monaco が自分で受け取る）、差分・読むだけの表は右上の検索の欄（`ui/FindBar`）。
- 木の縦の線（インデントガイド。利用者の依頼で VS Code の既定 `renderIndentGuides: onHover` と同じにした。VS Code の本体のコードで確かめた）: 開いたフォルダの中身の段に、親のフォルダの開閉の矢印の下から縦の線を引く。一覧にマウスを乗せている間だけ全部を薄く出し（VS Code の `tree.inactiveIndentGuidesStroke` = 濃い線の 40%）、選んでいる行・ピントのある行の親の段の線（その行が中身のある開いたフォルダ（`data-open-group`）なら、その中身の段の線）は乗せていなくても濃く出す（`tree.indentGuidesStroke`）。出し入れは 0.1 秒で薄く・濃く。線は入れ子の `ul.file-tree[role="group"]` の `::before`（`--guide-depth` は親のフォルダの段）で、ファイル・変更（木の表示）・履歴の詳細・メモの木（`MemoTree`）で同じ。検索の結果は、ファイルの中の行の一覧（`.code-search-lines`）に同じ線（`styles/editor/editor-explorer.css`）。
- フォルダ・ファイルのアイコンは `FileIcon`（VS Code の Material Icon Theme。対応表 `fileIcons.ts` は使うときだけ読み込む）。
- チャットのファイル（返答のチップ・ターンの変更カード・ツールの行）は、ふだんはチャットの画面の右の欄に開き（下の「右の欄の変更とファイル」）、⌘クリック・右クリックの「ファイルタブで開く」・右の欄の「ファイルタブで開く」で `openProjectFile` によりファイルタブでそのファイルを開く（URL の `#/projects/:id/files?file=&line=&worktree=`。以前の `changes?file=` もファイルタブで開く。開いたら URL から外す）。
- 差分（`DiffView`）は、左右に並べる設定でも、2 つ並べると読めない幅（`SPLIT_MIN_WIDTH`。`hooks/useNarrowerThan`）では 1 列で出す（設定は変えない）。`bare` で見出しを出さない（右の欄の変更）。

## 右の欄の変更とファイル（`SideChanges`・`SideFileView`）

チャットの画面の右の欄（`features/panel/CLAUDE.md`）のタブの中身。チャットの作業場所（ワークツリーならそのフォルダ。`WorktreeContext` で渡す）を見る。Git の状態は `useGitStatus`（チャットが動いた・作業中にツールの結果が届いた（SSE の `chat_event` の `tool_result`）・ウィンドウに戻ったら取り直すので、AI が作業を続けて変わっても差分が追いつく。続けて届く知らせは最初の知らせから 1.5 秒後の 1 回にまとめる（届くたびに待ち直すと、ツールが続く間は取り直さない）。5 秒ごとの取り直しはしない。以前はチャットの行の変化だけを見ていて、作業が終わるまで差分が止まっていた）。

- 変更（`SideChanges`）: コミットしていない変更のあるファイル（`sideFile.ts` の `changedFiles`。同じファイルは 1 つにまとめ、どの差分を出すかは `changeOf`: 競合 → 未ステージ → ステージ済み）を、上に一覧、下に差分を縦に並べる。上の帯に件数・表示のしかた（`DIFF_LAYOUT`。ファイルタブと共通）・取り直し。押したファイル（タブの `focus` / `focusAt`。押し直しても移る）の位置へ移り、一覧の行でもそのファイルへ移る。ファイルごとに見出しで畳め（20 個より多ければ、初めは移る先のファイルだけ開く）、見出しはスクロールしても上に残る。見出しの右に「確認済み」と「ファイルタブで開く」、見出し・一覧の右クリックはファイルのメニュー。差分は 1 つのファイルにつき 1 回だけ読む（`useFileDiff` を見出しで読み、開いていれば `DiffView` の `source` に渡す。読むのは開いている・確認済みの印があるファイルだけ）。
- 確認済み: 見出しの「確認済み」を付けると差分を畳み、一覧に ✓、上の帯に「確認済み n/m」。確認したときの差分の指紋（`sideFile.ts` の `diffFingerprint`）を作業場所ごとに覚え（`sideViewedFiles`）、あとで差分が変わったら（`viewedStateOf` の `changed`）「確認後に変更」と出して開き、確認済みに数えない（付け直すといまの差分で覚え直す）。もう変更のないファイルの印は外す（`pruneViewed`）。差分の行を選ぶと「チャットに追加」で、右クリックの、足す先のチャットの名前の組で、足す先のチャットの入力欄に引用・パスを足せる（`useCodeQuoteMenu`。`features/chat/CLAUDE.md` の「選択部分をチャットに追加」）。
- ファイル（`SideFileView`）: 中身（`FileView`。開いたらすぐ書け、Git との違いの帯も出す。行の番号があればその行へ移る）。上の帯に、コミットしていない変更があれば「差分を見る」（変更のタブのそのファイルの位置へ）と「ファイルタブで開く」。中身の行も、選ぶ・右クリックで差分と同じく足す先のチャットに足せる（Monaco の選択はページの選択にならないので、`CodeEditor` が入れ物（`data-quote-path`）に選んでいる行と文の読み方を置き（`codeSelection.ts` の `registerCodeSelection`）、`pickedInCode` と `useCodeQuoteMenu` がピントのある部品から読む。右の欄・別ウィンドウでは Monaco の右クリックのメニューを出さず、チャットに足すメニューにする（`nativeContextMenu`）。読むだけの表は行の `data-no`、表の `data-quote-path`）。
- タブの名前の前は、ファイルの種類のアイコン（`FileTabLead`）。

## 履歴（`features/history/HistoryTab`）

Fork と同じ形: 左にブランチ・リモート・タグ・stash・ワークツリーなどの一覧 `HistorySidebar`（名前で絞り込め、押すとそのコミットを表で選ぶ。まとまりは `RefSection` / `RefItem`。ワークツリーの作成・削除は `useWorktreeActions`）、右上にコミットの表 `CommitTable`（線つきの件名・作者・番号・日時 `formatDayTime`）、右下に選んだコミットの詳細 `CommitView`（「コミット」「変更」のタブ。変わったファイルは木・一覧 `COMMIT_FILES_LIST`、差分は `DiffView` の `commit`）。上下の境目はドラッグで動かせる（`HistoryMain`・`HISTORY_SPLIT`）。読み込みは `useGitLog`（表示している間だけ読み、「さらに読み込む」で続きを足す）、ブランチの線は `commitGraph.ts` の `layoutGraph`。
