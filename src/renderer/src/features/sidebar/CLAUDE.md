# 左のサイドバー（`features/sidebar`）

上に新しいチャット・全プロジェクト・検索（押すと開く・作るものだけ）、その下にプロジェクトごとのチャット一覧、左下に設定。グループの操作の共通部分（`features/group/`）もここに書く。まとめ方・数え方・開閉の仕組みは `features/chatList/CLAUDE.md`、プロジェクトの印・メニュー・並び・タグは `features/project/CLAUDE.md`。

- 上の「新しいチャット」（`NewChatButton`。⌘N と同じ `startNewChat`）は、押したらいまどんなチャットができるかが分かるよう、右クリックのメニューの「新しいチャット」と同じグループの札と作業場所の札（`features/chat/NewChatItem.tsx` の `useNewChatPlace` ＋ `NewChatPlaceBadges`）を「新しいチャット」と ⌘N の間に添える（利用者の依頼）。作成先は App が渡す `newChatProject`（開いているプロジェクト、なければサイドバーで選んでいるもの `useFallbackProject`）で、⌘N はグループなし・本体で始めるので札は「No Group」「本体」（作業場所の札は、ほかの「新しいチャット」と同じく Git のリポジトリのときだけ）。乗せたときの説明にはプロジェクトの名前も出す。プロジェクトが 1 つもなければ札を出さない。札が入らない幅では、先に ⌘N を隠し、さらに狭ければグループの札も隠して作業場所の札だけにする（`sidebar.css` の `@container nav-rows`）。
- 開閉（⌘B）と幅（右端のドラッグ、ダブルクリックで既定に戻す。200〜480px）は `useSidebar` ＋ `Sidebar`。閉じているときの「開く」ボタン `SidebarOpenButton` は、Electron のドラッグ領域より優先されるよう画面のいちばん後ろに置く。
- プロジェクトの並びの状態と操作は `useProjectNav`（並べ方・並び順・しまったものを出すか・要対応だけ・検索・いま選んでいるプロジェクト（`saveCurrentProject`。⌘N・全プロジェクトのボードの「新規」の作成先と、全プロジェクトの画面のチャット欄の持ち主にも使う。読むのは `currentProject.ts` の `useFallbackProject`（もうなければ先頭））と切り替え・ショートカット・スワイプ・すべて閉じる / 開く）、表示は `ProjectNav`（縦並び `ProjectStack` / スライド `ProjectSlides`）。1 プロジェクトのページは `WorkspacePage`（中身の変わらないページは描き直さない）、その行の絞り込みと分け方は `useWorkspaceRows`（段の決め方 `sidebarLevels` は `sidebarChatOrder.ts`。同じ分け方でチャットの並びだけを返す `useSidebarChatOrder` を、パネルの一覧のペインのチャットのタブの並びにも使う）。

## 一覧の上の見出し（`ProjectListHead`）

- 見出しはビューのタブ 1 行（利用者の依頼で、前は下の 3 行をいつも出していて縦の幅（約 180px）を取っていた。いまは約 30px）。左からビューのタブ・すべて閉じる / 開く（`foldAll("sidebar", …)`）・要対応の数（一覧に数が出ていないとき = 要対応がオフか「要対応だけ」のときだけ。一覧の上・プロジェクト内にまとめているときは、そのまとまりの見出しに数がある。利用者の依頼で、前は要対応の入ったビューのタブごとに同じ数を出していて、初めの 3 つのビューのタブすべてと一覧の「要対応 n」に同じ数が並んだ）・⚙（「見え方を調整」。`SidebarViewTuner` を `Popover` で開く）。その下にタグの絞り込みの行（その場の絞り込みなのでビューに入れない）。
- ビュー（`sidebarViews.ts` の `SidebarViewState`。読み方・比べ方は純粋関数、一覧の操作はボードの保存したビューと共通の `lib/namedViews.ts`）は、下の 3 行のボタンの値（並べ方・プロジェクトの並び順・カードの行・しまったプロジェクト・まとめ方・チャットの並び順・チャットの行・アーカイブ済みのチャット・要対応のオン / オフ・出し方 × 並べ方）の組に名前を付けたもの。ビューはその組を覚えるだけで、見え方はそれぞれの設定のまま（`useSidebarViews` の `apply` で書き込む）。要対応がオフどうしなら、出し方 × 並べ方は比べない。保存は `SIDEBAR_SAVED_VIEWS`（初めは「標準」（縦スライド・2 行・グループ別・最近順・チャットのアーカイブを表示・要対応を一覧の上に（プロジェクト別））・「コンパクト」（標準をプロジェクトもチャットも 1 行にし、チャットのアーカイブは隠す）・「要対応」（縦並び・要対応だけ（プロジェクト別））の順。利用者が示した形。いちど利用者の依頼でコンパクトを先頭にしたが、利用者の依頼で標準を先頭に戻した。すべて消したら `[]` を覚えて戻さない）。
- タブを押すとその見え方にし、最後に選んだビューとして覚える（`SIDEBAR_VIEW_SELECTED`）。いまの見え方に合ういちばん前のタブを選択中（`.active`）に、合うものがなければ最後に選んだタブを点線の枠（`.modified`。「このビューから変えている」）で見せる。ライトモードでは、共通の枠と地の色がサイドバーの地とほぼ同じで見えなかったので、選択中は白い地に枠と薄い影、点線の枠は薄い文字の色にする（`sidebar-views.css`。利用者の指摘）。まだ一度も選んでいなければ、開いたときに最初のビュー（初めは標準）を当てて選ぶ（利用者の依頼。前はいまの見え方に合うビューを選んでいて、初めの見え方の標準になった）。タブは 1 行だけ見せ、入らないタブは折り返した先に送って隠し（実際に折り返したかで決める）、▾ のメニューに出す（メニューの項目も、右クリックでタブと同じメニューを開く。▾ のメニューは閉じる。利用者の依頼）。列はスクロールできない切り取り（`overflow: clip`）にする（hidden だと、2 行目の名前の欄にピントが入ったときに列が 1 行分スクロールしたまま戻らず、名前を変えたあとタブが 1 つも見えなくなった）。右クリックで名前を変更（ダブルクリック・ピントがあるときの Enter でも。利用者の依頼。名前を変える欄は ✓ ✕ を含めると列のほぼ 1 行分あるので、変えている間は先頭に並べて行いっぱいに出し、ほかのタブは隠れる行へ送る。前はタブの場所に置いていて、前にタブがあると隠れる 2 行目へ折り返し、欄が見えないまま選択中のタブも ▾ に入った）・いまの見え方で上書き（同じなら押せない）・削除（確かめる）、ドラッグで並べ替え（共有の `ui/useViewTabDrag`。利用者の依頼で、▾ のメニューの項目もドラッグでき（縦に並ぶので上下の半分で前後を決め、線は項目の上か下に横に引く `tabProps(id, "y")`）、タブの行とメニューの間でも動かせる。タブを ▾ に重ねると枠を付けて、落とすといちばん後ろへ、重ねたまま 0.6 秒待つとメニューが開き、その中の好きな位置へ落とせる `endProps`）。同じ名前は付けられない（`viewNameTaken`）。
- ⚙ の窓（`SidebarViewTuner`）: 窓の中を押しても閉じず、× ・窓の外側・Esc で閉じる（利用者の依頼。窓の中でいろいろ変えて、終わったら × で閉じる）。開いているかは見出しの外（`ProjectListHead.tsx` の `tunerOpen`）に持つ（見出しは並べ方ごとに別の部品の中に描くので、窓の中で並べ方を変えると見出しが作り直され、前は窓が閉じた）。下の 3 行と、変えた見え方を残す「「（選んでいるビュー）」に上書き」（同じなら押せない）・「今のビューを新規保存」（利用者の依頼で、前の名前は「新しいビューとして保存」。ボードと同じ名前にした。その場で名前を聞く。いまの見え方と同じビューがもうあれば押せなくし、ボタンの下に「いまの見え方と同じビュー「標準」がすでにあります」と書く（`lib/namedViews.ts` の `sameViewExistsText`。名前の欄でも同じ理由で決めさせない）。同じ見え方のビューを 2 つ作らないため。利用者の依頼）・「ビューを管理」（設定の「サイドバー」）。
- 設定の「サイドバー」（`SidebarViewSettings`）: ビューの一覧（↑↓ で並べ替え・名前の変更・中身の変更（同じ項目を `Segmented` で。変えるとすぐ保存し、表示中のビューならいまの見え方にも当てる）・削除）と「新しいビュー」（いまの見え方から「ビュー n」を作り、中身を開く）。
- ⚙ の窓の 3 行は、何に効くかで行を分け、設定の種類（ジャンル）ごとのボタンを並べる（1 つのボタンには 1 種類だけ。種類の違う設定を 1 つのボタンにまとめない）。3 つ以上あるものはメニューから選ぶ `HeadMenu`（`ChoiceMenu` を開く）、2 択は押すたびに切り替える `HeadToggle`。どちらも 2 段で、上に種類の名前・下にいまの値。幅は取りうる値 `values` のいちばん長いものに固定し、選び直しても変わらない（窓は中身の幅に合わせるので、前のように文字を隠してアイコンだけにする詰め方はしない）。
  - 1 行目「プロジェクト」: 並べ方（縦並び `stack` / 横スライド `slide` / 縦スライド `rail`。`SIDEBAR_LAYOUT`。初めは縦スライド）・並び順（手動 / 最近動いた順。`SIDEBAR_PROJECT_ORDER`。初めは最近動いた順。最近動いた順のときもドラッグで並べ替えられ、落とすと手動に切り替わる）・表示（カードを 1 行 / 2 行。初めは 2 行）・アーカイブ（しまったプロジェクトを出すか `SIDEBAR_SHOW_ARCHIVED_PROJECTS`。初めは閉じる。縦並びでは一覧の下の見出しでも切り替える）。
  - 2 行目「チャット」: まとめ方（まとめない / グループ別 / 作業場所別。メニューの見出しは「チャットのまとめ方」、名前は右のパネルのタブのまとめ方と同じ `CHAT_GROUPING_LABELS`。初めはまとめない。メニューの下に「まとまりを色付きで表示」（`HeadMenu` の `extra`。選んでも閉じない））・並び順（最近順 / 状態順 / 手動。3 つなのでメニュー `HeadMenu`。メニューでは「最近動いた順」「手動（ドラッグで並べた順）」。パネルのタブの列の「表示」のメニューの「チャットの並び順」と同じ設定）・表示（行を 1 行 / 2 行。初めは 1 行）・アーカイブ（出すか。初めは隠す）。「すべて閉じる / 開く」は、その場の操作なのでビューのタブの行の右に置く。
  - アーカイブはどちらの行も右端。「表示」はプロジェクトのカードとチャットの行で別々に切り替え、1 つの設定で両方を変えない。
  - 3 行目「要対応」（いつも出す。名前の横に待っているチャットの数。利用者の依頼で、前の名前は「自分待ち」。「回答待ち」と同じ「待ち」で終わり、どちらが誰を待つのか紛らわしかったため、対応が要るものと言う）: オン / オフ（`HeadToggle` の `pressed`。オンは値とアイコンをアクセントの色に）・出し方（要対応だけ / 一覧の上に / プロジェクト内。3 つなのでメニュー `HeadMenu`）・並べ方（プロジェクト別 ⇔ 状態順。`HeadToggle`）（`WaitingRow`。ほかの行と同じく 1 つのボタンに 1 種類。名前の短いオン / オフを 1 列、名前の長い出し方を 2 列分の幅に置く。ボタンの名前は短く、メニューと説明で「プロジェクト内の上にまとめる」のように言う）。オフのときは出し方・並べ方を押せなくし、プロジェクト内では並べ方はプロジェクト別だけなので並べ方を押せなくする（`canChooseOrder`。どちらも隠さず薄くする）。名前とアイコンは `waitingView.ts` の `WAITING_SCOPE_META` / `WAITING_ORDER_META`。利用者の依頼で、前はオン / オフを上の段（新しいチャット・全プロジェクト・検索の並び）の「要対応」に置き、この行はオンのときだけ出していた（上の段は押すと開く・作るもので、絞り込みの切り替えだけが性質が違ったため）。
  - ビューのタブの行の下の「タグ」の行（`TagFilterRow`。タグがあるときだけ）: 名前「タグ」の右に、使っているタグと「タグなし」の小さなボタンを並べた 1 行（利用者の依頼。前は名前の下の行に並べて 2 行を取っていた。見出しは格子でないので、この行だけで 2 列にし、入らないボタンは右の列の中で折り返す。名前は 1 段目にそろえる）。ボタンは押すたびに絞り込みを付け外しする（複数選べ、選んだタグのどれかが付いているプロジェクトだけを出す。選んでいるものはアクセントの色、× で外す）。利用者の依頼で、タグはドラッグで並べ替え（ビューのタブと同じ `ui/useViewTabDrag`。並びは `PROJECT_TAG_ORDER`）、右クリックで名前を変更・削除…、ピントがあるときの Enter で名前の変更（その場の `InlineName`）。名前の変更・削除は付いているすべてのプロジェクトに効く（`features/project/tagActions.ts`）。「タグなし」は動かせず、メニューもない。1・2 行目のボタンを増やさないため（増やすと既定の幅でも文字が隠れる）。
- すべてのプロジェクトに効く設定は、プロジェクトのメニューに入れずこの見出しに置く。下の行は主な操作だけ（縦並びは新しいプロジェクト、スライドはプロジェクトの丸）で、表示方法の操作を足さない。
- 見出しの「要対応」の行のオン / オフ（`SIDEBAR_WAITING_ONLY`）は、回答待ち・エラー・未読のチャットに目を向ける切り替え（初めはオン。数はしまったプロジェクト・タグで隠れたプロジェクトを除く `waitingChats`。`useProjectNav` の `head.waiting`）。要対応の一覧と数・見出しの状態ごとの数 `HeadCounts`・スライドの丸の角の数は、子チャット（孫も）も数える（`stores/chats.ts` の `useChatsWithChildren` / `useChatsWithChildrenByProject`。利用者の依頼。前は親のないチャットだけで、未読の子チャットがあっても「要対応 0」だった）。要対応の一覧の子チャットの行は、押すと設定の開き方（右の欄 / 別ウィンドウ）で開く。「要対応だけ × プロジェクト別」・状態の数を押して絞ったときは、合う子チャットも行に並べる（`useWorkspaceRows` の `counted`。親の中に閉じたままだと見えないため）。その行と要対応の一覧の行は、名前の前に深さの札「子 / 孫 / ひ孫」（`features/chat/children/ChildDepthMark`。右の欄のタブの札と同じ形と色。乗せると「「親の名前」の子チャット」。`ChatRow` の `childMark`）を付け、親の下に並んでいなくても子チャットだと分かるようにする（利用者の依頼）。状態の数で絞っているときは、アーカイブ済みのチャットを出さない（数にアーカイブ済みは入らないのに、アーカイブ済みのまとまりが開いて出ていたため。利用者の指摘）。オンのときの表示は、出し方 × 並べ方の 5 通り（保存は 1 つの値 `SIDEBAR_WAITING_VIEW`。軸との行き来は純粋関数の `waitingAxes.ts`。今までの値はそのままの意味で読む）:
  - 要対応だけ × プロジェクト別（`filter`）: 待っているチャットのあるプロジェクトだけを、その中の待っているチャットだけで並べる（下書きのあるプロジェクトも並べる）。
  - 要対応だけ × 状態順（`list`）: プロジェクトの一覧の代わりに、待っているチャットだけをプロジェクトをまたいで並べる（`WaitingInbox` の `list`）。
  - 一覧の上に × 状態順（`inbox`）/ × プロジェクト別（`inbox-project`。初め）: 一覧のいちばん上に「要対応 n 件」のまとまり（`WaitingInbox` の `top`。開閉を覚える）を置き、その下はオフのときと同じすべての一覧。スライドではスライドの上に置き、高さの上限を付けて中でスクロールする。
  - プロジェクト内（`in-project`。並べ方はプロジェクト別だけ）: 各プロジェクトの中のいちばん上（下書き・固定より上）に「要対応 n」のまとまり（`WorkspacePage`。中は状態順。開閉はプロジェクトごとに覚える）を置き、その下はいつもの一覧（待っているチャットは両方に出す。一覧の上にと同じ）。検索・状態で絞っている間は出さない。
  - 言い方の決まり: 「〜順」は並べる順、「〜別」は見出しに分ける（チャットの並び順の「最近順 / 状態順」・まとめ方の「グループ別 / 作業場所別」と同じ）。
  - 状態順は、状態の見出し（回答待ち → 失敗 → 未読）に分け、見出しの中は待っている時間の長い順（回答待ちはいちばん古い依頼が届いた時刻、ほかは最後に動いた時刻。純粋関数の `inboxOrder.ts` の `inboxSections` / `waitingSince`）。プロジェクト別のまとまりは、サイドバーのプロジェクトの並びでプロジェクトの見出し（印と名前・件数。開閉を覚える）に分け、中は状態順（`inboxByProject`）。行はプロジェクトの一覧と同じ `ChatRow` で、状態順のときはどのプロジェクトかの印（`project`）を添える。出すのは、しまっていない・タグの絞り込みに合うプロジェクトのチャット。プロジェクトとチャットの行を絞るのは「要対応だけ × プロジェクト別」のときだけ（`useProjectNav` の `filterByWaiting`・`useWorkspaceRows`）。「要対応だけ × プロジェクト別」で要対応がない・タグで絞って合うプロジェクトがないときは、その旨と戻すボタンを出す（下書きは数に入れない `hasWaiting`）。プロジェクトが 1 つもないときは、要対応かどうかに関係なく、ここに何が並ぶかの一言と「新しいプロジェクト」（`.workspace-empty`）。

## 並べ方とプロジェクトの切り替え

- 縦並びは見出し・すべてのプロジェクトをまたぐ検索欄（チャット名で絞り、一致するプロジェクトだけを開いて並べる。プロジェクトの検索欄が空のときに効く）・プロジェクトのカードの列。固定したプロジェクトがあれば「固定」「プロジェクト」の見出し（`.project-section-label`）で分ける。カードを 1 行で表示のときは、チャット数とタグの行を出さない。
- スライドは 1 ページ = 1 プロジェクト。横スライドは丸の列（`WorkspaceDots`）を下に並べて横にスワイプ、縦スライドは丸を左に縦に並べて縦にスワイプ（`useWorkspaceSwipe` の `axis: "y"`。一覧がその向きにスクロールできる間・スクロールの慣性では切り替えず、端まで来てからのスワイプだけ。指に追従させる間は React の再描画を挟まず transform を直接動かす）。丸の帯の上のスワイプでも切り替える（`stripHandlers`。横スライドは横方向だけ、縦スライドは縦・横どちらでも）。固定したプロジェクトがあれば丸の列に区切りを入れる。丸の角には状態ごとのチャット数 `StateCornerCounts`。
- ショートカット: どの並べ方でも ⌥⌘← / → と ⌃Tab / ⌃⇧Tab で前後へ（⌃Tab は端で反対の端へ回る）、⌃1〜9 で n 番目。縦スライドは ⌥⌘↑ / ↓ でも前後へ（チャットにピントがあるときは、チャットの前後の指示へ移るのが先。`defaultPrevented` なら見ない）。どれもタグの絞り込みのあとの並び。
- プロジェクトの並べ替えのドラッグは `useProjectReorder`（縦並びのカード・横スライドと縦スライドの丸・全プロジェクトのボードのプロジェクトの段の見出しで共通。しまっていないプロジェクトだけ。ドラッグはタグで隠れたものを含む並び全体の中で動かす）。並び順が最近動いた順でもつかめ、落とすと、いま見えている並びのまま動かしたものだけを動かした順を手動の並びとして保存し（`api.reorderProjects`）、並び順を手動に切り替える（`onManual`）。入る位置の線は、横に並ぶ横スライドの丸では縦線、縦に並ぶ縦スライドの丸・縦並びのカードでは横線（`sidebar-list.css`。利用者の依頼で、前は縦スライドの丸でも縦線だった）。利用者の依頼で、前は手動の並びのときだけつかめ、初めの最近動いた順ではドラッグしても何も起きなかった。

## 下書き（`DraftRows`）

すべてのボード・チャット欄の下書き（送る前の新しいチャット）を、サイドバーの各プロジェクトにも出す（`useProjectDrafts`。仕組みは `features/panel/CLAUDE.md`）。名前は、最初のチャットを送るまで「New Chat」のまま（タブと同じ。利用者の依頼で、書きかけの文の 1 行目を出すのをやめた）。右クリックの「名前を変更」で付けた名前があればそれ（`draftTitleOf`）。いまの画面のプロジェクトのチャットのパネル（チャットタブ・ボードの右のパネル）でその下書きのタブを表示しているときは、チャットの行と同じく選択中に見せる（`useDraftSelected`。チャットの行はタブで選ぶと URL になって選択中になる。`features/panel/CLAUDE.md` の「欄の殻」）。押すとそのパネルで開き（別の画面のものはその画面へ移ってから）、右クリックはチャットの行と同じ並びの `DraftMenuItems`（`features/chat/CLAUDE.md` の「操作・名前・メニュー」。名前の変更は行の名前を入力欄 `DraftTitleInput` にする）。ドラッグでグループ・グループなしへ落とすと作成先のグループを変える。ピン留めした下書き（タブの `pinned`。`togglePinDraft`。再起動しても残る）は、まとめ方にかかわらずプロジェクトのいちばん上の「固定」の中（固定したチャットの上。数にも入れる）に抜き出し、グループの中・いちばん上には出さない（`useWorkspaceRows` の `pinnedDrafts`）。送ると、できたチャットも固定する（`PanelTabPage`）。グループの下書きはそのグループの中に、グループなし・もうないグループのものは、グループの見出しを出しているときは「No Group」の中（チャットの上。`ungroupedDrafts`）、見出しがないときはいちばん上に並べる。並び順が手動のときは、まとまりのいちばん上ではなく、タブの列（その欄の一覧のペイン）での下書きのタブの位置に合わせて、チャットの行の間に置く（利用者の依頼。`useDraftPlacement`: タブの列で下書きより前に見える同じまとまり（グループ・見出しの下の一覧。作業場所別なら同じ作業場所）のチャットのすぐ後ろ。純粋関数は `manualOrder.ts` の `draftAnchor`、タブの位置は `panelDrafts.ts` の `draftTabSpot`。前に同じまとまりのチャットのタブがなければ、いままでどおりいちばん上。「要対応」のまとまりには出さない）。行の字下げは、同じまとまりのチャットの行とそろえる（グループの中のチャットの行だけに残っていた 10px の余白を消し、下書き・No Group・状態ごとの段と同じ位置にした）。数は、やり取りのあるチャットと同じに数える（利用者の依頼。プロジェクトの見出しの「N チャット」・グループ・「No Group」・固定の見出しの数に足す。手動の並びでチャットの行の後ろに置いたものも、そのまとまりの数に入れる。`useWorkspaceRows` の `chatCount`・`draftCounts`）。下書きのあるグループは絞り込み中（要対応）も隠さない。検索・状態での絞り込み中は出さない。
