# プロジェクト（`features/project`）

プロジェクト全般（印・札・色・タグ・並び・メニュー・絞り込み）、プロジェクトの画面（`page/`）、編集のダイアログ（`settings/`）、新しいプロジェクト（`new/`）。サイドバーのカード・見出しの行は `features/sidebar/CLAUDE.md`、ボードは `features/board/CLAUDE.md`。

## 印・札・色

- プロジェクトの色を出すのは印 `ProjectMark` だけ（プロジェクトの色の角丸の四角に頭文字 `initialOf`。`size` は `sm` = 16px（バッジ・メニュー・段・文言の全文検索 / ⌘⇧A の絞り込み）/ `md` = 20px（サイドバーの見出し・画面の見出しの名前）。`project` がなければ全プロジェクトの灰色の印）。CSS は `styles/project/project-mark.css`、色は横スライドの丸 `.workspace-dot` と同じ。
- 名前を出す札は、どこでも「印 ＋ 名前 ＋ プロジェクトの色の薄い地」の形にそろえる（地と枠の色は `project-mark.css` の `.workspace-head` / `.project-switch` / `.project-chip` に 1 か所で持つ。色は要素か親の `--ws-hue`（`projectHueStyle`）。後ろのファイルの各部品の規則では地と枠の色を書かない（`border` の一括指定も枠の色を消すので `border-width` / `border-style` で書く）。全プロジェクトの見出しは灰色）。名前は普通の文字色、開閉の矢印は灰色、カンバンのカードに色の線は付けない。
- バッジは `ProjectChip`（押してカンバンを開くなら `linked`、名前の代わりに選択欄などを置くなら children）。
- プロジェクトの色はプロジェクトの `hue`（`@shared/project/colors.ts` の `PROJECT_HUES` の 10 色から、作ったときにほかと被らない色を `pickProjectHue` で選んで覚える。編集の「基本情報」で変えられる）。画面は `projectHue(id)` で読む（App がプロジェクトの一覧を読むたびに `setProjectHues` で入れる）。

## 並び・絞り込み・メニュー

- サイドバーの並びは `projectOrder.ts` の `sidebarOrder`（上に固定したものが先、そのあとドラッグで並べ替えた順。しまったものは出さない）、最近動いた順は `recentOrder`（固定したものの次は、チャットが最後に動いた順）、しまったものは `archivedProjects`（名前順）。サイドバーと同じく見せるプロジェクトは `useVisibleProjects`（`active` = しまっていないもの・`visible` = そのうちタグの絞り込みに合うもの・`archived`。サイドバー・全プロジェクトの画面・⌘⇧A・パネルのタブ・下のパネルで共通。最近動いた順のときだけチャットの一覧から並びを読み、並びが変わらなければ描き直さない）。
- 固定・しまう・タグの変更は `changeProject`（失敗はお知らせ）。アーカイブするときも戻すときも確かめる（`confirmArchiveProject` / `confirmRestoreProject`）。
- 右クリックのメニューは `useProjectMenu`（サイドバーの見出しのカード・下の丸）。操作をまとまりに分けて並べる: このプロジェクト（新しいチャット・グループを作成・作業中・待ちのチャットを一覧（⌘⇧A の一覧をこのプロジェクトで絞り込んで開く）・Finder）/ 整理（固定・開閉・アーカイブ）/ タグ（使っているタグのチェック・「新しいタグ…」）/ 編集・削除（`ProjectEditDialog`）。すべてのプロジェクトに効く設定はここに入れず、サイドバーの見出しの行に置く。
- チャットのメニューの「プロジェクトを変更」で横に開く一覧は `ProjectPickFlyout`（上に「プロジェクトを検索または作成」の欄、「新規プロジェクト」、区切り線、サイドバーの並びのプロジェクト（いまのプロジェクトにチェック。しまったものは出さない））。右に入らなければメニューの左に出し、ほかの項目に乗せる・← で閉じる。Enter は絞り込んだ先頭、合うものがなければ書いた名前で作る。↑↓ は一覧の中だけで動く（`useMenuKeys` は `data-menu-scope` の内と外を分ける）。「新規プロジェクト」は `new/openNewProject.ts` の `openNewProject({ name, onCreated })` で App の新しいプロジェクトのダイアログを開き、作ったらそのプロジェクトへ移す。

## タグ

- タグはプロジェクトの `tags`（文字の配列。`api.updateProject` の `tags` で置き換え、前後の空白・重複を除く。上限は `MAX_TAG_LENGTH`（30 文字）・`MAX_TAGS`（20 個）。整え方・照らし合わせ・一覧は `@shared/project/tags.ts`）。
- 付け方は編集の「基本情報」の `TagEditor`（Enter・読点・カンマで足し、× で外す。ほかのプロジェクトのタグを候補に出す（↑↓・Enter・Esc）。足す・外すと、すぐ保存する。入力欄を先に置く: `Field` は label なので、名前を押したときに最初のチップの × が押されないように）と、右クリックのメニューの「タグ」。表示は小さなチップ `ProjectTags`（サイドバーのカードの 2 行目、チャット数の後ろ）。
- タグの並びは、サイドバーのタグの行でドラッグして並べた順（`PROJECT_TAG_ORDER`。並べていないタグは後ろに名前順。`@shared/project/tags` の `orderTags`。読むのは `projectTagFilter.ts` の `useOrderedTags`。タグの行・右クリックのメニューの「タグ」で同じ順）。名前の変更・削除は `tagActions.ts` の `renameTag` / `deleteTag`（付いているすべてのプロジェクトのタグを 1 つずつ書き換える。同じ名前のタグがもうあれば確かめて 1 つにまとめ、削除は確かめてから外す（プロジェクトは消えない）。絞り込みで選んでいるか・並びも付け替える）。
- 絞り込みは `projectTagFilter.ts` の `useProjectTagFilter()`（`tags`（使っているタグ・並べた順）/ `move`（ドラッグで並べ替え）/ `selected` / `active` / `toggle` / `clear` / `matches(project)`）。保存は `PROJECT_TAG_FILTER`（選んだタグの配列。`""`（`UNTAGGED`）はタグなし。空なら絞り込まない。部品どうしでそろう）。どのプロジェクトにももう付いていないタグは選んでいないものとして扱う。効かせる場所: サイドバーの並び（どの並べ方でも。⌃Tab・⌥⌘← → ・⌃1〜9 もこの並び）・「要対応」の数・全プロジェクトの画面（カンバン・状態ごとの数）・⌘⇧A。合うプロジェクトがないときはその旨と「絞り込みを外す」を出し、サイドバー以外の画面には絞り込んでいる印 `TagFilterNotice`（× で外す）を出す。

## プロジェクトの画面（`page/`）

- `ProjectPage`（データは `useProjectData`。プロジェクト・チャット・グループの店から読み、まだ届いていないものがあれば、届くまで前に出していたプロジェクトの画面を薄くして出す。もうないとわかったプロジェクト（消した・URL の番号が違う。`useProjects().missing`）は中身の部品を出さず（グループ・Git の状態を読みに行かない）、案内だけを出す（`ProjectsEmpty.tsx`）: プロジェクトが 1 つもなければ始め方の案内 `NoProjectsWelcome`（何をする所か・始め方の 3 段（用意する → チャットで頼む → 要対応で受け取る）・新しいプロジェクト / 既存のフォルダを取り込む。全プロジェクトの画面の空のとき・新しいチャットの案内のダイアログ（下の「新しいプロジェクト」）と共通。しまったプロジェクトだけがあれば「表示中のプロジェクトがありません」とその数）、ほかにあれば `MissingProject`（ID と理由・全プロジェクトへ / 新しいプロジェクト・ほかのプロジェクトの一覧（サイドバーと同じ並びで 6 件まで））。取り込むボタンは `openNewProject({ mode: "import" })` で、ダイアログを取り込む側で開く。App も、そのプロジェクトをチャット欄・下のパネル・下の帯に渡さない）。タブはボード（カンバン。以前のグループのボード `groups` の URL はボードに戻る）・チャット（`chats`。チャットをボードと分ける置き方のときだけ。`ChatsTab`。`features/panel/CLAUDE.md`）・ファイル（`files`）・検索（`search`）・変更（`changes`。この 3 つは以前の「エディタ」タブの中の切り替え。開いたファイルは 3 つで共有。`features/editor/CLAUDE.md`）・履歴（`history`）・メモ（`memos`。`features/memo/CLAUDE.md`）・DB（`db`。DB クライアント。`features/database/CLAUDE.md`。この Mac のアプリの中だけで、ブラウザ・スマホから開いたときはタブを出さず、URL で来てもボードを出す）・GitHub（`github`。連携先の issue・PR。`features/github/CLAUDE.md`。DB と同じくこの Mac のアプリの中だけ）。どのタブでも同じ横幅にする。本体はいつも `.project-main`（横並び）＞ `.project-content`（縦に伸ばす）に入れる（置き方で DOM の深さを変えない）。
- 見出し `ProjectHeader`: 名前（`ProjectSwitcher`）・設定の歯車（編集のダイアログ）・しまったものを戻すボタン・状態ごとのチャット数 `StateStats`（作業中・回答待ち・未読。子チャットも数えて並べ、押すと `StateChatsPopover`。子チャットは設定の開き方で開く）・すべてのプロジェクトの状態ごとのチャットのボタン（`page/AllStateChats`。アイコンは ⌘⇧A と同じ `Activity`。ほかのプロジェクトに要対応があるかを見るため。数が 0 でも出す。右上にすべてのプロジェクトの要対応（回答待ち・未読。サイドバーの「要対応」と同じ数え方。`useAllWaiting`）の数を重ね、回答待ちがあればオレンジ、なければ緑（`features/palette` の `WaitingCountBadge`・`.active-chats-badge`）。押すと、左の状態ごとの数と同じ一覧 `StateChatsPopover` を開き、上の切り替え（`.state-chats-scope`）で「すべてのプロジェクト / このプロジェクト」を選ぶ。開くたびに「すべてのプロジェクト」から（保存しない）で、行にプロジェクト名を添える。数える範囲は ⌘⇧A の「すべて」と同じ `useAllProjectChats`。利用者の依頼で、前は ⌘⇧A の一覧を「すべて」で開いていた）と、横並びのときはタブの列（`.project-tabs-row`）。
  - 名前の行の出し方（`page/headerMode.ts` の `PROJECT_HEADER_MODE`）: 下の帯と同じく、表示 / 寄せたときだけ表示 / 非表示から、名前の行の右クリックと設定の「表示」→「プロジェクトの見出し」で選ぶ（利用者の依頼。名前は下の帯の `FOOTER_MODE_LABELS` と共通）。タブを横並びにしていれば、タブの列はどれでも残す。
    - 寄せたときだけ表示（`.project-title-row.auto-hide`）: 画面の上に重ね（縦の幅を取らない）、ふだんは上端の 6px だけを残して透明にし、マウスを寄せると出す。乗せている間・キーでピントを移している間・中の一覧やメニューを開いている間は出したまま。ウィンドウのドラッグ領域にはしない（ドラッグ領域にはマウスの動きが届かず、乗せても出せないため）。
    - 右上のレイアウトの開閉（`app/LayoutToggles` の `reveal`。プロジェクトの画面・チャット・新しいチャットの URL のとき）も合わせる: 寄せたときだけ表示なら名前の行と一緒に出し入れし（置き場所はそのまま。隠している間は押せなくする。名前の行がない分、下の画面が上に詰まり、見えないボタンがチャット欄の右上のボタンに重なるため。乗せている間は名前の行も出したまま）、非表示なら出さない（利用者の依頼。⌘B・⌘J・⌥⌘B はそのまま）。
    - サイドバーを閉じているときは、名前の行がなくても信号機ボタンと開くボタンの下（34px）から始め、空いた帯をウィンドウのドラッグ領域にする（`.page-board::before`）。
- フォルダの変更 `changeProjectFolder(project)`（設定の「基本情報」の「変更…」。利用者の依頼で、見出しにはプロジェクトフォルダの場所を出さない。前は名前の横にパスを出し、押すとここへ来た）: フォルダを選ぶ（`window.kickoff.dialog.pickFolder`。macOS の窓は題を出さないので、窓の上の文に「「プロジェクト名」のプロジェクトフォルダを変更します。…（いま: …）」、決めるボタンを「このフォルダに変更」にし、いまのフォルダから開く）→ 点検（`inspectWorkspace`。選んだフォルダをそのまま本体にする: git のリポジトリの中のフォルダなら、変更・履歴・ワークツリーはその中だけと添える。ほかのプロジェクトと同じフォルダ（「名前」を出す。DB の `repo_path` は重ねられない）・いまと同じフォルダは知らせて終わり、ほかのプロジェクトのフォルダの中・中にあるフォルダは確かめの頭に ⚠ で知らせて変えられる）→ いまと新しいパス・引き継ぐもの（チャット・設定）・ワークツリーで作業しているチャットの行き先（いまのワークツリーの一覧の本体の `root` と、選んだフォルダの `git_root` が同じなら同じワークツリーの中、違えば本体）を書いた確かめ（git の管理を始めるかは、取り込みと同じチェック `gitInitChoice.ts` の `gitInitChoice` を `confirmWithCheck` で添える。初めはオフ）→ `setProjectRepoPath`（`PUT /api/projects/:id/repo-path`）→ ワークツリーの一覧を取り直す。ファイルは移さないので、空のフォルダ（点検の `empty`）を選んだら、確かめの頭で「Finder で移してから選び直す」よう知らせる。変わったプロジェクトは SSE で店に届く。ブラウザから開いたときはフォルダを選べないので、設定の「変更…」は出さない。
- 画面の見出しの名前 `ProjectSwitcher`（全プロジェクトの画面は `project` なし）: 押すと全プロジェクト・ほかのプロジェクトを選べ、プロジェクトどうしはいまのタブのまま切り替わる（全プロジェクトから選んだときはカンバン）。メニューの先頭で全プロジェクトに戻る。しまったプロジェクトは下の「アーカイブ済み」に分ける。
- タブの置き方は設定の「表示」→「プロジェクトのタブ」（上に横並び / 左に縦並び（アイコン）。`PROJECT_TABS_LAYOUT` の `top` / `side`、初めは `side`。`useProjectTabsLayout`、名前は `PROJECT_TABS_LAYOUT_LABELS`）と、タブの列の右クリック（`ChoiceMenu`）で切り替える。縦並びは本体の左 `.project-side-tabs`（アイコンだけ。名前と数は aria-label と、乗せるとタブの右に出す説明（`data-tip-side="right"`。利用者の依頼で、OS の title から変えた））で、見出しの下の行がなくなり本体の縦の幅が広がる。タブはまとまりごとに並べる（`TAB_GROUPS`: ボード・チャット / ファイル・検索・変更・履歴（どれも作業場所のコードと Git）/ メモ / DB / GitHub）。2 つ以上のタブのまとまりは薄い地でつなぎ（`.project-tab-group.boxed`）、まとまりの間を空けて、どれが同じ仲間か見て分かるようにする（縦並び・横並びのどちらでも）。タブはドラッグで並べ替えられる（`useProjectTabOrder`。決まりは純粋関数の `tabOrder.ts`）: ほかのまとまりの上に落とすとまとまりごと動き（ボード・チャット / ファイル・検索・変更・履歴はいつも一緒）、同じまとまりの中では 1 つずつ並べ替える。落とす先の線は、前後の隙間の真ん中にまっすぐ引き（`::after`。角の丸いまとまりでも曲がらない。上の後ろと下の前のどちらでも同じ位置に 1 本だけ出るよう、まとまりの間の隙間は margin に `.tabs` の gap を足して計る）、落としても並びが変わらない所（すぐ前の後ろ半分・すぐ後ろの前半分）には出さず落とせない（`isNoopDrop`）。2 つ以上のタブのまとまりには、端（縦並びは上・横並びは左）にまとまりごと動かすつまみ（`.project-tab-group-handle`・`groupHandleProps`。いつも薄く見せ、乗せると濃く）を置き、つかむとはじめからまとまりごと動く（写しもまとまり全体）。タブが 1 つのまとまり（メモ・DB・GitHub）はタブをつかめばまとまりごと動くので付けない。落とす先には前・後ろの線（`.tab-drop-before` / `.tab-drop-after`）、動かしているものは薄く。並びは `PROJECT_TAB_ORDER`（タブの名前の列。どのプロジェクトでも同じ）に覚え、タブの列の右クリックの「タブの並びを元に戻す」で消す。
- タブの数（`ProjectTabs`）: チャットのタブ（チャットをボードと分ける置き方のとき。分けないならボード。チャットを開く所に付ける）には状態ごとのチャット数（子チャットも数える。`StateCornerCounts`。縦並びはアイコンの角に重ね、横並びは名前の後ろに `inline`）、変更には変更のあるファイルの数（チャットの状態の色と被らない紫 `--sec-schedule` の地に白い字。`.tab .change-count`）。VS Code のバッジと同じく、取り直している最中は数の代わりに回る印 `.tab-refreshing` を出す（チャットのタブ = チャットの一覧の読み込み、変更 = `useGitStatus` の `refreshing`（開いた・ウィンドウに戻った・チャットが動いた・取り直しのボタン。5 秒ごとの取り直しでは立てない）。すぐ終わる取り直しでも見えるよう `useBusyBadge` で少なくとも 0.5 秒は出す）。

## 編集のダイアログ（`settings/`）

プロジェクト名の横の歯車・サイドバーの右クリックから開く `ProjectEditDialog`（`TabbedDialog`。画面は移らない）。項目は `PROJECT_SETTINGS_SECTIONS`: 基本情報（いちばん上にプロジェクト名と概要（AI に渡すプロジェクトの説明。空なら 2 行の高さで、書いた分だけ伸ばす `.project-description`。利用者の依頼で、前は「概要・アイデア」という名前で、フォルダ・色・タグの下にあり、空でも 4 行あった）とその「保存」、その下にプロジェクトフォルダ・メモフォルダ（その場で変える `MemoFolderField`。ふだんは空欄で薄い文字にいまの場所、書く・選ぶとこのプロジェクトだけ別の場所。利用者の依頼で、前は別の項目「メモ」で変えていた）・名前・説明・色・タグ。`BasicInfo`）・参照資料（AI がいつでも読めるフォルダ・ファイル。その場で保存。`ReferenceEditor`）・AI（どの AI を使うかのカードと、その AI の既定 `AiSection` / `AiDefaults`。「アプリの設定に従う」を選べる）・GitHub（このプロジェクトで使う gh のアカウント・連携先のリポジトリ（GitHub の remote。2 つ以上なら自動と各 remote を選ぶ。1 つなら見せるだけ）・ワークツリーの PR を見張るか。変えたらその場で保存し、`GET /api/projects/:id/github` を取り直していまの連携先を出す。gh からなくなったアカウント・もうない remote も、選んでいることが分かるよう選択肢に残す。`GitHubSection`。利用者の依頼）・定型文（このプロジェクトで使う定型文。`features/snippet` の `SnippetSettings`）・圧縮前・圧縮後指示（このプロジェクトの圧縮前指示・圧縮後指示。`CompactPromptSettings`。利用者の依頼で定型文から分けた）・削除（`DeleteProject`）。

## 新しいプロジェクト（`new/`）

`NewProjectDialog`（新規作成 `CreateForm` / 既存フォルダの取り込み `ImportForm`（点検の結果 `InspectionPanel`）。2 つの作り方は、どちらも置いたまま隠すだけにして（`hidden`）、切り替えてもダイアログを閉じるまでそれぞれの入力を残す（利用者の依頼。前は切り替えるたびに作り直して消えていた）。git で管理するかは、どちらも「git の管理」の欄の始める / 始めないのボタンの組（`GitInitField`。`Segmented`。利用者の依頼で、前はチェックだった）で選ぶ: 新規作成は「git で管理する / 管理しない」（初めは管理する。保存先を点検し、git のリポジトリの中なら「このフォルダで新しく始める / 親のリポジトリの中で使う」にして初めは使う方。手で選んだらそのまま）、取り込みは `gitInitChoice` の `on` / `off`（初めは始めない。始めなくても取り込める）。取り込むフォルダがもう git で管理されていれば（コミットのあるリポジトリの一番上・親のリポジトリがこの中を管理しているフォルダ）、ボタンの代わりに「すでに git で管理されています（ブランチ: …）。そのまま使います。」などを出す（`gitManagedNote`）。フォルダの変更は同じ `gitInitChoice` をチェックで確かめに添える（初めはオフ）。`gitInitChoice` の場合分け: git でない・コミットがないフォルダは「git の管理を始める」、git のリポジトリの中のフォルダは「このフォルダで新しく git の管理を始める」（オフなら親のリポジトリの中のフォルダとして使い、変更・履歴・ワークツリーはその中だけ。親がこの中のファイルを管理していれば出さない）、コミットのあるリポジトリの一番上は出さない。オフのときは、使えなくなるもの（`GitInitNotice.tsx` の `GIT_FEATURES`）を説明に出す。git で管理していないプロジェクトは、変更・履歴のタブと右の欄の「変更」に `GitInitNotice`（ファイル・検索のタブは Git なしでも中身を出す。利用者の依頼。前はファイルのタブも案内だけだった）（「git の管理を始める…」。確かめてから `startProjectGit` → `api.initProjectGit`、始めたら Git の状態を取り直す）を出し、設定の「基本情報」のフォルダの欄にも同じボタンを出す。フォルダは `FolderField`（アプリでは「選択…」で Finder から選べる））。どちらにも「メモの保存先」の欄 `MemoDirField` を置く（利用者の依頼）: ふだんは保存先・フォルダから自動で決まる場所（設定のメモの親フォルダ（`memos_dir`。なければ `api.memoDefaults` の既定）/ 新規作成はフォルダ名・取り込みは取り込むフォルダの名前。ほかのプロジェクトのフォルダ名と重なれば「名前-2」。コアと同じ `@shared/memo/names` の `projectMemoFolder`）を見せるだけで、「変更…」で書ける欄（絶対パス・「選択…」・「自動に戻す」）に替わる。送る形は `memoDirBody`（自動なら `memo_folder` にフォルダ名、手で決めたら `memo_path`）。

ほかのプロジェクトとの被りは、どこでも同じ判定と文で知らせる（利用者の依頼）: プロジェクトフォルダは `folderOverlaps.ts`（`folderOverlaps` = 同じ・その中・中にある。リンクを解いた実体のパスで比べる。文は `folderOverlapLines`）、メモフォルダは `MemoOverlapNotice`（`features/memo`。文は `memoOverlapLines`）。行の見た目は `OverlapList`（点検の一覧 `.inspection` と同じ。✕ = 使えない / ⚠ = 使えるが知らせる）。新しく作るは保存先の実体＋フォルダ名が登録済みなら ✕ で「作成」を押せず（コアも 409）、その中・中にあるは ⚠。取り込みは点検の一覧に「「名前」としてすでに登録されています」（✕。取り込めない）とその中・中にある（⚠）。メモの保存先は自動・手入力どちらも同じなら ⚠（使える）。基本情報のプロジェクトフォルダ・メモフォルダの欄には、被っていればいつも ⚠ を出し、プロジェクトの設定の「メモ」の欄も入力に合わせて出す。部品からは `openNewProject(request)` で開く（App が受け取る）。作ったら知らせを待たずに店へ入れ（`addProject`）、そのプロジェクトで新しいチャットを開く（`onCreated` があればそれに任せる）。

プロジェクトがないのに新しいチャットを始めようとしたとき（サイドバー・⌘N / ⌘T・パネル・ボードの「新しいチャット」）は、いきなりこのダイアログを開かず、案内のダイアログ `NoProjectsGuide` を出す（`openNoProjectsGuide()`。App が受け取る。パネルは作成先がないときの `usePanel` の `startNewChat`）。中身は全プロジェクトの画面の空のときと同じ `NoProjectsWelcome` を `forNewChat` にしたもので、すべてのチャットはプロジェクト（AI が作業するフォルダ）の中で行うこと・作るとそこで新しいチャットが開くことを先に伝え、始め方の 3 段・新しいプロジェクト / 既存のフォルダを取り込むを並べる（押すと案内を閉じて、このダイアログをその作り方で開く）。
