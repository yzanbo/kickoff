# 作業場所と並行開発（`features/worktree`）

チャットごとに作業場所（`chats.worktree_path`。`null` なら本体）を持ち、エージェントはその中で動く。`GitWorktree` の `path` は作業するフォルダ（プロジェクトのフォルダがリポジトリの中のフォルダなら、ワークツリーの中の同じ位置）、`root` は git が取り出している一番上。チャットの作業場所・`?worktree=`・パスのつなぎ方は `path` を使い、フォルダの名前を出すとき（ブランチがない・置き場所の「<名前>-worktrees」）は `root` を使う（`worktreeLabel`）。並行して進めるときはチャットごとにワークツリーを使う。ファイル・検索・変更・履歴の画面は `features/editor/CLAUDE.md`。

- ワークツリーの一覧はプロジェクトごとの店 `stores/worktrees.ts`（`useWorktrees` / `useWorktreesOf`。30 秒たってから使ったとき・ウィンドウに戻ったときに取り直す）の 1 系統だけで、部品ごとに fetch しない。作った・片付けた・消した API はそのあとの一覧を返すので `worktreesStore.set` で入れ、`invalidate` ですぐ取り直す。
- チャットの作業場所とブランチの出し方は `workplace.ts` の `workplaceOf` に集める（ブランチの印・作業場所でまとめた見出し・ボードの段で共通。種類は 本体 `main` / ワークツリー `worktree` / フォルダなし `missing`（アプリの外で消された）/ 以前のブランチ `past`（片付けて本体に戻った）。名前は `WORKPLACE_KIND_LABELS`）。ブランチ名はいまの一覧 → チャットが最後に作業したブランチ `chats.branch`（送るたびに覚え、片付けても消さない）の順。画面からは `useChatWorkplace(chat)`（作業場所と、その色 `hue`）、本体のいまのブランチは `useMainBranch`。並びは `compareWorkplaces`（本体 → ワークツリー（名前順）→ フォルダなし → 以前のブランチ）。
- 作業場所とブランチの印 `WorktreeChip`: すべてのチャットに「本体｜main」「WT｜ブランチ名」の形で出す（作業場所が主で、先頭の短い名前 `WORKPLACE_SHORT_LABELS`（本体・WT。フォルダなしは WT、以前のブランチは本体）は省かずに太く、ブランチ名は細い区切りの後ろに少し薄く出す補足で、狭ければブランチ名だけを「…」で省く。正式な名前と場所は乗せたときの説明。Git でない本体は出さない）。色は作業場所ごとの色（`workplaceHue.ts` の `workplaceHue`。本体も色を付ける）で、タブを作業場所別にまとめたときのまとまりの札・タブの線と同じ色（まとまりの色も `workplaceHead` の `hue` で同じ関数から取る）。いまある作業場所（本体 → ワークツリー（ブランチ名の順））どうしは被らない色を選び、一覧にないもの（フォルダなし・以前のブランチ）と一覧を読む前はキーから決まる色。フォルダなし・以前のブランチは点線の枠で少し薄く（説明に理由）。ワークツリーの実行環境があれば、乗せたときの説明にアプリの URL と対応表（「db 5432 → 20101」）・分けられない理由・整えきれていない所の数を添える（`worktreeEnvText.ts` の `worktreeEnvLines`）。
- 新しいチャットの作業場所は `WorkplacePicker`（本体・いまあるワークツリー・新しいワークツリー。見た目はチャットの見出しの印 `WorktreeChip` と同じ札（作業場所の色・「本体｜main」「WT｜ブランチ名」。新しく作るものは「新しい WT｜ブランチ名」。札の先頭の種類は `ChipPicker` の `kind`）に ▾ を付けたもので、選択肢も同じ「本体｜main」の形。押すと選ぶメニュー（`ui/ChipPicker`）。「新しいワークツリー…」を選ぶとブランチ名を聞き（`askNewWorktreeBranch`。やりたいことを書いて「AI で提案」（⌘Enter）を押すと、ブランチ名の案が 3 つ並ぶ（`api.suggestBranches`）。押した案が名前の欄に入る）、チャットを始めるときに作る）。新しく作ったワークツリーには、コアが本体の `node_modules` を APFS の複製で写す。
- 同じ作業場所で作業中のほかのチャットは知らせる（数え方は `countBusyAt`、画面からは `useBusyNeighbors`。チャットの画面ではチャット欄の上の `.composer-notice`）。新しいチャットを、作業中のチャットがある作業場所に送るときは、送る前に「このまま送る / 新しいワークツリーで始める」を選んでもらう（`busyWorkplace.ts` の `chooseBusyWorkplaceAction`。送るときのいまのチャットの一覧で確かめる。質問だけのチャットもあるので、一律には止めない）。既定は設定の「チャット」（`BUSY_WORKPLACE_ACTION`。毎回聞く / このまま送る / 新しいワークツリーで始める。初めは毎回聞く）で、決めていれば聞かない。ダイアログの「次からはこれにする」でも既定にできる（チャットの ✕ の扱いと同じ形）。
- ファイル・検索・変更・履歴のタブで見る作業場所は上の `WorktreePicker`（ワークツリーが本体だけなら出さない。選んでいたワークツリーがなくなったら本体に戻す）で切り替え、プロジェクトごとに覚える（`editorWorktree(projectId)`）。中の部品へは `WorktreeContext` で配る。
- ワークツリーを選んでいるときは `WorktreeBar`（プッシュして GitHub に PR を作る → PR の状態 → GitHub でマージされたら「片付ける」でワークツリーとブランチを消して本体をプル。PR は gh。右端のごみ箱で、PR の状態にかかわらず消せる）。ワークツリーの実行環境があれば［アプリを開く］（チャット欄の埋め込みブラウザで `<ブランチ名>.localhost:<帯+00>`）と、「ポートを分けられません」「整えきれていない所 n 件」（押すと理由・一覧のお知らせ）も出す。
- 画面からワークツリーを消すのは `removeWorktree.ts` の `confirmRemoveWorktree`（履歴の左の一覧・`WorktreeBar` のごみ箱。消す前に `api.worktreeRemovalInfo` でコミットしていない変更・プッシュしていないコミット・このブランチにしかないコミットを知らせ、「ワークツリーだけ消す」か「ブランチも消す」を選んでもらう。失うコミットがあるのにブランチも消すときは、もう一度確かめる）。消す・片付けるときは、作業中なら止め、そこのチャットを本体に戻す（コア）。履歴の左の一覧からの作成・削除は `useWorktreeActions`（ワークツリーはリポジトリの隣の `<名前>-worktrees/` に作る）。
- ワークツリーの PR の知らせ（`prNotice/`。利用者の依頼: GitHub でマージしたあとも、ワークツリーとチャットが残りがちだったため）: コアが 5 分ごと・窓に戻ったときに、ワークツリーのブランチのいちばん新しい PR を GitHub に聞き（`core/CLAUDE.md` の「Git」）、マージされた・マージせずに閉じられたものを知らせる（`WorktreePrNotice`。店は `stores/worktreePrs.ts` の `useWorktreePrNotices` / 作業場所から引く `useWorktreePrLookup`。SSE の `worktree_prs` でプロジェクトの分を入れ替える）。Kickoff を閉じている間・この機能の前にマージされたものも、ワークツリーが残っていれば知らせる。
  - 確認（`PrNoticeDialog.tsx`。App がメインウィンドウにだけ置く `PrNoticeHost`。開いたとき・窓に戻ったときに `api.refreshWorktreePrs`）: まだ閉じていない知らせを 1 つずつ自動で開く。ワークツリー（ブランチも消す / ワークツリーだけ消す / 残す。初めはマージなら「ブランチも消す」、閉じたなら作業を失わないよう「ワークツリーだけ消す」）と、そのワークツリーのチャット（子チャットも。アーカイブ（初め）/ 削除 / そのまま。チャットがなければ出さない）を 1 つで選ぶ（選択肢と注意は純粋関数の `prNoticePlan.ts`）。注意は作業中のチャット（あれば消す・アーカイブはできない）・コミットしていない変更（知らせたうえで force で消す）・プッシュしていないコミット・このブランチにしかないコミット（ブランチも消すときだけ）・削除は戻せないこと。マージなら、消したあと本体をプルする（できなければお知らせ）。チャットは子孫ごと扱うので、親も入っている子は除く（`rootChatIds`）。「あとで」・Esc で閉じると、DB に覚えて同じ PR では確認を出し直さない（`api.dismissWorktreePr`。どの窓・スマホで閉じても同じ）。片付けると知らせと覚えが消える。
  - 印（`PrNoticeMark.tsx`。「マージ済み」「閉じた」。押すと確認を開き直す `openPrNotice`。行・カードの中でも押した行は開かない）: チャットの作業場所の札 `WorktreeChip` の後ろ（サイドバーの行はアイコンだけ `markIconOnly`）・履歴の左のワークツリーの一覧（アイコンだけ）。チャットのないワークツリーでも気づけるよう、ファイル・検索・変更の作業場所の切り替え `WorktreePicker` の選択肢の名前に「（マージ済み）」などを添える。知らせがあるときの `WorktreeBar` の「片付ける」は、この確認を開く（チャットの扱いも一緒に選べるように）。
- ワークツリーの実行環境（ポートの帯・Docker の組の名前。コアは `core/CLAUDE.md` の「ワークツリーの実行環境」）: ワークツリーの一覧の各 `GitWorktree` の `env`（`WorktreeEnv`。本体・この機能の前に作ったものは null）で受け、店の外からは `worktreeEnvOf(projectId, path)`、React からは `useWorktreeEnv`（`stores/worktrees.ts`）で引く。画面の文は `worktreeEnvText.ts` にまとめる（札の説明 `worktreeEnvLines`・ブラウザで開く表記 `appAddress`・消す確認のチェック `downVolumesCheck`）。消す確認（`confirmRemoveWorktree`・`WorktreeBar` の「片付ける」・PR の知らせの確認）は、Kickoff が組の名前を割り当てたワークツリー（`compose_names` がある）だけ「コンテナとデータも消す」を選んだ状態で出し（`choiceDialogWithCheck` / `confirmWithCheck` / `CheckField`）、選んだまま消すと `api.removeWorktree` の `downVolumes` でコアが `docker compose down -v` を流す。本体と同じ組の名前のままのワークツリーでは出さない（本体のデータが消えるため）。［AI で整える］は段階 2。
- 開発版の Kickoff は保存先とポートが 1 つなので、同時に起動できるのは 1 つのワークツリーだけ。
