# 作業場所と並行開発（`features/worktree`）

チャットごとに作業場所（`chats.worktree_path`。`null` なら本体）を持ち、エージェントはその中で動く。並行して進めるときはチャットごとにワークツリーを使う。ファイル・検索・変更・履歴の画面は `features/editor/CLAUDE.md`。

- ワークツリーの一覧はプロジェクトごとの店 `stores/worktrees.ts`（`useWorktrees` / `useWorktreesOf`。30 秒たってから使ったとき・ウィンドウに戻ったときに取り直す）の 1 系統だけで、部品ごとに fetch しない。作った・片付けた・消した API はそのあとの一覧を返すので `worktreesStore.set` で入れ、`invalidate` ですぐ取り直す。
- チャットの作業場所とブランチの出し方は `workplace.ts` の `workplaceOf` に集める（ブランチの印・作業場所でまとめた見出し・ボードの段で共通。種類は 本体 `main` / ワークツリー `worktree` / フォルダなし `missing`（アプリの外で消された）/ 以前のブランチ `past`（片付けて本体に戻った）。名前は `WORKPLACE_KIND_LABELS`）。ブランチ名はいまの一覧 → チャットが最後に作業したブランチ `chats.branch`（送るたびに覚え、片付けても消さない）の順。画面からは `useChatWorkplace(chat)`、本体のいまのブランチは `useMainBranch`。並びは `compareWorkplaces`（本体 → ワークツリー（名前順）→ フォルダなし → 以前のブランチ）。
- ブランチの印 `WorktreeChip`: すべてのチャットに作業中のブランチを出す。ワークツリーは色付き、本体は控えめ、フォルダなし・以前のブランチは点線の枠（説明に理由）。
- 新しいチャットの作業場所は `WorkplacePicker`（本体・いまあるワークツリー・新しいワークツリー。見た目は VS Code の左下と同じブランチの印とブランチ名。「新しいワークツリー…」を選ぶとブランチ名を聞き（`askNewWorktreeBranch`）、チャットを始めるときに作る）。新しく作ったワークツリーには、コアが本体の `node_modules` を APFS の複製で写す。
- 同じ作業場所で作業中のほかのチャットは知らせる（数え方は `countBusyAt`、画面からは `useBusyNeighbors`。チャットの画面ではチャット欄の上の `.composer-notice`）。新しいチャットを、作業中のチャットがある作業場所に送るときは、送る前に「このまま送る / 新しいワークツリーで始める」を `choiceDialog` で選んでもらう（送るときのいまのチャットの一覧で確かめる。質問だけのチャットもあるので、一律には止めない）。
- ファイル・検索・変更・履歴のタブで見る作業場所は上の `WorktreePicker`（ワークツリーが本体だけなら出さない。選んでいたワークツリーがなくなったら本体に戻す）で切り替え、プロジェクトごとに覚える（`editorWorktree(projectId)`）。中の部品へは `WorktreeContext` で配る。
- ワークツリーを選んでいるときは `WorktreeBar`（プッシュして GitHub に PR を作る → PR の状態 → GitHub でマージされたら「片付ける」でワークツリーとブランチを消して本体をプル。PR は gh。右端のごみ箱で、PR の状態にかかわらず消せる）。
- 画面からワークツリーを消すのは `removeWorktree.ts` の `confirmRemoveWorktree`（履歴の左の一覧・`WorktreeBar` のごみ箱。消す前に `api.worktreeRemovalInfo` でコミットしていない変更・プッシュしていないコミット・このブランチにしかないコミットを知らせ、「ワークツリーだけ消す」か「ブランチも消す」を選んでもらう。失うコミットがあるのにブランチも消すときは、もう一度確かめる）。消す・片付けるときは、作業中なら止め、そこのチャットを本体に戻す（コア）。履歴の左の一覧からの作成・削除は `useWorktreeActions`（ワークツリーはリポジトリの隣の `<名前>-worktrees/` に作る）。
- 開発版の Kickoff は保存先とポートが 1 つなので、同時に起動できるのは 1 つのワークツリーだけ。
