# チャット（`features/chat`）

チャット全般（状態・操作・名前・メニュー・状態の印）と、1 つのチャットの画面。チャット欄の音声入力（`features/dictation/`）と返答のファイルのチップ（`features/fileLinks/`）もここに書く。まとめ方・数え方は `features/chatList/CLAUDE.md`、タブの入れ物は `features/panel/CLAUDE.md`。

## 状態と未読

- 状態は `chatStateOf(chat, pending)`（`@shared/chat/state.ts` の `agentStateOf` を回答待ちの一覧で引く）、カンバンの列は `boardColumnOf`（作業中・回答待ち・未読・既読。人は動かさない）。色は `tones.ts` の `COLUMN_TONE` / `STATE_TONE`。
- 行の先頭の状態の印は `StatusSlot`（作業中 = 回るリング・回答待ち = 琥珀色の！・未読 = 緑の点・エラー = 赤の点・既読 = 薄い点）。作業中のまま未読のもの（`busyWithUnread`）は、列・数は作業中のまま、リングに緑の点を重ね（`unread`）、名前を太字・カードに「未読あり」。
- 未読にする「新しい結果」は AI の文章の返答（サブエージェントのものは除く）・作業の終わり・失敗（`isUnreadEvent`。ツールの実行などの途中経過では付けない）で、作業中でも返答が届けば付ける（コア）。
- 印を消すのは、チャットを表示していて・Kickoff が前にあり・流れの一番下が見えているとき（`timeline/useMarkSeen.ts`。新しい結果が届いた・一番下まで来た・表示した・Kickoff に戻ったときに確かめる）。`api.markSeen(chatId, eventId)` に一番下まで見た記録の ID を渡し、それより新しい結果があれば消さない（メニューの「既読にする」は ID なしでそのまま消す）。印の付け外しでは最後に動いた時刻（一覧の並び順）を変えない。見ている間に「未読にする」で付けた印は、次に上のどれかが起きるまで残す。

## 操作・名前・メニュー

- アーカイブ・削除などは `chatActions.ts`（`toggleArchiveChat` / `confirmArchiveChats` / `confirmDeleteChat` / `confirmDeleteChats` / `markChatsSeen` / `moveChatsToGroup` / `togglePinChat`。まとめての操作で断られたものは最後にまとめて知らせる。削除したチャットの書きかけの文 `chatDraft` も消す）。
- 名前をその場で変えるのは `useChatRename` ＋ `ChatTitleInput`（ダイアログは使わない。`onError` を省くとお知らせで出す）。上限は `CHAT_TITLE_MAX`。
- 右クリックのメニューの項目は `ChatMenuItems` 1 つ（開く（タブでは出さない）・子チャットを作成（「子チャットで聞く」の画面を開く。アーカイブ済みでは出さない）・名前を変更・既読 / 未読・固定・セッション ID をコピー・プロジェクトを変更・アーカイブ・削除。場所だけの項目は `before` / `after`）。サイドバーの行・ボードのカードは `ChatMenu`、パネルのタブは `TabMenu` から使う。
- 「プロジェクトを変更」は乗せる・押す・→ で項目の横に `ProjectPickFlyout`（`features/project/CLAUDE.md`）を開き、確かめてから `api.moveChat`（グループ・作業場所・ブランチは外れ、作業場所は移した先の本体。並び順は変えない。作業中は 409。会話は resume で続く）。いま開いているチャットを移したら、移した先で開き直す。移したチャットはチャットの店の知らせで元の一覧から外れる。
- チャットのタブの ✕ は `closeChatWithChoice`（表示だけ消す・アーカイブ・削除を選んでから閉じる。既定は `CHAT_CLOSE_ACTION`（`ask` / `close` / `archive` / `delete`）で、設定の「チャット」と、聞いたときの「次からはこれにする」で変える。アーカイブ・削除は既定にしても毎回確かめる）。Esc・タブのメニューの「閉じる」は聞かずに閉じる。

## 1 つのチャットの画面（`pane/`）

- `ChatPane` が中身を読み（`useChatDetail`）、読めたら `ChatView`（チャットごとに作り直す）を描く。送る前にすることがあれば `beforeSend`（メモのチャットで、書きかけのメモを保存する。`useChatSend` が送る前に待つ）。状態と操作は `useChatView`、`ChatView` は描くだけ。チャットはいつもパネルのタブの中に開く。`ChatView` は自分の中身（見出し・流れ・チャット欄）を右の欄の殻 `AgentSplit`（`features/panel/CLAUDE.md`）で包み、右にサブエージェントの画面を並べられる（同じ context の中なので、右の欄の中身も記録・操作をそのまま使う）。
- `useChatDetail` はチャット・記録・回答待ち・作業中の様子（`ChatLive`。送信待ち・裏の作業・再試行・再接続待ち・圧縮中・停止中）を読み、SSE で追う（作業中の様子は `chat_live` で丸ごと置き換え、中身の変わらない部分は前のものを使う `keepUnchanged`）。読み込みの最中に届いた知らせは届いた中身にもう一度当て、SSE をつなぎ直したら取り直す（決まりは純粋関数の `chatDetail.ts`）。別のプロジェクトへ移しても読み直さない。
- 子の部品（流れの項目・ピル・送信待ち・検索・質問のカード・動きなど）への操作は `ChatPaneContext`（`ChatPaneActions`: `revealSubagent` / `openSubagent`（設定の開き方で開く）/ `openSubagentSide`（右の欄に開く）/ `openSubagentWindow`（別ウィンドウで開く）/ `canOpenSide` / `toggleSubagent` / `toggleSubagentFull` / `tellSubagent` / `closeTell` / `show` / `focusActivity` / `clearActivityFocus` / `revealInConversation` / `rewind` / `resend` / `restoreFiles` / `retry` / `jumpTo` / `reveal` / `stepPrompt` / `fillComposer` / `focusComposer` / `askInNewChat`）1 つで配る。props で中継しない・クラス名で DOM を探さない。`ChatView` がチャットごとに 1 回だけ作り、描き直しても同じもの（memo した項目を描き直させない）。変わる様子（失敗した作業の直し方・開いているサブエージェントのカード `openSubagents`・高さの制限を外したカード `fullSubagents`・会話か動きか `showing`・動きの絞り込み `activityFilter`・動きで強調するサブエージェント `activityFocus`・「伝える」の入力欄を開いているカード `tellOpen`）は `state` に置き、`useChatPaneState` で読む（保存しない。チャットを開き直すと会話から）。画面の外でも描く部品（発言・ツールのまとまり・サブエージェントのカード）は `useOptionalChatPane`（外では書き直し・再試行・カードの開閉を出さない）。
- チャットのキー（⌘↓・⌘⌥↑ / ↓・⌃R・⌘F）は `useChatHotkey`（`chatHotkeys.ts`）で、ピントがそのチャットにあるときだけ受け取る（⌘F は、どこにもピントがなく最後に押したのがそのチャットのときも）。隠れているタブ・閉じたパネルのチャットでは受け取らない。捕捉で先に受け取り、アプリ全体の ⌘F・縦スライドのプロジェクトの切り替えより優先する。

### 見出し

- `ChatHeader` にはプロジェクト・グループ・作業場所のバッジ（この順。`ProjectChip`・`features/group/GroupChip`（サイドバーの行の 2 行目と共通）・`WorktreeChip`。グループの札はそのグループの色 `ChatGroup.hue`（タブの札・グループ別のまとまりと同じ色））と、右に道具・ターン数と API 換算、右端に右の欄の開閉（`features/panel/agents/AgentPanelToggle`。アイコンは右の欄の閉じるボタンと同じ形で、開いているときは閉じる向き `PanelRightClose`・閉じているときは開く向き `PanelRightOpen`。色はほかの見出しのボタンと同じ白（開いているかは向きで分かるので、アクセントの色にしない）。タブがなければ空の欄の案内を出す。右の欄を置けない画面（子チャットの画面の中など。`canOpenSide`）では出さない）を出す。名前・閉じる・状態の印はタブにあるので出さない（名前はタブのダブルクリックで変える）。確かめずにアーカイブするボタンは置かない。見出しはパネルのタブの列の下にあり、ウィンドウの上端ではないので、ウィンドウのドラッグ領域にしない（ドラッグ領域では右クリックが画面に届かない）。
- 右の道具（`ChatHeaderTools`）は左から、会話 / 動きの切り替え（`.chat-show-toggle`。下の「動き」。狭い見出しではアイコンだけ）・文の幅（`TextWidthToggle`。動きの幅にも効く）・会話の文字の大きさ（`ChatFontSizeButton`。押すと 5 段階のメニュー）・上に貼り付ける指示の表示（`.chat-sticky-toggle`。出しているときはアクセントの色。`STICKY_PROMPT_HIDDEN` で設定の「表示」と共通）・チャットの中の検索欄（`ChatFind`）。指示の表示と検索欄は会話だけに効くので、動きを見せている間は出さない。
- 見出しの表示（`ChatDisplayMenu.tsx` の `ChatDisplayItems`。タブの列の「表示」のメニューの「チャットの画面（どのチャットでも共通）」と、見出しの何もないところ・会話の流れの何もないところ（発言・まとまりの外。`ChatTimeline` の右クリックで、`useQuoteMenu` の `openInRegion` が開かなかったとき）の右クリックで同じもの）: タブの列（チャットのパネルのタブの列。`CHAT_TAB_ROW_HIDDEN`。設定の「表示」→「チャットのタブの列」でも切り替える。隠すとタブの列の道具も出ないので、戻すのは会話・見出しの右クリックと設定）・見出しの行（`CHAT_HEADER_ROW_HIDDEN`。⌥⌘T（Finder・Safari の「ツールバーを隠す」と同じキー。`app/shortcuts.ts`）・設定の「表示」→「チャットの見出し」でも切り替える）・見出しの項目（横に開く子のメニュー `MenuFlyout`。バッジ = プロジェクト・グループ・作業場所 / 道具 = 会話 / 動き・文の幅・会話の文字の大きさ・指示の帯の表示・検索欄 / 数 = ターン数・API 換算 / 右の欄 = 右の欄の開閉を、閉じずに続けて切り替える。項目は `chatHeaderItems.ts` の `CHAT_HEADER_ITEMS`、覚えるのは隠した項目だけ `CHAT_HEADER_HIDDEN`（初めは会話 / 動き・会話の文字の大きさ・ターン数・API 換算を隠す。隠したものがなくなっても空の一覧で覚え、初めの値に戻さない）。何か隠していれば「すべて表示する」）・指示の帯・定型文の帯（`SNIPPET_BAR_HIDDEN`）・会話の文字の大きさ（横に開く子のメニュー）・文の幅を広げる・チャット欄をコンパクトに。切り替えを見出しの外（タブの列）に置くのは、見出しを隠しても戻せるようにするため。
- 見出しの行を隠したとき（`.chat-header.collapsed`。高さを持たない）: 動きを見ている間（会話へ戻れるように）とアーカイブ済みのチャット（気づけるように）は出す。会話 / 動きはタブの右クリックの「動きを見る / 会話に戻る」でも切り替える。検索欄を見出しに出していないとき（行・項目を隠した）は、⌘F でチャットの右上（見出しのすぐ下）に浮かせて出す（`ChatFind` の `floating`。下の会話は動かさない。ピントが入っている・文が残っている間だけ出し、ふだんはピントを受けられるよう描いたまま見えなくする）。バッジの中身はタブに乗せたときの説明、ターン数と API 換算はチャット欄のメーターのポップオーバーにも出す。
- 会話の文字の大きさ（極小・小・標準・大・特大。Chrome の文字サイズの言い方にそろえる。本文がおよそ 12 / 13 / 14 / 16 / 18px。`chatFontSize.ts` の `CHAT_FONT_SIZE`、どのチャットでも同じ。見出しの行のボタン・タブの列の「表示」・設定の「表示」で選ぶ）: 会話に出るもの（発言・返答・ツール・サブエージェントのカード・承認と質問のカード・動き）の文字だけを変え、見出し・入力欄・ピル・メニューは変えない。App が `useApplyChatFontSize` で `<html>` に倍率 `--chat-font-scale` を与え、会話の入れ物（`.timeline-wrap`・`.activity`・`.subagent-screen-scroll`）が `--chat-scale` にして、会話の CSS の文字の大きさ・行の高さ（`calc(… * var(--chat-scale, 1))`）にかける（入れ物の外では 1 のまま）。会話に出る部品の CSS で文字の大きさを足すときは、同じ書き方にする。
- 送る前のチャット（新しいチャット `NewChatPane`・新しい子チャット `NewChildPane`）も、同じ決まりの枠 `DraftChatPage` で描く: 見出しの行を隠していれば出さない・バッジは見出しの項目の設定どおり同じ順（新しいチャットのグループと作業場所は、同じ札の形に ▾ を付けた選べる札 `GroupPicker` / `WorkplacePicker`（`ui/ChipPicker`。押すと下に 1 つ選ぶメニュー。グループなしは色なしの「No Group」）、新しい子チャットは親の札で、作ったあとの子チャットと同じくグループの札は出さない（子チャットはグループに入らない））・右の道具は会話がなくても効く文の幅と会話の文字の大きさだけ・文の幅（`.wide`）・見出しと流れの何もないところの右クリックで「チャットの画面」のメニュー。チャット欄も同じく定型文の帯と、右クリックの帯の表示・非表示（帯の ⌘クリック・「すぐ送る」は、その文で最初の指示を送ってチャットを作る）。
- 文の幅（標準 / 広げる。`CHAT_WIDE`・`useWideText`、設定の「表示」→「チャットの文の幅」と共通）はパネルの大きさを変えず、発言の流れ・チャット欄・上に貼り付ける指示の幅の上限（820px）を外す（`.chat-page.wide`。`messages.css`・`sticky-prompt.css` の末尾）。パネルの「横幅いっぱい」と見分けられるよう、呼び名は「文の幅を広げる / 文の幅を標準に戻す」、アイコンは標準のときは外向きの ↔（`MoveHorizontal`）、広げているときは内向きの → ←（`createLucideIcon` で作った `MoveHorizontalIn`）にし、パネルの `UnfoldHorizontal` / `FoldHorizontal` と形を分ける。パネルが上限より狭いときは押しても変わらないので、押せなくして「パネルが狭いため変わりません」と出す（幅は `ResizeObserver` で測り直す）。

## 流れ（`timeline/`）

- 組み立ては `timelineItems.ts` の `groupEvents`（連続するツールの実行を 1 つのまとまりにし、結果は呼び出しにぶら下げる。サブエージェントの起動（Agent / Task）はまとまりに入れずカードの項目 `subagent` にし、裏で動かしたものが終わったら、起動した流れのその時刻の位置に `subagentEnd`（1 行）。`scope` を渡すとそのサブエージェントの中身（行のキーと再開した回の呼び出し ID）。作業の終わりの項目に `turnStart`・`turnText`・`turnChanges` を付ける。終わった作業の分は作業の終わりの記録ごとに覚え、配列を作り直さない）。描くのは `ChatTimeline`（スクロール `useTimelineScroll`・上に貼り付ける指示 `useStickyPrompt`・作業中の文 `useWorkingStatus`・流れの終わり `TimelineEnd`）と `Timeline.tsx`（項目は memo）。
- 書いている途中の返答（`StreamingReply`）: 届いた塊のまま一度に出さず、フレームごとに少しずつ出す（`hooks/useStreamReveal`。速さは純粋関数の `lib/streamReveal.ts` の `nextRevealLength`: 遅れの分を `CATCH_UP_MS`（320ms）ほどで追いつき、最低でも 1 秒に 90 文字。サロゲートペアを切らない）。出たばかりの文字は、出てからの時間（`REVEAL_FADE_MS` を `REVEAL_BANDS` 段に分けた `revealBands`）ごとに `Markdown` の `tail` → rehype の `rehypeStreamTail` で `span.stream-fade-<段>` に包んで薄く出し、すぐ濃くする（コードブロックの中は包まない。`styles/chat/streaming.css`）。後ろにカーソルの印（緑の ▍）は付けない。伸びるたびに、一番下を見ているときだけこの部品の中で付いていく（流れ全体を描き直さない）。動きを減らす設定では、そのまま出す。
- 窓: 描くのは最近の項目だけ（`timelineWindow.ts` の `TIMELINE_WINDOW`（120）と `useTimelineWindow`）。上の端に近づく（画面の高さの 1.5 倍の手前。端に着いてから足すとトラックパッドの慣性が端で止まる）・「以前の発言を表示」で前を足し、読んでいた位置はブラウザのスクロールアンカーに任せる（合っていないときだけ JS で直す。書き換えると慣性のスクロールが止まる。一番下にいるときは足さない）。一番下へ戻った・一番下で新しい項目が届いたら元の大きさに戻す。窓は大きさが一定のまま進むので、新しい発言の見分けは項目の数ではなく最後の項目のキーで行う。
- 検索結果から開いた発言・指示の履歴から移る先が窓の外なら、その前後を描く範囲にしてから移る（`revealRange`。最新まで `MAX_TAIL`（400）件以内なら最新まで、遠ければ途中の一部分だけを描き、下の端・「以降の発言を表示」で後ろを足し、一番下へ戻るボタン・⌘↓ で最新の窓に戻す `latest`）。途中を描いている間は、書いている途中の返答・確認のカード・作業中の行を出さない。

## ツール（`tools/`）

- ツールの呼び出しは人が読める文にする（`toolDescribe.ts`。「ToDo を追加: 確認 1」。生の JSON を出さない。承認カードは `describeApprovalInput`）。まとまりと 1 件は `ToolGroup`（閉じた状態の要約は `summarizeTools`: 「2個のファイルを編集 および 3個のコマンドを実行」。で、分類できないものだけ「その他」）。サブエージェントの起動はまとまりに入れず、流れの中のカード（`subagents/`）。
- 状態のアイコン（`ToolStatusIcon`。決め方は純粋関数の `toolStatus.ts`）: 1 件の行の左端と、まとまりの開閉の矢印の右（「> ✓ 2個のコマンドを実行」）に、実行中 = 回る印・完了 = 緑の ✓・失敗 = 赤の ✕・中断（結果が届かないまま終わった）= 灰色の −。1 件は `callStatus`（動いていれば実行中、終わっていれば結果の `is_error` で完了か失敗、結果がなければ中断。動いているかは `isCallRunning`）、まとまりは `groupStatus`（実行中 → 失敗 → 中断 → 完了の順）。乗せると状態の名前。裏で動かしたコマンドは「裏で始めた」という結果がすぐ届くが、裏の作業の一覧（`ChatLive.background`）に残っている間は、作業をまたいでも実行中（回る印・経過時間・まとまりの「いま」）として見せ、終わってから完了にする（作業の `tool_use_id` を `backgroundCallIds` で集め、`ChatView` と別ウィンドウのサブエージェントの画面が `BackgroundCallsContext` で配る。下に流れていった一覧の行だけでなく、上の流れの中でも終わっていないと分かるように）。
- 時刻（`ToolTime`。数え方は純粋関数の `toolTimes.ts`）: 1 件は行の右に「始めた時刻 · かかった時間」（実行中は経過時間）。まとまりの見出しは要約の後ろに、実行中は「最初に始めた時刻 – 最後に始めた時刻」、終われば「最初に始めた時刻 – 最後に終わった時刻 · ◯時間◯分◯秒」（1 件の行の「始めた時刻 · かかった時間」と同じ形。`formatStampRangeWithRunTime`。実行時間は、並べた開始と終了の時刻の差 `formatStampRunTime`（秒より下を切り捨てた時刻どうし。実際の長さを切り捨てると「13:27:37 – 13:27:38 · 0秒」のように時刻と合わなかった）を `formatRunTime` で、いちばん大きい単位から下をすべて出す。時刻が 1 つだけのときは添えない）。思考の行は考え始めた時刻（記録は考え終えたときに残るので、かかった時間を引く）。書式は `lib/time.ts` の `formatStamp` / `formatStampRange`（秒まで。今日は時刻だけ、別の日は日付も、日をまたいだ範囲は終わりにも日付）、乗せると年月日（`formatFullStamp`）とかかった時間。実行中として見せるのは、作業中のチャットのいまの作業（最後の作業の終わりより後。過去の一部分を描いている間はなし）の、結果の届いていない呼び出しだけ（前の作業で中断したまま結果のないものは実行中にしない）。
- 実行中のコマンドの出力（`CommandLive`）: コアが Claude Code の出力ファイルを読んで送る SSE の `chat_command_output`（最後の 40 行。保存しない）を、呼び出し ID・作業 ID ごとの店 `commandOutputs.ts`（`useCommandOutput` / `useTaskOutput`。`useSyncExternalStore` でキーごとに購読し、届いたコマンドの部品だけを描き直す）に入れ、実行中のまとまりの下に枠で流す（閉じていても見える）。枠は終わったあとの `BashOutput` と同じ 2 段（上に「コマンド」の欄 = 打ったコマンド。`BashOutput` の `BashCommandSection` を共有。下に「出力」の欄 = 見出しに回る印と「実行中」、いちばん下に付いていき、上へ戻したら止まる）。終わると消え、結果は今までどおり `BashOutput`。裏で動かしたコマンドも、終わるまで流れの中のまとまりの下に流し（作業をまたいでも。上の「状態のアイコン」）、裏の作業の一覧の行には最後の 1 行（乗せると最後の 10 行。名前を押すと流れの中のその行へ）。
- コマンドの出力は `BashOutput`（上の「コマンド」の欄（「$ コマンド」。沈んだ地）と下の「出力」の欄を、見出しと境目の線で分け、それぞれの欄の中でスクロールする。長いコマンド・heredoc と出力の境目が分からなかったため。失敗したら終了コードを出力の見出しの右に赤で。終了コードは `bashResult.ts`。結果が届くまでは出力の欄を出さない）。コマンドはシェルの文法で色を付け（`HighlightedCode` の `shellscript`。heredoc の本文は、言語が分かればその言語で）、出力も中身に合わせて色を付ける（`toolResultParse.ts` の `outputLanguage`: JSON として読める → json、`git diff` / `git show` / `git log -p`・「diff --git」で始まる → diff、1 つのファイルの中身を出すだけのコマンド（`cat a.ts`・`head -n 40 a.py`・`sed -n '1,20p' a.css`。パイプ・つなぎがあれば読まない）→ そのファイルの言語、ほかはログの形 `log`（日時・エラー・数・文字列など））。色付けは、その呼び出しを一度開いてから始める（`ToolItem` の `opened`。閉じたままの呼び出しが多くても重くしない）。まとまりを開いて見える一覧の 1 行のコマンドにも同じく色を付ける（`ToolGroup` の `opened` → `listed`。改行は空白に見え、長いものは「…」で切る。色付けの結果は開いた欄と共有）。
- 読む・検索の行（`ToolResultCode.tsx`。読み分けは純粋関数の `toolResultParse.ts`）: 見出しの行は、読むはパス（フォルダを薄く、ファイル名を本文の色で `ToolPath`。ファイルを変えるツールの行のファイル名も同じ形）、検索（Grep）は探す正規表現に正規表現の文法で色（`regexp`）、ファイル検索（Glob）はパターンをパスの形で出し、探した場所をパスの形で添える（`SearchTitle`）。開いた中身は、読むは左に行番号の欄（選んでコピーしても入らない）を分けてファイルの言語で色（`ReadResult`。結果の「番号\t中身」を `parseNumberedLines` で分ける。番号付きの形でなければ文字のまま）、検索はパスの一覧をパスの形で、見つかった行（output_mode が content）は薄いパス・行番号・そのファイルの言語で色を付けた中身で（`SearchResult`。同じファイルの続いた行をまとめて色付けする `searchRuns`。文脈の行は少し薄く）。どちらも初めは 60 行までで「… ほか n 行」。色付けはコマンドと同じく、見出しはまとまりを開いてから、中身はその呼び出しを開いてから始める。失敗の結果は今までどおり赤い文字のまま。
- 読むで読んだ画像（`ReadImage`。パスの拡張子が画像 = `@shared/chat/toolImage` の `toolImageType`）: コアは結果の画像を記録に残さず「[image]」の文字だけなので、その呼び出しを開いたときに、入力のパスから、いまのファイルを読んで出す（`api.toolImage` → コアの `GET /api/chats/:id/tool-image`。記録を重くしない・閉じたままの呼び出しでは読まない）。パスは見出しの行にあるので、中身は縮小した画像（欄の幅と 320px の高さに収める）と「縦 × 横 · ファイルの大きさ」。押すと `ImageViewer` で大きく見る（右クリックでコピー・保存。`useAttachmentViewer`）。ファイルを変えた時刻が読んだ時刻（結果の記録の時刻）より後なら「読んだあとに変わっています（いまのファイルを表示しています）」と注意の色で添える。作業場所・添付・メモのフォルダの外・ないファイルは、コアの断りの文（「…外のファイルは表示しません」「ファイルがありません」）だけを出す。パスのない画像（MCP のツールが直接返すスクリーンショットなど）は、いまは「[image]」のまま。
- ターンの変更カード（`TurnChanges`）: 作業の終わりの行の上に、その作業で変えたファイル（「3 個のファイルを変更 +7 −1」）。開くとファイルの一覧で、押すと `FileLinkContext` の `open` で右の欄に開く（下の「返答のファイルのチップ」と同じ開き方。⌘クリックはファイルタブ・右クリックはファイルのメニュー）。見出しの「差分を見る」は、右の欄の変更のタブを、この作業で変えた最初のファイルの位置で開く（`openChanges`）。作業場所の外のファイルは押せない行。ファイルを変えるツール（Edit・MultiEdit・Write）の行のファイル名も、同じく押して開ける（`ToolGroup` の `ToolFileArg`。行の開閉はしない）。数え方は純粋関数の `turnFileChanges.ts`（`changesOf` / `lineDelta`。Edit・MultiEdit は置き換えの前後を最長共通部分列で比べ、Write は「新規」「書き直し」（書き直しは足した行だけ）、NotebookEdit は足した行。失敗した・結果がまだないものは数えない。サブエージェントの変更も含める）。

## 作業中の様子（`status/`）

- 作業中の行の文は `workingLabel`（止めている・通信を再試行している・会話を圧縮している・返答を書いている・ツールを実行中・考えている）で、作業中の行と一番下へ戻るボタンの両方に使う（`useWorkingStatus` が 1 回だけ組み立てる）。返答を書き終えて裏の作業を待っているときは「返答は終わりました。裏で動いているサブエージェント 1 件（調査）とコマンド 1 件（npm run dev）の終わりを待っています」（`backgroundLabel.ts`）。
- 本当に動いているかは、最後に何かが届いた時刻で見る（Claude Code に問い合わせる手段はない。`stall.ts` の `activityOf` / `activityText`）。1 分静かなら「最後の動き n 分前」、`STALL_MS`（10 分）動きがなければ「n 分動きがありません（Bash の結果待ち）」と注意の色（`.activity-stalled`）。作業中の行は記録・書いている途中の返答・実行中のサブエージェントのいちばん新しい時刻、サブエージェントは中の発言・ツール・知らせ（`lastActivityAt` / `pendingTool`）と途中経過の時刻で決め、作業中は `useTicker` で描き直す。長く動きのないサブエージェントは作業中の行（「サブエージェント『調査』が 12 分動いていません」）・ピル（「n 件動きなし」）・一覧の行・カードで知らせる（子孫が動いている間は、待っている祖先を動きなしにしない）。
- 裏で動いている作業の一覧（`BackgroundTasks`。作業中の行の下）は 1 件ずつ止められる（`api.stopBackgroundTask`。チャット全体は止めない。サブエージェントは報告が届かなくなるので確かめる）。サブエージェントは名前を押すと設定の開き方（流れの中のカード / 右の欄）で開き、最後の動きを添える（作業 ID で一覧の行と結びつける）。コマンドは名前を押すと、流れの中のそのコマンドの行（回る印と、下に流れる出力 `CommandLive`）へ移って枠で示す（`revealInConversation`。移る先は純粋関数の `backgroundTarget.ts` の `backgroundCallTarget`: 作業の `tool_use_id` の呼び出しの記録と、サブエージェントの中で動かしたものならそのサブエージェント（再開した回の呼び出し ID も `scopeOf` で引き当て、設定の開き方で開いてその行へ）。記録は押したときだけ探す）。
- 中断は、裏で動いているサブエージェント・コマンドも止まることを確かめてから（`confirmStopAgents`。止めると Claude Code のプロセスごと終わる）。止めるよう頼んでから終わるまでは停止中（`ChatLive.stopping`）で、停止ボタンを回る印にして押せなくし（Esc でも止め直さない）、横に「停止中…」を出す。
- 通信が切れて再試行している間は作業中の行・一番下へ戻るボタンに「接続が切れています。再試行 n/m」（`RetryLabel`。動いていたサブエージェントも止まっている可能性を添える）。再試行しきって、つながるのを待っている間は作業中の行の代わりに `ReconnectRow`（通信で止まったサブエージェントも続きから再開することを添える `reconnectLabel`。「自動で再開しない」で `api.stopReconnect`）。何度再開しても続かなかったとき・使用枠の上限で止まって枠が戻ったときは、承認と同じ回答待ちのカード（`ReconnectCard`）で続けるかを聞く。
- チャット欄の丸いメーター（`ContextMeter`）を押して開く詳細は、区切り線で 3 つのまとまりに分ける: 使っている量（見出し「コンテキストウィンドウ」・大きな % と右にトークン数・棒・ターン数とセッションコスト（API 換算）を名前と値の 2 列で）→ 圧縮の設定（「自動圧縮」と「圧縮前指示」「圧縮後指示」を、見出しを左・値を右の同じ形の行で）→ いちばん下に幅いっぱいの「会話を圧縮」。プランの使用枠（5 時間・週）は下の帯で見るので、ここには出さない（前はここにも出していたが、詳細が長く読みにくかった）。詳細はチャット欄（`.composer`）の中に描かれるので、中の書く欄はチャット欄の書く欄の決まりを打ち消して、ふつうの入力欄の見た目にする（`context-meter.css`）。
- 会話の圧縮中（`ChatLive.compacting`。始めた時刻ときっかけ `trigger`）は、作業中の行の代わりに圧縮中の行 `CompactingRow`（ふだんの灰色の 1 行と見分けがつくよう、アクセントの色の枠と薄い地に、見出し・始めた時刻と経過・きっかけの説明。圧縮は数十秒〜数分かかり、その間は返答もツールも動かないので、止まったと思わせないため）を出す。見出しは `compactingLabel`（自動のときは「会話を自動で圧縮しています」と、コンテキストが上限に近づいたため・終われば作業を続けると添える。手で圧縮したときは「会話を圧縮しています」）で、一番下へ戻るボタンも同じ文。設定で自動圧縮を始める量（`auto_compact_pct`）を決めていれば、チャット欄の丸いメーター（`ContextMeter`）の円の外にその位置を指す小さな矢印、ポップオーバーの棒（`UsageBar` の `mark`）に縦線を出す。始める量はポップオーバーの「自動圧縮」（`AutoCompactSelect`。既定 / 10〜90%（このチャットの窓でのトークン数を添える）。選んだらすぐ設定に保存し、設定の「チャット」と同じ値）でも選べる（位置は `@shared/chat/autoCompact` の `autoCompactThreshold`。Claude Code は窓の終わりの余白より先では始めないので、その分を引く）。その下の「圧縮前指示」（`features/snippet` の `PreCompactPromptEditor`。開閉の行にいま送る指示の範囲を添え、開くと共通 / プロジェクト（プロジェクト名で出す）の指示をその場で書いて保存する。設定の「定型文」と同じ値）で、圧縮の前に送る指示も書ける。圧縮中のメーターは短い弧を作業中の色（`--dot-running`。回る印はどこでもこの色で、ツールの行・サブエージェントの印・チャットの状態の丸と同じ）で回す（使用率が高いと弧がほぼ一周で、回しても分かりにくいため）。メーターのポップオーバーの「会話を圧縮」を押したら、ポップオーバーを閉じて弧と圧縮中の行で知らせる（始められなかったときだけ開き直して失敗の文を見せる）。作業中は「このやり取りのあとで圧縮」になり、押すと、圧縮前指示があれば予約せずにいまの作業へ伝え（コアの `ChatLive.compact_after_turn`）、ポップオーバーには「このやり取りが終わったら圧縮します」だけを出す（指示はもう伝えたので取り消せない。前はボタンが元のまま残り、頼めたか分からず、押し直すと圧縮の行も入って 2 回圧縮した）。圧縮前指示がない・もう送ったときは予約する（送信待ちのいちばん上に「会話を圧縮」の行が入り、いまのやり取りが終わったら、送信待ちより先にすぐ圧縮が始まる。下の「送信待ち」）。予約している間（`queue/queuedHint.ts` の `reservedCompact`。いちばん上の圧縮の行で、その上で止めていないもの）は、ポップオーバーに「このやり取りが終わったら圧縮します」と「取り消す」（その行を送信待ちから消す）を出す。始まると圧縮中の行に変わる。終わると、同じ枠の見た目のまま記録の行 `CompactedRow`（`compact` の記録。「会話を圧縮しました / 会話を自動で圧縮しました」・始めた時刻 – 終わった時刻 · かかった時間・要約の前後のトークン数。始めた時刻は記録の時刻からかかった時間 `duration_ms` を引いて出し、なければ終わった時刻だけ）が流れに残る。
- ToDo はチャット欄の上のピル（`TodoChip`。「ToDo 2/5」。押すと一覧）。組み立ては `todoList.ts` の `collectTodoList`（TodoWrite は毎回すべて、TaskCreate / TaskUpdate は 1 件ずつ）で、3 つに分ける: いまの作業 `items`（未完了と、いまの作業の中で完了したもの。ピルの数はこれだけ）・前の作業から残っているもの `stale`（未完了のまま、付けた・変えた作業のあと `STALE_AFTER_RESULTS`（2）回の作業で触られていない（触った作業そのものの終わりは数えない。短い質問を 1 つ挟んだだけでは回さない）・前のセッションで完了しなかったもの。AI の完了にし忘れが多い）・これまでの ToDo `history`（完了したものを、付けたときの作業を始めた指示ごとに。新しい指示が先）。長く使うチャットで、TaskCreate の完了した分が消えずに溜まり、新しい ToDo に混ざって数が膨らんだため。作業の始まりは、作業の終わり（`result`）のあとの最初の自分の発言（作業中に伝えた発言は同じ作業の続き）。Claude Code のセッションが替わる（`context_cleared`・`init` の `session_id` の変化）と Task の番号が #1 から振り直されるので、それまでの分を締めて新しい番号と混ぜない。TodoWrite の書き直しで消えた完了済みはこれまでの ToDo に残し、同じ文のものは付けた指示を引き継ぐ。一覧は、いまの作業の下に閉じたまとまり「前の作業から残っているもの n」「これまでの ToDo n」（`FoldSection` を `.composer-archived` の形で。開閉は `useFold("composer", "todo-stale" / "todo-history")`。中は薄く）。これまでの ToDo は指示の 1 行目と時刻を見出しにし、押すとその指示へ移る（`jumpTo`）。出し方は `todoVisibility`: いまの作業がすべて完了したら「✓ ToDo 5/5」と控えめにし（`.todo-chip.finished`）、次の指示を送るとこれまでの ToDo に移って隠れる。残っているもの・これまでの ToDo だけではピルを出さない。一覧の下の「この一覧を隠す」で手でも隠せる（チャットごとの `todoHidden` にいまの作業の印 `todoSignature` を覚え、書き換わったらまた出す）。

## 失敗した作業の直す操作（`rewind/`）

いちばん新しい作業が失敗で終わったとき（そのあと発言していない。通信の切断・使用枠の上限はそれぞれの仕組みに任せて除く。`retryActions.ts` の `failedTurnOf`）、終わりの行の下に `FailedTurnActions` を並べる: 続きから再試行（`RETRY_PROMPT` をいまの選択で送る `retryTurn`）・深さを下げて再試行（`lowerEffort`。そのモデルで選べる中で 1 段下げる。決まっていなければ既定の深さから、既定も分からなければ中。最も低ければ出さない）・別のモデルで再試行（モデルの一覧のメニュー。下に収まらなければボタンの上に開く。新しいモデルで選べない深さは指定しないにする）・巻き戻して再試行（その作業を始めた発言から、同じ文で送り直す。確かめは巻き戻しと同じ）。深さ・モデルを変えたときはチャット欄の選択も同じに変える。選択肢は `useRetryChoices` が作り（モデルの一覧はあとから届くので、届いたら作り直す）、`ChatPaneState.retry` に入れる。

## チャット欄（`composer/`・`options/`・`attachments/`）

- 上から、流れ → 同じ作業場所で作業中のほかのチャットの知らせ（`.composer-notice`。注意の色と ⚠。`useBusyNeighbors`。押して開くピルの列に混ぜない）→ チャットの情報のピル（`.composer-chips`。指示の履歴・ToDo・サブエージェント・一番下へ戻るボタンの置き場所）→ 定型文の帯（`features/snippet/CLAUDE.md`）→ 送信待ち（次に送るもの）→ 入力欄（いま書いているもの）の順（`ChatComposerArea`）。ピルは `ComposerChip`（押すと上に一覧を開き、もう一度押す・外を押す・Esc で閉じる。`.chip-wrap` / `.chip-popover`）。
- `Composer`: Enter で送信・Shift+Enter で改行。枠の中のいちばん上（文を書く欄の上）に `header` を置ける（チャットでは定型文の帯 `SnippetBar`。送信待ちとの区切り線の下になる）。送る処理は `useComposerSend`（アップロードの途中・送っている途中は送らない。送る前の確かめでやめたら `SendCancelled`）、右下の操作（中断・送信・送り方の切り替え・メーター）は `ComposerActions`。ほかの送り先（`sendTo`）を渡すと、送信ボタンの右クリックと、丸いボタン（中断・送信）の右の ▾（`.send-more`。右クリックに気づかなくても選べるように。作業中で中断のボタンだけのときも出す）でその送り先を選ぶメニューを開く（ふだんの送り方（「あとで送る」など）は送信ボタンと同じなので並べない）（作業中でも送れる。録音中は文字起こしが済むまで選べない。送れたら入力欄を空にする `useComposerSend` の `sendVia`）。外から動かす口は `handleRef`（`ComposerHandle` の `fill` / `insert` / `focus`。`fill` の `append`・`attachments`・`focus: false`。`insert` はキャレットの位置に文を差し込み、書いている文は残す（定型文の帯））。既存のチャットの書きかけの文は `chatDraft(chatId)` に残す。文を書く欄と下の道具の行の何もないところ（ボタン・選択欄の上はそのものに任せる）の右クリックは `useComposerTextMenu`（見出し「クリップボード」の組 `ClipboardItems`: 切り取り・コピー・貼り付け。右クリックしたときの文を書く欄の選択範囲に効き、書き換えは `execCommand` で入れて ⌘Z で戻せる。その下に `menuItems`（チャットとメモの下の入力欄では「定型文の帯を表示 / 隠す」）、いちばん下に「チャット欄をコンパクトに」（`COMPOSER_COMPACT` のチェック。どのチャット欄でも同じ））。
- 高さは CSS で伸ばす（`composer.css` の `.composer textarea` の `field-sizing: content` と `max-height: 240px`。空なら 1 行、上限を超えたら中でスクロール）。コンパクト表示（`COMPOSER_COMPACT`。設定の「表示」→「チャット欄」・チャット欄の右クリック・タブの列の「表示」）は `Composer` に `compact` のクラスを付けて文字・余白・下の道具を小さくする（`composer.css` の末尾。後ろのファイルの送信ボタンなどには `.composer.compact` で詳細度で勝たせる）。
- よく使うキー（`composerKeys.ts`）: 作業中の Esc を 2 回で中断（1 回目は中断ボタンの横に「もう一度 Esc で中断」`.composer-stop-hint` を 2 秒出すだけ。Esc はパネルを閉じるのにも使うので、うっかり止めないため。作業中でなければパネルを閉じる Esc に任せる）・入力欄の Shift+Tab で権限モードを順に切り替える（`permissionChoices` のうち、そのモデルで選べるもの）・⌘L でチャット欄にピントを移す（`focusChatComposer`。ピントのあるパネル → ピントのあるペイン → 見えている最初のチャット欄の順。`app/shortcuts.ts` から呼ぶ）。録音中の Esc・候補の一覧の Esc など、先に扱ったキーは見ない。入力欄が空のときの ↑↓ は前に送った自分の発言を呼び出す（`usePromptHistory`。判定は `prompts/promptHistory.ts` の `historyMove`）。
- `/` と `@`: `suggestTarget`（作業場所）を渡すと出る（`suggest/` の `useSuggest` ＋ `SuggestList`、照らし合わせは `suggestMatch.ts`）。`/` は文の先頭で Claude Code のコマンド・スキル（ターミナル専用のものはコアが除く）、`@` は作業場所のファイル。↑↓・Enter / Tab・Esc。一覧はキーごとの店で持つ。
- モデル・推論の深さ・権限モード・ファストモードは入力欄の下の `ChatOptionsBar`（状態は `useChatOptions`）。新しいチャットはプロジェクトの既定（なければ設定の既定。`withDefaults`）から始まり、ここでの変更はそのチャットだけに効く。新しいチャットでプロジェクトを替えたら、そのプロジェクトの既定に当て直す。既存のチャットはそのチャットの選択から始める。深さを指定しないときは、Claude Code が実際に使う深さを「既定（最大）」のように添える（どこにもなければ「既定（モデル任せ）」。`api.effortDefault`）。選択肢の部品は `ModelOptions` / `EffortOptions` / `PermissionOptions`、選べる値は `options/models.ts` の `effortsFor` / `permissionChoices` / `groupModels`。
- 添付は `useComposerFiles`（📎 `AttachButton`・ドラッグ＆ドロップ・貼り付け。選んだ時点でアップロードし、送信を待たせない）。選んだばかりの添付は `PendingFileChips`（× で外す。チップの大きさは保存したあとの大きさ）、送った添付は `AttachmentChips`（画像は押すと大きく表示し、同じ発言の画像は ← / → で前後へ `viewerImagesOf`。画像以外はアプリの中でダウンロード）、1 行に収める添付は `AttachmentPeek`（1 つ目だけを小さく出し、2 つ以上なら数を重ね、押すと並べて表示 `AttachmentGrid`。送信待ちの行・上に貼り付ける指示の帯）。画像の右クリック（コピー・大きく表示・保存）は `useAttachmentViewer`。メモの添付（`Attachment.memo`。アップロードしない）は付箋のアイコンとパスのチップ（`MemoAttachmentChip`。足し方は `features/memo/CLAUDE.md` の「「チャット名」に添付」）。
- ほかのチャットを参照（`ChatContextButton`。📎 の隣。`Composer` の `chatContext` を渡したときだけ。既存のチャットと新しいチャットの両方）: 読ませるだけだと分かるよう「参照」と呼ぶ（「添付」は何が付くのか、「取り込む」はこのチャットに混ぜるように聞こえる）。一覧（見出し「参照するチャット」）はアーカイブ済みも含めて同じプロジェクトを先に最近動いた順、名前で絞り込み（`SearchField` の `onKeyDown` ＋ `useListNavigation`）。選ぶと `useComposerFiles` の `addChat` → `api.chatTranscript` で、そのチャットのやり取りを Markdown の添付ファイル（`チャット履歴-<チャット名>.md`。自分の発言・メインエージェントの返答を古い順に、作業ごとに変えたファイルと失敗・中断を添える）にして添え、ほかの添付と同じく AI が Read で読む（送る指示は膨らまない）。

### 作業中の送り方（いま / あとで）

- 作業中に送るときの扱いは、チャット欄の切り替え（`QueueModeToggle`。左から「あとで」（リストのアイコン。送信待ちに足す）/「いま」（吹き出しのアイコン。いまのやり取りへ追加の指示として送る。送信待ちを止めているときは送信待ちより先に送る））。`QUEUE_MODE`（`queue` / `tell`）で、初めは「いま」。いつ送るかの対で短く見せ、「送信待ちに追加」「いまのやり取りに追加指示」のような長い言い方は説明（`Segmented` の `tip`。ショートカットは `keys`）に回す。押すと送られるボタンに見えないよう、送るアイコン（`SendHorizontal`）は使わず、アイコンに文字を添えた切り替えにする（とても狭い欄（420px 以下）ではアイコンだけ）。見た目は隣の丸いボタンと同じ高さ 28px の丸いピルで、選んでいる方は一段明るい丸い地・選んでいない方は薄い文字（`styles/chat/queue-mode.css` の `.view-toggle.queue-mode`）。
- キーでも決められる（⌘Enter = いま・⌘⇧Enter = あとで。`sendModeOf` → `onQueue` の `mode`）。チャット欄で ⌘ / ⌘⇧ を押している間だけ、Enter で使われる方のボタンを選んでいる方とは別の青で光らせる（`heldMode`。`.busy-controls.held-tell` / `held-queue` と `Segmented` のボタンの `data-value`。選んでいる送り方は変えない）。
- 「いま」は作業を止めずにいまのやり取りに足す（`api.tellChat`。メインエージェントがいまの手順の切れ目で読む。裏のサブエージェント・コマンドは動き続ける。足せないとき（順番待ちなど）は待ちの列へ、作業中でなければすぐ送る。圧縮中と、圧縮前指示を送ってから圧縮が終わるまで（`ChatLive.awaiting_compact`。圧縮前指示の作業中も）はコアが預かり（`ChatLive.after_compact`）、流れの終わり（圧縮中の行・作業中の行の下）に、送る前の薄い吹き出し（`status/AfterCompactMessages`。「圧縮が終わったら伝えます」）で送る順に出す。圧縮後指示があれば、いちばん上に「圧縮後指示」の札付きの点線の吹き出し（「圧縮が終わったら、最初に送ります」。コアが預かりに入れる前は `useSentCompactPrompt` の文で先に見せる）を置き、預かった指示には「圧縮後指示のあとに伝えます」と添える（コアが必ずその順で伝える）。圧縮後指示は送信待ちに入らない（前の版で送信待ちに入った圧縮後指示の行は、コアが起動したときに預かりへ移す。それでも残った行には文の前に同じ札を付ける。`QueuedRow`）。圧縮を待っていないのに預かりに残った圧縮後指示（通信の切断などで作業ごと終わった・前の版から移したもの）の吹き出しには、作業中なら「いまの作業に伝えます」、作業していなければ「次に送る指示と一緒に伝えます」と添える（`until`）。圧縮が終わると伝わって自分の発言になり、圧縮の行の下に残る。圧縮前指示の作業の区切りまで圧縮が来なければ、コアがその終わりで続けて圧縮してから送る）。止めたいときは停止を押す。
- 圧縮前指示の作業中（`awaiting_compact` で、まだ圧縮していない間）は、いま / あとでの切り替えを出さず（停止のボタンは出す）、Enter は「いま」= 預かる（案内は「圧縮前指示の作業中です。Enter で送ると、このあとの会話の圧縮が終わってから（圧縮後指示があればそのあとに）伝えます」、送信ボタンの名前は「圧縮が終わったら伝える」。`useChatSend` の `compactHold`）。
- 会話の圧縮中は、作業中でもチャット欄の右下をふだんの見た目（メーター・送信・▾）にする（`Composer` の `plainActions` → `ComposerActions` の `plain`。圧縮の間は返答もツールも動かず、送った文は圧縮が終わってから伝わるので、いま / あとでの切り替えも停止のボタンも出さない）。Enter は選んでいる方によらず「いま」（コアが預かる。⌘⇧Enter はあとで）、案内と送信ボタンの名前は「圧縮が終わってから伝えます」（`useChatSend` の `compactHold`）。止めたいときは Esc を 2 回。
- 作業していなくても送信待ちが残っている（止めている）ときは、同じ切り替えを「すぐ送る / ためておく」として出す（`queueWhileIdle`。すぐ送る = 送信待ちより先にいま送る、ためておく = 送信待ちの最後に足す `api.queueMessage` の `hold`）。案内と送信ボタンの名前は `queueModeTexts`。
- 質問として送る（送信ボタンの右クリック・▾ の「質問として送る」。下に「答えが返ったら、送信待ちを一時停止」と添え、アイコンは一時停止の線と同じ `OctagonPause`。`ChatComposerArea` の `sendTo` の先頭で、メモのチャット・アーカイブ済みでも出す。`useChatSend` の `onAsk`）: 質問で終わる指示を送り、答えを見てから次を決めるためのもの。いまの送り方（作業していなければすぐ送る、作業中・送信待ちがあるときは いま / あとで・すぐ送る / ためておく）で送り、コアに `pause_after` を付ける。あとで・ためておく = 入れたその指示のすぐあとに一時停止の印、いま・すぐ送る = その作業が終わったら止める（1 件目の上の印。作業のあいだに来た指示の前で止まり、何も来なければ作業の終わりにコアが外す）。送信待ちが空でこの印だけのときは、送信待ちの場所に「この作業が終わったら一時停止します」の 1 行（`queue/QueuedPauseNotice`。× でやめる）を出す。

## 送信待ち（`queue/`）

作業中に送った次の指示の待ちの列（`QueuedMessages`）。いまの作業が終わったら（止めた・失敗したときも）先頭から順に送る。状態は `ChatLive.queue`（`QueueState`: `messages` / `paused` / `stops` / `waiting_edit`）で、変える API の応答も同じ形。操作の失敗は `queueFailed`（お知らせ）。

- 起動したときの送信待ちの確かめ（`QueueResumeDialog` の `QueueResumeHost`。App がメインウィンドウにだけ置き、開いたときに 1 回 `api.queueResumes` を読む）: 前回の終了で、自動で送るまま送信待ちが残ったチャットがあれば、ダイアログ「送信待ちが残っています」でチャットごとに並べ（プロジェクトの印・名前・件数・次に送る指示・作業の途中で止まったか）、送る / 続けてから送る（作業の途中で止まったチャットだけ）/ 止めておく を選んでもらう（`Segmented`。初めは、途中で止まったチャットは続けてから送る、ほかは送る。名前は `QUEUE_RESUME_ACTION_LABELS`）。「この内容で決める」で `api.resolveQueueResumes`、「すべて止めておく」・Esc で閉じたときはすべて止めておく（答えずに閉じても勝手に送らない）。止めていた・線で待っていた送信待ちは、終えたときのまま戻るので聞かない（コアが一覧に入れない）。

- 置き場所と見た目: ピルの列の下・入力欄のすぐ上。入力欄とは区切り線だけでつなげて 1 枚の枠に見せる（`queued.css` の `.queued-messages + .composer`。区切り線は 1px のまま、濃い色 `--divider-strong`。分割したペインのピントの色も両方に付ける）。
- 初めは畳んで 1 行にする（`QUEUE_COLLAPSED`。どのチャットでも同じ）。1 行には件数・止める位置などの短い案内・「次: 次に送る指示の初めの行」を出し、狭ければ「次:」から省く（`queuedHint.ts` の `queuedHint` / `nextQueuedText`）。止める予定（「1 件目のあとで一時停止」）は一時停止の線と同じ注意の色 `--warn` と同じアイコン（`OctagonPause`）で出す（`.queued-hint.stop`）。
- 見出し: 左に件数の側（`.queued-head-main`。件数・案内・次: と、そのすぐ後ろの「すべて表示」（`QUEUE_EXPANDED`。一覧の見え方の操作なので、送る・消すと分ける））、右に操作のまとまり（`QueuedHeadActions.tsx` の `QueuedHeadTools`。`.queued-head-tools` の中に、何に効くかで 3 つの `.queued-head-group` を間を空けて並べる）:
  - 追加（見出し「＋追加」。前は「＋挟む」だったが、押すと何が起きるのか分かりにくかった。列に行・線を 1 つ足す物。足したら、たたんでいれば一覧を開いて見せる）: 「一時停止」（`QueuedStopButton`。線と同じ注意の色 `.queued-add-stop`。押した結果ではなく、列に挟む物の名前で呼ぶ）で一時停止をいちばん上（位置 0）に挟む（1 件目の上にもう印があれば押せない）。「圧縮」「コンテキスト消去」（`QueuedActionButton`。行と同じ色 `.queued-add-action` ＋ tone）でその行をいちばん下に足す（下の「挟む行」）。
  - 送り方（`.queued-head-send`。列全体の送り方）: `QueuedModeButton`（`queued-mode`。「自動で送る / 止めています」。チャットごとの `api.setQueuePaused`。止めておくと終わっても送らず、行の「すぐ送る」で 1 件ずつ送る。自動に戻すと、作業中でなければ先頭をすぐ送る。列が空になったら自動に戻る）と、すべて送る（`SendAllMenu`。2 件以上のとき。ボタンの上に開くメニューで「まとめて 1 件で送る」= 1 つの指示につなげていま送る `api.sendAllQueued`（作業中なら止めずに伝える）/「1 件ずつ順に送る」= 別々の指示として終わるたびに次を送る `api.sendQueuedInOrder`（止めておくのをやめ、印も外して最後まで送る））。
  - すべて消す（`.queued-remove`。2 件以上のとき。取り消せないので、ほかと離していちばん右に）。
  - 狭ければ操作のまとまりがまるごと 2 行目へ回って横幅いっぱいに広がり（件数の側は 240px を取れるかで決める）、最初のまとまり（追加。選んでいるときは並べ替え）を左端、残り（送り方・すべて消す）を右端に置く。欄の幅（`@container queued`）が 690px 以下で操作のまとまりが 1 行に入らないときは、左寄せにして、最初のまとまり（追加 / 並べ替え）だけで 1 行、残り（送り方・すべて消す）は次の行に横に並べる（入らないときだけまとまりごと折り返す。前は 1 行に 1 つずつ縦に並べていたが、すべて消すが空いている横に入らず 1 行増えていた。まとまりの中は、1 つだけでも入らないときに限り折り返す）。ボタンの文字は狭くても隠さず（アイコンだけにしない）、440px 以下では案内だけを隠す（`queued-head.css`）。
- 選ぶ: ⌘ / Shift ＋クリックで行を選ぶ（`useQueueSelection`。決まりは `useMultiSelect`、範囲は列の順。Esc でやめる）。選んでいるときは見出しの右の操作のまとまりを `QueuedSelectionActions` に入れ替え、並べ替え（いちばん上へ・いちばん下へ。`.queued-head-moves`）｜ 書き直す・1 つにまとめる・まとめて送る・消す・選ぶのをやめる の 2 つのまとまりにする。
- 1 つにまとめる（見出しと行の右クリック。2 件以上）: 送らずに 1 件にする（`api.mergeQueued`。選んだ順ではなく列の順に空行でつなぎ、添付も合わせ、選んだうちのいちばん上の位置に残す。印は `remapStops` で合わせる）。
- 一時停止の印（`QueuedStopLine`）: 指示に付けず、列の中の位置で持つ独立した行（0 = 1 件目の上、n = n 件目のあと。いくつでも置ける。前の指示を送った・消した・まとめた分だけ上に寄る）。自動で送る次の指示の上に印があれば送らずにその線で待つ（印は残り、「止めています」には切り替えない。見出しは「一時停止中」と印の色で出す）。待っている線を消す・動かす・指示を線の上へ移すと、コアがそのまま次の印まで送る。すべて送ったあとの印は、その作業のあいだに次に来た指示の前で止める（次の指示が来ないまま作業が終わったら、コアが外す）。線は送信待ちの行と同じ扱いで動かす: 左のつまみのドラッグ・右の ↑↓（指示 1 件ぶん。書き直す・送るの位置は `.queued-stop-space` で空ける）・右クリック（いちばん上へ・1 つ上へ・1 つ下へ・いちばん下へ・外す）・ごみ箱で外す（どれも `api.setQueueStops` で丸ごと置き換え）。行の右クリックの「この指示のあとに一時停止を挟む / あとの一時停止を外す」は `api.setQueueStopAfter`、「この指示の前に…」は `api.setQueueStops`（1 件目では列のいちばん上）。純粋関数は `@shared/chat/queueStops.ts`（`normalizeStops` / `remapStops` / `moveToSlot`。コアの並べ替えと、画面の「動かすと変わるか」で共通）。
- 並べ替え: 指示を動かすときは、印の線を見た目の並びの 1 行として扱い、動かした指示だけが線の上下を移る（動かしていない指示は線の同じ側に残る）。いちばん上・下へ移しても 1 件目の上・いちばん下の線は端に残り、行の ↑↓ はすぐ隣が線なら並びを変えずに線だけを越える。ドラッグ（`useQueueDrag`）は落とす位置が線のすぐ上か下かで決める（行の上半分 = その行の前で上の線の下、下半分 = 後ろで下の線の上、線の上では上半分 = 線の上・下半分 = 線の下。見出しの行 `.queued-head-row` に落とすといちばん上 = 1 件目の上の線よりも上 `overTop`。落とす位置の線もその側に出す。`api.moveQueuedMany` の `belowStop`）。選んだ行のつまみをドラッグすると、選んだものを並びを保ったまままとめて動かす。入る位置の線は左端に丸を付け、一覧の上下の余白で端でも切らない。
- ドラッグの絵は、つかんだ行（線）の半透明の写しで、つかんだところがカーソルの下にあるまま付いて動く（`queueDragImage.ts` の `startQueueDragGhost`。ブラウザの既定の絵は透明にし、送信待ちの枠と同じ入れ物 `.queued-messages.queued-drag-ghost` に写した行を画面のいちばん上に重ねて `dragover` で動かす。透けるので下の入る位置の線も見える。まとめて動かすときは右上に「n 件」。もとの行は薄くする）。
- 行（`QueuedRow`）: つまみ・番号・添付（`AttachmentPeek`）・文・操作。右の操作は 2 つのまとまりに分けて縦線で区切る: 並べ替え `.queued-row-moves`（↑↓）｜ その指示への操作 `.queued-row-actions`（書き直す・送る・消す）。狭い欄では ↑↓ とボタンの文字を隠す（右クリックに同じ操作）。文は選んでコピーでき、ダブルクリックで書き直す。右クリックのメニューは、書き直す → 送る → 止める（前・あと）→ このあとで挟む（「このあとで会話を圧縮」「このあとでコンテキストを消去」）→ 並べ替え（「いちばん上へ移動」「1 つ上へ移動」など）→ 別のチャットへ（新しいチャットで聞く・移す、子チャットで開く・移す）→ 消す（「送信待ちから消す」）の順に区切り線で分ける（行が画面の下にあるので、メニューは測って上へ寄る）。選んでいる行の右クリックは、選んだもの全体への操作になる。
- 新しいチャットで聞く（送信待ちに残す）/ 新しいチャットに移す（送信待ちから外す）: 文（列の順に空行でつなぐ）と添付（アップロード済みのものをそのまま）を新しいチャットのタブの入力欄に入れて開く（`askInNewChat.ts` の `seedOf` / `useAskInNewChat` → `ChatPaneActions.askInNewChat`。パネルの `openNew(target, seed)` でタブの `seed` になり、`NewChatPane` が `fill` の `attachments` で入れる）。作成先は元のチャットと同じプロジェクト・グループで、新しいチャットの見出しで選び直せる。送るのは自分で。
- 子チャットで開く（送信待ちに残す）/ 子チャットに移す（送信待ちから外す）: メニューではそれぞれを見出し（`.menu-label`）にし、その下に始め方「会話を引き継ぐ / 新しく始める」（`InheritChoice` の `INHERIT_LABELS`。乗せると `inheritHelp` の説明）の 2 つを並べる（`QueuedRow` の `ChildAskItems`）。文（列の順に空行でつなぐ）と添付で、選んだ始め方の子チャットを作ってすぐ送り（チャット欄の「新規の子チャットに送る」と同じ。選択（モデルなど）は渡さず、設定どおりの既定）、設定の「子チャットを作ったとき」で開く（`askInChildChat.ts` の `useAskInChildChat` → `openCreatedChild`）。メモのチャット・アーカイブ済みでは出さない（`QueuedMessages` の `childChats`）。挟む行は持っていかない。
- 挟む行（会話の圧縮 `QueuedMessage.compact`・コンテキストの消去 `clear`。種類は `@shared/types` の `QueueAction`、見分けは `@shared/chat/queueActions` の `queueActionOf`）: 見出しの「＋追加」の「圧縮」「コンテキスト消去」でいちばん下に、行の右クリックの「このあとで会話を圧縮 / このあとでコンテキストを消去」（一時停止の項目の下）でその指示のすぐあとに足す（`api.queueAction`。たたんでいれば一覧を開く）。アイコン・色・文言は `queueActionLooks.ts` の `QUEUE_ACTION_LOOKS` 1 か所（圧縮 = `Shrink` とアクセントの色、消去 = `Eraser` と青 `--info`。行の文は `QUEUE_ACTION_LABELS`「会話を圧縮 / コンテキストを消去」で、畳んだ 1 行の「次:」も同じ。`.queued-text.queued-action` ＋ tone の class）。指示と同じく並べ替え・消す・一時停止を挟めるが、書き直す・新しいチャットで聞くは出さない（書き直すボタンの場所は空けて、送る・消すの位置をそろえる）。送るボタンは作業中なら「このやり取りのあとですぐ圧縮 / 消去」（いちばん上へ移す = メーターの予約と同じ）、作業していなければ「いますぐ圧縮 / 消去」。まとめる・まとめて送る・新しいチャットで聞くでは除かれて列に残る。コンテキストを消去すると、次の指示は新しい会話（セッション）で始まり、このチャットの記録は残る。流れには消去した位置に青い点線の区切り「コンテキストを消去しました（ここから新しい会話）」（`Timeline.tsx` の `context_cleared`。`.context-cleared-divider`）、動きには同じ文のお知らせの行。
- 一覧の高さの上限は上端のつまみ `.queued-resizer` のドラッグで変え（`QUEUE_HEIGHT`、ダブルクリックで 5 件ほどに戻す）、書き直している行の高さの合計（画面の 6 割まで）より低くしない。
- 書き直す欄（`QueuedEditor`）はいくつでも同時に開ける（`useQueuedEdits`。指示ごとに書いている途中の文と添付を持ち、保存・やめるはその 1 件だけを閉じる。列から消えた指示の欄は閉じる。選んでいるときは見出しの「書き直す」・右クリックの「選んだ n 件を書き直す」でまとめて開く）。Enter で保存・⌘Enter で保存していま送る（`api.sendQueuedNow`。作業中なら止めずに伝える。欄の右の送るボタンも同じで、⌘ を押している間は青く光らせる `.queued-editor-send.held`）。折り返した行も含めて文の終わりまで見せる（`field-sizing: content`。画面の 4 割まで）。添付は × で外し、📎・貼り付け・ドラッグ＆ドロップで足せる（`useComposerFiles`・`PendingFileChips`。保存は `api.editQueued` の `attachments` で置き換え。アップロードの途中は保存しない）。
- 次に送る指示（1 件目）を書き直している間は、作業が終わっても自動で送らずに書き直しが終わる（保存・やめる・一覧をたたむ）のを待つ: 開いている欄の指示を `api.setQueueEditing` で丸ごと知らせ、開いている間は持ち時間 `EDIT_HOLD_TTL_MS`（20 秒）の 1/4 ごとに知らせ直す。画面を閉じた・落ちたときは持ち時間で外れて送る（勝手に止まったままにしない）。欄ごと消えた（チャットを閉じた・切り替えた）ときも外す。一覧をたたむと書き直しの欄を閉じ、書いている途中の文も捨てる（`discardAll`。見えないところで止め続けないため）。作業が終わって書き直しを待っているとき（`waiting_edit`）だけ、見出しの案内 1 か所に「次の指示の送信準備ができています。書き直しを保存すると送ります」とアクセントの色で伝える（`queuedHint` の `readyForEdit`）。

## サブエージェント（`subagents/`）

サブエージェントはパネルのタブにせず、チャットの流れの中で見せる（どの依頼から起動し、いつ何をしているかを、メインエージェントとのつながりのまま見るため。依頼を出すタブはメインエージェントだけ）。別に、同じチャットの画面の右の欄に、チャットと同じような画面で並べても見られる（下の「右の欄」。チャットの流れを左に置いたまま、階層とカードの印でつながりを見せる）。

- カード（`SubagentCard`）: Agent / Task の呼び出し 1 つが流れの中の 1 枚。閉じた状態でも、状態（実行中は回る印）・「サブエージェント」の札（そのサブエージェントの色。右の欄の画面の見出しと同じ `SubagentKind`。サブエージェントの中で起動したもの（入れ子）は頭に「↳」を付け、乗せると「『調査』の中で起動したサブエージェント」）・名前・種類・状態の文・開始〜終了（実行中は開始〜最後の動き。書式はツールと同じ `formatStampRange`、終わったものは実行時間も添える `formatStampRangeWithRunTime`）と、2 行目に、実行中なら「いま」いちばん新しい呼び出し（中で起動したサブエージェントのものは「洗い出し › コマンド: …」。`subagentTree.ts` の `latestActivity`）・最後の動きからの時間・トークン数、終わったものなら「完了 · ツール n 回 · トークン数 · かかった時間 · サブエージェント n 件」、右に操作（`SubagentActions`・「右の欄で開く」（設定が右の欄のときは「流れの中で開く / 閉じる」）・「動きで見る」（動きを開き、そのサブエージェントと配下の行を強調して移る `focusActivity`）・「伝える」）。見出しを押す・Enter では、設定の開き方（`SUBAGENT_OPEN_IN`。流れの中 / 右の欄（初め）/ 別ウィンドウ）で開く: 別ウィンドウならそのサブエージェントの別ウィンドウ、流れの中なら開閉し、開くと起動したエージェントからの依頼（初めは 1 行にたたむ）→ そのサブエージェントの手順（`groupEvents(events, scopeOf(entry))`。時刻付きのツールのまとまり・返答・入れ子のカード・実行中の行）→ 起動したエージェントへの報告を、左の縦線で字下げして出す。右の欄なら右の欄にその画面を開く。右の欄で表示しているカードには「右の欄で表示中」と添える（`useShownInAgentPanel`）。閉じているカードの下には、中で起動したサブエージェントを木の枝の形で 1 行ずつ並べる（`SubagentChildRows`。「└ ✳ 洗い出し 完了 · 50秒」。枝はその子の色、実行中は最後のツール、孫がいれば「中に n 件」。3 件まで出して「ほか n 件」。行を押すとその子を設定の開き方で開く。見出しの札「中に n 件」だけでは、中にサブエージェントがいると分かりにくかったため）。狭い欄でも名前を先に残し、時刻を縮め、入らない札はカードの幅（`@container`）で種類 → 「右の欄で表示中」→「サブエージェント」の文字の順に隠す（1 文字だけ残さない。入れ子の「↳」と子の色の点は残す）。
- 右の欄（サブエージェントの画面 `SubagentScreen`。チャットの画面の右の欄 `agents` のタブの中身）: 1 つのサブエージェントを、チャットの画面と同じような画面で見る。上から、階層（「メインエージェント › 調査 › 洗い出し」。メインエージェントは流れの中のそのカードへ、途中の階層はその画面をこの欄に開く）・見出し（「サブエージェント」の札（入れ子は「↳」）・名前・種類・中で起動したサブエージェントの札（`SubagentChildren`。子の色の点（実行中の子は明滅）と「中のサブエージェント n 件」。乗せると子の名前と状態、押すとこの画面の中の最初の子のカードへ）・状態・開始〜終了と、いまの動き / 終わったもののまとめ・操作（再開・やり直すなど `SubagentActions`・「流れで見る」・「動きで見る」）。そのサブエージェントの色で薄く染め、左に太めの帯。チャットの見出しと見分け、どのサブエージェントかも色で分かるように）→ 起動したエージェントからの依頼 → 手順（チャットの流れと同じ `TimelineItems`。入れ子のカードもカードのまま出し、そのカードの「右の欄で開く」で別のタブ）→ 親への報告 → そのサブエージェントに伝える入力欄（カードの「伝える」と同じ `SubagentTellComposer`）。手順は画面いっぱいにスクロールし、実行中は最新に付いていく（`useFollowScroll`）。この画面ではサブエージェントの返答もメインエージェントの返答と同じ見た目（流れの中で付ける左の線と薄い文字を外す）。カードと共通の部品（時刻・いまの動き・まとめ・依頼・手順・報告・`useSubagentItems`）は `subagentParts.tsx`。いくつ開いても、右の欄の中で上下・左右に分けて並べられる（通常のパネルと同じ操作。`features/panel/CLAUDE.md`）。開くのは `ChatPaneActions.openSubagentSide(key, eventId?)`（その画面の中の記録へも移る `data-agent-screen`）、設定の開き方に従うのは `openSubagent`。
- 手順の窓（`SubagentWindow`）: いちばん外側のカードの手順は、流れの見えている高さ（`ChatTimeline` が CSS の `--timeline-h` に入れる）の半分ほどの、枠で囲んだ窓の中だけでスクロールする（長いサブエージェントでチャットの流れが下へ押し流されないように。メインエージェントの配下の窓として見せる）。依頼は窓の上、報告は窓の下に置いていつも見せる。実行中は最新（いちばん下）に付いていき、中で上へ戻したら止まる（いちばん下へ戻せばまた付いていく。ターミナルと同じ。`hooks/useFollowScroll`。右の欄の画面と共通）。終わったものは上から。入れ子のカードは窓の中でふつうに開く（窓の中に窓を作ると、スクロールが何重にもなるため）。はみ出しているときだけ右下に「全体を表示」（高さの制限を外す。`ChatPaneState.fullSubagents`・`toggleSubagentFull`）。目次・裏の作業の一覧から移るとき（`revealSubagent`）は `scrollIntoView` で窓の中まで動く。
- 色と枝分かれ: サブエージェントの色は、メインエージェントが起動したもの（いちばん外側）に起動した順に決め、中で起動したもの（入れ子。孫・ひ孫も）はいちばん外側の祖先と同じ色にする（`agentHues.ts` の `agentHues`。どの仕事の配下かを色で見分けるため。外側どうしは続けて起動したものが似ないよう離れた色を交互に並べ、あとから足されても前の色は変えない。アーカイブで隠したものも含めた一覧全体から決める）。カードの左の端の細い帯・開いた中身の縦線・目次の点（`.agent-dot`）・動きの線で同じ色（CSS の `--agent-hue`。色そのものはテーマに合わせて `subagent-window.css` が決める）。チャットの流れのカードは少し右へ寄せ、上から曲がって入る線（その色）で、メインエージェントから枝分かれした配下だと見せる。
- 入れ子: 中で起動したサブエージェントも同じカードとして中身の中に出す（地の色を交互にする）。ただし Claude Code は、サブエージェントの中で起動したサブエージェント（孫より深いもの）の中の手順を送ってこない（届くのは起動・終わりの知らせ・途中経過の最後のツール・ツールの回数・トークン数・報告）。そのカードの中身にはその旨を出し、親のカードの「いま」は子の途中経過（「内側の確認 › Glob」）にする。途中経過の時刻も祖先の「最後の動き」に伝える（`useSubagents` の `bubbleProgress`）。`FLAT_DEPTH`（3）段より深いものは字下げをやめ、見出しに外側からの道筋（「調査 › 洗い出し ›」）を添える。木は `subagentTree.ts`（`subagentTree` / `childrenOf` / `pathOf` / `flattenTree` / `scopeOf`）。
- カードが読むもの（チャット・作業中か・記録・木）は `SubagentsContext`（`ChatView` が配る。変わるとカードだけが描き直る）、開閉はチャットの画面の状態 `openSubagents`（`toggleSubagent`）。カードの中の流れは描く側（`TimelineItems`）から `renderItems` で渡す（流れの部品を読むと輪になるため）。
- 目次: チャット欄の上のピル `SubagentChip`（「サブエージェント N 件」。左に状態の印 `StatusSlot` = 作業中のものがあれば回るリング、失敗・通信で中断・報告が届かずがあれば赤の点、ほかは薄い点。まとめ方は `chatState.ts` の `summaryState`）の一覧は、入れ子を親のすぐ下に字下げして並べ（`flattenTree`）、行の右に「会話内で開く」「右で開く」「新規ウィンドウで開く」のボタン（設定によらずその場所に。`composer/OpenPlaceControls.tsx` の `OpenPlaceButtons`。右の欄を置けない画面・別ウィンドウを開けないブラウザでは出さない）、一覧の上に「行を押したとき」の切り替え（`DefaultOpenPlace`。設定の `SUBAGENT_OPEN_IN` をここでも変える）。アーカイブしたサブエージェントは、いちばん下の閉じたまとまり「アーカイブ済み n」（`ui/ArchivedFold`。開閉は `useFold("composer", "subagents")`）に薄く出して戻せる。行を押すと設定の開き方で開く（`openSubagent`。流れの中なら `revealSubagent`: 外側のカードから自分まで開き、いちばん外側のカードを窓に入れ、開いた中身が描かれてから移って強調する。右の欄なら `openSubagentSide`）。裏の作業の一覧の名前・「やり直した回を見る」も同じ。裏で動いていて流れの上に流れていったカードにも、ここから戻れる。
- 裏で動かしたサブエージェントが終わったら、起動した流れのその時刻の位置に「裏で動かしたサブエージェント『…』が終わりました 時刻 開く」（`SubagentEndNote`。「開く」は設定の開き方）。
- 伝える: カードの「伝える」で、そのカードのいちばん下に入力欄を開く（`tellSubagent` → `tellOpen`。閉じているカードでも開き、すぐ書けるようにピントを置く。`SubagentTell.tsx` の `SubagentTellBox`）。チャット欄の宛先を切り替える作りはやめた（宛先を戻し忘れる・メインエージェントに送るつもりの文をサブエージェントに送りやすかったため）。入力欄は右の欄の画面と同じ `SubagentTellComposer`（チャット欄と同じ `Composer`。添付・音声入力も使える。書きかけの文はサブエージェントごとに `subagentTellDraft` に残し、カードと右の欄で共通）。Enter で送って閉じ、Esc・× でやめる（書きかけは残り、もう一度「伝える」で戻る。Esc はパネルを閉じる Esc に渡さない）。終わったサブエージェントでは、伝えると終わったところから再開することを案内に出す。開いている間に入力欄が流れの上へ流れていかないよう、開いたら一番下への付いていきを止める（`scroll.release`）。送ると、Kickoff から直接は送れないので、メインエージェントに SendMessage でそのまま伝えてもらう（文の形は `@shared/chat/prompts.ts` の `relayMessage`、カードの流れには `relayedText` で自分の発言として混ぜる。`api.tellChat` で送り、メインエージェントが作業中なら止めずに伝える）。サブエージェントの ID が届いていなければ「伝える」を出さない（右の欄では送れない旨）。
- 子チャットで聞く: 「伝える」の入力欄（カード・右の欄の画面で共通）の上の切り替えで、送り先を「サブエージェントに伝える」（上の中継。メインエージェント経由で届き、作業に反映される）/「子チャットで聞く」（会話の記録を読んだ別の AI が答える）から選ぶ（子チャットの「会話を引き継ぐ / 新しく始める」と同じ形。最後に選んだ方を `SUBAGENT_ASK_MODE` で覚え、初めは中継）。子チャットで聞くと、コアがそのサブエージェントの会話の記録（Claude Code の記録を読んで Markdown にしたもの）を添付にした子チャットを作る（`api.askSubagentInChild`。コアの `subagentChild.ts`）。メインエージェントにもサブエージェント本人にも伝わらないので、メインエージェントが作業中でもいま / あとでを聞かずにすぐ送り、作った子チャットは設定の「子チャットを作ったとき」で開く（`openCreatedChild`）。子チャットの始まりの位置はサブエージェントを起動した呼び出しなので、カードの下に子チャットの札（`ChildChatMarks`）を出す。子チャットの最初の発言は、AI への前置き（`@shared/chat/prompts.ts` の `subagentAskMessage`）を隠して書いた文だけを出し、上に「サブエージェント『…』について聞く」の札（前の「【サブエージェントに直接聞く】」で始めた発言も見分ける）（`.message-kind-label`）を添える（`subagentAskOf`。指示の履歴も書いた文だけ。もう一度送る・書き直すときは前置きを付け直す）。
- 一覧の組み立ては、コアと共有の `@shared/chat/subagents.ts`（`collectSubagents` / `subagentReport` と、コアの作業の終わりのお知らせ `unfinishedSubagents`・通信が戻ったときの再開 `networkStoppedSubagents` で同じ数え方にする）。表示名・状態の文だけ画面の `subagentList.ts`。行は作業 ID でまとめる（SendMessage で再開すると、知らせの呼び出し ID が再開を頼んだ SendMessage のものになるため）。報告の本文は `subagentReport`。裏で動かしたものは一覧から消えたら終わったとみなし（報告を渡していれば完了、なければ中断）、起動の知らせ（`isBackgroundLaunch`）を完了と数えない。
- 状態の文（`subagentStatusLabel`・乗せたときの説明 `subagentStatusTitle`・色 `subagentStatusClass`）:
  - 通信の切断で止まったもの（`network`。API のエラーで失敗した・通信で親ごと終わったときに動いていた）は「通信の切断で中断」と注意の色（ピルの数も失敗と分ける）。
  - 出力の上限（`isOutputLimitError`）で止まったものは「失敗（出力の上限）」。再開・やり直すの頼みには「報告は短く・大きなファイルは分けて」と添える（`resumeRequest` / `retryRequest` の `outputLimit`）。
  - 完了は、報告が起動したエージェント（メインエージェント・入れ子なら外のサブエージェント）に届いたかで分ける（`delivery`。待つ形は起動したツールに結果が返ったら、裏で動かしたものは報告のあとに起動したエージェントが動いたら受け取った = 完了）。まだ動いていなければ「報告済み（受け取り待ち）」、動かないまま作業が終わったら「報告が届いていません」と注意の色。届かなかった報告はコアが次に送る指示に本文を自動で添えて渡し、受け取った = 完了になる。待たずに渡すなら行の「報告をいま渡す」（`HAND_OVER_NOW` を `api.tellChat`。本文はコアが添える）。ピルにも「n 件受け取り待ち」「n 件届かず」。
  - 止まったあとに親が同じ仕事を新しいサブエージェントでやり直したもの（`supersededBy`。判定は `@shared/chat/subagentSupersede.ts` の `markSuperseded`。決まりは `src/shared/CLAUDE.md`）は「やり直し済み」と控えめな色。止まった理由とやり直した回の名前は title、「やり直した回を見る」でその回のカードへ移る。再開・やり直すを出さず、ピルの失敗の数・通信が戻ったときの再開にも数えない。
- 止まった（失敗・中断）行とカードには「再開」（SendMessage で止まったところから続ける）と「やり直す」（同じ依頼で最初から。確かめてから）を置く（`SubagentActions`。文は `resumeRequest` / `retryRequest`、メインエージェントには `api.tellChat` で伝える）。実行中なのに長く動きのないものは「止める」（作業中だけ。確かめてから `api.stopBackgroundTask`。止めたら再開・やり直すで戻せる）。
- 作業中にサブエージェントだけが通信のエラー・出力の上限で止まったときは、システムプロンプトで 1 回だけ SendMessage で続きから再開させる（ほかの失敗・利用者が止めたものは再開せず伝える。コア）。

## 動き（`activity/`）

メインエージェントとすべてのサブエージェントの動きを、時刻の順に 1 本に並べる見え方（いつ何をしたか・どこが並行していたかを、メインエージェントの配下であることのまま見るため。依頼を出すタブはメインエージェントだけのまま）。チャットの見出しの「会話 / 動き」（`ChatPaneActions.show`）で、同じタブの中で切り替える。会話は隠しても描いたまま残す（`ChatPane` の `ChatBody`・`ChatTimeline` の `hidden`。読んでいた位置・開いたカード・窓の中の位置を保つ）。

- 行（純粋関数の `activityRows.ts` の `activityRows`）: メインエージェント（`groupEvents(events)`）と各サブエージェント（`groupEvents(events, scopeOf(entry))`）の項目を 1 行ずつにして、時刻の順に並べる（同じ時刻なら親が先）。1 行 =「時刻・誰が・何を・かかった時間」。続けてのツールは会話と同じまとまりで 1 行（1 件ならそのツールの中身「コマンド: npm test」、いくつもならまとめ「2個のファイルを読み取り および 1回検索」。左の矢印で 1 回ずつに広げる）、自分の指示・返答（サブエージェントのものは「発言」）は 1 行目だけ、チャット欄から伝えた指示は「伝える → 調査「…」」、要約・お知らせ・エラー・作業の終わりも 1 行。サブエージェントは起動の行（起動した側の線）で始まり、終わりの行（「報告 → 調査」/ 失敗 / 中断と、起動からのかかった時間）で終わる。中の手順が届かない（孫より深い）実行中のものは、途中経過の最後のツールを「いま: …」として 1 行。考えた行は出さない。実行中（結果の届いていないツール）は、持ち主が動いているときだけ（メインエージェントは作業中で、最後の作業の終わりより後のもの）。
- 線（純粋関数の `activityRails.ts` の `layoutRails`。Git のグラフと同じ考え方）: 列は使うときに空いている左から取り、起動した子は親より右の空いている列。起動の行で親の節から右へ曲がって子の線が始まり、終わりの行の節で閉じ、その列はあとで使い回す。線は絞り込んだ行の全体で決める（描くのが最近の分だけでも、前から続く線を上から通す）。色は持ち主のサブエージェントの色（カードの帯・目次の点と同じ `agentHues`）、メインエージェントは灰色。節は、自分の指示 = 白抜きの丸・起動 = 少し大きい丸・終わり = ひし形・失敗 = 赤・実行中 = 明滅。描くのは `ActivityLine`（行は memo。線の欄の幅はすべての行で同じ。別の日の行があれば時刻の欄を日付の入る幅に `--activity-time-w`）。
- 絞り込み（上のチップ。`ChatPaneState.activityFilter`・`filterActivity`）: すべて・メインエージェントだけ・そのサブエージェントと配下（その起動の行は外し、自分の線から始める）。チップは起動した順で色の点付き、入れ子は道筋を説明に。右に動作中の数。
- 強調（カード・右の欄の画面の「動きで見る」。`focusActivity(key)` → `ChatPaneState.activityFocus`（押すたびに `nonce` を増やす）・`useActivityFocus`）: 絞り込みを「すべて」に戻し、そのサブエージェントと配下の行（その起動の行も。`agentScope` ＋ `focusedRowIndexes`）を薄く塗り、初めの行へ移って枠で示す（描く窓の外なら、そこまで描く範囲を広げる）。チップの下の帯 `ActivityFocusBar` に「名前の動き n / m」と ↑↓（前・次の強調する行へ。端で回り込む `stepIndex`）と ×（`clearActivityFocus`）。移るときは一番下への付いていきをやめる。チップを押すと強調をやめる。別ウィンドウのサブエージェントの画面からは、メインのウィンドウの動きで強調する（`showActivity`）。
- 描くのは最近の `ACTIVITY_WINDOW`（300）行（上の「以前の動きを表示」で足す）。一番下を見ている間は新しい行に付いていく（初めと絞り込みを変えたときは一番下から）。
- 会話との行き来: 行を押すと会話に戻り、その場所へ移って強調する（`revealInConversation`）。サブエージェントの行は設定の開き方で開く（`agentTargetOf` → `openSubagent`。流れの中なら外側のカードから開いて窓の中まで `revealSubagent(key, eventId)`、右の欄なら動きを見せたまま右の欄のその画面の中へ `openSubagentSide(key, eventId)`。起動の行・終わりの行・いまの行はそのサブエージェントを開く。広げた 1 回ずつの行はその呼び出しへ）。サブエージェントの行の右端の 2 つのボタン（「会話の流れの中で見る」「右の欄で開く」。行が多いので乗せた行・ピントのある行にだけ出す `.activity-open-actions`）と右クリックのメニューで、設定によらずどちらで開くかを選べる（右の欄を置けない画面では出さない）。カード・右の欄の画面の「動きで見る」は `focusActivity(key)`（下の「強調」）。

## 承認と質問（`approvals/`）

- 回答待ちのカードは `ApprovalCard`（ツールの承認・`question` は `QuestionCard`・`reconnect` / `usage_limit` は `ReconnectCard`）。回答を送るのは `useResolve`（`useResolveApproval.ts`。送れたらカードごと消えるので送信中のまま）。承認カードの入力は `describeApprovalInput`（Bash のコマンドは、実行のあとの欄と同じく色を付ける）。
- AI からの質問（`QuestionCard`。AskUserQuestion。）: 選択肢は枠で囲まず細い区切り線で並べた行で、丸の代わりに番号の箱（選ぶと青・複数選ぶ質問はチェック。キーの 1〜9 でも選べる）。最後の行は鉛筆の箱と枠のない「その他の回答」の欄 `QuestionOtherField`（チャット欄と同じく書いた分だけ伸び、Enter で回答・次へ／Shift+Enter で改行。📎・貼り付け・ドラッグで添付でき、アップロード中は回答させない。文がなく添付だけでも答えられる。ドラッグで添付したときも「その他」を選ぶ）。
- 質問が 2 つ以上なら、見出しの「1 問ずつ / すべて」で出し方を切り替える（`QUESTION_LAYOUT`。初めは 1 問ずつ）。1 問ずつは上に質問の見出しを並べていまの位置と答えたものを示し、1 つ選ぶ質問は選ぶと次へ進む。最後は「回答する」。すべては番号だけを付け（薄い見出しは出さない。見出しは質問が 1 つのときだけ）、質問どうしを 1px の濃い境界線で分ける。見出しの矢印でたたむと、いまの質問の 1 行だけになる。1 問ずつ・たたんでも欄は作り直さずに隠す（書いた文・添付を残す）。質問の文・説明は AI の改行のまま出す。
- 「その他」の添付は回答の `attachments`（質問ごと）で送り、コアが回答の文にパスと Read ツールで開くよう書き添えてから Claude Code に渡す（AskUserQuestion の回答は文字だけなので）。答えた内容は記録 `approval_resolved` に残り、`QuestionAnswerMessage` で出す。

## 指示の一覧（`prompts/`）

- 自分の指示の一覧は記録から `promptListOf` で 1 回だけ作り、指示の履歴・⌘⌥↑ / ↓・上に貼り付ける指示の帯・↑↓ の呼び出し・失敗した作業の巻き戻しで共通に使う。
- 指示の履歴（`PromptsChip`。チャット欄の上のピル「指示の履歴 n」）: 圧縮前指示・圧縮後指示の行は文の前に「圧縮前指示」「圧縮後指示」の札。行でその指示へ移って強調し、右のボタンで入力欄に入れる（`fillComposer`）。一覧は会話の順で、開いたらいちばん下を見せる。上の欄で絞り込み、↑↓ で選んで Enter で入力欄に入れる・⌘Enter でその指示へ移る。チャットにピントがあるときの ⌃R でも開き（シェルの履歴の検索と同じ）、開いている間の ⌃R は 1 つ前の一致へ。閉じたらチャット欄にピントを戻す。
- 前後の指示へは ⌘⌥↑ / ↓（`usePromptKeys`。チャットにピントがあるときだけ、捕捉で先に受け取り、縦スライドのプロジェクトの切り替えより優先する）。前に移った先がまだ見えていればその前後へ、なければ位置で決める（判定は純粋関数の `promptNav.ts` の `adjacentPrompt`）。指示でないもの（AI からの質問への回答）を見ているときは、その前後のいちばん近い指示へ（`promptAround`）。
- 上に貼り付ける指示（`StickyPrompt` ＋ `useStickyPrompt`）: 読んでいる返答の元の自分の指示（流れの上端より上から始まるいちばん下の吹き出し。いちばん上を見ているときは最初の吹き出し。`readingPrompt`）を、流れに重ねずに流れの上の段に置き、いつも出す（`chat.css` の `.timeline-wrap` の `grid-template-rows`。列は `grid-template-columns: minmax(0, 1fr)` で枠の幅に固定する。既定の auto では、1 行にたたんだ長い指示の幅まで列が広がり、流れごと右へはみ出した）。見出しは「指示」で、すぐ右に ↑ / ↓（前・次の指示へ。⌘⌥↑ / ↓ と同じ数え方。移る向きの矢印 `ArrowUp` / `ArrowDown`）、その右に開閉の矢印（初めは 1 行にたたみ、全文は `STICKY_PROMPT_EXPANDED`。1 行に収まるときも場所を取ったまま押せなくする）、添付は `AttachmentPeek`（帯の高さは変えない）。押して何かが起きるのは ↑ / ↓・開閉・添付だけで、見出しと文は押しても何もしない（乗せても地の色を変えない）。スクロールと描いた項目の変化で確かめ直し、同じ発言のままなら描き直さない（`samePinned`）。AI からの質問への回答（`QuestionAnswerMessage`。自分の吹き出しと同じ `.bubble.user` だが `.bubble-text` がない）を読んでいるときは、文の前に「質問への回答」の札を付け、たたんでいる間は答えだけを「 / 」でつないで 1 行に、全文では質問ごとに質問の文と答えを出す（吹き出しから読む `answersOf`。たたむと質問の文が隠れるので、開閉はいつも押せる）。↑ / ↓ は回答には止まらず、その前後のいちばん近い指示へ（`promptAround`）。帯を出すかは、タブの列の「表示」→「指示の帯」・帯の右クリックの「指示の帯を隠す」（全文の開閉も）・見出しの行のボタン・設定の「表示」→「上に貼り付ける指示」（どれも `STICKY_PROMPT_HIDDEN`）。

## チャットの中の検索（`find/`）

`ChatFind`。チャットの見出しの行の右に置く検索欄（見出しの行・項目を隠したときは、⌘F でチャットの右上に浮かせて出す `floating`。上の「見出し」）で、ふだんは細く、ピントが入る・文を入れると広げ、件数・前後・大文字小文字・消すは文を入れたときだけ出す。狭い見出し（`@container` 420px 以下）では虫眼鏡だけにして、押す・⌘F で広げる。⌘F でこの欄にピントを移して文を選ぶ（`useChatHotkey`）。Esc で文を消してチャット欄にピントを戻す。↑ / Shift+Enter で前、↓ / Enter で次（初めて移るときはいちばん新しい一致へ）。

- 探すのは記録から（`chatFindMatches.ts` の `findMatches`。自分の発言とメインエージェントの返答）で、移るときにその発言の前後だけを描く（`reveal`）。流れをすべて描かない。印は描いている範囲だけに CSS Custom Highlight API で付け（`::highlight(chat-find)`）、DOM を書き換えない。閉じたツールのまとまり・思考の中は探さない。
- 打った文は前後の空白も削らずに探す（半角・全角の空白も）。右の「Aa」（⌥⌘C。`CHAT_FIND_CASE`。入れているときは `.find-option.on`）で大文字・小文字を区別する。照らし合わせは記録と画面の印で共通の `matchOffsets`。

## 音声入力（`features/dictation/`）

- チャット欄の下の道具のマイク `DictationButton` ＋ `useDictation`（1 回押して話し、もう一度押すと文字起こしして、キャレットの位置（選んでいればその範囲）に入れる。入れ方は純粋関数の `insertDictation`（英字とくっつくときだけ空白を補う））。録音は `recorder.ts`（`getUserMedia` ＋ `MediaRecorder`）、マイクの失敗の文は `micErrorMessage`。
- 録音中は赤く経過時間、文字起こし中は「文字起こし中…」、失敗は `DictationError`（`ErrorText` と、録った音声で起こし直す「もう一度」）。録音中の送信ボタン・Enter・⌘Enter は、入れてそのまま送る。⌘⇧Space（チャット欄にピントがあるときだけ。`DICTATION_SHORTCUT`）で開始・停止、Esc でやめる。
- 準備の状態は店の `useVoiceStatus`（設定の変更で取り直し、ダウンロードの進み具合はその場で直す）で、準備ができていなければ押したときに設定の「音声入力」を開く（`openSettings("voice")`）。設定は `features/settings/CLAUDE.md`。

## 返答のファイルのチップ（`features/fileLinks/`）

返答の中のファイルのパスは、チャットのパネルの中（`ChatPane` が `FileLinksProvider` で `FileLinkContext` と、ui の Markdown が読む `MarkdownFileLinksContext` を入れる）だけチップにする（`useFileLinks`。チャットの作業場所のファイルの一覧を読み、作業が終わるたびに読み直す。一覧が読めない間はチップにしない）。

- 押したとき（チップ・ターンの変更カード・ツールの行で共通の `open`）: 会話を残したまま、チャットの画面の右の欄（サブエージェントと同じ欄。`panelActions(panelKey("agents", チャット))`）に開く。行の番号があればファイルのタブ（`openFile`。中身でその行を目立たせる）、作業場所にコミットしていない変更があれば変更のタブのそのファイルの位置（`openChanges`。押した時に `api.gitStatus` で `changeOf` を見る）、なければファイルのタブ。右の欄を置けない所ではファイルタブ（`openProjectFile`）。差分はコミットしていない変更すべて（そのターンの分だけではない。ファイルタブの差分と同じ）。
- ⌘クリックはファイルタブへ直接（`openByClick`）。右クリックはファイルのメニュー `FileMenu`（右の欄で開く・ファイルタブで開く・VS Code / 既定のアプリで開く・Finder で表示（IPC の `externalApps.revealPath`）・パスのコピー（相対・絶対）。`FileLinksProvider` が 1 つだけ描く。チップの右クリックは返答のメニューより先に受け取る）。開く関数は同じものにして、返答の Markdown を描き直させない。
- 右の欄の中身は `features/editor/CLAUDE.md` の「右の欄の変更とファイル」。
判定と Markdown の木の書き換え（`remarkFileLinks`）は純粋関数の `fileRefs.ts`（作業場所のファイルの一覧にあるものだけ。インラインコード・リンク先・地の文の絶対パス）。

## 子チャット（`children/`）

- 横道の質問を、親の会話とは別のチャットで聞く（データとサーバーは `src/core/chat/CLAUDE.md` の「子チャット」）。子チャットの選択（モデル・深さ・権限・ファスト）は、どの始め方でも親から引き継がず、設定どおり（プロジェクトの既定 → 設定の既定。コアの `resolveChatOptions`）にする（新しいチャットのタブで選び直したものだけ効く）。一覧（`selectChats`。サイドバー・ボード・⌘K など）には出さず、親の中にだけ置く（`stores/chats.ts` の `childChatsOf` / `useChildChats`。親 → 子の一覧）。
- 始め方: 発言の右クリックの「子チャットで聞く」（`useMessageMenu`。選んだ文、なければ発言の全体）と、チャットのメニューの「子チャットを作成」（サイドバーの行の「…」・右クリック・ボードのカード・パネルのタブ。`ChatMenuItems`。引用なし・聞いた位置なし）→ `openAskChild` で `AskChildHost`（App と別ウィンドウに 1 つ）が聞く: 聞く欄（選んだ文を引用 `> ` にして初めから入れておき、書き換え・消しができる。キャレットは引用の下。Enter で送る）と、そのすぐ上の始め方の切り替え（`InheritChoice`。下の「会話を引き継ぐか」）。選んだ文は聞く欄の文に入れて送るので、`quote` は送らない。送ったら閉じ、作った子チャットを設定の「子チャットを作ったとき」で開く（`openCreatedChild`。親は作業を続けられる）。
- チャット欄の送信ボタンの右クリック・▾ の「新規の子チャットに送る」の組（送るたびに子チャットを新しく作ることが分かるよう「新規の」を付ける。前は「新規の子チャットに送る」で、いまある子チャットに送るように読めたため。`ChatComposerArea` の `sendTo`。「質問として送る」の下に区切り線を挟み、「新規の子チャットに送る」の見出しの下に「会話を引き継ぐ」（`MessagesSquare`。下に「このチャットの会話の続きとして始める」）・「新しく始める」（`MessageSquarePlus`。「会話は渡さず、書いた文だけで始める」）の 2 つ。前は 2 項目とも「新規の子チャットに送る（…）」と同じ言葉をくり返し、違いが括弧の中だけで読み分けにくかった。送り先の項目は `ComposerActions` の `SendTarget`（`group` の見出し・`icon`・`hint` の一言）。乗せると `inheritHelp` の説明。メモのチャット・アーカイブ済みでは出さない）: 書いた文と添付をそのまま、選んだ始め方の子チャットで送る（`api.createChildChat` の `attachments`。引用なし・聞いた位置なし。選択（モデルなど）は渡さず、設定どおりの既定）。親が作業中でも送れ、親は止めない。作った子チャットは設定の「子チャットを作ったとき」で開く（`openCreatedChild`。入力欄の上のピルにも並ぶ）。
- 右の欄の「新しい子チャット」のボタン（タブの列の新しいタブのボタンの位置・空の欄の「新しい子チャット」。`features/panel/CLAUDE.md`）: 入力欄だけの「新しい子チャット」のタブ（`NewChildPane`）を開く。右の欄のチャットの子チャットになることは開いた時点で決まっているので、作ったあとの子チャットの画面（`SideChildChat`）と同じく、いちばん上に上の帯（`NewChildBar`。親までの系譜・深さの呼び名・名前は「新しい子チャット」・「親チャットに渡す」は答えがないので押せない）を出す（前は帯がなく、送るまで親が画面から分からなかった）。見出しにプロジェクトと作業場所（グループは出さない）、入力欄のすぐ上に始め方の切り替え（`InheritChoice`。下の「会話を引き継ぐか」。入力欄の薄い案内も選んだ方に合わせ「親の会話の続きで聞きたいこと / 新しく頼みたいこと」）、入力欄の選択（モデルなど）は親から引き継がず、新しいチャットと同じく設定どおり（プロジェクトの既定 → 設定の既定）から始め、このタブで変えたものだけ効かせる。最初の文を送ると `api.createChildChat`（引用なし・聞いた位置なし・添付も送れる）で子チャットを作り、`addChat` で一覧に入れてから、そのタブを同じ位置のまま子チャットのタブに置き換える（設定の「子チャットを作ったとき」には従わない。右の欄で書いて送ったので、そのままそこで続ける）。
- 会話を引き継ぐか（`InheritChoice`。新しい子チャットのタブと「子チャットで聞く」の画面で同じ形）: 「会話を引き継ぐ / 新しく始める」の 2 つから選ぶ切り替え（`Segmented`。初めは引き継ぐ）と、そのすぐ横に選んだ方の説明 1 行。書く欄のすぐ上に置く（前は見出しのプロジェクトの札の横のチェックと、画面の真ん中の説明だったが、札に見えて選べるものと分からず、外したときの意味も名前から読めなかったため）。作った子チャットの会話のいちばん上には、コアのお知らせ「親のチャット『…』の会話を引き継いで始めました / 会話を引き継がずに始めました」が残る（`src/core/chat/CLAUDE.md`）。チャット欄の「新規の子チャットに送る」・送信待ちの「子チャットで開く / 移す」は、メニューの項目を始め方ごとに分けて選ぶ（切り替えを開く手間をかけず、1 回押せば送れるように）。
- 札: 聞いた発言の下に `ChildChatMarks`（子ごとに状態 = 作業中・回答待ち・失敗・答えあり（未読）・既読）、入力欄の上のピルに `ChildChatsChip`（「子チャット n 件 · m 件答えあり」。見てほしい数は様子ごとに「· 1 件回答待ち · 1 件失敗 · 2 件答えあり」と分け、左の印と同じ色（黄・赤・緑）で添える（前は 3 つをまとめて「答えあり」と数え、回答待ちも「答えあり」に見えた）。左に子チャットの状態をまとめた印 `StatusSlot`（`summaryState`: 回答待ち > 作業中 > 失敗 > 答えあり（未読）> 既読。作業中で、ほかに答えありがあればリングに緑の点を重ねる。サイドバーの行と同じ見た目なので、開かなくても様子が分かる）。押すと一覧。行はサブエージェントの一覧と同じ形（`.subagent-row`）で、状態の印・名前・様子 · モデル · 最後に動いた時刻、右に「右で開く」「新規ウィンドウで開く」（`OpenPlaceButtons`。`openChildChat` の `place`）とアーカイブ・削除（チャットと同じく確かめてから `toggleArchiveChat` / `confirmDeleteChat`。その子チャットの子も一緒に。作業中は出さない）。上に「行を押したとき」の切り替え（`CHILD_CHAT_OPEN_IN`）。アーカイブした子チャットは一覧と件数から外し、いちばん下の閉じたまとまり「アーカイブ済み n」（`ui/ArchivedFold`。サイドバー・ボードのアーカイブ済みと同じ見出し。開閉は `useFold("composer", "children")`）の中に薄く出して「一覧に戻す」で戻せる（サブエージェントの一覧と同じ形。数えるためにアーカイブ済みのチャットの一覧も読む `useChildChats({ archived: true })`。すべてアーカイブしていればピルは「アーカイブ済みの子チャット n 件」））。答えが来ても開かず、通知（`app/notifications.ts`。題名に「子チャット: 」）を出す。
- 作ったときの開き方（`openCreatedChild`。チャット欄の「新規の子チャットに送る」・「子チャットで聞く」の画面・送信待ちの「子チャットで開く / 移す」で共通）は設定の「子チャットを作ったとき」（`CHILD_CHAT_OPEN_ON_CREATE`。右の欄で開く（初め）/ 別ウィンドウで開く / 開かない）。作った子チャットは知らせを待たずに `addChat` で一覧に入れてから開く（入っていないと親をたどれず、右の欄でなくふつうのチャットのタブで開くため）。開く場所は下の `openChildChat` に `place` で渡す。
- 新しくできた子チャットの知らせ: 入力欄の上の「子チャット n 件」のピルを 2.4 秒ほどアクセントの色で 2 回明滅させる（`useNewChildFlash` → `ComposerChip` の `chipClassName` に `child-chats-new`）。作られてから 10 秒以内に一覧に現れ、まだ光らせていない子だけ（画面を開き直したときに前からある子で光らせない。どの作り方でも、ほかのウィンドウで作っても同じ）。開かない設定でも、作ったことと置き場所が分かる。
- 開き方（`openChildChat`。札・サイドバーの子の行・通知で共通）は設定の「子チャットを開く場所」（`CHILD_CHAT_OPEN_IN`。初めは右の欄。別ウィンドウを開けないブラウザでは右の欄）:
  - 右の欄（`openChildSide`）: いちばん上の親（`rootChatOf`。読み込んだ一覧を `knownChat` で引く）のチャットの画面の右の欄に、子チャットのタブ（`child`。孫・ひ孫も同じ欄に並べる）。親の画面が見えていなければ、先にチャットのパネルで親を開く（`openInRootSide`。見えているかは `pane/windowMessages.ts` の `isChatPaneShown`）。別ウィンドウの中からは、メインのウィンドウに頼む（知らせ `openChild`）。中身は `SideChildChat`（上の帯と `ChatView`。子の画面の中には右の欄を重ねない = `PanelHostContext` を null にする。子のサブエージェントは流れの中、ファイルはファイルタブ）。タブの名前の前は子の状態の印（`ChildTabLead`）と、深さの札「子 / 孫 / ひ孫」（下の「右の欄のタブ」）、タブの × はチャットの ✕ と同じく閉じ方を聞く（表示だけ消す = タブを閉じる）。タブの右クリックの「別ウィンドウで開く」で別ウィンドウへ移せる。
  - 別ウィンドウ（`features/popout/PopoutChildChat`）: 最小化は閉じ方を聞かずに閉じる（子は残る）。✕・⌘W はチャットの ✕ と同じ `closeChatWithChoice`（既定は `CHAT_CLOSE_ACTION`）。
- 上の帯（`ChildChatBar`。右の欄・別ウィンドウ・送る前の新しい子チャット（`NewChildBar`）で共通。形は `ChildBarFrame` 1 つで、親の ID から描く）: 左に親チャットまでの系譜（「↖ 親 根 › … › 親 › 」。祖先は `childChats.ts` の `ancestorsOf`（根 → 親。読み込んだ一覧を `knownChat` で引く）で、3 段より深ければ根と親の間を「…」にまとめる。親は状態の印 `StatusSlot` と名前の札で、押すとその親の画面を見せて、すぐ下の子を聞いた発言へ `revealInParent`。親が一覧になければ名前なしの「親のチャット」）→ 深さの呼び名（「子チャット / 孫チャット / ひ孫チャット」。`@shared/chat/childDepth` の `childDepthLabel`。色も深さで変え、子 = 青・孫 = 桃・ひ孫より深い = 黄緑（`--child-depth-<n>`。右の欄のタブの札・下線と同じ色）。`.child-depth-<n>`）→ 名前 → 右に「親チャットに渡す」（いちばん新しい答えを引用にして親の入力欄の後ろに足す `handBackToParent` / `handBackText`。送るのは自分で。親の画面がなければ書きかけの文 `chatDraft` に足してから開く）。狭い帯（`@container child-chat-bar`）では、560px 以下で根の側の札と「親」の文字、440px 以下で深さの呼び名、340px 以下で「親チャットに渡す」の文字を隠す（直接の親の札と名前は残す）。前は「親を見る」のボタンだけで、どれが親か画面から分からなかったため。閉じるボタンは置かない（右の欄はタブの ×、別ウィンドウは ✕・最小化。子は残り、札から開き直せる）。別ウィンドウからは知らせ `childToParent` でメインのウィンドウに頼む（`app/mainWindowMessages.ts`）。
- アーカイブ・削除（決まりはコアの `src/core/chat/CLAUDE.md` の「子チャット」）: 親をアーカイブすると子孫も一緒にアーカイブし、親を戻すと一緒にアーカイブした子孫だけが戻る（子チャットだけで先にアーカイブしていたものはそのまま）。子チャットだけをアーカイブ・戻すときは親に触らない。削除は子孫ごと。確かめのダイアログ（`chatActions.ts` の `childNote`）は、読み込んだ一覧に子孫があれば「子チャット n 件（孫も）も一緒にアーカイブします / 削除します」、戻すときは一緒に戻ることを添える（数えるのは `stores/chats.ts` の `knownDescendantCount`）。まとめての操作の確かめにも同じ断りを添える。
- 右の欄のタブ: 名前の前は子の状態の印（`ChildTabLead`）、種類の札は深さで「子 / 孫 / ひ孫」（`ChildTabBadge`。`childDepthShort`。種類の表の `BadgeText`）にし、札と表示中の下線を帯の呼び名と同じ深さの色にする（札の中の `.child-depth-mark-<n>` を `:has()` で見て `--tab-color` を替える。孫・ひ孫も同じ欄に子と並ぶので、タブで見分けられるように）。
