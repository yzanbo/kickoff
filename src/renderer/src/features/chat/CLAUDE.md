# チャット（`features/chat`）

チャット全般（状態・操作・名前・メニュー・状態の印）と、1 つのチャットの画面。チャット欄の音声入力（`features/dictation/`）と返答のファイルのチップ（`features/fileLinks/`）もここに書く。まとめ方・数え方は `features/chatList/CLAUDE.md`、タブの入れ物は `features/panel/CLAUDE.md`。

## 状態と未読

- 状態は `chatStateOf(chat, pending)`（`@shared/chat/state.ts` の `agentStateOf` を回答待ちの一覧で引く）、カンバンの列は `boardColumnOf`（作業中・回答待ち・未読・既読。人は動かさない）。色は `tones.ts` の `COLUMN_TONE` / `STATE_TONE`。
- 行の先頭の状態の印は `StatusSlot`（作業中 = 回るリング・回答待ち = 琥珀色の！・未読 = 緑の点・エラー = 赤の点・既読 = 薄い点）。作業中のまま未読のもの（`busyWithUnread`）は、列・数は作業中のまま、リングに緑の点を重ね（`unread`）、名前を太字・カードに「未読あり」。
- 未読にする「新しい結果」は AI の文章の返答（サブエージェントのものは除く）・作業の終わり・失敗（`isUnreadEvent`。ツールの実行などの途中経過では付けない）で、作業中でも返答が届けば付ける（コア）。
- 印を消すのは、チャットを表示していて・Kickoff が前にあり・流れの一番下が見えているとき（`timeline/useMarkSeen.ts`。新しい結果が届いた・一番下まで来た・表示した・Kickoff に戻ったときに確かめる）。`api.markSeen(chatId, eventId)` に一番下まで見た記録の ID を渡し、それより新しい結果があれば消さない（メニューの「既読にする」は ID なしでそのまま消す）。印の付け外しでは最後に動いた時刻（一覧の並び順）を変えない。見ている間に「未読にする」で付けた印は、次に上のどれかが起きるまで残す。

## 操作・名前・メニュー

- アーカイブ・削除などは `chatActions.ts`（`toggleArchiveChat` / `confirmArchiveChats` / `confirmDeleteChat` / `confirmDeleteChats` / `markChatsSeen` / `moveChatsToGroup` / `togglePinChat`。まとめての操作で断られたものは最後にまとめて知らせる。削除したチャットの書きかけの文 `chatDraft` も消す）。
- 名前をその場で変えるのは `useChatRename` ＋ `ChatTitleInput`（ダイアログは使わない。`onError` を省くとお知らせで出す）。上限は `CHAT_TITLE_MAX`。
- 右クリックのメニューの項目は `ChatMenuItems` 1 つ（開く（タブでは出さない）・名前を変更・既読 / 未読・固定・セッション ID をコピー・プロジェクトを変更・アーカイブ・削除。場所だけの項目は `before` / `after`）。サイドバーの行・ボードのカードは `ChatMenu`、パネルのタブは `TabMenu` から使う。
- 「プロジェクトを変更」は乗せる・押す・→ で項目の横に `ProjectPickFlyout`（`features/project/CLAUDE.md`）を開き、確かめてから `api.moveChat`（グループ・作業場所・ブランチは外れ、作業場所は移した先の本体。並び順は変えない。作業中は 409。会話は resume で続く）。いま開いているチャットを移したら、移した先で開き直す。移したチャットはチャットの店の知らせで元の一覧から外れる。
- チャットのタブの ✕ は `closeChatWithChoice`（表示だけ消す・アーカイブ・削除を選んでから閉じる。既定は `CHAT_CLOSE_ACTION`（`ask` / `close` / `archive` / `delete`）で、設定の「チャット」と、聞いたときの「次からはこれにする」で変える。アーカイブ・削除は既定にしても毎回確かめる）。Esc・タブのメニューの「閉じる」は聞かずに閉じる。

## 1 つのチャットの画面（`pane/`）

- `ChatPane` が中身を読み（`useChatDetail`）、読めたら `ChatView`（チャットごとに作り直す）を描く。状態と操作は `useChatView`、`ChatView` は描くだけ。チャットはいつもパネルのタブの中に開く。`ChatView` は自分の中身（見出し・流れ・チャット欄）を右の欄の殻 `AgentSplit`（`features/panel/CLAUDE.md`）で包み、右にサブエージェントの画面を並べられる（同じ context の中なので、右の欄の中身も記録・操作をそのまま使う）。
- `useChatDetail` はチャット・記録・回答待ち・作業中の様子（`ChatLive`。送信待ち・裏の作業・再試行・再接続待ち・圧縮中・停止中）を読み、SSE で追う（作業中の様子は `chat_live` で丸ごと置き換え、中身の変わらない部分は前のものを使う `keepUnchanged`）。読み込みの最中に届いた知らせは届いた中身にもう一度当て、SSE をつなぎ直したら取り直す（決まりは純粋関数の `chatDetail.ts`）。別のプロジェクトへ移しても読み直さない。
- 子の部品（流れの項目・ピル・送信待ち・検索・質問のカード・動きなど）への操作は `ChatPaneContext`（`ChatPaneActions`: `revealSubagent` / `openSubagent`（設定の開き方で開く）/ `openSubagentSide`（右の欄に開く）/ `openSubagentWindow`（別ウィンドウで開く）/ `canOpenSide` / `toggleSubagent` / `toggleSubagentFull` / `tellSubagent` / `closeTell` / `show` / `revealInConversation` / `rewind` / `restoreFiles` / `retry` / `jumpTo` / `reveal` / `stepPrompt` / `fillComposer` / `focusComposer` / `askInNewChat`）1 つで配る。props で中継しない・クラス名で DOM を探さない。`ChatView` がチャットごとに 1 回だけ作り、描き直しても同じもの（memo した項目を描き直させない）。変わる様子（失敗した作業の直し方・開いているサブエージェントのカード `openSubagents`・高さの制限を外したカード `fullSubagents`・会話か動きか `showing`・動きの絞り込み `activityFilter`・「伝える」の入力欄を開いているカード `tellOpen`）は `state` に置き、`useChatPaneState` で読む（保存しない。チャットを開き直すと会話から）。画面の外でも描く部品（発言・ツールのまとまり・サブエージェントのカード）は `useOptionalChatPane`（外では書き直し・再試行・カードの開閉を出さない）。
- チャットのキー（⌘↓・⌘⌥↑ / ↓・⌃R・⌘F）は `useChatHotkey`（`chatHotkeys.ts`）で、ピントがそのチャットにあるときだけ受け取る（⌘F は、どこにもピントがなく最後に押したのがそのチャットのときも）。隠れているタブ・閉じたパネルのチャットでは受け取らない。捕捉で先に受け取り、アプリ全体の ⌘F・縦スライドのプロジェクトの切り替えより優先する。

### 見出し

- `ChatHeader` にはプロジェクト・作業場所・グループのバッジ（`ProjectChip`・`WorktreeChip`・`.chat-group-chip`。グループの札はそのグループの色 `ChatGroup.hue`（タブの札・グループ別のまとまりと同じ色））と、右に道具・ターン数と API 換算、右端に右の欄の開閉（`features/panel/agents/AgentPanelToggle`。アイコンは右の欄の閉じるボタンと同じ形で、開いているときは閉じる向き `PanelRightClose`・閉じているときは開く向き `PanelRightOpen`。開いているときはアクセントの色。タブがなければ空の欄の案内を出す。右の欄を置けない画面（子チャットの画面の中など。`canOpenSide`）では出さない）を出す。名前・閉じる・状態の印はタブにあるので出さない（名前はタブのダブルクリックで変える）。確かめずにアーカイブするボタンは置かない。見出しはパネルのタブの列の下にあり、ウィンドウの上端ではないので、ウィンドウのドラッグ領域にしない（ドラッグ領域では右クリックが画面に届かない）。
- 右の道具（`ChatHeaderTools`）は左から、会話 / 動きの切り替え（`.chat-show-toggle`。下の「動き」。狭い見出しではアイコンだけ）・文の幅（`TextWidthToggle`。動きの幅にも効く）・会話の文字の大きさ（`ChatFontSizeButton`。押すと 5 段階のメニュー）・上に貼り付ける指示の表示（`.chat-sticky-toggle`。出しているときはアクセントの色。`STICKY_PROMPT_HIDDEN` で設定の「表示」と共通）・チャットの中の検索欄（`ChatFind`）。指示の表示と検索欄は会話だけに効くので、動きを見せている間は出さない。
- 見出しの表示（`ChatDisplayMenu.tsx` の `ChatDisplayItems`。タブの列の「表示」のメニューの「チャットの画面（どのチャットでも共通）」と、見出しの何もないところの右クリックで同じもの）: 見出しの行（`CHAT_HEADER_ROW_HIDDEN`。⌥⌘T（Finder・Safari の「ツールバーを隠す」と同じキー。`app/shortcuts.ts`）・設定の「表示」→「チャットの見出し」でも切り替える）・見出しの項目（横に開く子のメニュー `MenuFlyout`。バッジ = プロジェクト・作業場所・グループ / 道具 = 会話 / 動き・文の幅・会話の文字の大きさ・指示の帯の表示・検索欄 / 数 = ターン数・API 換算 / 右の欄 = 右の欄の開閉を、閉じずに続けて切り替える。項目は `chatHeaderItems.ts` の `CHAT_HEADER_ITEMS`、覚えるのは隠した項目だけ `CHAT_HEADER_HIDDEN`（初めはすべて出す）。何か隠していれば「すべて表示する」）・指示の帯・会話の文字の大きさ（横に開く子のメニュー）・文の幅を広げる・チャット欄をコンパクトに。切り替えを見出しの外（タブの列）に置くのは、見出しを隠しても戻せるようにするため。何か隠していれば「表示」のボタンに点（`useChatDisplayHides`）。
- 見出しの行を隠したとき（`.chat-header.collapsed`。高さを持たない）: 動きを見ている間（会話へ戻れるように）とアーカイブ済みのチャット（気づけるように）は出す。会話 / 動きはタブの右クリックの「動きを見る / 会話に戻る」でも切り替える。検索欄を見出しに出していないとき（行・項目を隠した）は、⌘F でチャットの右上（見出しのすぐ下）に浮かせて出す（`ChatFind` の `floating`。下の会話は動かさない。ピントが入っている・文が残っている間だけ出し、ふだんはピントを受けられるよう描いたまま見えなくする）。バッジの中身はタブに乗せたときの説明、ターン数と API 換算はチャット欄のメーターのポップオーバーにも出す。
- 会話の文字の大きさ（極小・小・標準・大・特大。Chrome の文字サイズの言い方にそろえる。本文がおよそ 12 / 13 / 14 / 16 / 18px。`chatFontSize.ts` の `CHAT_FONT_SIZE`、どのチャットでも同じ。見出しの行のボタン・タブの列の「表示」・設定の「表示」で選ぶ）: 会話に出るもの（発言・返答・ツール・サブエージェントのカード・承認と質問のカード・動き）の文字だけを変え、見出し・入力欄・ピル・メニューは変えない。App が `useApplyChatFontSize` で `<html>` に倍率 `--chat-font-scale` を与え、会話の入れ物（`.timeline-wrap`・`.activity`・`.subagent-screen-scroll`）が `--chat-scale` にして、会話の CSS の文字の大きさ・行の高さ（`calc(… * var(--chat-scale, 1))`）にかける（入れ物の外では 1 のまま）。会話に出る部品の CSS で文字の大きさを足すときは、同じ書き方にする。
- 文の幅（標準 / 広げる。`CHAT_WIDE`・`useWideText`、設定の「表示」→「チャットの文の幅」と共通）はパネルの大きさを変えず、発言の流れ・チャット欄・上に貼り付ける指示の幅の上限（820px）を外す（`.chat-page.wide`。`messages.css` の末尾）。パネルの「横幅いっぱい」と見分けられるよう、呼び名は「文の幅を広げる / 文の幅を標準に戻す」、アイコンは標準のときは外向きの ↔（`MoveHorizontal`）、広げているときは内向きの → ←（`createLucideIcon` で作った `MoveHorizontalIn`）にし、パネルの `UnfoldHorizontal` / `FoldHorizontal` と形を分ける。パネルが上限より狭いときは押しても変わらないので、押せなくして「パネルが狭いため変わりません」と出す（幅は `ResizeObserver` で測り直す）。

## 流れ（`timeline/`）

- 組み立ては `timelineItems.ts` の `groupEvents`（連続するツールの実行を 1 つのまとまりにし、結果は呼び出しにぶら下げる。サブエージェントの起動（Agent / Task）はまとまりに入れずカードの項目 `subagent` にし、裏で動かしたものが終わったら、起動した流れのその時刻の位置に `subagentEnd`（1 行）。`scope` を渡すとそのサブエージェントの中身（行のキーと再開した回の呼び出し ID）。作業の終わりの項目に `turnStart`・`turnText`・`turnChanges` を付ける。終わった作業の分は作業の終わりの記録ごとに覚え、配列を作り直さない）。描くのは `ChatTimeline`（スクロール `useTimelineScroll`・上に貼り付ける指示 `useStickyPrompt`・作業中の文 `useWorkingStatus`・流れの終わり `TimelineEnd`）と `Timeline.tsx`（項目は memo）。
- 窓: 描くのは最近の項目だけ（`timelineWindow.ts` の `TIMELINE_WINDOW`（120）と `useTimelineWindow`）。上の端に近づく（画面の高さの 1.5 倍の手前。端に着いてから足すとトラックパッドの慣性が端で止まる）・「以前の発言を表示」で前を足し、読んでいた位置はブラウザのスクロールアンカーに任せる（合っていないときだけ JS で直す。書き換えると慣性のスクロールが止まる。一番下にいるときは足さない）。一番下へ戻った・一番下で新しい項目が届いたら元の大きさに戻す。窓は大きさが一定のまま進むので、新しい発言の見分けは項目の数ではなく最後の項目のキーで行う。
- 検索結果から開いた発言・指示の履歴から移る先が窓の外なら、その前後を描く範囲にしてから移る（`revealRange`。最新まで `MAX_TAIL`（400）件以内なら最新まで、遠ければ途中の一部分だけを描き、下の端・「以降の発言を表示」で後ろを足し、一番下へ戻るボタン・⌘↓ で最新の窓に戻す `latest`）。途中を描いている間は、書いている途中の返答・確認のカード・作業中の行を出さない。
- スクロールの持ち主は `useTimelineScrollHandle`（`following` = 一番下に付いていくか。送った・一番下へ戻ったら付き、上へスクロールした・発言へ移ったら離れる。`BOTTOM_SLACK_PX`）。発言へ移って強調するのは `jumpToEvent`（`#ev-<記録の ID>` の要素か、その呼び出しを含むツールのまとまり（`data-tool-ids`）。`scrollIntoView` なのでサブエージェントのカードの窓の中にも届く。`.flash`（ツールのまとまりは `.tool-group.flash` の枠）。色はアクセントの緑で、薄れて消える。黄は検索で見つかった文字と注意の色なので使わない）。移ったら流れにピントを置く。
- 一番下へ戻るボタン（`ScrollBottomPill`。⌘↓ でも戻る）: 上を読んでいる間だけ出し、いまの状態を添える（決め方は純粋関数の `scrollPill.ts` の `scrollPillOf`: 答えを待っている → つながるのを待っている（黄）→ 上を読んでいる間に返答が届いた・失敗した → 作業中（作業中の行と同じ文。再試行中は黄）→ 終わっている）。待っているとき・返答が届いたときは目立たせる。枠はサイドバー・カンバンの状態の点と同じ色そのもの（作業中 `--dot-running`・回答待ち `--dot-needs-input`・未読 `--dot-unread`。終わっているときだけ控えめな灰色）。置き場所はチャット欄の上のピルの列（`.composer-chips`）の右端の `.composer-chips-dock`（`ChatPane` が `pillDock` で渡し、`createPortal` で置く。高さはピルと同じ 26px）で、ピルがない・ピルの幅の合計とボタンの幅が列に入らないときは流れの右下に浮かせる（列を 1 行増やすと流れの高さが変わって画面が動くため。入るかは置き場所によらない幅で決めるので行き来しない。幅は `ResizeObserver`、ピルの増減は `MutationObserver` で測り直す。置き場所が空のときは `:has()` で列ごと隠す）。

## 発言（`messages/`）

- 自分の発言は `UserMessage`（長文の折りたたみ「もっと見る / たたむ」・時刻 `formatMessageTime`（乗せると年月日）・コピー・書き直し。右クリックでも同じ操作）、AI の返答は `AssistantMessage`。右クリックは `useMessageMenu`（「メッセージをコピー」。返答は書式付き `copyRich`（Markdown を HTML にし、text/html と text/plain（Markdown のまま）の両方を入れる。貼る先が書式を受け取れれば見出し・表・コードのまま。文中の HTML は文字として書く）で、「Markdown のままコピー」も並べる。自分の発言は文のまま。リンク・コードブロックの上でもこの 1 つにそろえる。チャットの画面の中では「メモに追加」の項目 `MemoMenuItems` も並べる。`features/memo/CLAUDE.md`）。作業の終わりの行には「返答をコピー」（書式付き）と「ここから分岐」（`api.forkChat`。止めた・失敗した作業の終わりからは分岐できない）。
- 書き直しは吹き出しの中の `BubbleEditor` で直して送り直す（その発言から後ろを消して巻き戻す。`ChatPaneActions.rewind` → `api.rewindChat`）。その発言のあとに AI が変えたファイルがあれば「会話だけ戻して送り直す / ファイルも戻して送り直す」を選ぶ（`rewind/rewindActions.ts` の `confirmRewindSend`）。ファイルだけ戻すのは吹き出しの下・右クリックの「ファイルをこの発言の前に戻す」（`restoreFilesBefore`。戻すファイルと「戻すと +a −b 行」を見せて確かめる。`api.rewindFiles` を先に dry run）。戻るのは Claude Code の編集のツールで変えたファイルだけ（コマンド・アプリの外で変えたものは戻らない）。書き直し・ファイルを戻すのはチャットの画面の中だけで、作業中はできない。
- 自分の発言に、届かなかったサブエージェントの報告を添えたときは、吹き出しの下に「サブエージェントの報告 n 件を添えました」（記録の `handover`）。
- AI からの質問に答えた内容は `QuestionAnswerMessage`（自分の発言と同じ吹き出しに「質問への回答」と添え、質問ごとに質問の文と答え・添付を並べる。スキップは「質問をスキップしました」）。
- 選んだ範囲へのコメント（`SelectionComment`）: AI の返答 1 つの中で文を選ぶ・右の欄の「変更」の 1 つのファイルの差分の行を選ぶと上に「コメント」のボタン、押すとコメントの欄。「入力欄に添える」（Enter）で、選んだ文の引用（`> …`）とコメントをチャット欄の文の後ろに空行を挟んで足す（`quoteComment.ts` の `quoteComment` / `appendBlock`、足すのは `fillComposer` の `append`）。差分の行は「`パス` の 12〜15 行目（変更後）:」とコードのブロックで引用する（`quoteCode`。変更後の行を選んでいれば変更後だけ、なければ変更前。行の番号と側は差分の表のセルの `data-no` / `data-side`）。何件か書いてから、まとめて送れる。送るのは自分で。選んだ範囲の見つけ方と足す先を渡せる部品は `SelectionCommentBox`（別ウィンドウでは、メインのウィンドウのチャット欄に知らせる）。別ウィンドウからの知らせ（チャット欄に足す・会話のその場所へ移る・動きを開く）は `ChatView` が `windowMessages.ts` の `useWindowMessagesFor` で受け取る（`features/popout/CLAUDE.md`）。

## ツール（`tools/`）

- ツールの呼び出しは人が読める文にする（`toolDescribe.ts`。「ToDo を追加: 確認 1」。生の JSON を出さない。承認カードは `describeApprovalInput`）。まとまりと 1 件は `ToolGroup`（閉じた状態の要約は `summarizeTools`: 「2個のファイルを編集 および 3個のコマンドを実行」。で、分類できないものだけ「その他」）。サブエージェントの起動はまとまりに入れず、流れの中のカード（`subagents/`）。
- 状態のアイコン（`ToolStatusIcon`。決め方は純粋関数の `toolStatus.ts`）: 1 件の行の左端と、まとまりの開閉の矢印の右（「> ✓ 2個のコマンドを実行」）に、実行中 = 回る印・完了 = 緑の ✓・失敗 = 赤の ✕・中断（結果が届かないまま終わった）= 灰色の −。1 件は `callStatus`（結果があれば `is_error` で完了か失敗、なければ実行中か中断）、まとまりは `groupStatus`（実行中 → 失敗 → 中断 → 完了の順）。乗せると状態の名前。
- 時刻（`ToolTime`。数え方は純粋関数の `toolTimes.ts`）: 1 件は行の右に「始めた時刻 · かかった時間」（実行中は経過時間）。まとまりの見出しは要約の後ろに、実行中は「最初に始めた時刻 – 最後に始めた時刻」、終われば「最初に始めた時刻 – 最後に終わった時刻 · ◯時間◯分◯秒」（1 件の行の「始めた時刻 · かかった時間」と同じ形。`formatStampRangeWithRunTime`。実行時間は、並べた開始と終了の時刻の差 `formatStampRunTime`（秒より下を切り捨てた時刻どうし。実際の長さを切り捨てると「13:27:37 – 13:27:38 · 0秒」のように時刻と合わなかった）を `formatRunTime` で、いちばん大きい単位から下をすべて出す。時刻が 1 つだけのときは添えない）。思考の行は考え始めた時刻（記録は考え終えたときに残るので、かかった時間を引く）。書式は `lib/time.ts` の `formatStamp` / `formatStampRange`（秒まで。今日は時刻だけ、別の日は日付も、日をまたいだ範囲は終わりにも日付）、乗せると年月日（`formatFullStamp`）とかかった時間。実行中として見せるのは、作業中のチャットのいまの作業（最後の作業の終わりより後。過去の一部分を描いている間はなし）の、結果の届いていない呼び出しだけ（前の作業で中断したまま結果のないものは実行中にしない）。
- 実行中のコマンドの出力（`CommandLive`）: コアが Claude Code の出力ファイルを読んで送る SSE の `chat_command_output`（最後の 40 行。保存しない）を、呼び出し ID・作業 ID ごとの店 `commandOutputs.ts`（`useCommandOutput` / `useTaskOutput`。`useSyncExternalStore` でキーごとに購読し、届いたコマンドの部品だけを描き直す）に入れ、実行中のまとまりの下に枠で流す（閉じていても見える。いちばん下に付いていき、上へ戻したら止まる）。終わると消え、結果は今までどおり `BashOutput`。裏で動いているコマンドは、裏の作業の一覧の行に最後の 1 行（乗せると最後の 10 行）。
- コマンドの出力は `BashOutput`（上の「コマンド」の欄（「$ コマンド」。沈んだ地）と下の「出力」の欄を、見出しと境目の線で分け、それぞれの欄の中でスクロールする。長いコマンド・heredoc と出力の境目が分からなかったため。失敗したら終了コードを出力の見出しの右に赤で。終了コードは `bashResult.ts`。結果が届くまでは出力の欄を出さない）。コマンドはシェルの文法で色を付け（`HighlightedCode` の `shellscript`。heredoc の本文は、言語が分かればその言語で）、出力は色を付けない。色付けは、その呼び出しを一度開いてから始める（`ToolItem` の `opened`。閉じたままの呼び出しが多くても重くしない）。まとまりを開いて見える一覧の 1 行のコマンドにも同じく色を付ける（`ToolGroup` の `opened` → `listed`。改行は空白に見え、長いものは「…」で切る。色付けの結果は開いた欄と共有）。
- ターンの変更カード（`TurnChanges`）: 作業の終わりの行の上に、その作業で変えたファイル（「3 個のファイルを変更 +7 −1」）。開くとファイルの一覧で、押すと `FileLinkContext` の `open` で右の欄に開く（下の「返答のファイルのチップ」と同じ開き方。⌘クリックはファイルタブ・右クリックはファイルのメニュー）。見出しの「差分を見る」は、右の欄の変更のタブを、この作業で変えた最初のファイルの位置で開く（`openChanges`）。作業場所の外のファイルは押せない行。ファイルを変えるツール（Edit・MultiEdit・Write）の行のファイル名も、同じく押して開ける（`ToolGroup` の `ToolFileArg`。行の開閉はしない）。数え方は純粋関数の `turnFileChanges.ts`（`changesOf` / `lineDelta`。Edit・MultiEdit は置き換えの前後を最長共通部分列で比べ、Write は「新規」「書き直し」（書き直しは足した行だけ）、NotebookEdit は足した行。失敗した・結果がまだないものは数えない。サブエージェントの変更も含める）。

## 作業中の様子（`status/`）

- 作業中の行の文は `workingLabel`（止めている・通信を再試行している・会話を圧縮している・返答を書いている・ツールを実行中・考えている）で、作業中の行と一番下へ戻るボタンの両方に使う（`useWorkingStatus` が 1 回だけ組み立てる）。返答を書き終えて裏の作業を待っているときは「返答は終わりました。裏で動いているサブエージェント 1 件（調査）とコマンド 1 件（npm run dev）の終わりを待っています」（`backgroundLabel.ts`）。
- 本当に動いているかは、最後に何かが届いた時刻で見る（Claude Code に問い合わせる手段はない。`stall.ts` の `activityOf` / `activityText`）。1 分静かなら「最後の動き n 分前」、`STALL_MS`（10 分）動きがなければ「n 分動きがありません（Bash の結果待ち）」と注意の色（`.activity-stalled`）。作業中の行は記録・書いている途中の返答・実行中のサブエージェントのいちばん新しい時刻、サブエージェントは中の発言・ツール・知らせ（`lastActivityAt` / `pendingTool`）と途中経過の時刻で決め、作業中は `useTicker` で描き直す。長く動きのないサブエージェントは作業中の行（「サブエージェント『調査』が 12 分動いていません」）・ピル（「n 件動きなし」）・一覧の行・カードで知らせる（子孫が動いている間は、待っている祖先を動きなしにしない）。
- 裏で動いている作業の一覧（`BackgroundTasks`。作業中の行の下）は 1 件ずつ止められる（`api.stopBackgroundTask`。チャット全体は止めない。サブエージェントは報告が届かなくなるので確かめる）。サブエージェントは名前を押すと設定の開き方（流れの中のカード / 右の欄）で開き、最後の動きを添える（作業 ID で一覧の行と結びつける）。
- 中断は、裏で動いているサブエージェント・コマンドも止まることを確かめてから（`confirmStopAgents`。止めると Claude Code のプロセスごと終わる）。止めるよう頼んでから終わるまでは停止中（`ChatLive.stopping`）で、停止ボタンを回る印にして押せなくし（Esc でも止め直さない）、横に「停止中…」を出す。
- 通信が切れて再試行している間は作業中の行・一番下へ戻るボタンに「接続が切れています。再試行 n/m」（`RetryLabel`。動いていたサブエージェントも止まっている可能性を添える）。再試行しきって、つながるのを待っている間は作業中の行の代わりに `ReconnectRow`（通信で止まったサブエージェントも続きから再開することを添える `reconnectLabel`。「自動で再開しない」で `api.stopReconnect`）。何度再開しても続かなかったとき・使用枠の上限で止まって枠が戻ったときは、承認と同じ回答待ちのカード（`ReconnectCard`）で続けるかを聞く。
- 会話の圧縮中（`ChatLive.compacting`。始めた時刻ときっかけ `trigger`）は、作業中の行の代わりに圧縮中の行 `CompactingRow`（ふだんの灰色の 1 行と見分けがつくよう、アクセントの色の枠と薄い地に、見出し・始めた時刻と経過・きっかけの説明。圧縮は数十秒〜数分かかり、その間は返答もツールも動かないので、止まったと思わせないため）を出す。見出しは `compactingLabel`（自動のときは「会話を自動で圧縮しています」と、コンテキストが上限に近づいたため・終われば作業を続けると添える。手で圧縮したときは「会話を圧縮しています」）で、一番下へ戻るボタンも同じ文。チャット欄の丸いメーター（`ContextMeter`）は短い弧を文字のアクセントの色（`--accent-fg`。ダークの `--accent` は暗くて回っているのが見えなかった）で回す（使用率が高いと弧がほぼ一周で、回しても分かりにくいため）。メーターのポップオーバーの「会話を圧縮」を押したら、ポップオーバーを閉じて弧と圧縮中の行で知らせる（始められなかったときだけ開き直して失敗の文を見せる）。作業中は「このやり取りのあとで圧縮」になり、押すと予約する（いまのやり取りが終わったら、送信待ちより先にすぐ圧縮が始まる。コアの `compact_next`）。予約している間は、ポップオーバーに「このやり取りが終わったら圧縮します」と「取り消す」、作業中の行の下に点線の枠の `CompactNextRow`（「このやり取りが終わったら、すぐに会話を圧縮します」と「取り消す」。`api.cancelCompact`）を出す。始まると圧縮中の行に変わる。終わると、同じ枠の見た目のまま記録の行 `CompactedRow`（`compact` の記録。「会話を圧縮しました / 会話を自動で圧縮しました」・始めた時刻 – 終わった時刻 · かかった時間・要約の前後のトークン数。始めた時刻は記録の時刻からかかった時間 `duration_ms` を引いて出し、なければ終わった時刻だけ）が流れに残る。
- ToDo はチャット欄の上のピル（`TodoChip`。「ToDo 2/5」。押すと一覧。組み立ては `todoList.ts` の `collectTodoList`: TodoWrite は毎回すべて、TaskCreate / TaskUpdate は 1 件ずつ。最後に一覧が変わった記録 `changedAt` も持つ）。サブエージェントのような 1 件ずつのアーカイブは持たない（ToDo はいまの計画の一覧が 1 つあるだけで、増えて困るのではなく、終わった一覧が残り続けるのが困るため）。出し方は `todoVisibility`: すべて完了したら「✓ ToDo 5/5」と控えめにし（`.todo-chip.finished`）、そのあと自分が次の指示を送ったら前の作業の一覧として隠す。一覧の下の「この一覧を隠す」で手でも隠せる（チャットごとの `todoHidden` に一覧の印 `todoSignature` を覚え、一覧が書き換わったらまた出す）。

## 失敗した作業の直す操作（`rewind/`）

いちばん新しい作業が失敗で終わったとき（そのあと発言していない。通信の切断・使用枠の上限はそれぞれの仕組みに任せて除く。`retryActions.ts` の `failedTurnOf`）、終わりの行の下に `FailedTurnActions` を並べる: 続きから再試行（`RETRY_PROMPT` をいまの選択で送る `retryTurn`）・深さを下げて再試行（`lowerEffort`。そのモデルで選べる中で 1 段下げる。決まっていなければ既定の深さから、既定も分からなければ中。最も低ければ出さない）・別のモデルで再試行（モデルの一覧のメニュー。下に収まらなければボタンの上に開く。新しいモデルで選べない深さは指定しないにする）・巻き戻して再試行（その作業を始めた発言から、同じ文で送り直す。確かめは巻き戻しと同じ）。深さ・モデルを変えたときはチャット欄の選択も同じに変える。選択肢は `useRetryChoices` が作り（モデルの一覧はあとから届くので、届いたら作り直す）、`ChatPaneState.retry` に入れる。

## チャット欄（`composer/`・`options/`・`attachments/`）

- 上から、流れ → 同じ作業場所で作業中のほかのチャットの知らせ（`.composer-notice`。注意の色と ⚠。`useBusyNeighbors`。押して開くピルの列に混ぜない）→ チャットの情報のピル（`.composer-chips`。指示の履歴・ToDo・サブエージェント・一番下へ戻るボタンの置き場所）→ 送信待ち（次に送るもの）→ 入力欄（いま書いているもの）の順（`ChatComposerArea`）。ピルは `ComposerChip`（押すと上に一覧を開き、もう一度押す・外を押す・Esc で閉じる。`.chip-wrap` / `.chip-popover`）。
- `Composer`: Enter で送信・Shift+Enter で改行。送る処理は `useComposerSend`（アップロードの途中・送っている途中は送らない。送る前の確かめでやめたら `SendCancelled`）、右下の操作（中断・送信・送り方の切り替え・メーター）は `ComposerActions`。外から動かす口は `handleRef`（`ComposerHandle` の `fill` / `focus`。`fill` の `append`・`attachments`・`focus: false`）。既存のチャットの書きかけの文は `chatDraft(chatId)` に残す。
- 高さは CSS で伸ばす（`composer.css` の `.composer textarea` の `field-sizing: content` と `max-height: 240px`。空なら 1 行、上限を超えたら中でスクロール）。コンパクト表示（`COMPOSER_COMPACT`。設定の「表示」→「チャット欄」）は `Composer` に `compact` のクラスを付けて文字・余白・下の道具を小さくする（`composer.css` の末尾。後ろのファイルの送信ボタンなどには `.composer.compact` で詳細度で勝たせる）。
- よく使うキー（`composerKeys.ts`）: 作業中の Esc を 2 回で中断（1 回目は中断ボタンの横に「もう一度 Esc で中断」`.composer-stop-hint` を 2 秒出すだけ。Esc はパネルを閉じるのにも使うので、うっかり止めないため。作業中でなければパネルを閉じる Esc に任せる）・入力欄の Shift+Tab で権限モードを順に切り替える（`permissionChoices` のうち、そのモデルで選べるもの）・⌘L でチャット欄にピントを移す（`focusChatComposer`。ピントのあるパネル → ピントのあるペイン → 見えている最初のチャット欄の順。`app/shortcuts.ts` から呼ぶ）。録音中の Esc・候補の一覧の Esc など、先に扱ったキーは見ない。入力欄が空のときの ↑↓ は前に送った自分の発言を呼び出す（`usePromptHistory`。判定は `prompts/promptHistory.ts` の `historyMove`）。
- `/` と `@`: `suggestTarget`（作業場所）を渡すと出る（`suggest/` の `useSuggest` ＋ `SuggestList`、照らし合わせは `suggestMatch.ts`）。`/` は文の先頭で Claude Code のコマンド・スキル（ターミナル専用のものはコアが除く）、`@` は作業場所のファイル。↑↓・Enter / Tab・Esc。一覧はキーごとの店で持つ。
- モデル・推論の深さ・権限モード・ファストモードは入力欄の下の `ChatOptionsBar`（状態は `useChatOptions`）。新しいチャットはプロジェクトの既定（なければ設定の既定。`withDefaults`）から始まり、ここでの変更はそのチャットだけに効く。新しいチャットでプロジェクトを替えたら、そのプロジェクトの既定に当て直す。既存のチャットはそのチャットの選択から始める。深さを指定しないときは、Claude Code が実際に使う深さを「既定（最大）」のように添える（どこにもなければ「既定（モデル任せ）」。`api.effortDefault`）。選択肢の部品は `ModelOptions` / `EffortOptions` / `PermissionOptions`、選べる値は `options/models.ts` の `effortsFor` / `permissionChoices` / `groupModels`。
- 添付は `useComposerFiles`（📎 `AttachButton`・ドラッグ＆ドロップ・貼り付け。選んだ時点でアップロードし、送信を待たせない）。選んだばかりの添付は `PendingFileChips`（× で外す。チップの大きさは保存したあとの大きさ）、送った添付は `AttachmentChips`（画像は押すと大きく表示し、同じ発言の画像は ← / → で前後へ `viewerImagesOf`。画像以外はアプリの中でダウンロード）、1 行に収める添付は `AttachmentPeek`（1 つ目だけを小さく出し、2 つ以上なら数を重ね、押すと並べて表示 `AttachmentGrid`。送信待ちの行・上に貼り付ける指示の帯）。画像の右クリック（コピー・大きく表示・保存）は `useAttachmentViewer`。
- ほかのチャットを参照（`ChatContextButton`。📎 の隣。`Composer` の `chatContext` を渡したときだけ。既存のチャットと新しいチャットの両方）: 読ませるだけだと分かるよう「参照」と呼ぶ（「添付」は何が付くのか、「取り込む」はこのチャットに混ぜるように聞こえる）。一覧（見出し「参照するチャット」）はアーカイブ済みも含めて同じプロジェクトを先に最近動いた順、名前で絞り込み（`SearchField` の `onKeyDown` ＋ `useListNavigation`）。選ぶと `useComposerFiles` の `addChat` → `api.chatTranscript` で、そのチャットのやり取りを Markdown の添付ファイル（`チャット履歴-<チャット名>.md`。自分の発言・メインの AI の返答を古い順に、作業ごとに変えたファイルと失敗・中断を添える）にして添え、ほかの添付と同じく AI が Read で読む（送る指示は膨らまない）。

### 作業中の送り方（いま / あとで）

- 作業中に送るときの扱いは、チャット欄の切り替え（`QueueModeToggle`。左から「あとで」（リストのアイコン。送信待ちに足す）/「いま」（吹き出しのアイコン。いまのやり取りへ追加の指示として送る。送信待ちを止めているときは送信待ちより先に送る））。`QUEUE_MODE`（`queue` / `tell`）で、初めは「いま」。いつ送るかの対で短く見せ、「送信待ちに追加」「いまのやり取りに追加指示」のような長い言い方は説明（`Segmented` の `tip`。ショートカットは `keys`）に回す。押すと送られるボタンに見えないよう、送るの矢印は使わず、アイコンに文字を添えた切り替えにする（とても狭い欄（420px 以下）ではアイコンだけ）。見た目は隣の丸いボタンと同じ高さ 28px の丸いピルで、選んでいる方は一段明るい丸い地・選んでいない方は薄い文字（`styles/chat/queue-mode.css` の `.view-toggle.queue-mode`）。
- キーでも決められる（⌘Enter = いま・⌘⇧Enter = あとで。`sendModeOf` → `onQueue` の `mode`）。チャット欄で ⌘ / ⌘⇧ を押している間だけ、Enter で使われる方のボタンを選んでいる方とは別の青で光らせる（`heldMode`。`.busy-controls.held-tell` / `held-queue` と `Segmented` のボタンの `data-value`。選んでいる送り方は変えない）。
- 「いま」は作業を止めずにいまのやり取りに足す（`api.tellChat`。メインのエージェントがいまの手順の切れ目で読む。裏のサブエージェント・コマンドは動き続ける。足せないとき（順番待ち・要約中など）は待ちの列へ、作業中でなければすぐ送る）。止めたいときは停止を押す。
- 作業していなくても送信待ちが残っている（止めている）ときは、同じ切り替えを「すぐ送る / ためておく」として出す（`queueWhileIdle`。すぐ送る = 送信待ちより先にいま送る、ためておく = 送信待ちの最後に足す `api.queueMessage` の `hold`）。案内と送信ボタンの名前は `queueModeTexts`。

## 送信待ち（`queue/`）

作業中に送った次の指示の待ちの列（`QueuedMessages`）。いまの作業が終わったら（止めた・失敗したときも）先頭から順に送る。状態は `ChatLive.queue`（`QueueState`: `messages` / `paused` / `stops` / `waiting_edit`）で、変える API の応答も同じ形。操作の失敗は `queueFailed`（お知らせ）。

- 置き場所と見た目: ピルの列の下・入力欄のすぐ上。入力欄とは区切り線だけでつなげて 1 枚の枠に見せる（`queued.css` の `.queued-messages + .composer`。区切り線は 1px のまま、濃い色 `--divider-strong`。分割したペインのピントの色も両方に付ける）。
- 初めは畳んで 1 行にする（`QUEUE_COLLAPSED`。どのチャットでも同じ）。1 行には件数・止める位置などの短い案内・「次: 次に送る指示の初めの行」を出し、狭ければ「次:」から省く（`queuedHint.ts` の `queuedHint` / `nextQueuedText`）。止める予定（「1 件目のあとで一時停止」）は一時停止の線と同じ注意の色 `--warn` と同じアイコン（`OctagonPause`）で出す（`.queued-hint.stop`）。
- 見出し: `QueuedModeButton`（`queued-mode`。「自動で送る / 止めています」。チャットごとの `api.setQueuePaused`。止めておくと終わっても送らず、行の「すぐ送る」で 1 件ずつ送る。自動に戻すと、作業中でなければ先頭をすぐ送る。列が空になったら自動に戻る）、そのすぐ右の「一時停止」（`QueuedStopButton`。線と同じ注意の色 `.queued-add-stop`。押した結果ではなく、列に挟む物の名前で呼ぶ）で一時停止をいちばん上（位置 0）に挟む（たたんでいれば一覧を開いて線を見せる。1 件目の上にもう印があれば押せない）。件数のすぐ後ろ（左寄せ）に「すべて表示」（`QUEUE_EXPANDED`。一覧の見え方の操作なので、送る・消すと分ける）。右に、すべて送る（`SendAllMenu`。ボタンの上に開くメニューで「まとめて 1 件で送る」= 1 つの指示につなげていま送る `api.sendAllQueued`（作業中なら止めずに伝える）/「1 件ずつ順に送る」= 別々の指示として終わるたびに次を送る `api.sendQueuedInOrder`（止めておくのをやめ、印も外して最後まで送る））・すべて消す（2 件以上のとき）。
- 選ぶ: ⌘ / Shift ＋クリックで行を選ぶ（`useQueueSelection`。決まりは `useMultiSelect`、範囲は列の順。Esc でやめる）。選んでいるときは見出しの右に、並べ替え（いちばん上へ・いちばん下へ。`QueuedMoveActions`）｜ 書き直す・1 つにまとめる・まとめて送る・消す・選ぶのをやめる（`QueuedHeadActions`）。
- 1 つにまとめる（見出しと行の右クリック。2 件以上）: 送らずに 1 件にする（`api.mergeQueued`。選んだ順ではなく列の順に空行でつなぎ、添付も合わせ、選んだうちのいちばん上の位置に残す。印は `remapStops` で合わせる）。
- 一時停止の印（`QueuedStopLine`）: 指示に付けず、列の中の位置で持つ独立した行（0 = 1 件目の上、n = n 件目のあと。いくつでも置ける。前の指示を送った・消した・まとめた分だけ上に寄る）。自動で送る次の指示の上に印があれば送らずに止め（印は残る）、自動で送るに戻すとその印を越えて次の印まで送る。すべて送ったあとの印は、次に来た指示の前で止める。線は送信待ちの行と同じ扱いで動かす: 左のつまみのドラッグ・右の ↑↓（指示 1 件ぶん。書き直す・送るの位置は `.queued-stop-space` で空ける）・右クリック（いちばん上へ・1 つ上へ・1 つ下へ・いちばん下へ・外す）・ごみ箱で外す（どれも `api.setQueueStops` で丸ごと置き換え）。行の右クリックの「この指示のあとに一時停止を挟む / あとの一時停止を外す」は `api.setQueueStopAfter`、「この指示の前に…」は `api.setQueueStops`（1 件目では列のいちばん上）。純粋関数は `@shared/chat/queueStops.ts`（`normalizeStops` / `remapStops` / `moveToSlot`。コアの並べ替えと、画面の「動かすと変わるか」で共通）。
- 並べ替え: 指示を動かすときは、印の線を見た目の並びの 1 行として扱い、動かした指示だけが線の上下を移る（動かしていない指示は線の同じ側に残る）。いちばん上・下へ移しても 1 件目の上・いちばん下の線は端に残り、行の ↑↓ はすぐ隣が線なら並びを変えずに線だけを越える。ドラッグ（`useQueueDrag`）は落とす位置が線のすぐ上か下かで決める（行の上半分 = その行の前で上の線の下、下半分 = 後ろで下の線の上、線の上では上半分 = 線の上・下半分 = 線の下。見出しの行 `.queued-head-row` に落とすといちばん上 = 1 件目の上の線よりも上 `overTop`。落とす位置の線もその側に出す。`api.moveQueuedMany` の `belowStop`）。選んだ行のつまみをドラッグすると、選んだものを並びを保ったまままとめて動かす。入る位置の線は左端に丸を付け、一覧の上下の余白で端でも切らない。
- ドラッグの絵は、つかんだ行（線）の半透明の写しで、つかんだところがカーソルの下にあるまま付いて動く（`queueDragImage.ts` の `startQueueDragGhost`。ブラウザの既定の絵は透明にし、送信待ちの枠と同じ入れ物 `.queued-messages.queued-drag-ghost` に写した行を画面のいちばん上に重ねて `dragover` で動かす。透けるので下の入る位置の線も見える。まとめて動かすときは右上に「n 件」。もとの行は薄くする）。
- 行（`QueuedRow`）: つまみ・番号・添付（`AttachmentPeek`）・文・操作。右の操作は 2 つのまとまりに分けて縦線で区切る: 並べ替え `.queued-row-moves`（↑↓）｜ その指示への操作 `.queued-row-actions`（書き直す・送る・消す）。狭い欄では ↑↓ とボタンの文字を隠す（右クリックに同じ操作）。文は選んでコピーでき、ダブルクリックで書き直す。右クリックのメニューは、書き直す → 送る → 止める（前・あと）→ 並べ替え（「いちばん上へ移動」「1 つ上へ移動」など）→ 新しいチャットへ → 消す（「送信待ちから消す」）の順に区切り線で分ける（行が画面の下にあるので、メニューは測って上へ寄る）。選んでいる行の右クリックは、選んだもの全体への操作になる。
- 新しいチャットで聞く（送信待ちに残す）/ 新しいチャットに移す（送信待ちから外す）: 文（列の順に空行でつなぐ）と添付（アップロード済みのものをそのまま）を新しいチャットのタブの入力欄に入れて開く（`askInNewChat.ts` の `seedOf` / `useAskInNewChat` → `ChatPaneActions.askInNewChat`。パネルの `openNew(target, seed)` でタブの `seed` になり、`NewChatPane` が `fill` の `attachments` で入れる）。作成先は元のチャットと同じプロジェクト・グループで、新しいチャットの見出しで選び直せる。送るのは自分で。
- 一覧の高さの上限は上端のつまみ `.queued-resizer` のドラッグで変え（`QUEUE_HEIGHT`、ダブルクリックで 5 件ほどに戻す）、書き直している行の高さの合計（画面の 6 割まで）より低くしない。
- 書き直す欄（`QueuedEditor`）はいくつでも同時に開ける（`useQueuedEdits`。指示ごとに書いている途中の文と添付を持ち、保存・やめるはその 1 件だけを閉じる。列から消えた指示の欄は閉じる。選んでいるときは見出しの「書き直す」・右クリックの「選んだ n 件を書き直す」でまとめて開く）。Enter で保存・⌘Enter で保存していま送る（`api.sendQueuedNow`。作業中なら止めずに伝える。欄の右の送るボタンも同じで、⌘ を押している間は青く光らせる `.queued-editor-send.held`）。折り返した行も含めて文の終わりまで見せる（`field-sizing: content`。画面の 4 割まで）。添付は × で外し、📎・貼り付け・ドラッグ＆ドロップで足せる（`useComposerFiles`・`PendingFileChips`。保存は `api.editQueued` の `attachments` で置き換え。アップロードの途中は保存しない）。
- 次に送る指示（1 件目）を書き直している間は、作業が終わっても自動で送らずに書き直しが終わる（保存・やめる・一覧をたたむ）のを待つ: 開いている欄の指示を `api.setQueueEditing` で丸ごと知らせ、開いている間は持ち時間 `EDIT_HOLD_TTL_MS`（20 秒）の 1/4 ごとに知らせ直す。画面を閉じた・落ちたときは持ち時間で外れて送る（勝手に止まったままにしない）。欄ごと消えた（チャットを閉じた・切り替えた）ときも外す。一覧をたたむと書き直しの欄を閉じ、書いている途中の文も捨てる（`discardAll`。見えないところで止め続けないため）。作業が終わって書き直しを待っているとき（`waiting_edit`）だけ、見出しの案内 1 か所に「次の指示の送信準備ができています。書き直しを保存すると送ります」とアクセントの色で伝える（`queuedHint` の `readyForEdit`）。

## サブエージェント（`subagents/`）

サブエージェントはパネルのタブにせず、メインのチャットの流れの中で見せる（どの依頼から起動し、いつ何をしているかを、メインのエージェントとのつながりのまま見るため。依頼を出すタブはメインのエージェントだけ）。別に、同じチャットの画面の右の欄に、メインと同じような画面で並べても見られる（下の「右の欄」。メインの左に置いたまま、階層とカードの印でつながりを見せる）。

- カード（`SubagentCard`）: Agent / Task の呼び出し 1 つが流れの中の 1 枚。閉じた状態でも、状態（実行中は回る印）・「サブエージェント」の札（そのサブエージェントの色。右の欄の画面の見出しと同じ `SubagentKind`。サブエージェントの中で起動したもの（入れ子）は頭に「↳」を付け、乗せると「『調査』の中で起動したサブエージェント」）・名前・種類・状態の文・開始〜終了（実行中は開始〜最後の動き。書式はツールと同じ `formatStampRange`、終わったものは実行時間も添える `formatStampRangeWithRunTime`）と、2 行目に、実行中なら「いま」いちばん新しい呼び出し（中で起動したサブエージェントのものは「洗い出し › コマンド: …」。`subagentTree.ts` の `latestActivity`）・最後の動きからの時間・トークン数、終わったものなら「完了 · ツール n 回 · トークン数 · かかった時間 · サブエージェント n 件」、右に操作（`SubagentActions`・「右の欄で開く」（設定が右の欄のときは「流れの中で開く / 閉じる」）・「動きで見る」（そのサブエージェントに絞った動き）・「伝える」）。見出しを押す・Enter では、設定の開き方（`SUBAGENT_OPEN_IN`。流れの中 / 右の欄（初め）/ 別ウィンドウ）で開く: 別ウィンドウならそのサブエージェントの別ウィンドウ、流れの中なら開閉し、開くと親からの依頼（初めは 1 行にたたむ）→ そのサブエージェントの手順（`groupEvents(events, scopeOf(entry))`。時刻付きのツールのまとまり・返答・入れ子のカード・実行中の行）→ 親への報告を、左の縦線で字下げして出す。右の欄なら右の欄にその画面を開く。右の欄で表示しているカードには「右の欄で表示中」と添える（`useShownInAgentPanel`）。閉じているカードの下には、中で起動したサブエージェントを木の枝の形で 1 行ずつ並べる（`SubagentChildRows`。「└ ✳ 洗い出し 完了 · 50秒」。枝はその子の色、実行中は最後のツール、孫がいれば「中に n 件」。3 件まで出して「ほか n 件」。行を押すとその子を設定の開き方で開く。見出しの札「中に n 件」だけでは、中にサブエージェントがいると分かりにくかったため）。狭い欄でも名前を先に残し、時刻を縮め、入らない札はカードの幅（`@container`）で種類 → 「右の欄で表示中」→「サブエージェント」の文字の順に隠す（1 文字だけ残さない。入れ子の「↳」と子の色の点は残す）。
- 右の欄（サブエージェントの画面 `SubagentScreen`。チャットの画面の右の欄 `agents` のタブの中身）: 1 つのサブエージェントを、メインの会話と同じような画面で見る。上から、階層（「メイン › 調査 › 洗い出し」。メインは流れの中のそのカードへ、途中の階層はその画面をこの欄に開く）・見出し（「サブエージェント」の札（入れ子は「↳」）・名前・種類・中で起動したサブエージェントの札（`SubagentChildren`。子の色の点（実行中の子は明滅）と「中のサブエージェント n 件」。乗せると子の名前と状態、押すとこの画面の中の最初の子のカードへ）・状態・開始〜終了と、いまの動き / 終わったもののまとめ・操作（再開・やり直すなど `SubagentActions`・「流れで見る」・「動きで見る」）。そのサブエージェントの色で薄く染め、左に太めの帯。メインの見出しと見分け、どのサブエージェントかも色で分かるように）→ 親からの依頼 → 手順（メインと同じ `TimelineItems`。入れ子のカードもカードのまま出し、そのカードの「右の欄で開く」で別のタブ）→ 親への報告 → そのサブエージェントに伝える入力欄（カードの「伝える」と同じ `SubagentTellComposer`）。手順は画面いっぱいにスクロールし、実行中は最新に付いていく（`useFollowScroll`）。この画面ではサブエージェントの返答もメインの返答と同じ見た目（流れの中で付ける左の線と薄い文字を外す）。カードと共通の部品（時刻・いまの動き・まとめ・依頼・手順・報告・`useSubagentItems`）は `subagentParts.tsx`。いくつ開いても、右の欄の中で上下・左右に分けて並べられる（通常のパネルと同じ操作。`features/panel/CLAUDE.md`）。開くのは `ChatPaneActions.openSubagentSide(key, eventId?)`（その画面の中の記録へも移る `data-agent-screen`）、設定の開き方に従うのは `openSubagent`。
- 手順の窓（`SubagentWindow`）: いちばん外側のカードの手順は、流れの見えている高さ（`ChatTimeline` が CSS の `--timeline-h` に入れる）の半分ほどの、枠で囲んだ窓の中だけでスクロールする（長いサブエージェントでメインの会話が下へ押し流されないように。メインの配下の窓として見せる）。依頼は窓の上、報告は窓の下に置いていつも見せる。実行中は最新（いちばん下）に付いていき、中で上へ戻したら止まる（いちばん下へ戻せばまた付いていく。ターミナルと同じ。`hooks/useFollowScroll`。右の欄の画面と共通）。終わったものは上から。入れ子のカードは窓の中でふつうに開く（窓の中に窓を作ると、スクロールが何重にもなるため）。はみ出しているときだけ右下に「全体を表示」（高さの制限を外す。`ChatPaneState.fullSubagents`・`toggleSubagentFull`）。目次・裏の作業の一覧から移るとき（`revealSubagent`）は `scrollIntoView` で窓の中まで動く。
- 色と枝分かれ: サブエージェントの色は、メインが起動したもの（いちばん外側）に起動した順に決め、中で起動したもの（入れ子。孫・ひ孫も）はいちばん外側の祖先と同じ色にする（`agentHues.ts` の `agentHues`。どの仕事の配下かを色で見分けるため。外側どうしは続けて起動したものが似ないよう離れた色を交互に並べ、あとから足されても前の色は変えない。アーカイブで隠したものも含めた一覧全体から決める）。カードの左の端の細い帯・開いた中身の縦線・目次の点（`.agent-dot`）・動きの線で同じ色（CSS の `--agent-hue`。色そのものはテーマに合わせて `subagent-window.css` が決める）。メインの流れのカードは少し右へ寄せ、上から曲がって入る線（その色）で、メインから枝分かれした配下だと見せる。
- 入れ子: 中で起動したサブエージェントも同じカードとして中身の中に出す（地の色を交互にする）。ただし Claude Code は、サブエージェントの中で起動したサブエージェント（孫より深いもの）の中の手順を送ってこない（届くのは起動・終わりの知らせ・途中経過の最後のツール・ツールの回数・トークン数・報告）。そのカードの中身にはその旨を出し、親のカードの「いま」は子の途中経過（「内側の確認 › Glob」）にする。途中経過の時刻も祖先の「最後の動き」に伝える（`useSubagents` の `bubbleProgress`）。`FLAT_DEPTH`（3）段より深いものは字下げをやめ、見出しに外側からの道筋（「調査 › 洗い出し ›」）を添える。木は `subagentTree.ts`（`subagentTree` / `childrenOf` / `pathOf` / `flattenTree` / `scopeOf`）。
- カードが読むもの（チャット・作業中か・記録・木）は `SubagentsContext`（`ChatView` が配る。変わるとカードだけが描き直る）、開閉はチャットの画面の状態 `openSubagents`（`toggleSubagent`）。カードの中の流れは描く側（`TimelineItems`）から `renderItems` で渡す（流れの部品を読むと輪になるため）。
- 目次: チャット欄の上のピル `SubagentChip`（「サブエージェント N 件」）の一覧は、入れ子を親のすぐ下に字下げして並べ（`flattenTree`）、行の右に「会話内で開く」「右で開く」「新規ウィンドウで開く」のボタン（設定によらずその場所に。`composer/OpenPlaceControls.tsx` の `OpenPlaceButtons`。右の欄を置けない画面・別ウィンドウを開けないブラウザでは出さない）、一覧の上に「行を押したとき」の切り替え（`DefaultOpenPlace`。設定の `SUBAGENT_OPEN_IN` をここでも変える）。行を押すと設定の開き方で開く（`openSubagent`。流れの中なら `revealSubagent`: 外側のカードから自分まで開き、いちばん外側のカードを窓に入れ、開いた中身が描かれてから移って強調する。右の欄なら `openSubagentSide`）。裏の作業の一覧の名前・「やり直した回を見る」も同じ。裏で動いていて流れの上に流れていったカードにも、ここから戻れる。
- 裏で動かしたサブエージェントが終わったら、起動した流れのその時刻の位置に「裏で動かしたサブエージェント『…』が終わりました 時刻 開く」（`SubagentEndNote`。「開く」は設定の開き方）。
- 伝える: カードの「伝える」で、そのカードのいちばん下に入力欄を開く（`tellSubagent` → `tellOpen`。閉じているカードでも開き、すぐ書けるようにピントを置く。`SubagentTell.tsx` の `SubagentTellBox`）。チャット欄の宛先を切り替える作りはやめた（宛先を戻し忘れる・メインに送るつもりの文をサブエージェントに送りやすかったため）。入力欄は右の欄の画面と同じ `SubagentTellComposer`（チャット欄と同じ `Composer`。添付・音声入力も使える。書きかけの文はサブエージェントごとに `subagentTellDraft` に残し、カードと右の欄で共通）。Enter で送って閉じ、Esc・× でやめる（書きかけは残り、もう一度「伝える」で戻る。Esc はパネルを閉じる Esc に渡さない）。終わったサブエージェントでは、伝えると終わったところから再開することを案内に出す。開いている間に入力欄が流れの上へ流れていかないよう、開いたら一番下への付いていきを止める（`scroll.release`）。送ると、Kickoff から直接は送れないので、メインのエージェントに SendMessage でそのまま伝えてもらう（文の形は `@shared/chat/prompts.ts` の `relayMessage`、カードの流れには `relayedText` で自分の発言として混ぜる。`api.tellChat` で送り、メインが作業中なら止めずに伝える）。サブエージェントの ID が届いていなければ「伝える」を出さない（右の欄では送れない旨）。
- 一覧の組み立ては、コアと共有の `@shared/chat/subagents.ts`（`collectSubagents` / `subagentReport` と、コアの作業の終わりのお知らせ `unfinishedSubagents`・通信が戻ったときの再開 `networkStoppedSubagents` で同じ数え方にする）。表示名・状態の文だけ画面の `subagentList.ts`。行は作業 ID でまとめる（SendMessage で再開すると、知らせの呼び出し ID が再開を頼んだ SendMessage のものになるため）。報告の本文は `subagentReport`。裏で動かしたものは一覧から消えたら終わったとみなし（報告を渡していれば完了、なければ中断）、起動の知らせ（`isBackgroundLaunch`）を完了と数えない。
- 状態の文（`subagentStatusLabel`・乗せたときの説明 `subagentStatusTitle`・色 `subagentStatusClass`）:
  - 通信の切断で止まったもの（`network`。API のエラーで失敗した・通信で親ごと終わったときに動いていた）は「通信の切断で中断」と注意の色（ピルの数も失敗と分ける）。
  - 出力の上限（`isOutputLimitError`）で止まったものは「失敗（出力の上限）」。再開・やり直すの頼みには「報告は短く・大きなファイルは分けて」と添える（`resumeRequest` / `retryRequest` の `outputLimit`）。
  - 完了は、報告が親に届いたかで分ける（`delivery`。待つ形は親のツールに結果が返ったら、裏で動かしたものは報告のあとに親が動いたら受け取った = 完了）。親がまだ動いていなければ「報告済み（親の受け取り待ち）」、親が動かないまま作業が終わったら「報告が親に届いていません」と注意の色。届かなかった報告はコアが次に送る指示に本文を自動で添えて渡し、受け取った = 完了になる。待たずに渡すなら行の「いま親に渡す」（`HAND_OVER_NOW` を `api.tellChat`。本文はコアが添える）。ピルにも「n 件受け取り待ち」「n 件届かず」。
  - 止まったあとに親が同じ仕事を新しいサブエージェントでやり直したもの（`supersededBy`。判定は `@shared/chat/subagentSupersede.ts` の `markSuperseded`。決まりは `src/shared/CLAUDE.md`）は「やり直し済み」と控えめな色。止まった理由とやり直した回の名前は title、「やり直した回を見る」でその回のカードへ移る。再開・やり直すを出さず、ピルの失敗の数・通信が戻ったときの再開にも数えない。
- 止まった（失敗・中断）行とカードには「再開」（SendMessage で止まったところから続ける）と「やり直す」（同じ依頼で最初から。確かめてから）を置く（`SubagentActions`。文は `resumeRequest` / `retryRequest`、メインには `api.tellChat` で伝える）。実行中なのに長く動きのないものは「止める」（作業中だけ。確かめてから `api.stopBackgroundTask`。止めたら再開・やり直すで戻せる）。
- 作業中にサブエージェントだけが通信のエラー・出力の上限で止まったときは、システムプロンプトで 1 回だけ SendMessage で続きから再開させる（ほかの失敗・利用者が止めたものは再開せず伝える。コア）。

## 動き（`activity/`）

メインとすべてのサブエージェントの動きを、時刻の順に 1 本に並べる見え方（いつ何をしたか・どこが並行していたかを、メインの配下であることのまま見るため。依頼を出すタブはメインだけのまま）。チャットの見出しの「会話 / 動き」（`ChatPaneActions.show`）で、同じタブの中で切り替える。会話は隠しても描いたまま残す（`ChatPane` の `ChatBody`・`ChatTimeline` の `hidden`。読んでいた位置・開いたカード・窓の中の位置を保つ）。

- 行（純粋関数の `activityRows.ts` の `activityRows`）: メイン（`groupEvents(events)`）と各サブエージェント（`groupEvents(events, scopeOf(entry))`）の項目を 1 行ずつにして、時刻の順に並べる（同じ時刻なら親が先）。1 行 =「時刻・誰が・何を・かかった時間」。続けてのツールは会話と同じまとまりで 1 行（1 件ならそのツールの中身「コマンド: npm test」、いくつもならまとめ「2個のファイルを読み取り および 1回検索」。左の矢印で 1 回ずつに広げる）、自分の指示・返答（サブエージェントのものは「発言」）は 1 行目だけ、チャット欄から伝えた指示は「伝える → 調査「…」」、要約・お知らせ・エラー・作業の終わりも 1 行。サブエージェントは起動の行（起動した側の線）で始まり、終わりの行（「報告 → 調査」/ 失敗 / 中断と、起動からのかかった時間）で終わる。中の手順が届かない（孫より深い）実行中のものは、途中経過の最後のツールを「いま: …」として 1 行。考えた行は出さない。実行中（結果の届いていないツール）は、持ち主が動いているときだけ（メインは作業中で、最後の作業の終わりより後のもの）。
- 線（純粋関数の `activityRails.ts` の `layoutRails`。Git のグラフと同じ考え方）: 列は使うときに空いている左から取り、起動した子は親より右の空いている列。起動の行で親の節から右へ曲がって子の線が始まり、終わりの行の節で閉じ、その列はあとで使い回す。線は絞り込んだ行の全体で決める（描くのが最近の分だけでも、前から続く線を上から通す）。色は持ち主のサブエージェントの色（カードの帯・目次の点と同じ `agentHues`）、メインは灰色。節は、自分の指示 = 白抜きの丸・起動 = 少し大きい丸・終わり = ひし形・失敗 = 赤・実行中 = 明滅。描くのは `ActivityLine`（行は memo。線の欄の幅はすべての行で同じ。別の日の行があれば時刻の欄を日付の入る幅に `--activity-time-w`）。
- 絞り込み（上のチップ。`ChatPaneState.activityFilter`・`filterActivity`）: すべて・メインだけ・そのサブエージェントと配下（その起動の行は外し、自分の線から始める）。チップは起動した順で色の点付き、入れ子は道筋を説明に。右に動作中の数。
- 描くのは最近の `ACTIVITY_WINDOW`（300）行（上の「以前の動きを表示」で足す）。一番下を見ている間は新しい行に付いていく（初めと絞り込みを変えたときは一番下から）。
- 会話との行き来: 行を押すと会話に戻り、その場所へ移って強調する（`revealInConversation`）。サブエージェントの行は設定の開き方で開く（`agentTargetOf` → `openSubagent`。流れの中なら外側のカードから開いて窓の中まで `revealSubagent(key, eventId)`、右の欄なら動きを見せたまま右の欄のその画面の中へ `openSubagentSide(key, eventId)`。起動の行・終わりの行・いまの行はそのサブエージェントを開く。広げた 1 回ずつの行はその呼び出しへ）。サブエージェントの行の右端の 2 つのボタン（「会話の流れの中で見る」「右の欄で開く」。行が多いので乗せた行・ピントのある行にだけ出す `.activity-open-actions`）と右クリックのメニューで、設定によらずどちらで開くかを選べる（右の欄を置けない画面では出さない）。カードの「動きで見る」で、そのサブエージェントに絞った動きを開く（`show("activity", { kind: "agent", key })`）。

## 承認と質問（`approvals/`）

- 回答待ちのカードは `ApprovalCard`（ツールの承認・`question` は `QuestionCard`・`reconnect` / `usage_limit` は `ReconnectCard`）。回答を送るのは `useResolve`（`useResolveApproval.ts`。送れたらカードごと消えるので送信中のまま）。承認カードの入力は `describeApprovalInput`（Bash のコマンドは、実行のあとの欄と同じく色を付ける）。
- AI からの質問（`QuestionCard`。AskUserQuestion。）: 選択肢は枠で囲まず細い区切り線で並べた行で、丸の代わりに番号の箱（選ぶと青・複数選ぶ質問はチェック。キーの 1〜9 でも選べる）。最後の行は鉛筆の箱と枠のない「その他の回答」の欄 `QuestionOtherField`（チャット欄と同じく書いた分だけ伸び、Enter で回答・次へ／Shift+Enter で改行。📎・貼り付け・ドラッグで添付でき、アップロード中は回答させない。文がなく添付だけでも答えられる。ドラッグで添付したときも「その他」を選ぶ）。
- 質問が 2 つ以上なら、見出しの「1 問ずつ / すべて」で出し方を切り替える（`QUESTION_LAYOUT`。初めは 1 問ずつ）。1 問ずつは上に質問の見出しを並べていまの位置と答えたものを示し、1 つ選ぶ質問は選ぶと次へ進む。最後は「回答する」。すべては番号だけを付け（薄い見出しは出さない。見出しは質問が 1 つのときだけ）、質問どうしを 1px の濃い境界線で分ける。見出しの矢印でたたむと、いまの質問の 1 行だけになる。1 問ずつ・たたんでも欄は作り直さずに隠す（書いた文・添付を残す）。質問の文・説明は AI の改行のまま出す。
- 「その他」の添付は回答の `attachments`（質問ごと）で送り、コアが回答の文にパスと Read ツールで開くよう書き添えてから Claude Code に渡す（AskUserQuestion の回答は文字だけなので）。答えた内容は記録 `approval_resolved` に残り、`QuestionAnswerMessage` で出す。

## 指示の一覧（`prompts/`）

- 自分の指示の一覧は記録から `promptListOf` で 1 回だけ作り、指示の履歴・⌘⌥↑ / ↓・上に貼り付ける指示の帯・↑↓ の呼び出し・失敗した作業の巻き戻しで共通に使う。
- 指示の履歴（`PromptsChip`。チャット欄の上のピル「指示の履歴 n」）: 行でその指示へ移って強調し、右のボタンで入力欄に入れる（`fillComposer`）。一覧は会話の順で、開いたらいちばん下を見せる。上の欄で絞り込み、↑↓ で選んで Enter で入力欄に入れる・⌘Enter でその指示へ移る。チャットにピントがあるときの ⌃R でも開き（シェルの履歴の検索と同じ）、開いている間の ⌃R は 1 つ前の一致へ。閉じたらチャット欄にピントを戻す。
- 前後の指示へは ⌘⌥↑ / ↓（`usePromptKeys`。チャットにピントがあるときだけ、捕捉で先に受け取り、縦スライドのプロジェクトの切り替えより優先する）。前に移った先がまだ見えていればその前後へ、なければ位置で決める（判定は純粋関数の `promptNav.ts` の `adjacentPrompt`）。
- 上に貼り付ける指示（`StickyPrompt` ＋ `useStickyPrompt`）: 読んでいる返答の元の自分の指示（流れの上端より上から始まるいちばん下の吹き出し。いちばん上を見ているときは最初の吹き出し。`readingPrompt`）を、流れに重ねずに流れの上の段に置き、いつも出す（`chat.css` の `.timeline-wrap` の `grid-template-rows`。列は `grid-template-columns: minmax(0, 1fr)` で枠の幅に固定する。既定の auto では、1 行にたたんだ長い指示の幅まで列が広がり、流れごと右へはみ出した）。見出しは「指示」で、すぐ右に ↑ / ↓（前・次の指示へ。⌘⌥↑ / ↓ と同じ数え方。移る向きの矢印 `ArrowUp` / `ArrowDown`）、その右に開閉の矢印（初めは 1 行にたたみ、全文は `STICKY_PROMPT_EXPANDED`。1 行に収まるときも場所を取ったまま押せなくする）、添付は `AttachmentPeek`（帯の高さは変えない）。押して何かが起きるのは ↑ / ↓・開閉・添付だけで、見出しと文は押しても何もしない（乗せても地の色を変えない）。スクロールと描いた項目の変化で確かめ直し、同じ発言のままなら描き直さない。帯を出すかは、タブの列の「表示」→「指示の帯」・帯の右クリックの「指示の帯を隠す」（全文の開閉も）・見出しの行のボタン・設定の「表示」→「上に貼り付ける指示」（どれも `STICKY_PROMPT_HIDDEN`）。

## チャットの中の検索（`find/`）

`ChatFind`。チャットの見出しの行の右に置く検索欄（見出しの行・項目を隠したときは、⌘F でチャットの右上に浮かせて出す `floating`。上の「見出し」）で、ふだんは細く、ピントが入る・文を入れると広げ、件数・前後・大文字小文字・消すは文を入れたときだけ出す。狭い見出し（`@container` 420px 以下）では虫眼鏡だけにして、押す・⌘F で広げる。⌘F でこの欄にピントを移して文を選ぶ（`useChatHotkey`）。Esc で文を消してチャット欄にピントを戻す。↑ / Shift+Enter で前、↓ / Enter で次（初めて移るときはいちばん新しい一致へ）。

- 探すのは記録から（`chatFindMatches.ts` の `findMatches`。自分の発言とメインの AI の返答）で、移るときにその発言の前後だけを描く（`reveal`）。流れをすべて描かない。印は描いている範囲だけに CSS Custom Highlight API で付け（`::highlight(chat-find)`）、DOM を書き換えない。閉じたツールのまとまり・思考の中は探さない。
- 打った文は前後の空白も削らずに探す（半角・全角の空白も）。右の「Aa」（⌥⌘C。`CHAT_FIND_CASE`。入れているときは `.find-option.on`）で大文字・小文字を区別する。照らし合わせは記録と画面の印で共通の `matchOffsets`。

## 音声入力（`features/dictation/`）

- チャット欄の下の道具のマイク `DictationButton` ＋ `useDictation`（1 回押して話し、もう一度押すと文字起こしして、キャレットの位置（選んでいればその範囲）に入れる。入れ方は純粋関数の `insertDictation`（英字とくっつくときだけ空白を補う））。録音は `recorder.ts`（`getUserMedia` ＋ `MediaRecorder`）、マイクの失敗の文は `micErrorMessage`。
- 録音中は赤く経過時間、文字起こし中は「文字起こし中…」、失敗は `DictationError`（`ErrorText` と、録った音声で起こし直す「もう一度」）。録音中の送信ボタン・Enter・⌘Enter は、入れてそのまま送る。⌘⇧Space（チャット欄にピントがあるときだけ。`DICTATION_SHORTCUT`）で開始・停止、Esc でやめる。
- 準備の状態は店の `useVoiceStatus`（設定の変更で取り直し、ダウンロードの進み具合はその場で直す）で、準備ができていなければ押したときに設定の「音声入力」を開く（`openSettings("voice")`）。設定は `features/settings/CLAUDE.md`。

## 返答のファイルのチップ（`features/fileLinks/`）

返答の中のファイルのパスは、チャットのパネルの中（`ChatPane` が `FileLinksProvider` で `FileLinkContext` と、ui の Markdown が読む `MarkdownFileLinksContext` を入れる）だけチップにする（`useFileLinks`。チャットの作業場所のファイルの一覧を読み、作業が終わるたびに読み直す。一覧が読めない間はチップにしない）。

- 押したとき（チップ・ターンの変更カード・ツールの行で共通の `open`）: 会話を残したまま、チャットの画面の右の欄（サブエージェントと同じ欄。`panelActions(panelKey("agents", チャット))`）に開く。行の番号があればファイルのタブ（`openFile`。中身でその行を目立たせる）、作業場所にコミットしていない変更があれば変更のタブのそのファイルの位置（`openChanges`。押した時に `api.gitStatus` で `changeOf` を見る）、なければファイルのタブ。右の欄を置けない所ではファイルタブ（`openProjectFile`）。差分はコミットしていない変更すべて（そのターンの分だけではない。ファイルタブの差分と同じ）。
- ⌘クリックはファイルタブへ直接（`openByClick`）。右クリックはファイルのメニュー `FileMenu`（右の欄で開く・ファイルタブで開く・VS Code / 既定のアプリで開く・Finder で表示（IPC の `externalApps.revealPath`）・パスのコピー（相対・絶対）。`FileLinksProvider` が 1 つだけ描く。チップの右クリックは返答のメニューより先に受け取る）。開く関数は同じものにして、返答の Markdown を描き直させない。
- 右の欄の中身は `features/editor/CLAUDE.md` の「右の欄の変更とファイル」。
判定と Markdown の木の書き換え（`remarkFileLinks`）は純粋関数の `fileRefs.ts`（作業場所のファイルの一覧にあるものだけ。インラインコード・リンク先・地の文の絶対パス）。

## 子チャット（`children/`）

- 横道の質問を、親の会話とは別のチャットで聞く（データとサーバーは `src/core/chat/CLAUDE.md` の「子チャット」）。一覧（`selectChats`。サイドバー・ボード・⌘K など）には出さず、親の中にだけ置く（`stores/chats.ts` の `childChatsOf` / `useChildChats`。親 → 子の一覧）。
- 始め方: 発言の右クリックの「子チャットで聞く」（`useMessageMenu`。選んだ文、なければ発言の全体）→ `openAskChild` で `AskChildHost`（App と別ウィンドウに 1 つ）が聞く: 聞く欄（選んだ文を引用 `> ` にして初めから入れておき、書き換え・消しができる。キャレットは引用の下。Enter で送る）・「会話を引き継ぐ」（初めはオン）。選んだ文は聞く欄の文に入れて送るので、`quote` は送らない。送ったら閉じるだけで、画面は移らず子も開かない（親は作業を続けられる）。
- 札: 聞いた発言の下に `ChildChatMarks`（子ごとに状態 = 作業中・回答待ち・失敗・答えあり（未読）・既読）、入力欄の上のピルに `ChildChatsChip`（「子チャット n 件 · m 件答えあり」。押すと一覧。行はサブエージェントの一覧と同じ形（`.subagent-row`）で、状態の印・名前・様子 · モデル · 最後に動いた時刻、右に「右で開く」「新規ウィンドウで開く」（`OpenPlaceButtons`。`openChildChat` の `place`）とアーカイブ。上に「行を押したとき」の切り替え（`CHILD_CHAT_OPEN_IN`））。答えが来ても開かず、通知（`app/notifications.ts`。題名に「子チャット: 」）を出す。
- 開き方（`openChildChat`。札・サイドバーの子の行・通知で共通）は設定の「子チャットを開く場所」（`CHILD_CHAT_OPEN_IN`。初めは右の欄。別ウィンドウを開けないブラウザでは右の欄）:
  - 右の欄（`openChildSide`）: いちばん上の親（`rootChatOf`。読み込んだ一覧を `knownChat` で引く）のチャットの画面の右の欄に、子チャットのタブ（`child`。孫・ひ孫も同じ欄に並べる）。親の画面が見えていなければ、先にチャットのパネルで親を開く（`openInRootSide`。見えているかは `pane/windowMessages.ts` の `isChatPaneShown`）。別ウィンドウの中からは、メインのウィンドウに頼む（知らせ `openChild`）。中身は `SideChildChat`（上の帯と `ChatView`。子の画面の中には右の欄を重ねない = `PanelHostContext` を null にする。子のサブエージェントは流れの中、ファイルはファイルタブ）。タブの名前の前は子の状態の印（`ChildTabLead`）、タブの × はチャットの ✕ と同じく閉じ方を聞く（表示だけ消す = タブを閉じる）。タブの右クリックの「別ウィンドウで開く」で別ウィンドウへ移せる。
  - 別ウィンドウ（`features/popout/PopoutChildChat`）: 最小化は閉じ方を聞かずに閉じる（子は残る）。✕・⌘W はチャットの ✕ と同じ `closeChatWithChoice`（既定は `CHAT_CLOSE_ACTION`）。
- 上の帯（`ChildChatBar`。右の欄・別ウィンドウで共通）: 「親を見る」（親の画面を見せて、聞いた発言へ `revealInParent`）・「メインに渡す」（いちばん新しい答えを引用にして親の入力欄の後ろに足す `handBackToParent` / `handBackText`。送るのは自分で。親の画面がなければ書きかけの文 `chatDraft` に足してから開く）。閉じるボタンは置かない（右の欄はタブの ×、別ウィンドウは ✕・最小化。子は残り、札から開き直せる）。別ウィンドウからは知らせ `childToParent` でメインのウィンドウに頼む（`app/mainWindowMessages.ts`）。
