# ボード（`features/board`）

チャットのカンバン（プロジェクトのボード `KanbanBoard` と、全プロジェクトの画面 `AllProjectsPage` の `AllProjectsKanban`。中身は共通の `KanbanView`。プロジェクトがないときは `NoProjectsWelcome`、タグの絞り込みに合うものがないときは `EmptyState` と「絞り込みを外す」。`features/project/CLAUDE.md`）。列をグループにすると、グループの列（下の「グループの列」）を並べる（全プロジェクトのボードはプロジェクトの段の中、プロジェクトのボードはそのまま）。列・段・リストのまとまりは `bucketChats`（`features/chatList/CLAUDE.md`）、右のパネルは `features/panel/CLAUDE.md`。

## 列の分け方と表示

- チャットを開く先は設定の「チャットを開く場所」で決まる: チャットタブ（初め。カードを押すとプロジェクトの「チャット」タブへ移って開く。ボードに右のパネルを置かない）/ ボードの右のパネル。ボードは `BoardChats`（`features/panel/CLAUDE.md` の「欄の殻」）だけを見て開き、`KanbanBoard` が置き方で中身の部品（パネルあり / なし）を選ぶ。
- 列の分け方は、どちらのボードもツールバーの「グループ」「状態」のオン・オフ（`BoardColumnsToggle`。並びは グループ | 状態 で、ボード / リストのすぐ右に置く（利用者の依頼。前は 状態 | グループ の順で、段の分け方の後ろだった）。共有の `ToggleButtons`。覚えるのは `useBoardColumns`: 全プロジェクト `ALL_PROJECTS_BOARD_COLUMNS`・プロジェクト `PROJECT_BOARD_COLUMNS` の state / groups / none と、共通の `BOARD_GROUPS_BY_STATE`）: 状態だけ = 状態の列 / グループだけ = グループの列 / 両方 = 下の「グループ×状態」/ どちらもオフ = 分けない（`FlatTasks`。ボードはカードを折り返し、リストは 1 列）。経緯: プロジェクトのボードには前に「状態 / グループ / グループ×状態」のボタンの組があり、グループを選ぶと別の画面（グループのボード `#/projects/:id/groups`）へ移って変な感じがしたので、ボタンと画面をなくした（以前の URL は知らないタブとしてボードに戻る。`app/router.ts`）。そのあと「要件定義・実装・テストのようなグループを縦の列に並べ、ドラッグで移したい」と頼まれ、画面を移らない同じボードの中の列の分け方として、全プロジェクトのボードと同じ「状態」「グループ」のオン・オフを置いた（その前の、リストだけの「状態」のオン・オフ `PROJECT_LIST_FLAT` はこれにまとめた）。プロジェクトのボードでグループの列にしているときは、段の分け方の「グループ」は出さない（列と同じ分け方になる。覚えた段はそのままで、分けない形で出す）。逆に、プロジェクトのボードのリストでは列の「グループ」を出さず「状態」だけにする（リストでは列: グループが段: グループとほぼ同じ見た目になるため。利用者の依頼。覚えた「グループ」は状態の列で出し、ボードに戻すとグループに戻る。リストで「状態」を押すと分けない（none）になる。全プロジェクトのボードには段のグループがないので、リストでも出す）。ボードのタブ・チャットの URL の行き先は置き方だけで決まる（`boardTabOf`: パネルをボードの右に置くならボード、チャットタブに分けるならチャット）。
- プロジェクトのボードの段: グループ（列は状態など）では、カードをドラッグしてほかのグループの段へ落とすと、そのグループへ移す（「No Group」の段ならグループから外す。`useGroupLaneDrop` → `BoardLanes` の `laneProps`。決まりはサイドバー・グループの列と同じ `useGroupDrop`。重ねている段の中の列は `.drop-target` の色。落とし先になるよう、チャットのないグループの段も出す `keepColumnsAndGroups`）。利用者の依頼。
- カンバンの列（作業中・回答待ち・未読・既読）は AI の状態から `boardColumnOf` で決め、人は動かさない。カードの名前の左の印はより細かい状態（`StatusSlot`。下の「列とカード」）。
- 表示はボード / リストの 2 つ（`useBoardView` の `view`。`BOARD_VIEW`。前の「表」はなくした。下の「並び順」。全プロジェクトのボードには「フィード」も。下の「フィード」）で、どれもツールバーの段の分け方のボタンの組「分けない / グループ / 作業場所 / プロジェクト」（`LaneSelect`。`Segmented`。利用者の依頼で、前は「段: …」の選択欄だった。出すのはそのボードで選べるものだけ: 全プロジェクトは 分けない / プロジェクト / 作業場所、プロジェクトのボードは 分けない / グループ / 作業場所）で段（スイムレーン）に分けられる（`split`。`BOARD_SPLIT`。表示を切り替えても段に分けたまま）。表示と段に分けるかはすべてのボードで共通。
- 段の分け方（`useKanbanLanes`。ボードとリストで共通）: 作業場所（ブランチ）・グループ（プロジェクトのボード）・プロジェクト（全プロジェクトのボード）。プロジェクトのボードは `PROJECT_BOARD_LANES`（初めは作業場所）、全プロジェクトのボードは `ALL_PROJECTS_BOARD_LANES` に別に覚える（初めはプロジェクト = プロジェクト別のカンバン）。作業場所の段にプロジェクト名を添えるのは、いくつかのプロジェクトが並ぶ全プロジェクトのボードだけ。
- 段の見出しは、サイドバーのプロジェクトのカードと同じく、薄い色の地を横幅いっぱいに敷いた角丸の帯にする（利用者の依頼。前は地のない 1 行の文字だった。`BoardLanes` の `useLaneTint`）。プロジェクトの段はプロジェクトの色（`--ws-hue`。地は `project-mark.css` の札と共通で、サイドバーの見出しと同じく枠の線なし）、グループ・作業場所の段はサイドバー・タブの列のまとまりと同じ色（`useBucketHueOf`・`--group-hue`。名前の前のアイコンもその色。設定の「まとまりを色付きで表示」に関係なくいつも付ける）、色のない段は灰色の地（`board-columns.css`）。
- 段（`BoardLanes`）は見出しで開閉し（名前だけでなく、見出しの空いているところ（名前の右・「グループを作成」の右など）を押しても開閉する。中のボタン・作成の欄はそちらの動き。利用者の依頼で、前は「グループを作成」を置いた段では名前の幅しか押せなかった。`useFolds(foldPlace, …)`。`foldPlace` はボードごとの `board:<パネルのキー>`）、段ごとに、ボードと同じくいちばん左に下書き（その段に入る作成先のもの。下書きだけの段も出す）、続けて状態の列を並べる（`StateColumns`）。リストを段に分けたときは、段の中に下書き → 状態ごと → アーカイブ済みを縦に並べる（`ListSections`）。全プロジェクトのボードのプロジェクトの段（段: プロジェクト・列: グループ）は、見出しのドラッグで並べ替える（`useProjectLaneReorder`。段の並びはサイドバーと同じ並びなので、サイドバーの `useProjectReorder` をそのまま使い、サイドバーの並びも変わる。最近動いた順なら落とすと手動に切り替わる。見出しに付けるものは `BoardLanes` の `headProps`、段のドロップ先・入る位置の線は `laneProps`）。利用者の依頼。
- リストの行はいつも 1 行（名前の左に状態の印、後ろに作業場所などの札を並べ、狭ければ名前から省く。`ChatRowContent`・`board-list.css` の `.list-main`）。利用者の依頼で、前はリストのときだけツールバーに「リストの行」の切り替え（2 行 = 名前の下に作業場所・状態 / 1 行。`BOARD_LIST_COMPACT`）があったが、なくして 1 行にそろえた。

## グループ×状態

利用者の依頼（「グループの中で状態別に分ける」）。列の「状態」「グループ」を両方オンにしたとき（`BoardColumnsToggle`。どちらのボードも）。グループの列の中を、状態（作業中・回答待ち・未読・既読）の小見出しの札（`ToneChip`）で区切る（`GroupSections` の `byState` → `StateParts`。チャットのない状態は出さない。アーカイブ済みはグループのいちばん下の閉じたまとまりのまま）。

- 覚えるのは列の分け方とは別の `BOARD_GROUPS_BY_STATE`（`useGroupsByState`）で、列の分け方そのもの（`useBoardColumns`）は groups のまま（覚えた値の意味を変えない）。
- 分け方は `by: ["group", "status"]`（`ProjectGroupColumns` は小分けのときだけ）。保存したビューの列の分け方には `groupsState` として入る。

## 並び順

- 表示は ボード / リスト の 2 つ（利用者の依頼で、前の「表」（Notion の表を参考にした、1 行 = チャット 1 つ・列の出し入れ `BOARD_TABLE_HIDDEN`・見出しで並べ替え）はいらなかったのでなくした。覚えていた表示 `table` は初めのボードに戻り、表で保存したビューはリストとして当てる）。
- 並び順（`useChatSort`。純粋関数は `chatSort.ts` の `chatComparator` / `nextChatSort`）は、ツールバーの「並び順」（`SortMenuButton`。どの表示でも。名前・プロジェクト（全プロジェクトのボードだけ）・グループ・状態・作業場所・モデル・ターン数・費用・コンテキスト・最終更新・作成日と、昇順 / 降順を選ぶ）。`BOARD_SORT` にすべてのボードで共通に覚え（初めの最後に動いた順なら消す）、`useChatBuckets` の `sort` に渡すので、ボード・リストの列・まとまりの中がその順になる。同じ値どうしは最後に動いた順、値のないもの（グループなし・モデル不明など）は向きによらずいちばん後ろ。
- 中身の描き分け（表示 × 段 × 列の分け方）は `KanbanBody`、状態と操作・ツールバーは `KanbanView`（`KanbanBoard.tsx`）。ツールバーの表示のまとまりは ボード / リスト → 列の分け方 → 段の分け方 → 表示項目 → 並び順。

## 表示項目

利用者の依頼（「並び順の左に表示項目を。どのバッジを出すかなどを選べるように」）。ツールバーの並び順のすぐ左の「表示項目」（`CardFieldsButton`。アイコンはタブの列の「表示」と同じ `SlidersHorizontal`。フィードのカードにも効くので、並び順を出さないフィードでも出す）で、カード・リストの行・フィードのカードに出す項目をチェックのメニューで 1 つずつ出す・隠す（押してもメニューは閉じない。いちばん下の「既定に戻す」で初めの選び方に）。

- 項目は `cardFields.ts` の `CARD_FIELDS`（メニューのまとまり: バッジ = 状態・プロジェクト（全プロジェクトのボードだけ `cardFieldSections`）・グループ・作業場所 ｜ 詳細 = モデル・回答待ちの数・ターン数・API 換算・コンテキスト ｜ 日時 = 最終更新・作成日）。名前（チャット名）とアーカイブ済みの札はいつも出す。
- 覚えるのは隠した項目だけ（`BOARD_CARD_HIDDEN`。すべてのボードで共通。補助は共有の `lib/hiddenItems`。チャットの見出しに出す項目と同じ形）。初めに出すのは状態・プロジェクト（全プロジェクトのボードだけ）・モデル・最終更新で、ほかは隠す（利用者の指定。前の初めの値はモデル・ターン数・API 換算・コンテキスト・作成日を隠す形だった。自分で選んだ値を覚えていれば、そちらのまま）。
- 描くのは `ChatCard.tsx` の `CardBadges`（札）・`CardStats`（詳細。値のない・0 のものは出さない `cardStatText`。モデルは `modelDisplayName` で「Opus 5.5」）・`CardTimes`（日時。フィードの最終更新は返答の時刻）。読むのは `useBoardCards` が `useCardFields` で 1 回読み、`show` で渡す。カードは出すものがない行（札・下の行）を描かず、下の行はカードの幅で折り返す（日時は縮めて省かずに次の行へ）。リストの行は状態の印を名前の左に、札・詳細を名前の後ろに、日時を右端（`.list-times`）に。
- 保存したビューにも `cardHidden` として入る（前の版のビューにはなく、そのときは当てても表示項目を変えず、比べない）。

## 保存したビュー

利用者の依頼（Notion のビューを参考に）。

- ツールバーの上のタブ（`SavedViewTabs`。全プロジェクトのボードと、プロジェクトのボード。`BoardShell` の `views`）。ビューは見え方の組（表示・段の分け方・列の分け方（どちらのボードも state / groups / groupsState / none）・並び順・アーカイブの絞り込み・表示項目（`cardHidden`）。前の版で保存したビューのリストの行 `compact`・表で隠す列 `hidden` は読まずに捨てる）に名前を付けたもの（`savedViews.ts` の `BoardViewState`。比べ方・並びの操作は純粋関数）。名前の検索・作業場所の絞り込みは入れない（その場の絞り込みなので）。
- プロジェクトのボードには、初めから 3 つのビュー「グループボード」（ボード・列: グループ）・「状態ボード」（ボード・列: 状態）・「グループリスト」（リスト・列: 状態・段: グループ）をこの順で置く（利用者の依頼。`storageKeys.ts` の `DEFAULT_PROJECT_VIEWS` を `PROJECT_SAVED_VIEWS` の初めの値にする。並び順は最後に動いた順・アーカイブは未アーカイブ・表示項目は入れない）。覚えた一覧があればそちらを使い（前から自分で作っていれば足さない）、すべて消したら `[]` を覚えて初めの 3 つには戻さない。全プロジェクトのボードも同じ決まりで、初めから 2 つ「プロジェクト別グループボード」（ボード・列: グループ・段: プロジェクト）・「プロジェクト別リスト」（リスト・列: 分けない・段: プロジェクト）をこの順で置く（`DEFAULT_ALL_PROJECTS_VIEWS`。利用者の依頼）。
- 押すとそのビューの見え方を、それぞれの設定（`BOARD_VIEW` など。アーカイブはサイドバーと連動する `useArchiveFilter` を通す）に書き込む（`useSavedViews` の `apply`）。プロジェクトのボードの前の版のビューで列の分け方のないもの（列がいつも状態だったころのもの）は、`projectViewState` で state として読む。ビューはその組を覚えるだけで、見え方の設定は今までどおり。いまの見え方に合ういちばん前のビューを選択中に見せる（`sameViewState`）。
- 「＋ ビューを保存」でいまの見え方に名前を付けていちばん後ろに足し、タブの右クリックで 名前を変更（ダブルクリックでも）/ いまの表示で上書き（同じなら押せない）/ 削除（確かめる）。同じ一覧に同じ名前は付けられない（利用者の依頼。`viewNameTaken`: 前後の空白・全角半角・大文字小文字の違いも同じとみなし、名前を変えるビュー自身は除く）。名前の欄（`InlineName` の `validate`）で書くたびに確かめ、同じ名前なら欄を赤くして下に「「…」というビューはもうあります」と出し、Enter・✓ では決めない（ピントを外すと取り消し）。全プロジェクトのボード `ALL_PROJECTS_SAVED_VIEWS`・プロジェクトのボード `PROJECT_SAVED_VIEWS`（すべてのプロジェクトで共通。利用者と相談して決めた。プロジェクトごとに作り直さずに済み、グループの名前など中身に依らない見え方の組なので）に localStorage で覚える（量が少なく、端末ごとの見え方の好みなので DB にしない）。
- タブはドラッグで並べ替えられる（利用者の依頼。`useSavedViewDrag`: タブの左右の半分で前・後ろを決め、落としても並びが変わらない所（自分の上・すぐ前の後ろ半分・すぐ後ろの前半分。`isNoopViewMove`）には線を出さず落とせない。並びは `moveView` で同じ一覧の保存に書き込む）。

## フィード（全プロジェクトのボードだけ）

利用者の依頼（Notion の参考案の 1 つ）。全プロジェクトのボードの表示の切り替えのいちばん右の「フィード」（`BoardHeader` の `feed`）。ボード / リスト（`BOARD_VIEW`。ほかのボードと共通）とは別に `ALL_PROJECTS_FEED` に覚える（プロジェクトのボードに「フィード」の値が渡らないように）。

- チャットごとに、メインエージェントの最新の返答 1 件の初めの部分を、返答の新しい順に 1 列のカード（`FeedList`。カードは `useBoardCards` の `feedCard` → `FeedCardContent`: プロジェクト・名前・グループ（`GroupChip`。サイドバーの行・チャットの見出しと同じ札。グループなしは出さない。利用者の依頼）・作業場所・状態（列の見出しと同じ色の札 `ToneChip`。利用者の依頼で、前は点と文だけ）・返答の時刻、その下に返答の初めの 4 行。Markdown の印は `feed.ts` の `feedPlainText` で外す）。押すとそのプロジェクトへ移って開き、右クリックはカードと同じメニュー。幅は画面いっぱいに使う（利用者の依頼。前は読みやすい幅 880px まで）。アーカイブ済みのチャットは、ほかのボードと同じく下の閉じたまとまり「アーカイブ済み n」（`ArchivedFold`。開閉はボードのほかのまとまりと同じ場所に `feed/archived` で覚える）に入れ、中も返答の新しい順（利用者の依頼。前は新しい順のまま混ぜていた）。
- 読むのは `useFeed`（`GET /api/feed`。フィードを出している間だけ。届いた返答（SSE の `chat_event`）は `feedItemOf` / `upsertFeedItem` でその場で入れ替え、つなぎ直したら読み直す）。出すのは、ボードの絞り込み（名前の検索・アーカイブ・作業場所・しまった / タグに合わないプロジェクト）を通ったチャットの分だけ（`shown` と突き合わせる）。
- フィードは返答の新しい順の 1 列なので、段・列の分け方・並び順は出さない（覚えた値はそのまま）。カードに出す項目は、ほかの表示と同じ「表示項目」で選ぶ。保存したビューには表示の 1 つ（`view: "feed"`）として入る。

## 全プロジェクトのボード（`AllProjectsKanban`）

全プロジェクトの画面ではチャットを開かず、そのプロジェクトへ移って開く（サイドバー・⌘⇧A・検索と同じ。全プロジェクトとプロジェクトの 2 つのパネルで、同じチャットが別々のタブ・分割で開いて「さっきのタブはどこ？」とならないように。全プロジェクトの画面は見渡す所、作業はプロジェクトで）。

- 右のパネルを持たない（`BoardShell` に `rightPanel` を渡さない。ツールバーのパネルの開閉も出さない）。
- カード・リストの行・右クリックの「開く」は `openChat` でそのプロジェクトのボードへ移り、そのパネルで開く。確かめのダイアログは出さない（戻るのはサイドバーの「全プロジェクト」1 回で、取り消せない操作ではないため）。代わりに、乗せると「プロジェクト「○○」で開く（そのプロジェクトの画面へ移ります）」（`useBoardCards` の `openTitle`）。
- ツールバーに「新規」は置かない（プロジェクトのボードにもない。上の「見出し（ツールバー）と外枠」。利用者の依頼。前は ⌘N と同じく、サイドバーで選んでいるプロジェクトへ移って始めていた）。新しいチャットは ⌘N・サイドバーから始める。ツールバーはボード / リストの切り替えから始まる（プロジェクトのボードは、その左に「グループを作成」）。
- 「下書き」の列には、すべての欄の下書き（`useAllDrafts`。出しているプロジェクトのもの）をプロジェクトのバッジ付きで並べ（`DraftCards` の `showProject`）、押すとその欄の画面へ移って開く（`openDraft`）。以前の全プロジェクトのパネルに残っていた下書きは、起動したときに作成先のプロジェクトのパネルへ移す（`features/panel/CLAUDE.md`）。
- 段・アーカイブ済みのまとまりの開閉を覚える場所は、パネルがあったときと同じ `board:kanban:all` のまま（覚えた開閉を消さない）。
- 列の分け方は上の「列の分け方と表示」の「状態」「グループ」（`BoardColumnsToggle`。利用者の依頼で、前は 状態 / グループ / グループ×状態 / 分けない から 1 つを選んでいた）。表示のまとまりのボード / リストのすぐ右。
- 列の「グループ」は、段がプロジェクトのときだけ出す（`BoardColumnsToggle` の `groups`。グループはプロジェクトごとのものなので。利用者の依頼で、前はいつも出し、選ぶと段の分け方を隠していつもプロジェクトの段にしていた）。ほかの段（分けない・作業場所）では、覚えた「グループ」は状態の列で出し（覚えた値は消さない）、段をプロジェクトに戻すとグループに戻る。グループのときは、プロジェクトの段（`by: "project"`。チャットのないプロジェクトの段も出す）の中に、そのプロジェクトのグループの列（`ProjectGroupColumns`。下の「グループの列」）を並べる。「グループを作成」は、ボード・リストとも段の見出しのプロジェクト名のすぐ右（`LaneGroupCreate`。押すとその場で名前の入力欄。`BoardLanes` の `actions`。利用者の依頼で、前はボードは段の中のいちばん右の列・リストは段の中のいちばん下の横幅いっぱいのボタンで、グループの多いプロジェクトでは探しにくかった）。カードはドラッグでき（`useBoardCards` の `drag`）、列へ落とすとそのグループへ移す。ほかのプロジェクトのグループへ落とすと、確かめてからそのプロジェクトへ移してそのグループに入れる（`useGroupDrop` の `onForeignChat`。作業中なら落とせない）。列の＋はそのプロジェクトへ移ってそのグループで新しいチャットを始める（`openNewChat`）。絞り込み（名前・アーカイブ・作業場所）は全プロジェクトのボードのものを使う。利用者の依頼。
- 分けないときは、利用者の依頼で、下書き・作業中・回答待ち・未読に関係なく、ただタスクが並んでいるだけの画面にする。下書き → チャット（並び順。初めは最後に動いた順 `byActive`）を 1 つの並びにする（`FlatTasks`。まとまりは状態で分けず、段に分けるなら段だけで分ける `by: [lanes]`、分けなければ見出しのないまとまり 1 つ `by: []`）。ボードはカードを幅に合わせて何列にも折り返し（`.flat-tasks-grid`）、リストは 1 列の行。アーカイブ済みはいちばん下の閉じたまとまり（開閉は段ごと、段がなければ `flat/archived`）。状態はカードの名前の左の印でだけ分かる。検索・絞り込み・段はそのまま使える。

## 列とカード

- 状態の列 1 本は `StateColumn`（見出し `ColumnHead`（色の点・名前・件数・右端の操作。件数はアーカイブしていないものだけ。色の点・名前・件数は列の色の札（共通の `ui/ToneChip.tsx`）に入れ、文字・枠・薄い地をその列の色（`COLUMN_TONE`。下書きは `DRAFT_TONE` の灰）にする。グループの列の見出しも同じ札で、グループの色 `ChatGroup.hue`（サイドバー・タブのまとまりと同じ）、「No Group」は灰。利用者の依頼）＋ カード ＋ いちばん下の閉じたまとまり `ArchivedFold`）。既読の列には `ArchiveAllButton`（確かめてから、列のチャットをすべてアーカイブ）。いちばん左の「下書き」の列は `DraftColumn`（まだ送っていない新しいチャット。新しいチャットは見出しの「新規」から始めるので、列に＋は置かない）。列の＋は、その列に意味があるとき（グループの列）だけ置く。
- アーカイブ済みのチャットは、列・まとまりのいちばん下の閉じたまとまり `ArchivedFold`（`ui/`。サイドバーの子チャット・入力欄の上の一覧と共通）に分ける（サイドバーと同じ見出し。開閉はボード・段・列ごとに覚える。中のカードは薄く `.archived`）。カンバンのリスト表示では、アーカイブ済みを状態のまとまりごとには畳まず、いちばん下の 1 つのまとまり `ArchivedListSection` にまとめ、その中を状態ごとに分ける（`StateColumn` の `foldArchived={false}`。下書きはアーカイブできないので分けない）。
- カードとリストの行の描き方は `useBoardCards`（`card` / `row`。アーカイブの印と「回答 n件」（`pendingCount`）はどのボードでもここで付け、ボードごとの差分は `classFor` / `style` / `projectName` / `openTitle` / `drag` だけ。右のパネルで表示中なら選択中）。操作は `chatCardProps`（クリック・Space で開く / カードにピントがあるときの Enter で名前を変える（Finder と同じ。利用者の依頼で、前は Enter でも開いていた。`lib/keys.ts` の `isRenameKey` / `isOpenKey`）/ 右クリックでメニュー / ドラッグはグループの列とプロジェクトのボードの段: グループのときだけ。カードの中のボタンを押したときは開かない）、右クリックは `useCardMenu`（開いている間はパネルを Esc で閉じない）。中身は `ChatCardContent` / `ChatRowContent`（出す項目は上の「表示項目」）。カードは名前の左に状態の印を、サイドバーの行と同じ `StatusSlot` で出す（作業中は回るリング・回答待ちは！・未読は緑の点・既読は灰の点、作業中のまま未読ならリングに緑の点を重ねる。利用者の依頼で、前は下の行に点と「既読」などの文・「未読あり」を出していた）。リストの行も同じく名前の左に `StatusSlot` を出す（利用者の依頼で、前は名前の後ろに点と「既読」などの文・「未読あり」。未読の点の縁は行の地の色に合わせる `board-list.css`）。フィードのカードは状態の札（`ToneChip`）のまま。
- 下書きのカード（`DraftCards`）の色・枠はほかのカードと同じ（目立たせない）。書いている途中の文があれば初めの 3 行を出し、押すとその欄で開く・右クリックで開く・削除。全プロジェクトのボードでは右上にプロジェクトのバッジ（`showProject`）。
- チャットはどちらのボードもチャットの店（`useChats`）から読み、アーカイブ済みを出すときだけそれも読む。

## 絞り込み

- アーカイブでの絞り込みは `ArchiveFilterSelect`（すべて / 未アーカイブ / アーカイブ済み。`archiveFilter.ts` の `useArchiveFilter` / `archiveMatches`）。アーカイブ済みを出すかはサイドバー・右のパネルのタブと共通の `SIDEBAR_SHOW_ARCHIVED`（`useShowArchivedChats`）で連動し、「未アーカイブ」を選ぶとどこでも隠し、「すべて」「アーカイブ済み」を選ぶとどこでも出す（値は `linkedArchiveFilter`）。「アーカイブ済みだけ」はボードの中だけの絞り込みとして `BOARD_ARCHIVE_FILTER` に覚える。絞り込み中の色（緑の枠）は、アーカイブ済みだけに絞っているときだけ。
- カンバンの絞り込み・候補・段は `useKanbanFilters`（アーカイブ・作業場所・名前の検索）/ `useWorktreeChoices`（ブランチ名で出し、フォルダが消えたものは「フォルダなし」と添える）/ `useKanbanLanes`、出すチャットは `useKanbanChats`（純粋関数 `kanbanChats`。全プロジェクトのボードではしまったプロジェクトの分を出さない）。カンバンにプロジェクトの絞り込みは置かない（見出しの名前 `ProjectSwitcher` から切り替える）。
- 名前で探す検索欄は見出しの `.board-search`（⌘F。`useChatSearch`）。右のボタンでチャットの中の文言の全文検索（⌘⇧F。`openContentSearch`）を開く。

## 見出し（ツールバー）と外枠

- 外枠は `BoardShell`（保存したビューのタブ（カンバンだけ）→ ツールバー `BoardHeader` → 失敗の文 → ボードの中身（`.board-main`）と右のパネル（プロジェクトのボードだけ。`rightPanel` に `useBoardPanel` を渡す）→ カードの右クリックのメニュー `ChatMenu`）。
- ツールバー（表示・グループの作成・検索などの帯。部品は `BoardHeader`。画面の文言では「見出し」と呼ばない）は道具を概念ごとのまとまりに入れる。「新規」（新しいチャット）はどのボードにも置かない（利用者の依頼で、プロジェクトのボードの左端の「新規」もなくした。新しいチャットは ⌘N・サイドバーのプロジェクトの鉛筆・パネルのタブの列の＋から）: 左から 整える（グループを作成。プロジェクトのボードだけ。`GroupCreateToolButton` で名前を聞くダイアログを開いて作る。利用者の依頼でいちばん左。前は表示の後ろだった）→ 表示（ボード / リストの切り替え → 列の分け方（グループ | 状態）→ 段の分け方 → 表示項目 → 並び順。利用者の依頼で、前は 段 → 列の順だった）→ 探す・絞り込む、右にパネルの開閉（`PanelToggle`。右のパネルのあるプロジェクトのボードだけ）。ブラウザ・ターミナルはツールバーに置かず、パネルのタブの列から開く。全プロジェクトの画面もプロジェクトのボードと同じく、ツールバーの左端に名前と件数（前の「カンバン n 件」「グループ」「タスク」「フィード」）を出さず、道具をボードの左端にそろえる（利用者の依頼）。
- ツールバーはいつも横幅いっぱいの上に置き、右のパネルはその下から始まる（パネルがボードを覆っても、横幅いっぱいにしても見える）。置き方の設定は持たない（以前の「パネル優先」= パネルを上端まで伸ばしてツールバーをボードの側だけに出す形はやめた）。チャットタブに分けるとき（`CHAT_PLACEMENT` が `separate`）はボードに右のパネルがないので、並べ方の違いはそもそも出ない。
- 狭いときの並べ方は `@container` で書く（真ん中の画面の幅は、ウィンドウより欄の幅で変わるため）: ツールバーは、狭くなるとまず道具のまとまりごと次の行へ折り返し（2 段までは文字のまま）、3 段目が要るときだけボタンの文字を隠してアイコンにする（`BoardHeader` が `useWrapCompact(2)` で実際の段の数を測って `.board-tools.icon-only`。決め打ちの幅では切り替えない。利用者の依頼で、前は `.board` の幅 1120px 以下ですぐアイコンにしていた）。`.board` の幅 600px 以下では、まとまりの箱をなくして道具を 2 段にそろえ、いつもアイコンだけ。列は `board-main` の幅で 420px 以下なら 1 本ずつめくる。

## グループの列（列: グループ）

列 = グループ、カード = チャット（グループを縦の列にして並べ、カードをドラッグして列の間で移す。要件定義 → 実装 → テストのような流れにも使える）。`ProjectGroupColumns` を、全プロジェクトのボードはプロジェクトの段ごとに、プロジェクトのボードはそのまま（段に分けるなら作業場所の段ごとに）置く（`KanbanBody`）。プロジェクトのボードの「グループを作成」はツールバーのボタン。状態と操作は `useGroupBoard`（グループの名前を変える・削除する（「…」メニュー `useGroupMenu`）、列へのドロップ（チャットを移す・列を並べ替える `useGroupDrop`。ほかのプロジェクトのチャットを落とすと、確かめてからこのプロジェクトへ移してその列のグループへ入れる（`onForeignChat` → `moveDroppedChatToProject`）。作業中のチャットは落とせず、列を赤い点線にしてカーソルの横に理由を出す（`foreignBlockedBy`。見た目は `dropClass`））、失敗の文。絞り込み・検索・表示はそのボードのもの）。列・まとまりは `GroupSections`、見出しは `GroupColumnHead`（ドラッグで並べ替え・名前のダブルクリックで名前を変える・右クリックと「…」でメニュー・＋でそのグループに新しいチャット）。「No Group」も見出しのドラッグでグループの間へ並べ替えられる（ボード・リストとも。並べ替えの並びの中の ID は `UNGROUPED_SORT_ID`（0）で、`useGroupDrop` に `ungroupedAt` を渡す）。グループの並びは DB（`api.reorderGroups`。変わったときだけ）、「No Group」の位置（前にあるグループの数）はプロジェクトごとに画面に覚える（`groupBoardUngroupedAt`。ボード・リスト・サイドバーで共通。覚えていなければボードは先頭・リストとサイドバーはいちばん下。並べ方は純粋関数の `features/group/groupOrder.ts` の `ungroupedPosition` / `orderGroupBuckets`（サイドバーと共有するので group に置く））。全プロジェクトのボードの「グループを作成」は段の見出しのプロジェクト名の右（`LaneGroupCreate`。上の「全プロジェクトのボード」）。
