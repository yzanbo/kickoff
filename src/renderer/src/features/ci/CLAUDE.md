# CI（`features/ci`）

プロジェクトの「CI」タブ（`#/projects/:id/ci`）。連携先のリポジトリの GitHub Actions の実行を見て、落ちたら AI に直してもらい、やり直す。要件定義書の「5.15 CI の結果」・メモの「CI の結果 仕様書」。コアは `src/core/CLAUDE.md` の「CI のタブ」、API は `api/ci.ts`。

- この Mac のアプリの中だけ（`window.kickoff`。GitHub タブと同じく、ブラウザ・スマホからはタブを出さない。コアの口は端末に開かない）。連携先とアカウントは GitHub タブと同じ（プロジェクトの設定の「GitHub」）。
- `CiTab`: 初めに連携を確かめ（`api.githubConnection`）、使えなければ理由と直し方・「もう一度確かめる」を `EmptyState` で出す。使えれば `CiBrowser`: 左に一覧（幅は `CI_LIST_WIDTH`）、右に開いた実行の中身。枠と行の見た目は GitHub タブのクラス（`github-tab` / `github-list` / `github-item` / `github-detail`）を使い、CI だけの部分は `styles/ci/ci.css`。中身の欄に `DETAIL_MIN_WIDTH`（GitHub タブと同じ）が残らない幅では一覧と中身を切り替える（`hooks/useNarrowSplit`）。開いている実行は `ciSelected(プロジェクト)`（「実行の ID」か「実行の ID:ジョブの ID」。読み書きは純粋関数の `ciView.ts` の `parseCiSelected` / `ciSelectedText`）。
- 一覧: いちばん上に外の CI（作業場所のブランチと既定のブランチの先頭のコミットの、GitHub Actions でないチェック・コミットの状態。成否・説明・リンクだけ `CiExternalRow`）、その下に GitHub Actions の実行（新しい 50 件。PR のない実行も。`CiRunRow`: 状態の印 `CiStateIcon`・題・ワークフロー #番号（やり直した回）・ブランチ（作業場所・既定のブランチ = 落ちたら知らせるブランチはアクセントの色）・PR・きっかけ・起こした人・時刻）。取り直しは GitHub タブと同じ `useGitHubRefresh`（開いたとき・窓に戻ったとき・ボタン）で、動いている実行・外の CI がある間（`hasPending`）は 15 秒ごと（`CI_PENDING_REFRESH_MS`）、ほかは 1 分ごと。見張りの `ci_failed` が届いたら、そのプロジェクトの一覧を取り直す。
- 中身（`CiRunDetailView`）: 見出しに題・状態の札・ワークフロー #番号・ブランチ・きっかけ・コミット・PR（押すと GitHub タブでその PR）・起こした人。操作は、落ちた実行は「失敗したジョブをやり直す」「すべてやり直す」と「AI に渡す ▾」、通った・取り消した実行は「すべてやり直す」だけ、動いている実行はなし（やり直したら知らせ（`showToast`）、中身と一覧を取り直す）。取り直し・URL のコピー・GitHub で開く。
- ジョブとステップ（`CiJobLog.tsx` の `CiJobSection`）: ジョブごとの開閉（見出しに状態・名前・かかった時間・GitHub のジョブのページ）。初めに開くのは、指したジョブ（PR のチェックの「ログを開く」）→ 落ちたジョブの最初 → 動いているジョブの最初（`jobToOpen`）で、あとは開閉を利用者に任せる。開いている間だけログを読み（`api.ciJobLog`）、ジョブの状態・終わった時刻が変わったら読み直す。ログはステップごとに畳んで全部出し（ジョブのステップとログのステップは名前で前から順に当てる `stepsWithLogs`）、初めに開いたジョブの落ちたステップ（`stepToOpen`）は開いてその位置まで流す。行は行番号と、アプリが付けた色のまま（Docker のログと同じ `features/docker` の `ansiSpans` と `SpanView`）。GitHub の印 `##[group]` は太字の見出し、`##[error]` / `##[warning]` / `##[notice]` は色、`##[endgroup]` は出さない（`ciLogLine`）。動いているジョブは GitHub がまだログを出さないので、理由と「GitHub で動いている様子を見る」とステップの進み具合（「ログなし」とは書かない）。
- AI に渡す（落ちた実行だけ。`CiHandoffMenu`）: 共通の「AI に渡す ▾」（`features/chat/CLAUDE.md` の「AI に渡す」）の `lead`（メニューの上）に「（ブランチ名）で直す」（`ciHandoff.ts` の `fixCiRun`: コアにそのブランチの作業場所を用意してもらい（`api.ciRunWorktree`。既定のブランチなら本体、ほかはワークツリー。なければ作る）、その作業場所のチャット（アーカイブしていないもの。実行の PR に結び付いたもの → 最近動いたもの）の入力欄に一言（`ciFixText`）と札を入れて開く。チャットがなければその作業場所で新しいチャットのタブ。GitHub の「レビューコメントで直す」と同じ流れ）。その下に共通の 4 つの渡し先（`ciHandOffItem`。新しいワークツリーの名前の案はそのブランチ、既定のブランチなら聞かずに本体）。札は押した時点の落ちたステップのログ（`api.ciFailedLog` → `ciFailedDocument`。実行の様子（ワークフロー・ブランチ・コミット・題・PR・URL）とジョブ / ステップごとのログ。ログの中の ``` で囲みが切れないよう、囲みを長くする）を `api.capture` に `ci_log`（外から来た中身。盾の印）・終わりを多めに残す `tail_share: 0.8` で渡す。実行に PR があればその PR に結び付ける（`ciLinkOf`）。
- ほかから開く: `ciLinks.ts` の `openCiRun(プロジェクト, 実行, ジョブ?)`（`selectCiRun` で開くものを書いてから CI のタブへ移る）。GitHub タブの PR のチェックの「ログを開く」（`features/github` の `GitHubChecksList`。GitHub Actions のチェックだけ）と、CI の失敗の通知を押したとき（`app/ciNotifications.ts`）が使う。
- 失敗の知らせ（`app/ciNotifications.ts` の `useCiFailureNotifications`。App が 1 回呼ぶ）: SSE の `ci_failed` を Mac の通知（「✕ CI が落ちました: ブランチ」・プロジェクト名とワークフロー #番号「題」）で出す。設定の「通知」（`desktop_notifications`）に従い、Kickoff を見ていてそのプロジェクトの CI のタブを開いているときは出さない。押すと `notifications.onOpenCi` → `openCiRun`（ブラウザから開いたときはブラウザの通知）。どのブランチを見るか・同じ実行は 1 回だけ・プロジェクトごとの切り替え（設定の「GitHub」の「CI の失敗を知らせる」）はコアが決める。
- テストは純粋関数の `ciView.test.ts`（開いているものの読み書き・自動の取り直し・開くジョブとステップ・札の中身・ログの行・ステップとログの当て方）。
