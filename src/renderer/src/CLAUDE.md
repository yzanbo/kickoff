# 画面（`src/renderer/src`）の決まり

画面全体の決まり（置き場所・データの持ち方・保存・API・共有部品・表示・性能）を書く。機能ごとの振る舞いは `features/<領域>/CLAUDE.md`、CSS は `styles/CLAUDE.md`。

- 依存の向きは `app → features → stores / api / ui / hooks / lib → @shared`。ui / hooks / lib / stores / api は features を import しない。app の全体のもの（`router.ts` の `useRoute` / `openChat` など・`chatStatesContext.ts` の `useChatStates`）は features から読んでよい。
- import は、同じフォルダなら `./`、それ以外は `@/…`、プロセスをまたぐ型と純粋な関数は `@shared/…`（型は `@shared/types`、`errorMessage` は `@shared/errors`）。`../` で上のフォルダをたどらない。
- 複数のファイルになる機能は `features/<領域>/` にまとめ、大きければサブフォルダに分ける（`chat/queue/` など）。どの領域にも属さない汎用のものだけを ui / hooks / lib に置く。
- 大きな部品は「状態と操作の hook（`useXxx`）」と「描く部品」に分ける（`usePanel` ＋ `Panel` / `PaneTabBar` / `PanelTabPage`、`useSidebar` ＋ `Sidebar`、`useProjectNav` ＋ `ProjectStack` / `ProjectSlides`、`useWorkspaceRows` ＋ `WorkspacePage`、`useChatView` ＋ `ChatView`、`useProjectData` ＋ `ProjectPage`）。要素に渡す props の束も hook から返してよい（`sidebar.layout`、`useBoardPanel` の `body` / `frame`）。
- 画面（ルート）を増やす前に、ダイアログや右のパネルで足りないか考える（設定は左下の歯車・⌘, から開くダイアログ）。ルートは `app/router.ts` の `Route`。チャット・新しいチャットは、プロジェクトのチャットのパネル（`kanban:<プロジェクト>`）で開く（`openChat` / `openNewChat`。全プロジェクトの画面からも、そのプロジェクトへ移って開く）。パネルの置き場所は設定の「チャットを開く場所」（`CHAT_PLACEMENT`）で、ボードと分けた「チャット」タブ（初め）か、ボードの右（`features/panel/CLAUDE.md` の「欄の殻」）。

## データ（`stores/` と全体の context）

- サーバーのデータは店に 1 つずつ持ち、部品ごとに取り直さない・props で 3 段以上中継しない。店は `createStore`（値 1 つ）/ `createKeyedStore`（プロジェクトの ID などの key ごと）で作り、読み込み（同時に頼まれても 1 回）・失敗（覚えずに、間隔を伸ばして自動で取り直す）・サーバーの知らせでの更新（`reduce` / `reloadOn` / `dropOn`）・SSE がつながったときの取り直し・`maxAge` / `refreshOnFocus` を同じ形で持つ（考え方は `stores/createStore.ts` の先頭）。React からは `useStore` / `useKeyedStore` / `useKeyedStores`（いくつかの key。渡した key が変わったときだけ描き直す）/ `useStoreStatus`。閉じているポップオーバーなどは `active: false` で読み込みを頼まない。
- 店: チャットの一覧 `stores/chats.ts`（`useChats({ projectId?, archived?, enabled? })`。全プロジェクトで 1 つで、アーカイブ済みは頼まれたときだけ読む。子チャット・メモのチャットは入れない。`useChatsValue`・`useChatsByProject`・部品の外では `currentChats`。要対応・⌘⇧A・状態ごとの数のように子チャットも数えるものは `useChatsWithChildren` / `useChatsWithChildrenByProject`（アーカイブしていないもの））、`useProjects()`（`projects` / `projectsById` / `projectName(id)` / `loaded` / もうないとわかったか `missing(id)`。`projects.find((p) => p.id === …)?.name` を書かない）、`useGroups` / `useGroupsOf` / `useGroup`（1 つのグループ。名前と色）、`useWorktrees` / `useWorktreesOf`、`useApprovals`、`useAppSettings`（`settingsStore`）、`usageStore`、`useProviders` / `useGitHubStatus` / `useModels`、`useVoiceStatus`、プロジェクトのメモの一覧 `useMemoList`（`stores/memos.ts`）、定型文 `useAllSnippets` / `useProjectSnippets`（`stores/snippets.ts`）、起動したときの送信待ちの確かめ `useQueueResumes`（`stores/queueResumes.ts`）、ワークツリーの PR の知らせ `useWorktreePrNotices` / `useWorktreePrLookup`（`stores/worktreePrs.ts`）、DB クライアントの接続 `useDbConnections`（`stores/dbConnections.ts`）。領域だけのデータは、その領域で店を作ってよい（`/` `@` の候補・外で開くアプリの一覧など）。
- 開いているチャットの中身（チャット・記録・回答待ち・作業中の様子・書いている途中の返答・サブエージェントの途中経過）は、チャットの店 `features/chat/store/`（`chatStore.ts` の `createChatStore`。説明は `features/chat/CLAUDE.md` の「1 つのチャットの画面」）にチャットごとに 1 つ持つ。記録の窓・途中の文の世代・つなぎ直したときの `?after=` があるので `createKeyedStore` には乗せず専用の店にしたが、考え方（同時に頼まれても 1 回・SSE で直す・つながったら取り直す・読み込みの最中の知らせを当て直す）は同じ。部品は用途ごとの口（詳細・記録・途中の文・途中経過）を要る所でだけ読む（メモの仕様書「0023_表示を軽くする」の M1）。記録は開くとき末尾（最新のターン）と索引だけを読み、記録全体から作るものは `digest` から作る（案 4）。
- 操作の応答で届いた値は `set` / `update` で入れ、知らせを待たずに画面をそろえる（作ったプロジェクトは `addProject`、作ったチャットは `addChat`、ワークツリーの一覧は `worktreesStore.set`）。
- チャットの状態（作業中・回答待ちなど）は `features/chat/chatState.ts` の `chatStateOf(chat, pending)` で決める。回答待ちの引き当ては App が `indexApprovals` で 1 回作り、`useChatStates()`（`approvals` / `pending` / `stateOf(chat)` / `pendingCount(chatId)`）で配る（部品で `api.approvals()` を呼ばない）。
- いまのルートは `useRoute()`（App が `useHashRoute()` で 1 回購読して `RouteContext` で配る）。`useHashRoute` は見ている画面を `LAST_ROUTE` に覚え（開くファイル・メモ・強調する発言のような一度きりの指定は外す `lastingRoute`）、起動したとき・ウィンドウを作り直したときは `main.tsx` が App を描く前に `restoreLastRoute` で、URL に画面の指定がなければ前回の画面を開く（利用者の依頼。前は起動するといつも全プロジェクトだった）。

## 表示の設定の保存（`lib/storage.ts`・`lib/storageKeys.ts`）

- localStorage / sessionStorage に残すもの（開閉・切り替え・幅・書きかけの文など）は、`lib/storageKeys.ts` でだけ `defineSetting(key, 形, { ids?, session? })` / `defineSettingFamily(prefix, 形)`（ID ごと。キーは頭 ＋ ID）で宣言する。形は `flag` / `optionalFlag` / `choice` / `number` / `text` / `list` / `record` / `json`。部品にキーの文字列を書かない。ここに宣言していない `kickoff:` のキーは、起動したときに消える（`pruneUndeclared`）。
- 別ウィンドウ（`features/popout/CLAUDE.md`）とは localStorage を共有し、ほかのウィンドウが書き換えた設定も `storage` の知らせで読んでいる部品に届く（sessionStorage はウィンドウごと）。
- 読み書きは React なら `useSetting(SETTING)` / `useSetting(family(id))`（同じ設定を読む部品どうしでそろい、`set` は参照が変わらないので memo した部品に渡せる）、保存しない入力欄もあるなら `useOptionalSetting`、React の外は `readSetting` / `writeSetting`。localStorage を部品から直接読み書きしない。
- キー名と保存する値は変えない（利用者の表示の好みを残すため）。選択肢を増やすときも、今までの値はそのままの意味で読めるようにする。
- プロジェクト・チャット・グループなどの ID を、キーか値に含むものは `ids: true` を付ける。起動したときに `prepareStorage`（`main.tsx` が App より先に呼ぶ）が `/api/status` の `database_id` と覚えた値（`DATABASE_ID`）を比べ、違えば `forgetIdSettings` で捨てる（DB を作り直すと ID が 1 から振り直され、別のものを指すため）。
- まとまりの開閉は `FOLDS` 1 つ（`hooks/useFold`。説明は `features/chatList/CLAUDE.md`）。

## API（`api/`）

- 通信の土台は `api/http.ts`（`request`（窓を閉じる間際にも届けたいものは `keepalive`。見ているものの「何も見ていない」）/ `postForm` / クエリの組み立て `withQuery` / 失敗 `ApiError`）だけで、資源ごとの関数は `api/<資源>.ts`（コアの `http/routes/<資源>.ts` と対応）に書き、`api/index.ts` で `api` 1 つにまとめる（名前が重なると後のもので上書きされるので、重ならないことを `index.test.ts` で確かめる）。本文・応答の型は `@shared/types`（`api.ts`）で、画面で書き直さない。
- SSE は App が `useServerConnection` で 1 回つなぎ、`api/events.ts` で配る（部品は `useServerEvent`、部品の外は `subscribeServerEvent`。つながったときは `subscribeServerOpen`）。

## hooks と補助

- window のイベントは `useWindowEvent`（effect の中で `addEventListener` しない。ほかより先に受け取るなら `capture`）。いまのテーマ（ダーク・ライト）は `hooks/useAppliedTheme.ts` の `useAppliedTheme`（React の外は `lib/appliedTheme.ts`。テーマを決めて出すのは `app/theme.ts`）。Kickoff が前にあるかは `useWindowFocused`、ネットワークは `useOnline`。
- CodeMirror 6 の編集の部品は `hooks/useCodeMirror`（作るのは 1 回・書き換わったら `onChange`・途中で変える拡張は `dynamic` と `dynamicDeps` で差し替える・外から動かす口は `onCreate`。SQL のタブの `SqlEditor` とメモの `MemoEditor`）。部品ごとに `new EditorView` を組み立てない。
- 一覧を下まで送ったら続きを読むのは `hooks/useWhenVisible`（返した ref を付けた要素が見えたら呼ぶ。読み足しても見えたままなら `again` を変えて呼び直す。GitHub タブの一覧）。重いもの（コードの色付け・Mermaid の図・AI が描いた図）を画面の手前 1200px まで来てから描くのは `hooks/useNearViewport`（一度来たら true のまま）。どちらも見張りは画面で共有する IntersectionObserver（`watchViewport`。枠と余白の組ごとに 1 つ。要素ごとに `new IntersectionObserver` しない）で、枠は要素のいちばん外側の `data-near-root` の先祖（チャットの流れ・サブエージェントのカードの窓・右の欄の画面。入れ子の枠は `scrollMargin` で広げる。枠を省くと途中のスクロールする枠の切り取りに余白が効かず、手前で動かない）。
- サーバーから読む: 店にないもの 1 つは `useAsync`、key（ファイル・コミット・作業場所など）ごとは `useKeyedAsync`（key が変わるまで前の表示を残す。`loaded`）。
- 操作の実行中と失敗は `useAction`（`run` で busy と失敗の文、`guard` は失敗だけ受け止める）、保存のボタンは `useSave` ＋ `SaveActions`、送れたら閉じるフォームは `useSubmit`。失敗をお知らせのダイアログで出すなら `ui/dialogs.tsx` の `reportFailure(title)`。画面を移さずに済ませた操作を知らせるなら `ui/toast.tsx` の `showToast(文, { label, run }?)`（画面の下に 6 秒。操作を 1 つ添えられる（「開く」など）。3 つまで重ねる。App と別ウィンドウが `ToastHost` を置く）。ドラッグ中に落とせない理由をカーソルの横に出すなら `ui/DropHint.tsx` の `showDropHint`（落とし先の dragover で呼び続ける。呼ばれなくなると消える。App の `DropHintHost` が描く）。

- 一番下への付いていきは、中身・枠の大きさの知らせ（ResizeObserver。レイアウトのあと・描く前に届く）の中で、ずれているときだけ寄せる（`lib/followScroll.ts` の `snapTarget`）。中身が伸びるたびに effect・`useLayoutEffect` で `scrollTop = scrollHeight` を書かない（読むたびに流れ全体のレイアウトを強い、書いている最中の入力 1 文字が 50ms ほどかかっていた。案 7a）。会話の流れの枠（`.timeline-wrap > .timeline`）は `contain: strict` で、中の変化を流れの外（見出し・チャット欄・ピル）のレイアウトに及ぼさない（大きさは格子で決まる。中身で高さが決まる置き場所の `.timeline` には付けない）。
- 流れの行（行の包み `.timeline-row`）は `content-visibility: auto` で、画面から離れた行のレイアウトと描画を省く（まだ描いていない行は窓が置いた `--row-est`（見え方の店の測った高さ、なければ `features/chat/timeline/rowEstimate.ts` の見積もり）、一度描いた行は大きさを覚える。いまの作業の行 `data-live`・光っている行・カードの中身の行は省かない。`styles/chat/timeline-row.css`。案 3）。省いている行の中の要素の位置（`getBoundingClientRect`・`scrollHeight`）を読むと、その行のレイアウトを強いるので、流れ全体をたどって位置を読むときは行の包みの位置で決め、線に掛かる行だけ中を読む（上に貼り付ける指示・前後の指示）。なめらかに移るときは、動いている間に行が描かれて行き先がずれるので、着いたかは行き先が真ん中あたりにあるかで決め、ずれたら寄せ直す（`jumpToEvent`）。
- 閉じた `<details>` の中身（コマンドの出力・読んだファイル・差分・依頼の Markdown）は初めて開くまで作らない（`ui/LazyDetails`。案 8）。
- 重いもの（Mermaid の図の組み立て・AI が描いた図の iframe・返答のコードの色付け）は、画面の手前 1200px まで来てから始める（`hooks/useNearViewport`。`content-visibility` は画面の外の描画を省くが、JS と読み込みは省かないため）。待つ間は前に描いたときの高さ（なければ見積もり）の枠で場所を取る（案 14a）。
- コードの色付け（Shiki の文法の読み込みと正規表現での解析）は画面のスレッドでせず、Web Worker で行う（`lib/highlightPool.ts` の `createHighlightPool({ spawn })` が待ち行列と取り消し・結果の覚え（512 件・合わせて 400 万字。1 件 20 万字を超えたら覚えない）を持ち、`lib/highlightWorker.ts` が `lib/highlightCore.ts` で色付けして `lib/tokenCodec.ts` で詰めて返す。`?worker` の import は薄い入口 `lib/highlightWorkerEntry.ts` だけ。Worker は 1 つで、見えているもの（開いた欄）を画面の手前のもの（`useHighlight` の near を渡したもの）より先にし、外れた・替わったまだのものは取り消す）。覚えた色は `peekHighlight` で最初の描画から出す（窓で行が外れて戻っても色なし → 色付きのちらつきにしない）。返答のコードブロックの色付けは、ブロックの memo の中で動くので、書き終えたブロックの色付けはやり直さない（メモの仕様書「0023_表示を軽くする」の案 20）。
- 入力欄の高さは CSS の `field-sizing: content` で伸ばす。JS で高さを auto に戻して `scrollHeight` を測らない（キーを押すたびにページ全体のレイアウトをやり直させ、長いチャットで文字入力が遅くなった）。
- ファイルのリンクの一覧（作業が終わるたびに取り直す）を Markdown の解析（remark の差し込みの設定）に入れない。差し込みはパスらしい文字に印を付けるだけで、開けるかはリンクの部品が小さな店からパスごとに選んで読む（`features/fileLinks/fileIndexStore.ts`。案 28）。解析に入れる値が変わると、すべての返答を解析し直す。
- memo した部品へ、描くたびに新しいオブジェクト（その場で書いた `{…}`・毎回作る操作の束）を渡さない。`useMemo` で作り置き、中の操作が描くたびに作られるなら押したときにいまのものを呼ぶ形にする（右の欄の `AgentSplit` の `frame`・パネルの `usePanel` の `pageOps`。案 29）。
- 時計（`useTicker`）で描き直すのは、時間で変わる値を出す部品だけにする。App・画面全体の hook に置かない（使用枠の残り時間は `UsageMeter`。前は App が持ち、60 秒ごとにアプリ全体が描き直っていた。案 30）。
- 店の値・まとまりの結果は、中身が同じなら同じ配列・オブジェクトを返す（`useChats` の見え方ごとの配列、`useSetting` の値など）。memo の依存に使えるようにするため。
