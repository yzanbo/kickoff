# Kickoff 実装計画（v0.1）

要件定義書 v0.2（`docs/requirements.md`）に基づく。マイルストーンごとに「動くアプリ」にしてコミットする。

## 構成

```
Kickoff.app（Electron）
├─ src/core      … Electron に依存しない中核（HTTP API サーバー・SQLite・エージェント実行）
│                   デスクトップ画面・スマホのブラウザ・将来のネイティブアプリが同じ API を使う
├─ src/main      … Electron のメインプロセス（コアの起動、ウィンドウ、フォルダ選択、macOS 通知）
├─ src/preload   … 画面に渡す最小限のネイティブ機能
└─ src/renderer  … 画面（React）
```

- AI 実行: Claude Agent SDK（`claude` のログインを使用）。プロバイダーを差し替えられる構造にして Codex を後で追加する
- GitHub: `gh` CLI（push と PR 作成、PR のマージ状態の確認のみ）
- データ: `~/Library/Application Support/Kickoff/` の SQLite

## マイルストーン

| # | 内容 | 終わった時点でできること |
|---|---|---|
| M0 | 基盤: Electron と React の骨組み、コア（API サーバー・SQLite）、設定画面（Claude / gh のログイン状態） | アプリが起動し、ログイン状態が見える |
| M1 | プロジェクトと要件定義: 新規作成（フォルダ・`git init`）、フェーズの現在地と「次にやること」、要件定義チャット（AI の質問に回答）、要件定義書の保存と確定、タスク分解と承認 | アイデアから要件定義書とタスク一覧までできる |
| M2 | 実装とレビュー: タスクごとの worktree とブランチ、並列実行（同時実行数の上限）、実行ログのリアルタイム表示、承認カード、中断・再開、差分表示、差し戻し、push と PR 作成、マージの検知 | タスクを AI に並列で実装させ、PR まで出せる |
| M3 | テストと動作確認: テストの実行とレポート、バグの起票、起動コマンドでのアプリ起動・停止 | AI のテスト結果を確認し、自分で動作確認できる |
| M4 | デプロイ: 手順の設定、事前チェック、承認、結果の記録 | 一通りの流れが最後まで通る |
| M5 | スマホ連携: LAN / Tailscale 経由のアクセス、トークン認証と QR ペアリング、スマホ向けの画面、通知（macOS・ntfy） | 外出先から承認・確認・指示ができる |

## 既存コードの扱い

要件確定前に書いた `src/core/` のコード（データ型・SQLite・フェーズ別の権限・AI 用ツール・Claude プロバイダー）は、方針と合っているため M0 で見直して再利用する。主な修正点:

- タスクのステータスに「PR 作成済み」を追加し、ブランチ名・worktree のパス・PR の URL を持たせる
- 実行の作業ディレクトリを、タスクごとの worktree に変更する
- 要件定義の確定（ゲート）を表す状態を追加する

## テスト方針

- コア（SQLite・権限の変換・ツール・worktree 操作）は `node:test` で単体テストを書く
- 各マイルストーンの最後に、サンプルプロジェクトで実際に AI を動かして通しで確認する
