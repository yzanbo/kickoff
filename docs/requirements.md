# Kickoff 要件定義書（v0.6）

> ステータス: 確定（2026-10-31）。変更があれば版を上げて「9. 決定事項」に追記する。

## 0. 用語

| 用語 | 意味 |
|---|---|
| **Kickoff** | この文書で定義するアプリ本体。**Mac のデスクトップアプリ**（Electron） |
| **開発対象アプリ** | Kickoff を使って開発するアプリ。種類は限定しない（Web / スマホ / デスクトップ など） |

3 章以降の「技術スタック」「デプロイ先」は、開発対象アプリについての話であり、Kickoff 本体についての話ではない。

## 1. 背景と目的

個人でアプリを新規開発するときに、AI エージェント（Claude Code / Codex）を使って、アイデアからデプロイまでをスムーズに進めたい。

既存のツールは、どれも会話（セッション）が中心になっている。そのため「このアプリは今どの段階か」「要件は何だったか」「次に何をやるか」が会話の中に散らばり、開発の流れ全体を追いにくい。

Kickoff は **チャット中心**のツールにする。開発のセクション（要件定義・スケジュール・実装・テスト・デプロイ）ごとにチャットを立て、AI と話しながら適宜決めていく。決まったこと（要件定義書・スケジュール・タスク）はセクションごとにまとまって見えるようにする。

- 開いた瞬間に、どのチャットが作業中・回答待ちかがわかる
- 要件・タスク・会話・成果物が 1 か所でつながっている
- AI がやったことを、人が要所でレビュー・承認できる

## 2. 利用者と利用環境

| 項目 | 内容 |
|---|---|
| 利用者 | 自分 1 人（配布しない） |
| 環境 | macOS（Apple Silicon）のデスクトップアプリ |
| スマホ | 外出先から操作したい。v1 はブラウザから使い、将来はネイティブアプリにする |
| AI エージェント | Claude Code（Agent SDK）に先に対応し、次に Codex。Gemini は検討中 |
| 認証 | 各 CLI のログイン（Claude / ChatGPT のサブスクリプション）をそのまま使う。API キーや従量課金は使わない |

## 3. 対象とする開発

- **アプリの新規開発**と、**開発途中の既存プロジェクトの取り込み**
- **開発対象アプリの種類は限定しない**。Web・スマホ・デスクトップなど、どの種類でも同じ流れで進められるようにする
- 技術スタックとデプロイ先・リリース方法は、プロジェクトごとに要件定義の中で AI と決める（Kickoff 側で特定のサービスに固定しない）

## 4. 想定する利用の流れ

決まった順番はなく、必要なセクションでチャットを立てて進める。典型的には次のようになる。

1. **構想**: アイデアを数行書いて、新規プロジェクトを作る（または既存フォルダを取り込む）
2. **要件定義**: 要件定義のチャットで AI と壁打ちする。AI が選択肢付きで質問し、人が答える。要件定義書（技術スタック・デプロイ方法を含む）ができる
3. **タスク分解**: チャットで依頼すると、AI が受け入れ基準付きのタスクを起票する。人が確認・調整する
4. **スケジュール**: スケジュールのチャットで、マイルストーンと予定日を相談してまとめる
5. **実装**: 実装のチャットごとに作業ブランチ（worktree）を作り、AI が実装する。複数のチャットを並列に進める
6. **レビュー**: 人が差分を見て、OK ならブランチを GitHub に push して PR を作る（マージは GitHub 上で行う）。直してほしければチャットで伝える
7. **テスト・動作確認**: テストのチャットで AI がテストを作って実行する。人はアプリ内からローカルでプレビューして確認する
8. **デプロイ**: デプロイのチャットで、人が承認しながら AI がデプロイし、URL とログを記録する
9. **改善**: 機能追加やバグを起票し、実装のチャットに戻る

外出中はスマホで次のことをする。

- AI の承認依頼・質問に答える
- 進み具合を確認する
- 次の指示を出す

## 5. 機能要件

優先度: **Must** = v1 に必須 / **Should** = v1 に入れたい / **Could** = 将来

### 5.1 プロジェクト

| 優先度 | 機能 |
|---|---|
| Must | 新規作成（名前・アイデア・保存先を指定 → フォルダ作成と `git init`） |
| Must | 一覧（各プロジェクトの現在のフェーズ・進捗・承認待ちの件数） |
| Must | 回答待ち・作業中のチャットがひと目で分かる表示 |
| Must | 既存フォルダの取り込み（git 未管理なら同意のうえ初期化。開始フェーズを選べる。登録済みのフォルダは重複登録しない） |

### 5.2 セクションとチャット

| 優先度 | 機能 |
|---|---|
| Must | サイドバーは プロジェクト → チャット の 2 段。チャットにはセクション（要件定義 / スケジュール / 実装 / テスト / デプロイ）のアイコンと色を付ける |
| Should | サイドバーのプロジェクトに、作業中・回答待ち・確認待ちのチャット数を出す（閉じていても分かる）。プロジェクトは最近動いた順にも並べられる。右クリックで、プロジェクトに対するすべての操作を出す |
| Should | サイドバーで、自分待ち（回答待ち・確認待ち）のチャットだけに絞れる。チャットをプロジェクトのいちばん上に固定できる。チャットを 1 行で詰めて出せる |
| Should | プロジェクトを上に固定（ピン留め）できる。使っていないプロジェクトはアーカイブでき、サイドバー・切り替え・全プロジェクトの画面に出なくなる（見出しの名前のメニューの「アーカイブ済み」から開いて戻せる。サイドバーでは、閉じた「アーカイブしたプロジェクト」を開くと出る） |
| Must | プロジェクトの「＋」（⌘N）で新しいチャットを始め、セクションは入力欄で選ぶ。チャットごとに状態（作業中・回答待ち・完了など）が見える |
| Must | プロジェクト画面はタブ（チャット / 要件定義書 / スケジュール / タスク / レポート / 設定）。チャット一覧はセクションで絞り込める |
| Should | AI の返答のストリーミング表示、ツール実行のまとめ表示と差分表示、チャット名の自動生成、⌘K でチャット・プロジェクトを検索 |
| Must | 関門（確定ボタンで次へ進む）は設けない。どのセクションでもいつでも自由にチャットできる |
| Must | セクションごとに AI の役割と権限を変える（要件定義・スケジュールは読み取り中心、実装は編集可、デプロイは全コマンド承認制 など） |
| Must | セクションを開くと、チャット一覧と、そのセクションで決まったこと（要件定義書・スケジュール・タスク・レポート）を表示する |

### 5.3 要件定義

| 優先度 | 機能 |
|---|---|
| Must | AI とのチャットで要件を詰める。AI の質問に選択肢か自由記述で答える |
| Must | 要件定義書を作って `docs/requirements.md` に保存する（git で版管理） |
| Must | チャットで依頼すると AI がタスクに分解する。タスクは人が編集できる |

### 5.3.1 スケジュール

| 優先度 | 機能 |
|---|---|
| Must | マイルストーン・予定日を AI とチャットで相談し、`docs/schedule.md` にまとめる |
| Should | 要件定義書とタスクをもとに、AI が所要時間の目安と予定の案を出す |

### 5.4 タスク

| 優先度 | 機能 |
|---|---|
| Must | ステータス: TODO / 実行中 / レビュー待ち / PR 作成済み / 完了 / ブロック |
| Must | 人も AI も起票できる（AI が起票したものは区別して表示する） |
| Must | タイトル・内容・受け入れ基準・優先度 |
| Could | タスク間の依存関係 |

### 5.5 エージェント実行（セッション）

| 優先度 | 機能 |
|---|---|
| Must | チャットでエージェントに指示する。追加の指示を出して会話を続けられる。チャットのモデル・推論の深さ・権限モードは入力欄で選ぶ |
| Must | 実装のチャットは 1 チャット = 1 つの作業ブランチ（worktree）にする |
| Must | 実行ログをリアルタイムで表示する（AI の発言・ツールの使用・コマンドの結果） |
| Must | 承認カード（許可 / 常に許可 / 拒否）と、AI の質問への回答 |
| Must | 中断と再開（アプリを再起動しても続きから再開できる） |
| Must | 複数タスクの並列実行（同時実行数に上限を設ける） |
| Must | タスクごとに git worktree とブランチで作業を分離する |
| Could | タスクごとにプロバイダー（Claude / Codex）を選ぶ |

### 5.6 レビュー

| 優先度 | 機能 |
|---|---|
| Must | 変更差分をファイルごとに表示する |
| Must | 承認したら、作業ブランチを GitHub に push して PR を作成する（`gh` CLI のログインを使う） |
| Must | PR のマージは GitHub 上で行う（Kickoff はマージしない）。マージされたらタスクを完了にする |
| Must | 差し戻すとき、コメントを AI に送って再実行する |

### 5.7 テスト・動作確認

| 優先度 | 機能 |
|---|---|
| Must | AI がテストを作って実行し、結果をレポートにまとめる |
| Must | 不具合が見つかったらバグタスクとして起票する |
| Should | 開発対象アプリをローカルで起動・停止して動作確認する（起動コマンドはプロジェクトごとに設定。Web ならブラウザでプレビュー） |

### 5.7.1 ブラウザ

| 優先度 | 機能 |
|---|---|
| Must | カンバン横のパネルのタブで埋め込みブラウザを開く（開発中のアプリのプレビュー・ドキュメント閲覧）。戻る・進む・再読み込み・URL 欄・開発者ツール・Chrome で開く |
| Must | 表示するページは信頼しない外部コンテンツとして扱う（Node.js 不可・専用セッション・http(s) のみ） |
| Should | Chrome 拡張機能の読み込み（開発者ツール向けの拡張。React DevTools はウェブストアから取得・Chrome から取り込み・フォルダ指定） |
| Could | AI に埋め込みブラウザ、または Claude Code の Chrome 連携を通じてブラウザを操作させる（どちらが使えるか確認してから決める） |

Bitwarden のようにポップアップや Chrome の機能を多く使う拡張は Electron で動かないため、ログインが必要なページは「Chrome で開く」で普段の Chrome に渡す。

### 5.7.2 ターミナル

| 優先度 | 機能 |
|---|---|
| Must | 画面の下のパネルで内蔵ターミナルを開く（VS Code と同じく、どの画面でも ⌃` / ⌘J・右上のレイアウトの開閉から開閉。複数のタブ・高さの変更・最大化） |
| Must | 右のパネルのタブでも内蔵ターミナルを開ける（タブの列の＋から。プロジェクトの本体、またはチャットの作業場所（ワークツリー）で始める） |
| Must | シェルは Mac のアプリの中だけで動かし、Kickoff のサーバー（スマホから届く）は通さない |
| Must | タブを裏に回しても・ボードを切り替えてもシェルは動き続け、戻ったら画面の内容をそのまま出す。タブを閉じる・アプリを終える・画面を読み直すとシェルを止める |
| Should | URL を ⌘ を押しながら押すと、アプリの中のブラウザのタブで開く |
| Could | 外の Ghostty で開く・Ghostty の設定（フォント・配色）を読み込む・描画を ghostty-web に替える |

### 5.8 デプロイ

| 優先度 | 機能 |
|---|---|
| Must | デプロイ先・リリース手順をプロジェクトごとに設定（要件定義で AI が提案し、人が確定） |
| Must | 事前チェック（テスト合格・未マージの変更なし）→ 人の承認 → 実行 → 結果（URL・ビルド成果物など）とログを記録 |
| Could | よく使うデプロイ先のテンプレート（Vercel、App Store など） |

### 5.9 スマホ連携

| 優先度 | 機能 |
|---|---|
| Must | 同じ Wi-Fi か Tailscale 経由で、スマホのブラウザから操作する（トークン認証・QR でペアリング） |
| Must | スマホでできること: 承認・質問への回答、進捗とログの確認、タスクの作成・実行の指示 |
| Should | 通知（承認待ち・完了・失敗）。v1 は macOS の通知と ntfy（任意） |
| Could | ネイティブアプリ（デスクトップと同じ API を使う）とプッシュ通知 |

### 5.10 設定

| 優先度 | 機能 |
|---|---|
| Must | プロバイダーのログイン状態の表示とモデルの選択 |
| Must | 同時実行数、通知、スマホ連携の on / off |

## 6. 非機能要件

- **ローカル完結**: データは Mac 内（SQLite）に置く。外部に送るのは AI プロバイダーへの通信と、任意で有効にする通知だけ
- **セキュリティ**: 外部からのアクセスはトークン必須。デプロイやリポジトリ外への書き込みなど、影響の大きい操作は承認制
- **使用量**: サブスクリプションの上限を意識する（同時実行数の上限、API 換算の推定コストを表示）
- **拡張性**: プロバイダーを追加しやすくする。HTTP API はデスクトップの画面・スマホのブラウザ・将来のネイティブアプリで共通にする
- **復旧性**: アプリが落ちても、中断した実行を続きから再開できる

## 7. 画面構成（案）

```
┌────────────────┬──────────────────────────────────────┐
│ ▾ Memo         │ Memo / 実装                     ＋ 新しいチャット │
│   ▸ 要件定義  ＋ │ ┌ チャット入力欄 ───────────────────┐ │
│   ▸ スケジュール＋ │ │ ✳ Opus 5.5 ⌄  ◎ High ⌄  ⛨ Auto mode ⌄ ↑ │ │
│   ▾ 実装     ＋ │ └──────────────────────────────┘ │
│      ログイン画面 ●│ チャット一覧 / タスク / 成果物                │
│      DB 設計   ? │                                      │
│   ▸ テスト    ＋ │                                      │
│   ▸ デプロイ   ＋ │                                      │
│ ＋ 新規          │                                      │
│ 5時間 ▬▬ 週 ▬   │                                      │
└────────────────┴──────────────────────────────────────┘
```

- 承認依頼と AI からの質問は、チャットの中と、サイドバーの印で分かるようにする
- スマホでは同じ画面を縦 1 列にして表示する

## 8. 前提条件

- 開発対象アプリのリポジトリは、GitHub 上に自分で作成し、remote（origin）を設定しておく（Kickoff はリポジトリを作成しない）
- Mac に `claude`（Claude Code）と `gh`（GitHub CLI）がインストールされ、ログイン済みであること
